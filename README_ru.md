# Проект μ16

μ16 — это простой 16-битный компьютер, построенный с нуля, вместе со всем, что нужно для работы с ним: спецификациями процессора и машины, двумя эмуляторами, ассемблером, языком системного программирования с компилятором, скриптовым языком, файловой системой и операционной системой **Монитор**. Всё подробно задокументировано, а спецификации нормативны: инструменты проверяются на соответствие им.

Проект задуман так, чтобы его можно было понять целиком. У процессора небольшая регулярная система команд, у машины — несколько устройств, отображённых на память, а операционная система не вытесняет процессы и не скрывает «магии». Систему можно изучать на любом уровне: от одной команды в отладчике до скрипта, работающего в готовой ОС.

## Как устроен проект

```text
 исходник B16 ──b16c──▶ ассемблер ──cpu16asm──▶ двоичный образ ──▶ cpu16 / веб-отладчик
 вручную написанный .asm ─────────────────────────▲                      │
                                                                         ▼
          BScript ──bsc──▶ байт-код ──bsvm──▶  Монитор (ядро, оболочка, утилиты)
          (сам написан на B16 и работает на машине CPU16)
```

| Уровень | Что это |
| --- | --- |
| Процессор CPU16 | 16-битный процессор: 16 регистров, компактные одно- и двухсловные команды, прерывания |
| Машина CPU16 | Карта памяти, цветной дисплей 80×25, клавиатура, таймер 50 Гц, часы реального времени, контроллер дисков, диспетчер памяти |
| Монитор | Операционная система: загрузка с диска, файловая система ФС16, процессы, сеансы, системные вызовы, оболочка, утилиты |
| Языки | ассемблер `cpu16asm`, **B16** (компилируемый язык системного программирования), **BScript** (динамический скриптовый язык) |
| Инструменты | эмулятор `cpu16`, веб-отладчик, компилятор `b16c`, ассемблер `cpu16asm` |

## Процессор CPU16

- **Регистры.** Шестнадцать 16-битных регистров: `R0`–`R11` общего назначения, `R12` — регистр возврата `LR`, `R13` — указатель стека `SP`, `R14` — счётчик команд `IP`, `R15` — флаги `FLAGS`. `IP` и `FLAGS` — обычные регистры: переход — это запись в `IP`, а `LD IP, LR` — возврат из подпрограммы.
- **Память.** Адресное пространство 64 КиБ с побайтовой адресацией, слова хранятся младшим байтом вперёд, слова и команды выровнены по чётным адресам.
- **Команды.** Занимают одно или два слова и обращаются к памяти не более одного раза. Формат двухадресный (`ADD R0, [R1++]` означает `R0 = R0 + [R1]`, затем `R1 += 2`). Режимы адресации: непосредственный, регистровый, косвенный, с автоинкрементом и автодекрементом, абсолютный и базовый со смещением.
- **Арифметика.** Сложение и вычитание с переносом для многословной арифметики, умножение 16×16 (`MUL`, `MULHU`), беззнаковые деление и остаток. Деление на ноль не вызывает исключения, а устанавливает флаг. Знаковое умножение и деление выполняются программно.
- **Подпрограммы.** `CALL` записывает адрес возврата в `LR`, а не в стек, поэтому листовым подпрограммам стек не нужен. По стандартному соглашению аргументы передаются в `R0`–`R3`, а `R4`–`R11` нужно сохранять.
- **Прерывания.** Восемь линий IRQ, программные прерывания (`TRAP #n`) и исключение ERRCMD для недопустимых команд; обработчики выбираются по таблице из 16 векторов с адреса `$FF00`.
- **Состояние после сброса.** Все регистры равны нулю, прерывания запрещены, выполнение начинается с адреса `$0000`.

Архитектура определена в документе «Минималистическая архитектура 16-битного процессора» (ревизия 6), а язык ассемблера — в «Справочнике по языку ассемблера».

## Машина CPU16

Спецификация машины (ревизия 9) описывает всё, что находится вне процессора:

- **Консоль и дисплей.** Один порт работает и как простой телетайп, и как текстовый дисплей 80×25 с цветом каждой ячейки, курсором, позиционным выводом и чтением экрана. Однобайтовая кодировка сочетает ASCII, символы псевдографики и кириллицу.
- **Клавиатура.** Коды символов, скан-коды и модификаторы Shift, Ctrl, Alt.
- **Таймер и часы.** Таймер 50 Гц на IRQ0 и часы реального времени, формат значения которых совпадает с форматом отметок времени файловой системы.
- **Контроллер дисков.** До восьми дисков с секторами по 512 байт; команды `READ`, `WRITE`, `INFO`, `FLUSH`; завершение сигнализируется по IRQ1.
- **Диспетчер памяти.** Восемь логических страниц по 8 КиБ отображаются на физические кадры, всего до 256 кадров (2 МиБ). Монитор использует его, чтобы у каждого процесса было своё адресное пространство.

Окно устройств занимает `$FF20–$FFFF`; обычные программы могут использовать всё адресное пространство ниже него.

## Инструменты

### Эмуляторы

- **`cpu16`** — эмулятор командной строки. Он запускает плоские двоичные образы, подключает образы дисков (`--disk N=файл[:ro]`) и поддерживает трассировку команд (`-t`), ограничение числа шагов (`-n`), проверку выравнивания, фиксированное начальное время для воспроизводимых запусков (`--rtc`) и вывод содержимого экрана по завершении (`--screen`).
- **Веб-отладчик** (`webdbg/cpu16_debugger.html`) — один HTML-файл, целиком работающий в браузере. В нём есть редактор, ассемблер, пошаговая отладка по исходному тексту с точками останова, дизассемблер, панели регистров, памяти и устройств, отдельное окно Display, менеджер дисков со встроенным загрузочным ПЗУ и файловый менеджер ФС16.

Оба эмулятора реализуют одну и ту же машину; их совпадение проверяется сравнением выполнения случайных программ.

### Ассемблер `cpu16asm`

```text
cpu16asm prog.asm            # создаёт prog.bin
cpu16asm prog.asm -l prog.lst -m prog.map
```

Метки (глобальные и локальные `@`), выражения, директивы `.org`, `.word`, `.asciz`, `.include` и другие; по желанию создаются листинг и карта памяти. Стандартная библиотека `stdlib.asm` содержит ввод-вывод на консоль, печать десятичных и шестнадцатеричных чисел, ввод строк, работу со строками и памятью, 32-битную арифметику, а также вспомогательные подпрограммы для дисплея, клавиатуры, таймера и часов.

### B16 и компилятор `b16c`

B16 — компилируемый язык системного программирования, близкий по духу к B и C. Он сделан так, чтобы машина оставалась видимой: каждый оператор превращается в короткую предсказуемую последовательность команд, а дорогие операции выглядят дорогими.

- Типы: `byte`, `char`, `int`, `uint`, `long`, `ulong`, типизированные указатели, массивы, структуры и указатели на функции.
- Несколько возвращаемых значений, обработчики `interrupt fn`, `goto` и встроенный ассемблер. Отдельные ассемблерные модули подключаются через `include asm`.
- Локальные переменные находятся в регистрах, если их не вынуждает уйти в память что-то другое.
- Нет препроцессора, чисел с плавающей запятой и скрытого копирования структур.

Программа на B16 собирается в исполняемый файл формата CX16, который при одном и том же образе работает и на голой машине, и под Монитором. Компилятор выдаёт текст на ассемблере для `cpu16asm`.

```text
include "io.b16"

fn main() {
    puts("Hello, CPU16!\n")
}
```

### BScript

BScript — небольшой динамический язык для задач, на которые на B16 уходит слишком много времени: обход каталогов, разбор текста, запуск утилит и проверка их вывода. В нём есть `int` (знаковое 16-битное), строки, массивы, словари, несколько возвращаемых значений, интерполяция строк и ошибки как значения, которые передаются вызывающему автоматически, если скрипт их не перехватил. Исходный текст компилируется в байт-код программой `bsc` и исполняется виртуальной машиной `bsvm`; запускатель `bs` хранит скомпилированный файл `.bsc` рядом с исходником. Все три программы написаны на B16 и работают на самой машине CPU16.

```text
println("hello, world")
```

## Операционная система Монитор

Монитор — компактная и читаемая операционная система. Ядро написано в основном на B16, а небольшая резидентная часть — на ассемблере.

**Загрузка.** ПЗУ читает три загрузочных сектора диска 0, загрузочный код тома находит на томе ФС16 файл `/sys/monitor.sys` и загружает его, а ядро запускает оболочку `A:/sys/shell.cx`. Веб-отладчик содержит встроенное загрузочное ПЗУ; для эмулятора командной строки ПЗУ — это файл `monitor/dist/rom.bin`.

**Процессы.** Программа — это исполняемый файл формата CX16, загружаемый по адресу `$0000` в собственное адресное пространство, без перемещения кода. Процессы образуют цепочку: процесс запускает потомка вызовом `SPAWN` и ждёт его, а работает только последний процесс цепочки. Ядро никогда само не переключает процессы и выполняется с запрещёнными прерываниями, поэтому системные вызовы атомарны и блокировки не нужны. Можно держать до четырёх **сеансов** (у каждого своя цепочка процессов и свой экран) и переключаться между ними, но в каждый момент работает только один.

**Системные вызовы.** Программы обращаются к ядру через `TRAP #9`. Интерфейс охватывает процессы (`SPAWN`, `EXEC`, `EXIT`), дескрипторы файлов и устройств, файловую систему, события консоли и позиционный вывод, память (включая расширенную), время, сеансы и прямой доступ к дискам.

**Файловая система.** ФС16 поддерживает тома до 128 МБ: сектор 512 байт, кластер 2 КиБ, 16-битные номера кластеров, 64-байтовые элементы каталога, в которых хранятся метаданные файла, прямые, косвенные и двойные косвенные указатели на данные и битовая карта свободного места. Тома обозначаются буквами `A:`–`H:`, имена нечувствительны к регистру, а флаг DIRTY и правила порядка записи позволяют `fsck` восстановить том после некорректного завершения работы.

**Оболочка и утилиты.** Оболочка поддерживает конвейеры, перенаправления (`<`, `>`, `>>`, `2>`), командные скрипты, стартовый скрипт (`A:/sys/startup`) и сеансы. В `A:/bin` находятся утилиты `ls`, `cat`, `cp`, `mv`, `rm`, `mkdir`, `rmdir`, `attr`, `df`, `mount`, `umount`, `sync`, `date`, `touch`, `mem`, `sysboot` и `fsck`. Есть две полноэкранные программы: **`fm`** — двухпанельный файловый менеджер в стиле Norton Commander и **`edit`** — текстовый редактор с выделением, буфером обмена, отменой действий, поиском и заменой. Рядом с ними установлены программы BScript (`bs`, `bsc`, `bsvm`).

Оболочка, утилиты, `fm`, `edit` и программы BScript — обычные программы: они пользуются только системными вызовами и не имеют особых привилегий.

## Быстрый старт

**Запуск программы на ассемблере** (положите `stdlib.asm` рядом или поправьте путь в `.include`):

```asm
        LD      SP, #$FF00      ; инициализировать стек
        LD      R0, #hello
        CALL    puts            ; библиотечная подпрограмма
        WFI                     ; остановиться
hello:  .asciz  "Hello, CPU16!\n"
        .include "stdlib.asm"
```

```text
cpu16asm hello.asm
cpu16 hello.bin
```

**Загрузка Монитора** из готового комплекта (`make dist` пересобирает его из исходников):

```text
cd monitor && make dist
../cpu16/build/cpu16 --disk 0=dist/system.img dist/rom.bin
```

В архив входят готовые файлы `monitor/dist/system.img` и `monitor/dist/rom.bin`; `make dist` создаёт их заново. Чтобы загрузиться в веб-отладчике, подключите `monitor/dist/system.img` как диск 0 и нажмите **Boot** (загрузочное ПЗУ встроено в отладчик). `fm` и `edit` рисуют прямо на дисплее, поэтому для них используйте окно **Display** отладчика: эмулятор командной строки не передаёт позиционный вывод в stdout.

**Сборка и запуск программы на B16** из каталога `b16c/` (компиляция, ассемблирование и запуск в эмуляторе):

```text
./run.sh examples/universal/hello.b16
```

## Сборка и проверка

```text
cd cpu16 && make test           # эмулятор, ассемблер, библиотека; веб-отладчик через ../webdbg

cd webdbg && make test-ui       # тесты интерфейса (Playwright)
cd monitor && make test         # операционная система
```
