# Монитор CPU16: формат исполняемого файла и запуск программ. Ревизия 4

Ревизия 3 согласует документ со спецификацией системных вызовов монитора и с B16 ревизии 2. Формат файла, заголовок, PIB и блок аргументов не меняются. Изменения по ревизиям собраны в разделе 11.

Документ описывает формат исполняемого файла для монитора CPU16, блок сведений о процессе (PIB), размещение аргументов командной строки и состояние программы при запуске.

## 1. Обзор

Программа хранится в файле как плоский образ памяти с адреса `$0000`, как его выводит ассемблер. Отличие от «голого» образа одно: сразу за начальным переходом лежит **заголовок** — 12 слов со сведениями для загрузчика.

Загрузчик монитора:

1. проверяет заголовок и выделяет программе память;
2. читает образ с адреса `$0000` и обнуляет неинициализированные данные;
3. кладёт разобранную командную строку (**блок аргументов**) сразу за статическими данными программы;
4. записывает **PIB** поверх заголовка: после загрузки заголовок больше не нужен;
5. передаёт управление на `$0000`.

Перемещения кода нет. Каждый процесс получает собственное адресное пространство через менеджер памяти и всегда загружается с адреса `$0000`.

**Термины:**

| Термин | Значение |
|---|---|
| образ | содержимое файла от адреса `$0000` до `image_end` |
| bss | неинициализированные статические данные `image_end … bss_end`; в файле не хранятся, загрузчик их обнуляет |
| `bss_end′` | `bss_end`, округлённый вверх до чётного |
| блок аргументов | массив `argv` и строки аргументов, начиная с `bss_end′` |
| `args_size` | размер блока аргументов в байтах, чётный (разд. 6) |
| `top` | верхняя граница памяти, выделенной процессу; кратна `$2000` |
| PIB | блок сведений о процессе по адресам `$0004–$001B` |

## 2. Адресное пространство процесса

Монитор работает при включённом менеджере памяти. Страница 7 (`$E000–$FFFF`) общая для всех процессов: в ней лежат ядро монитора, таблица векторов и окно устройств. Процессу доступны страницы 0–6.

| Адреса | Назначение |
|---|---|
| `$0000 … top − 1` | память процесса |
| `top … $DFFF` | не выделены; обращаться к ним запрещено |
| `$E000–$FFFF` | общая страница монитора (резидентная часть ядра, процедура выхода), векторы, устройства |

- `top` не больше `$E000`.
- Защиты памяти нет. Обращение за `top` и запись в страницу 7 — ошибка программы с неопределённым результатом.

## 3. Файл программы

### 3.1. Структура

| Смещение в файле | Содержимое |
|---|---|
| `$0000–$0003` | начальный переход `JMP #start` |
| `$0004–$001B` | заголовок |
| `$001C … image_end − 1` | код и инициализированные данные |
| `image_end …` | необязательные дополнительные данные; загрузчик их не читает |

Файл — образ памяти: байт со смещением A загружается по адресу A.

### 3.2. Заголовок

Все поля — слова. Порядок байтов машинный: младший байт по меньшему адресу.

| Адрес | Поле | Значение |
|---|---|---|
| `$0000` | переход | `$C873` — код команды `JMP #выр` |
| `$0002` | `start` | адрес точки входа |
| `$0004` | `magic` | 4 байта `"CX16"`: `$43 $58 $31 $36` |
| `$0008` | `version` | версия формата, 1 |
| `$000A` | `flags` | 0 |
| `$000C` | `image_end` | длина образа в байтах |
| `$000E` | `bss_end` | конец статических данных |
| `$0010` | `min_free` | минимум свободной памяти под стек и кучу, байт |
| `$0012` | `max_top` | желаемая верхняя граница памяти; 0 — максимум |
| `$0014–$001B` | резерв | 4 слова, должны быть равны 0 |

Начальный переход записывается в абсолютной форме `JMP #start`. Только она гарантированно занимает два слова, так что заголовок всегда начинается с `$0004`.

### 3.3. Требования к заголовку

Загрузчик отклоняет файл, если нарушено хотя бы одно условие:

1. слово по `$0000` равно `$C873`, байты `$0004–$0007` равны `"CX16"`;
2. `version` = 1;
3. `flags` = 0 (неизвестный бит — отказ, а не игнорирование);
4. резервные слова равны 0;
5. `$001C` ≤ `image_end` ≤ `bss_end` ≤ `$E000`;
6. `start` чётный и `$001C` ≤ `start` < `image_end`;
7. `min_free` чётный;
8. длина файла не меньше `image_end`.

`max_top` проверке не подлежит: значения больше `$E000` ограничиваются этим адресом (разд. 6).

## 4. Блок сведений о процессе (PIB)

После загрузки по адресам `$0004–$001B` лежит PIB. Поля `version` и `bss_end` стоят на тех же смещениях, что в заголовке.

| Адрес | Поле | Значение |
|---|---|---|
| `$0004` | `magic` | 4 байта `"CXPB"`: `$43 $58 $50 $42` |
| `$0008` | `version` | версия PIB, 1 |
| `$000A` | `flags` | бит 0 — стандартный ввод перенаправлен (дескриптор 0 — не консоль), бит 1 — стандартный вывод перенаправлен (дескриптор 1 — не консоль); остальные 0. Биты ставит монитор («Системные вызовы», разд. 7.1) |
| `$000C` | `argc` | число аргументов, не меньше 1 |
| `$000E` | `bss_end` | значение из заголовка |
| `$0010` | `argv` | адрес массива `argv[0..argc]` |
| `$0012` | `args_end` | первый байт за блоком аргументов (чётный) |
| `$0014` | `top` | верхняя граница выделенной памяти |
| `$0016–$001B` | резерв | 3 слова, равны 0 |

- Монитор PIB после запуска не читает и не изменяет. Программа может использовать эту память как угодно.
- Метки программы, попавшие в `$0004–$001B`, после загрузки указывают на поля PIB. Читать свой заголовок во время работы программа не должна.
- Сигнатура позволяет определить способ запуска: `"CXPB"` по `$0004` — программу запустил монитор; `"CX16"` — её запустили прямо из файла на голой машине (разд. 8).

## 5. Аргументы командной строки

### 5.1. Блок аргументов

Блок лежит с адреса `bss_end′` по `args_end − 1`. По возрастанию адресов:

1. массив `argv[0..argc]` — по слову на элемент: адреса строк, `argv[argc] = 0`;
2. строки аргументов в порядке номеров, каждая с завершающим нулём, вплотную друг к другу;
3. при нечётной общей длине — один байт 0 для выравнивания.

Поле `argv` в PIB всегда равно `bss_end′`. Программы всё равно должны брать адрес из PIB или из R1.

Блок — обычная память процесса. Монитор его не охраняет. Программа, которой аргументы нужны, должна прочитать или скопировать их до того, как займёт эту память под кучу (разд. 7).

### 5.2. Разбор

Командную строку разбирает монитор. Правила одинаковы для оболочки и для запуска из программы.

- **Разделители** — пробел (`$20`) и табуляция (`$09`). Несколько разделителей подряд равны одному, начальные и конечные игнорируются.
- **Кавычки.** Текст в двойных кавычках `"…"` входит в слово целиком, вместе с разделителями. Сами кавычки в аргумент не попадают. Кавычки могут стоять внутри слова: `a"b c"d` даёт `ab cd`. Незакрытая кавычка — ошибка. Экранирования нет: включить двойную кавычку в аргумент нельзя.
- **Пустой аргумент** `""` допустим и даёт строку нулевой длины.
- **`argv[0]`** — первое слово командной строки как есть: путь, по которому загрузчик открыл файл программы. Монитор не ищет программу по каталогам и не добавляет расширение — это делает оболочка («Системные вызовы», разд. 7.1).
- **Перенаправления** ввода и вывода обрабатывает оболочка до запуска. В блок аргументов они не попадают.
- **Ограничения:** командная строка не длиннее 255 байт, аргументов вместе с `argv[0]` не больше 32. При нарушении программа не запускается.

Исходная строка программе не передаётся: только разобранные аргументы.

## 6. Выделение памяти

Пусть `args_size` — размер блока аргументов (разд. 5.1) в байтах: 2·(argc + 1) плюс длины строк с нулями, с округлением вверх до чётного. Блок занимает адреса `bss_end′ … args_end − 1`, поэтому `args_end` = `bss_end′` + `args_size`. Обозначим через `⌈x⌉` округление вверх до кратного `$2000`.

| Величина | Формула |
|---|---|
| потребность `need` | `⌈bss_end′ + args_size + min_free⌉` |
| желание `want` | `$E000`, если `max_top` = 0 или `max_top` > `$E000`; иначе `⌈max_top⌉` |
| `top` | меньшее из `want` и объёма доступной памяти, но не меньше `need` |

- Если `need` больше `$E000` или больше доступной памяти, программа не запускается.
- Если `want` меньше `need`, берётся `need`.
- Вычисления выполняются без переполнения: промежуточные суммы, превысившие `$E000`, означают отказ.

Процесс получает `top / $2000` кадров в страницах 0 … `top/$2000 − 1`. Все выделенные кадры обнулены, кроме того, что записал загрузчик. Свободная память процесса — `args_end … top − 1`. Стек начинается с `top` и растёт вниз.

## 7. Память процесса после загрузки

| Адреса | Содержимое |
|---|---|
| `$0000–$0003` | `JMP #start` |
| `$0004–$001B` | PIB |
| `$001C … image_end − 1` | образ из файла |
| `image_end … bss_end − 1` | bss, нули |
| `bss_end′ … args_end − 1` | блок аргументов |
| `args_end … SP` | свободно |
| `… top − 1` | стек |

Свободная память ограничена снизу `bss_end′`, если программа уже прочитала аргументы, или `args_end`, если хочет их сохранить. Куча растёт вверх, стек вниз. Столкновение не обнаруживается.

## 8. Состояние при запуске

### 8.1. Под монитором

| Ресурс | Значение |
|---|---|
| IP | `$0000` |
| R0 | argc |
| R1 | argv |
| SP | `top` |
| LR | `$E000` — адрес процедуры выхода в мониторе |
| FLAGS | `$08`: IF = 1, прерывания разрешены; ZF, CF, SF, OF равны 0 |
| остальные регистры | 0 |

Процедура выхода завершает программу с кодом из R0. Поэтому программа, которая вернула стек и LR в исходное состояние, может закончить работу командой `RET`. Другой способ — вызов `EXIT`; коды завершения и завершение программы монитором описаны в «Системных вызовах», разд. 7.2.

Процедура выхода работает при любом значении IF: программа, завершающаяся внутри критической секции, не обязана сначала разрешать прерывания.

### 8.2. На голой машине

Файл в этом формате можно запустить эмулятором без монитора: `JMP #start` перешагнёт заголовок. В этом случае по `$0004` лежит `"CX16"`, PIB и аргументов нет, регистры равны 0 (в том числе SP), менеджер памяти выключен.

Прерывания на голой машине запрещены (IF = 0, спецификация процессора, разд. 9): таблица векторов не заполнена, и программа сама решает, нужны ли ей прерывания. Останавливает голую машину программа сама, по рецепту «Машины», разд. 3: выключить таймер, `STI`, `CLI`, `WFI`.

Программа, рассчитанная на оба режима, должна проверить сигнатуру до первого обращения к стеку (разд. 9.3) и не должна полагаться на начальное значение IF (разд. 8.3). Программа только для монитора может считать запуск без монитора ошибкой своего пользователя.

### 8.3. Прерывания под монитором

Программа работает с разрешёнными прерываниями. Монитор обслуживает прерывания устройств, которыми он владеет (таймер, контроллер дисков), пока программа выполняется. Обработчики монитора возвращают управление в прерванное место программы; регистры и флаги программы, кроме того, что сказано ниже, они не меняют.

**Стек.** Прерывание может прийти между любыми двумя командами программы. При входе в прерывание процессор кладёт на стек программы 4 байта: IP и FLAGS (спецификация процессора, разд. 8.3). Поэтому, пока IF = 1:

- 4 байта ниже SP, то есть адреса `SP − 4 … SP − 1`, должны быть памятью процесса (ниже `top`);
- данные, лежащие ниже SP, могут быть испорчены в любой момент: программа не должна хранить там ничего;
- SP нельзя использовать как регистр общего назначения.

Программа, которой нужно временно нарушить эти правила (например, сменить стек), делает это при IF = 0.

**Таблица векторов и обработчики** принадлежат монитору: они лежат в странице 7 (разд. 2). Программа не должна записывать векторы и включать или выключать таймер. Тики таймера программа получает через обработчик, установленный вызовом `TICKHOOK` («Системные вызовы», разд. 7.4). Какие устройства программа может использовать напрямую, а какие — только через вызовы, сказано в «Системных вызовах», разд. 2.2.

**Запрет прерываний.** Программа вправе запрещать прерывания (`CLI`), но только кратковременно — на критическую секцию из немногих команд. Пока IF = 0:

- монитор не обслуживает устройства: тики таймера сливаются в один запрос и теряются (машина, разд. 3), счёт времени по тикам отстаёт;
- монитор не забирает события клавиатуры: очередь вмещает 256 событий, лишние отбрасываются (машина, разд. 2.6);
- не действуют реакции монитора, которые выполняются в обработчиках прерываний: прерывание программы клавишами Ctrl+C («Системные вызовы», разд. 6.3) и вызов обработчика `TICKHOOK`.

Программа, оставившая IF = 0 надолго, нарушает работу монитора; программа, зациклившаяся при IF = 0, останавливает систему, и вернуть управление можно только сбросом машины. За длительность критических секций отвечает программа.

**Критическая секция** оформляется так, чтобы восстанавливалось прежнее значение IF, а не безусловно IF = 1:

```asm
        PUSH    FLAGS
        CLI
        ...                             ; критическая секция
        POP     FLAGS
```

Пара `CLI` … `STI` допустима, только если программа точно знает, что до `CLI` было IF = 1. Код, который может выполняться и под монитором, и на голой машине, должен пользоваться `PUSH FLAGS` / `POP FLAGS`: безусловная `STI` на голой машине разрешит прерывания при незаполненной таблице векторов.

**Системные вызовы** входят в монитор через `TRAP`, которая сбрасывает IF, и возвращаются через `IRET`, которая восстанавливает FLAGS программы целиком. Значение IF после вызова равно значению до вызова, если спецификация системных вызовов не говорит иного.

**`WFI`.** При IF = 1 команда `WFI` ждёт ближайшего прерывания, например тика таймера, и возвращает управление программе. Ожидание событий — ввода, времени — программа выполняет системными вызовами (`READ`, `CON_GETEV`, `SLEEP`), а не циклом с `WFI`. Рецепт остановки голой машины (разд. 8.2) под монитором неприменим: таймером владеет монитор, а `WFI` при работающем таймере — только ожидание. Для завершения служат процедура выхода и `EXIT`.

## 9. Рекомендации по реализации

### 9.1. Загрузчик

**Порядок работы:**

1. Найти файл и прочитать его первый сектор в буфер ядра. Скопировать поля заголовка в переменные ядра: дальше образ затрёт заголовок.
2. Проверить заголовок (разд. 3.3).
3. Разобрать командную строку во временный буфер ядра и вычислить `args_size` (разд. 6).
4. Вычислить `need`, `want`, `top` (разд. 6) и выделить кадры. На любом отказе до этого шага выделенные ресурсы освобождаются, и вызывающий получает ошибку.
5. Отобразить кадры процесса в страницы 0 … `top/$2000 − 1` и обнулить их.
6. Прочитать образ DMA прямо в память процесса.
7. Записать блок аргументов с `bss_end′`, затем PIB.
8. Установить регистры (разд. 8.1) и перейти на `$0000`.

**Передача управления.** IF = 1 должен установиться одновременно с переходом на `$0000`, иначе прерывание может прийти, пока регистры и отображение программы ещё не готовы. Удобный способ — `IRET`: загрузчик кладёт по адресам `top − 4` и `top − 2` слова FLAGS = `$08` и IP = `$0000`, ставит SP = `top − 4`, остальные регистры по разд. 8.1, и выполняет `IRET`. После неё SP = `top`. Два слова под `top` остаются в памяти процесса как обычный мусор стека.

**Где выполняется загрузчик.** Загрузчик — часть ядра монитора и работает в карте ядра: кадры нового процесса он по очереди отображает в окна карты ядра, обнуляет их и читает в них образ DMA. Карта процесса начинает действовать только при передаче управления. Её выполняет резидентная часть монитора в общей странице 7: она переключает страницы 0–6 на кадры процесса и выполняет `IRET`. Код в странице 7 при этом не меняет адреса, поэтому трамплин не нужен, а `IRET` служит точкой синхронизации и для смены отображения, и для кода, прочитанного DMA.

**Чтение образа.** Образ читается целыми секторами: `⌈image_end / 512⌉` секторов с адреса `$0000`. Последний сектор может захватить до 511 байт за `image_end`, но они не выходят за `top`, потому что `top` кратна 8 КБ, а 8 КБ кратны 512. Байты `image_end … ⌈image_end/512⌉·512 − 1` после чтения нужно обнулить снова: там могут оказаться дополнительные данные файла или мусор за концом файла.

**Обнуление.** Кадры нужно обнулять целиком, а не только bss: иначе процесс увидит данные предыдущего владельца. Удобный порядок — обнулить кадры до чтения образа. Тогда после чтения остаётся дочистить только хвост последнего сектора.

**Страницы за `top`.** Их тоже нужно на что-то отобразить, потому что у менеджера памяти нет признака «страница отсутствует». Рекомендуется отдельный «мусорный» кадр, общий для всех процессов: ошибочная запись за `top` портит только его, а не чужую память.

**Арифметика.** В 16 битах суммы разд. 6 переполняются: перед каждым сложением проверяйте перенос (CF) или сравнивайте слагаемые с `$E000` заранее. Округление `(x + $1FFF) & $E000` переполняется при `x > $E000`, поэтому проверка границы должна идти до него. В ядре на B16 проще считать `need` в `ulong` (B16, ревизия 2) и сравнивать результат с `$E000`: переполнения тогда нет.

**Ошибки загрузки.** Монитор различает следующие ошибки и возвращает их коды из `SPAWN` («Системные вызовы», разд. 8):

| Ошибка | Причина | Код |
|---|---|---|
| не найден | файла нет; ошибка пути | `NOENT` (4), ошибки пути («Системные вызовы», разд. 4.1); `ISDIR` (7), если путь — каталог |
| не исполняемый файл | нарушено условие разд. 3.3, кроме версии | `NOEXEC` (17) |
| неподдерживаемая версия | `version` ≠ 1 | `BADVER` (18) |
| ошибка аргументов | длина строки, число аргументов, незакрытая кавычка | `ARGS` (19) |
| не хватает памяти | `need` больше `$E000` или больше свободных кадров | `NOMEM` (20) |
| ошибка ввода-вывода | ошибка диска при чтении | `IO` (16) |

При любой из них процесс не создаётся, а вызывающий получает ошибку.

### 9.2. Стартовый код программы

- Сначала прочитать аргументы, затем инициализировать кучу. Начало кучи — `bss_end′` (поле `bss_end` в PIB, округлённое до чётного), если аргументы скопированы, или `args_end`, если программа хранит указатели из `argv`.
- Верхняя граница кучи — текущий SP минус запас под стек. Монитор об этом запасе не знает: `min_free` лишь гарантирует, что память есть.
- Адрес возврата из LR нужно сохранить, если программа собирается завершаться через `RET` после вызовов.
- Прерывания при входе уже разрешены (разд. 8.1). Стартовый код не должен выполнять `STI`, если программа может запускаться и на голой машине: там это решение принимает ветка голой машины после заполнения векторов. Смена стека, если она нужна, выполняется при IF = 0 (разд. 8.3).
- `min_free` выбирается с запасом на глубину стека. Для небольших утилит достаточно 1–4 КБ, для компилятора — сколько нужно его таблицам, если они в куче.
- Программа, которой нужна вся память, задаёт `max_top` = 0. Маленькая утилита задаёт `max_top`, равный `need`, чтобы не занимать кадры, нужные другим процессам.

### 9.3. Определение способа запуска

```asm
        .equ    PIB_MAGIC, $0004

start:  LD      R4, [PIB_MAGIC+2]
        CMP     R4, #'P' | 'B' << 8     ; "CXPB": вторая половина
        JZ      @under_monitor
        LD      SP, #$FF00              ; голая машина: стек свой
        ...
@under_monitor:
        ...
```

Достаточно сравнить второе слово сигнатуры: первое у заголовка и PIB совпадает (`"CX"`).

Проверка безопасна в обоих режимах. Под монитором прерывания разрешены, но SP уже равен `top`, и стек действителен с первой команды. На голой машине SP = 0, но прерывания запрещены, поэтому до установки SP на стек ничего не попадёт.

### 9.4. Пример программы

Программа выводит аргументы по одному в строке прямо в консоль и завершается командой `RET` с кодом 0. Прямой вывод в регистр DATA под монитором разрешён, но обходит перенаправление стандартного вывода («Системные вызовы», разд. 6.4); программа, вывод которой нужно перенаправлять, пишет через `WRITE`. Данных у неё нет, поэтому `image_end` и `bss_end` совпадают. Метки перед `.align` получают значение счётчика (Справочник ассемблера, правило «Метки и выравнивание»), поэтому так удобно обозначить конец образа.

```asm
        .equ    CON_DATA, $FF20

        .org    0
        JMP     #start
        .ascii  "CX16"
        .word   1, 0                    ; version, flags
        .word   image_end, bss_end
        .word   512                     ; min_free
        .word   $2000                   ; max_top: хватит одной страницы
        .word   0, 0, 0, 0              ; резерв

start:  LD      R2, R1                  ; R2 = argv
@arg:   LD      R3, [R2++]              ; очередной указатель
        CMP     R3, #0
        JZ      @done
@ch:    LDZX    R4, [R3++]
        CMP     R4, #0
        JZ      @eol
        STB     [CON_DATA], R4
        JMP     @ch
@eol:   LD      R4, #10
        STB     [CON_DATA], R4
        JMP     @arg
@done:  LD      R0, #0                  ; код завершения
        RET                             ; LR = процедура выхода

image_end:
bss_end:
        .align  2
```

### 9.5. Проверка загрузчика

Минимальный набор случаев:

- каждое условие разд. 3.3 по отдельности: неверный код перехода, магия, версия, флаги, ненулевой резерв, `image_end` < `$001C`, `bss_end` < `image_end`, `bss_end` > `$E000`, нечётный и выходящий за образ `start`, файл короче `image_end`;
- `image_end`, кратный 512, и не кратный;
- `bss_end` нечётный: блок аргументов начинается с `bss_end + 1`;
- `max_top` = 0, меньше `need`, больше `$E000`;
- `need` ровно `$E000` и на байт больше;
- командная строка 255 и 256 байт, 32 и 33 аргумента, пустой аргумент `""`, кавычки внутри слова, незакрытая кавычка;
- данные после `image_end` в файле не попадают в память;
- память выделенных кадров нулевая, кроме образа и блока аргументов;
- PIB заполнен целиком, резерв нулевой;
- регистры при входе соответствуют разд. 8.1, в том числе FLAGS = `$08`;
- тик таймера, пришедший в первую же команду программы, не портит её регистры и память выше `SP − 4`;
- программа, выполнившая `CLI` и завершившаяся через процедуру выхода, завершается корректно, и следующая программа запускается с IF = 1;
- каждая ошибка загрузки возвращает свой код из разд. 9.1, а при ошибке не остаётся занятых кадров.

## 10. Инструменты

Формат поддерживают ассемблер и компилятор B16. В ассемблерной программе заголовок пишется в исходном тексте вручную, неинициализированные данные кладутся директивой `.reserve` за меткой `image_end` и в файл не попадают. Компилятор B16 выводит заголовок, стартовый код и раскладку данных сам.

**Ассемблер (реализовано).** Нормативное описание — в «Справочнике ассемблера», разд. 17.5.

- **Директива `.reserve n`** сдвигает счётчик адреса на `n` байт, не выводя их.
  - `n` — от 0 до 65536 и не может зависеть от меток (как у `.space`). Метка перед `.reserve` получает адрес резерва.
  - Резерв в конце программы образ не удлиняет: файл заканчивается последним выведенным байтом, то есть на `image_end`, и bss в нём не хранится.
  - Резерв посреди образа (за ним есть вывод) записывается в файл нулями независимо от `--fill`.
  - Зарезервированные адреса считаются занятыми: вывод в них (например, после обратного `.org`) и резерв поверх вывода — ошибки перекрытия. Выход резерва за 64 КБ — ошибка.
  - Выравнивания `.reserve` не делает. Если счётчик может оказаться нечётным, а в резерве лежат слова, перед `image_end` нужен `.align 2`.
- **Метка в конце текста** (за ней нет элементов, занимающих место) получает значение счётчика адреса. Значение должно умещаться в 0..65535.
- **Проверка заголовка — ключ `--exec`.** Ассемблер проверяет готовый образ по условиям разд. 3.3:
  - слово по `$0000` равно `$C873` (`JMP #start`), байты `$0004–$0007` — `"CX16"`, `version` = 1;
  - `$001C` ≤ `image_end` ≤ `bss_end` ≤ `$E000`;
  - `start` чётный и `$001C` ≤ `start` < `image_end`;
  - `image_end` не больше длины выведенного файла;
  - после `image_end` нет ни одного выведенного байта (кода или инициализированных данных); области `.reserve` за `image_end` допустимы. Ошибка называет адрес первого байта за `image_end`.

  Последняя проверка ловит программу, у которой часть кода случайно оказалась за `image_end` (например, ассемблерный модуль, подключённый после вывода компилятора B16): на голой машине такая программа работает, а под монитором этот код не загружается. Дополнительные данные файла (разд. 3.1) поэтому не выводятся ассемблером, а дописываются к готовому файлу другими средствами.

  Поля `flags`, резервные слова и `min_free` ключ не проверяет. Нарушения — ошибки `executable header: …`, файлы при этом не записываются. Ключ требует `--base 0`. JS-ассемблер веб-отладчика содержит ту же проверку, но в интерфейсе она пока не выведена.

Типичный конец программы:

```asm
        .align  2                       ; .reserve не выравнивает
image_end:
buf:    .reserve 512                    ; в файл не попадает, загрузчик обнуляет
count:  .reserve 2
bss_end:
```

Примеры: `examples/calc_exec.asm` (калькулятор с заголовком и буфером в резерве) и `docs/skeleton_exec.asm` (заготовка программы). Обе программы определяют способ запуска (разд. 9.3) и работают и под монитором, и на голой машине.

**Компилятор B16 (реализовано).** Нормативное описание — в «Спецификации языка B16» (`B16_reference_ru.md`), разд. 3.4, 9.1, 9.2; ключи компилятора и раскладка образа — разд. 13.

- **Цель.** По умолчанию (`option target = std`) программа собирается в формате CX16; `option target = kernel` — код без заголовка и стартового кода (ядро монитора, модули для ассемблера). Параметры образа пишутся в главном файле программы (B16, разд. 3.6); ключи `--target`, `--code`, `--data`, `--min-free`, `--max-top` переопределяют их для разовой сборки.
- **Заголовок.** Образ начинается с `JMP #__start` и заголовка: `version` = 1, `flags` = 0, `image_end` = `__image_end`, `bss_end` = `__bss_end`, `min_free` и `max_top` — из `option min_free` (по умолчанию 2048) и `option max_top` (по умолчанию 0), резерв — нули. Результат проходит проверку `cpu16asm --exec`.
- **Порядок данных.** Код, инициализированные глобальные переменные и строковые литералы, затем `.align 2`, метка `__image_end`, неинициализированные переменные в `.reserve` и метка `__bss_end`. Резерв в файл не попадает. `option data = АДРЕС` переносит все переменные на заданный адрес; начальные значения инициализированных лежат образцом рядом с кодом, и стартовый код их копирует (программа в ПЗУ, данные в ОЗУ).
- **Стартовый код** работает в обоих режимах запуска (разд. 8) и определяет режим по сигнатуре, как в разд. 9.3. Под монитором он не устанавливает SP, не трогает таймер и векторы, не выполняет `CLI` и `WFI`: сохраняет LR, вызывает `main(argc, argv)` и завершает программу переходом по LR с кодом завершения в R0 (0, если у `main` нет результата). На голой машине он устанавливает стек `$FF00`, ставит вектор ERRCMD на остановку, а остальные векторы — на пустой обработчик (`IRET`), обнуляет bss (состояние памяти после сброса не определено), вызывает `main` с argc = argv = 0 и после возврата останавливает процессор.
- **`main`**: `fn main()`, `fn main(): int`, `fn main(argc: uint, argv: ptr ptr byte)` и тот же вариант с результатом `int`.
- **Ассемблерные модули** (например, обёртки системных вызовов) подключаются строкой `include asm "файл"` в исходном тексте (B16, разд. 3.2, 10.4) — обычно в библиотеке, которая объявляет функции модуля; ключ `--asm файл` делает то же из командной строки. Компилятор выводит `.include` модуля после функций и рантайма и перед данными, поэтому код модуля попадает в образ до `__image_end` и загружается монитором. В модуле допустимы только код и инициализированные данные, без `.reserve`.

  ```text
  // prog.b16
  include "sys.b16"               // объявления вызовов и include asm "sys.asm"
  option max_top = $6000          // 24 КБ хватает
  option min_free = 1024
  ```

  ```text
  b16c prog.b16 -o prog.s
  cpu16asm --exec -o prog.cx prog.s
  ```

  Подключать модуль ассемблерным файлом после вывода компилятора нельзя: код модуля окажется за `__bss_end`, и `cpu16asm --exec` такую сборку отвергнет.
- **Границы памяти** доступны программе на B16 как адреса `__image_end` и `__bss_end` (тип `ptr`): от `__bss_end` отсчитывается начало кучи. Программа, которая хранит указатели из `argv`, начинает кучу с `args_end` (поле PIB).

- **Связь со спецификацией системных вызовов.** Добавлена таблица связанных документов; ссылки «определит спецификация системных вызовов» заменены ссылками на разделы «Системных вызовов»:
  - процедура выхода по фиксированному адресу `$E000` (разд. 8.1);
  - `EXIT` и коды завершения (разд. 8.1);

  - числовые коды ошибок загрузки (разд. 9.1).

- **Остановка** (разд. 8.2, 8.3): рецепт остановки голой машины по «Машине» ревизии 6 (выключить таймер, `STI`, `CLI`, `WFI`); под монитором программа таймер не трогает и завершается процедурой выхода или `EXIT`.
- **Загрузчик** (разд. 9.1) работает в карте ядра через окна, а не в странице 7; карту процесса включает и передаёт управление резидентная часть монитора. Вычисления разд. 6 в ядре на B16 удобно вести в `ulong`.
- **Инструменты** (разд. 10):
  - `cpu16asm --exec` отвергает образ, в котором после `image_end` есть выведенные байты;
  - ассемблерные модули к программе на B16 подключаются ключом `--asm`.
- Пример разд. 9.4: прямой вывод в DATA обходит перенаправление.
- Разд. 9.5: проверка кодов ошибок загрузки.
- Ссылки на «Машину CPU16» и B16 указывают ревизию 6 и ревизию 2.

### Ревизия 2

- **Разд. 10:** доработки компилятора B16 (цели `std` и `kernel`, заголовок, стартовый код для обоих режимов запуска, `main` с аргументами и кодом завершения, bss в `.reserve`, данные отдельно от кода) описаны как реализованные, а не планируемые.
- **Прерывания при запуске разрешены** (разд. 8.1): FLAGS = `$08` (IF = 1) вместо 0. Запускать программу с запрещёнными прерываниями нелогично: монитор при этом не может обслуживать устройства, пока программа сама не выполнит `STI`.
