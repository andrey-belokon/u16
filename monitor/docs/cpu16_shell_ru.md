# Монитор CPU16: оболочка и утилиты. Ревизия 6

Документ описывает оболочку — программу `A:/sys/shell.cx`, которую монитор запускает первой, — и набор утилит первой очереди в `A:/bin`. Оболочка и утилиты — обычные программы формата CX16 на B16: они пользуются только системными вызовами и не имеют особых прав.

Разделы 1–7 нормативные. Раздел 8 — рекомендации по реализации.

## 2. Запуск и завершение

**Запуск монитором.** Монитор запускает оболочку командной строкой `A:/sys/shell.cx` («Системные вызовы», разд. 2.3). Оболочка:
1. **проверяет тома.** Для каждого тома, который монитор смонтировал только на чтение из-за DIRTY (`VOLINFO`, флаг `MNT_DIRTY`), выводит `shell: volume X: was not unmounted cleanly, running fsck` (X — буква тома), запускает `A:/bin/fsck.cx X` и при коде 0 перемонтирует том (`MOUNT` с `MOUNT_REMOUNT`, «Системные вызовы», разд. 5.3) с сообщением `shell: volume X: mounted read-write`. Так починяется и том `A:`, с которого загружена сама оболочка;
2. создаёт каталог `A:/tmp`, если его нет (разд. 4.4);
3. выполняет файл `A:/sys/startup`, если он есть, как сценарий (разд. 3.6);
4. выводит приглашение и читает команды с консоли.

Пункты 1–3 выполняются только при запуске системы: если оболочка — не единственный сеанс (`SESS_INFO` находит другой сеанс), это корень нового сеанса (`session new`, разд. 5.1), и она сразу переходит к п. 4.

**Сценарий.** Командная строка `shell.cx ФАЙЛ` выполняет команды из файла и завершает оболочку с кодом последней выполненной команды. Пункты 1–3 при этом не выполняются.

**Завершение.** Команда `exit` (разд. 5) завершает оболочку. Для оболочки, запущенной монитором, это останов системы при коде 0 и перезапуск оболочки при любом другом коде («Системные вызовы», разд. 2.3).

## 3. Командная строка

### 3.1. Ввод

Если стандартный ввод — консоль (`HINFO`), оболочка переводит её в сырой режим с флагом `NOBREAK` («Системные вызовы», разд. 6.1–6.3) и сама собирает строку из событий клавиатуры (`CON_GETEV`), выводя эхо:

| Клавиша | Действие |
| --- | --- |
| символы `$20` и выше, Tab | добавляются в строку (не больше 255) |
| Backspace | удаляет последний символ |
| Ctrl+U | удаляет всю строку |
| Enter | выполняет строку |
| ↑ (сканкод `$48`) | предыдущая строка истории |
| ↓ (сканкод `$50`) | следующая строка истории; после последней — строка, которую набирали до просмотра истории |
| Ctrl+C | отменяет набранную строку; оболочка выводит `^C` и приглашение заново |
| Ctrl+Z в начале пустой строки | конец ввода: оболочка ведёт себя как при `exit 0` |

Остальные клавиши игнорируются; редактирования внутри строки (← →) нет.

**История** — последние 16 выполненных строк, без пустых и без повтора предыдущей. История живёт, пока работает оболочка, и на диск не сохраняется.

Программы, запущенные из оболочки, получают консоль в обычном строчном режиме: режим принадлежит процессу («Системные вызовы», разд. 6.1).

Если стандартный ввод перенаправлен, оболочка читает его построчно, как сценарий (разд. 3.6), без приглашения-редактора.

**Приглашение** — текущий каталог (`GETCWD`) и `> `, например `A:/bin> `. Если в системе больше одного сеанса (разд. 5.1), перед каталогом стоит номер своего сеанса в квадратных скобках: `[1] A:/bin> `. Приглашение выводится перед каждой командой, поэтому на экране оболочки, ждущей ввода в другом сеансе, номер появится или пропадёт только после следующей команды.

**Тома** в путях обозначаются буквами `A:`–`H:` в любом регистре; прежние цифры `0:`–`7:` тоже понимаются («Системные вызовы», разд. 4.1). Утилиты принимают том в аргументе в любой из форм `B`, `b`, `B:`, `1` и выводят его буквой с двоеточием: `B:`.

Строка не длиннее 255 байт (ограничение монитора). Пустая строка и строка из пробелов ничего не делают.

### 3.2. Слова

Строка делится на слова по правилам формата CX16, разд. 5.2: разделители — пробел и Tab, кавычки `"` объединяют текст с пробелами в одно слово и сами в слово не входят, `""` — пустое слово, незакрытая кавычка — ошибка.

Вне кавычек особый смысл имеют:

| Знак | Значение |
| --- | --- |
| `;` | разделитель команд: команды выполняются по очереди |
| `\|` | конвейер (разд. 3.5) |
| `<`, `>`, `>>`, `2>` | перенаправления (разд. 3.4) |
| `#` в начале слова | комментарий до конца строки |

Особые знаки отделяют слова и без пробелов: `ls>out` — это `ls`, `>`, `out`. В кавычках они — обычные символы.

### 3.3. Команда

Первое слово команды — **имя**. Если это имя встроенной команды (разд. 5), оболочка выполняет её сама. Иначе это программа: оболочка ищет файл (разд. 4.1) и запускает его вызовом `SPAWN`.

Командную строку для `SPAWN` оболочка собирает заново:
- первое слово — найденный путь к программе;
- за ним — слова-аргументы; слово, содержащее пробел, Tab или особый знак, либо пустое, берётся в кавычки.

Слово не может содержать `"`: формат CX16 не даёт способа экранировать кавычку. Поэтому аргумент программы всегда передаётся без искажений.

Перенаправления в командную строку программы не попадают.

### 3.4. Перенаправления

| Запись | Действие |
| --- | --- |
| `< файл` | стандартный ввод из файла (`OPEN` с `O_READ`) |
| `> файл` | стандартный вывод в файл; файл создаётся или укорачивается (`O_WRITE \| O_CREATE \| O_TRUNC`) |
| `>> файл` | стандартный вывод в конец файла (`O_WRITE \| O_CREATE \| O_APPEND`) |
| `2> файл` | стандартный вывод ошибок в файл (как `>`) |

Имя файла — следующее слово. Перенаправление может стоять в любом месте команды; при повторении действует последнее. Путь может быть и устройством: `> dev:nul`.

Оболочка открывает файлы перед запуском, передаёт дескрипторы в `SPAWN` и закрывает их после завершения программы. Ошибка открытия отменяет команду с сообщением. Для встроенной команды перенаправление вывода действует на её вывод.

### 3.5. Конвейер

`a | b | c` выполняется по очереди через временные файлы (разд. 4.4):
1. `a` с выводом во временный файл T1;
2. `b` с вводом из T1 и выводом в T2;
3. `c` с вводом из T2.

Временные файлы удаляются после выполнения конвейера. Каждая команда конвейера может иметь свои перенаправления; явное перенаправление сильнее конвейера. Если команда завершилась с кодом `$8001` (Ctrl+C), остальные команды конвейера не выполняются.

Код конвейера — код последней команды.

### 3.6. Сценарий

Файл сценария — строки команд, разделённые `\n`. Каждая строка выполняется как строка, набранная с консоли. Выполнение прекращается:
- после `exit`;
- если программа завершилась с кодом `$8001` (Ctrl+C);
- в конце файла.

Стандартный ввод команд сценария — консоль, если он не перенаправлен.

## 4. Программы и файлы

### 4.1. Поиск программы

| Имя | Где ищется |
| --- | --- |
| содержит `/` или `:` | только по этому пути |
| иначе | текущий каталог, затем `A:/bin` |

В каждом месте проверяются по порядку `имя`, `имя.cx` и `имя.bs`. Имена файлов сравнивает монитор, без учёта регистра: `LS` находит `ls.cx`. Имя, которое уже оканчивается на `.cx` (в любом регистре), второй раз `.cx` и `.bs` не получает.

**Сценарии BScript.** Найденный файл с расширением `.bs` (без учёта регистра) запускается как `A:/bin/bs.cx путь аргументы...` («BScript: язык сценариев для CPU16», разд. 11.4); перенаправления оболочки действуют на эту программу. Так сценарий `A:/bin/backup.bs` вызывается просто как `backup`. Скомпилированный сценарий `.bsc`, названный явно (`prog.bsc`, `/t/prog.bsc`), запускается как `A:/bin/bsvm.cx путь -- аргументы...`: `--` говорит виртуальной машине, что путь исходника берётся из файла `.bsc`. Имя без расширения `.bsc` не получает: по имени находится исходник `.bs`, а его кеш проверяет `bs`.

Имена встроенных команд (разд. 5) тоже не различают регистр: `CD` и `cd` — одна команда. Подходит обычный файл (не каталог). Если файл найден, но не загружается, оболочка выводит сообщение об ошибке загрузки и дальше не ищет.

### 4.2. Код завершения

После каждой команды оболочка запоминает код завершения («Системные вызовы», разд. 7.2; встроенная команда — тоже).

| Код | Что выводит оболочка |
| --- | --- |
| 0 | ничего |
| `$0001–$7FFF` | `exit code N` (десятичное) в стандартный вывод ошибок |
| `$8001` | ничего: монитор уже вывел `^C` |
| `$8008`, `$8009` | ничего: монитор уже вывел сообщение |
| прочие `$8000–$FFFF` | `exit code $XXXX` |

### 4.3. Сообщения об ошибках

Оболочка и утилиты выводят ошибки в стандартный вывод ошибок (дескриптор 2) в виде `имя: объект: текст`, например `cat: A:/a: no such file or directory`. Текст — по коду ошибки «Системных вызовов», разд. 8 (таблица в разд. 8.2), на английском. Все сообщения оболочки (ошибки разбора, `command not found`, коды завершения, `help`) и утилит (разд. 6) — тоже на английском.

### 4.4. Временные файлы

Временные файлы конвейера — `A:/tmp/.pipeN`, где N — номер команды в конвейере. Оболочка создаёт `A:/tmp` при запуске. Если `A:/tmp` создать нельзя (том только на чтение), конвейер — ошибка.

## 5. Встроенные команды

| Команда | Действие |
| --- | --- |
| `cd [путь]` | сменить текущий каталог; без аргумента — `A:/` |
| `pwd` | вывести текущий каталог |
| `echo [слово ...]` | вывести слова через пробел и перевод строки |
| `exit [код]` | завершить оболочку с кодом (по умолчанию 0) |
| `cls` | очистить экран |
| `help` | список встроенных команд и утилит `A:/bin` |
| `session [N \| new [-b] [команда ...] \| kill [-f] [N]]` | сеансы, разд. 5.1 |

Код встроенной команды: 0 при успехе, 1 при ошибке, 2 при неверных аргументах.

### 5.1. Сеансы

Команда `session` работает с сеансами монитора («Системные вызовы», разд. 2.4). Переходить между сеансами удобнее клавишами: Ctrl+] — следующий сеанс, Ctrl+[ — предыдущий (в эмуляторе командной строки — только Ctrl+]).

| Форма | Действие |
| --- | --- |
| `session` | список сеансов |
| `session N` | перейти в сеанс N |
| `session new` | новый сеанс с оболочкой и переход в него |
| `session new команда ...` | новый сеанс, корень которого — программа; поиск программы и сценарии — как у обычной команды (разд. 4.1). Когда программа завершится, сеанс закроется |
| `session new -b ...` | то же без перехода: сообщение `session N started` |
| `session kill [N]` | завершить сеанс N (без N — свой). Сеанс, в котором работает больше одного процесса, не завершается: `session: the session runs several programs; use kill -f` |
| `session kill -f [N]` | завершить сеанс со всеми процессами |

Новый сеанс начинается в текущем каталоге оболочки, которая его создала, с пустым экраном. Сеанс, корень которого завершился, закрывается, и текущим становится следующий; оболочка последнего сеанса завершается как прежде (разд. 2).

Список — строка на сеанс: `*` у текущего, номер, память процессов сеанса в КБ, цепочка процессов от корня через ` > `:

```text
[1] A:/data> session
  0    80K  A:/sys/shell.cx > A:/bin/edit.cx s.bs
* 1    56K  A:/sys/shell.cx
```

Ошибки:
- `session: N: no such session` — сеанса нет или номер больше 3;
- `session: the only session; use exit` — единственный сеанс системы не завершается командой;
- ошибки `SESS_NEW` — в виде разд. 4.3 (`session: not enough memory`; `session: too many nested programs` — заняты все 4 сеанса или все 16 процессов).

## 6. Утилиты

Утилиты лежат в `A:/bin` и вызываются как обычные программы. Общие правила:
- **ошибки** — в дескриптор 2 в виде разд. 4.3;
- **код завершения:** 0 — успех, 1 — ошибка хотя бы с одним объектом, 2 — неверные аргументы;
- **флаги** — слова, начинающиеся с `-`, до первого слова-не-флага;
- **том** (X в таблице) — буква `A`–`H` в любом регистре, с двоеточием или без, или номер 0–7; в сообщениях — буква с двоеточием (`fsck: volume B: consistent`);
- утилита, которая получает **несколько файлов**, обрабатывает все, даже если с некоторыми ошибка.

| Утилита | Аргументы | Действие |
| --- | --- | --- |
| `ls` | `[-l] [-a] [путь ...]` | список каталога (по умолчанию текущего) или сведения о файле. `-l`: флаги (`d`, `r`, `h`, `s`), размер, дата и время изменения (у записи без метки времени — прочерки). Файлы с HIDDEN показываются только с `-a` |
| `cat` | `[файл ...]` | содержимое файлов подряд в стандартный вывод; без аргументов — стандартный ввод |
| `cp` | `откуда куда` | копировать файл. Если `куда` — каталог, файл копируется в него под тем же именем. Путь назначения, совпадающий с исходным без учёта регистра букв (`cp /a /A`), — ошибка `same file` |
| `mv` | `откуда куда` | переименовать или переместить (`RENAME`); между томами — копирование и удаление. Если `куда` называет тот же объект, что `откуда` (`mv readme README`), это смена регистра имени, а не перемещение в каталог: `RENAME` вызывается с `куда` как есть |
| `rm` | `файл ...` | удалить файлы (каталог — ошибка) |
| `mkdir` | `каталог ...` | создать каталоги |
| `rmdir` | `каталог ...` | удалить пустые каталоги |
| `attr` | `[+r\|-r\|+h\|-h\|+s\|-s ...] путь ...` | изменить флаги RDONLY, HIDDEN, SYSTEM; без флагов — вывести флаги |
| `df` | `[X ...]` | для смонтированных томов: буква (`A:`), метка, всего и свободно КБ, режим (`rw`, `ro`, `ro dirty`, `ro protected`) |
| `mount` | `X [-r]` | смонтировать том X (`-r` — только на чтение) |
| `umount` | `X` | размонтировать том X |
| `sync` | — | `SYNC` |
| `date` | `[ГГГГ-ММ-ДД ЧЧ:ММ:СС]` | вывести дату и время; с аргументами — установить |
| `touch` | `[-t ГГГГ-ММ-ДД ЧЧ:ММ:СС] файл ...` | создать файл, если его нет, и поставить время изменения: текущее или заданное (`SETMTIME`). Для каталога и файла с RDONLY только ставит время |
| `mem` | — | `top` своего процесса, его расширенная память, свободная память, глубина цепочки (`MEMINFO`, `SYSINFO`) |
| `sysboot` | `X [файл]` | записать код загрузки тома (по умолчанию `A:/sys/fsboot.bin`) в секторы 1–3 диска X («Загрузка с диска», разд. 6). Проверяет, что файл — код загрузки (`CXBT`, версия 1, до 1536 байт) и что на диске том ФС16; предупреждает, если на томе нет `/sys/monitor.sys` |
| `fsck` | `X [-n]` | проверка тома X по ФС16, разд. 8, и починка по разд. 10: обход дерева от ROOT с новой картой, обрезка файла перед неверным или общим кластером, удаление дубля после прерванного перемещения, обнуление адресов за размером и ненулевых свободных записей, новая карта, пересчёт FREE, снятие DIRTY. Недопустимые имена только сообщаются. Запись, имя которой совпадает с именем более ранней записи каталога без учёта регистра, переименовывается в имя с числом 2, 3, … в конце (ФС16, разд. 10, п. 6) с сообщением `fsck: /путь: name differs only in letter case from another entry, renamed to НОВОЕ` (с `-n` — `would be renamed to`). Работает через `DISK_IO`: том не смонтирован или смонтирован только на чтение; `-n` — только проверка, без записи, допустима и для тома на запись. Код: 0 — том целостен или починен, 1 — ошибки остались, 2 — неверные аргументы |

## 7. Ограничения

Нет редактирования внутри строки, переменных окружения, шаблонов имён (`*`), фоновых заданий, `&&` и `||`. Порядок вывода `ls` — порядок записей в каталоге.

## 8. Рекомендации по реализации

### 8.1. Строение

- Оболочка — один модуль B16 с обёртками вызовов (`sys.b16`, который подключает объявления `sysdefs.b16` и обёртки `sys.asm`). Утилиты — отдельные программы; общие функции (вывод, сообщения об ошибках, разбор флагов) — модуль `ulib.b16`.
- Каждой утилите достаточно `max_top` 16–24 КБ; `fsck` — 40 КБ (новая карта тома до 8 КБ и буферы кластеров). Значение пишется в исходнике утилиты: `option max_top = $6000` (у `fsck` — `$A000`). Это экономит память, когда утилита запущена из оболочки, запущенной из оболочки.
- Буфер копирования `cat` и `cp` — 4 КБ: чтение и запись целыми секторами идут прямо в память процесса.

### 8.3. Проверка

Оболочка проверяется сценариями стенда, как ядро: строка подаётся с клавиатуры (`type`), вывод сравнивается с ожидаемым. Утилиты — сценарием оболочки (разд. 3.6), который вызывает каждую утилиту и проверяет результат, например, через `cat` и сравнение вывода с эталоном.

## 9. Изменения

### Ревизия 6

- **Сборка программ (B16 ревизии 3).** `max_top` каждой утилиты задан в исходнике объявлениями `option`, обёртки вызовов подключает `sys.b16` строкой `include asm`; команда сборки — без ключей.
- **Буквы томов** («Системные вызовы», ревизия 6): пути оболочки и утилит — `A:/…`; утилиты принимают том буквой или, как прежде, номером и выводят его буквой (`A:  SYSTEM` в `df`, `fsck: volume A: consistent`, `sysboot: boot code installed on drive B:`); подсказки — `usage: mount A-H [-r]` и т. п. (разд. 2, 3, 6).
- **Номер сеанса в приглашении** — `[N] ` перед каталогом, если сеансов больше одного (разд. 3).

### Ревизия 5

- Встроенная команда `session` (разд. 5.1): список сеансов, переход, новый сеанс с оболочкой или программой, завершение, в том числе принудительное.
- Проверка томов, `A:/tmp` и `A:/sys/startup` — только при запуске системы, не в каждом новом сеансе (разд. 2).

### Ревизия 4

- Поиск программы (разд. 4.1): после `имя.cx` проверяется `имя.bs`; сценарий BScript запускается через `A:/bin/bs.cx` (требование BScript, разд. 11.4), скомпилированный сценарий `.bsc` — через `A:/bin/bsvm.cx`.
- Текст ошибки `MFILE` — `too many open files` (разд. 8.2), как в BScript.

### Ревизия 3

- Имена файлов без учёта регистра («Системные вызовы», ревизия 3): поиск программы (разд. 4.1), проверка `same file` в `cp`, смена регистра имени через `mv` (разд. 6).
- Имена встроенных команд не различают регистр (разд. 4.1); `help` отрезает `.cx` в любом регистре.
- `fsck` переименовывает записи, имена которых совпадают с другими без учёта регистра (разд. 6).

### Ревизия 2

- **История команд** (разд. 3.1): ввод с консоли — собственный редактор оболочки в сыром режиме, стрелки ↑ ↓.
- **Утилиты** `fsck`, `touch`, `sysboot` (разд. 6); проверка томов с DIRTY при запуске (разд. 2).
- Все сообщения оболочки и утилит — на английском (разд. 4.2, 4.3, 6, 8.2).

### Ревизия 1

Уточнения по итогам реализации: `cp` в тот же файл — ошибка; `ls -l` для записи без метки времени.
