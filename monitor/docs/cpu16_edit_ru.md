# Монитор CPU16: текстовый редактор edit. Ревизия 2

`edit` — экранный текстовый редактор. Это обычная программа формата CX16 на B16 (`A:/bin/edit.cx`), она пользуется только системными вызовами. Из файлового менеджера fm редактор вызывается клавишей F4, без файла — Shift+F4 («Файловый менеджер fm», разд. 3), из оболочки — командой `edit`.

Ревизия 2 вводит выделение Shift со стрелками и буфер обмена, как в Windows, отмену правок (Ctrl+Z), текст без имени и окно «Сохранить как». Изменения — в разделе 10.

Разделы 1–6 — описание для пользователя, раздел 7 — устройство программы, раздел 8 — проверка.

## 1. Запуск

    edit [файл]

- **С файлом.** Относительный путь редактор сразу превращает в полный (в строке состояния — полный путь). Если файла нет, редактор начинает с пустого текста (в строке состояния — `new file`) и создаёт файл при записи.
- **Без файла** — пустой текст «untitled». Первая запись (F2) открывает окно «Сохранить как» (разд. 6.2).
- Больше одного аргумента — `usage: edit [file]`, код 2.

Как и fm, редактор рисует экран прямым выводом в дисплей в координатном режиме («Системные вызовы», разд. 6.4); работать с ним удобно в веб-отладчике (окно «Display»). При выходе экран переводится в обычный телетайп и очищается.

Код завершения — 0; 1 — файл нельзя открыть (окно с ошибкой показано) или не хватило памяти при запуске.

## 2. Экран

```text
 A:/data/hello.txt                                * Ln 13/67  Col 34  Ins  CRLF  3937    строка состояния
Line number 10 of the text file, padded to be somewhat long.                           строки 1-23: текст
...
1Help   2Save   3Next   4Replac 5       6       7Search 8       9GoLine 10Quit        клавиши
```

- Слева — путь файла (длинный — хвостом), `untitled` у текста без имени, или сообщение последней операции (`saved`, `not found`, `5 replaced`, `nothing to undo`, `not enough memory` …) до следующей клавиши.
- Справа: `*` — текст изменён после чтения или записи; номер строки курсора и число строк; столбец; `Ins` или `Ovr` — режим вставки или замены; `CRLF` — файл с концами строк `\r\n` (разд. 6.1); `RO` — у файла флаг RDONLY; длина текста в байтах.
- Длинные строки не переносятся: текст сдвигается по горизонтали, когда курсор уходит за край.
- Табуляция показывается до столбца, кратного 8. Управляющие символы показываются значками дисплея («Машина», разд. 5).
- Выделение — чёрным на голубом; если в него входит конец строки, выделение тянется до края экрана.

## 3. Клавиши

| Клавиша | Действие |
| --- | --- |
| ← → ↑ ↓ | курсор; по вертикали курсор держит столбец, с которого начал движение |
| Ctrl+← Ctrl+→ | на слово влево, вправо |
| Home, End | начало, конец строки |
| PgUp, PgDn | страница вверх, вниз; текст не уходит ниже последней строки |
| Ctrl+Home, Ctrl+End | начало, конец текста; то же Ctrl+B, Ctrl+E — для терминалов, которые не передают модификаторы |
| Shift + любая из клавиш выше | выделение (разд. 4) |
| Ctrl+A | выделить весь текст |
| Ctrl+C, Ctrl+Ins | копировать выделение в буфер обмена |
| Ctrl+X, Shift+Del | вырезать |
| Ctrl+V, Shift+Ins | вставить; выделение заменяется |
| Ctrl+Z | отменить (разд. 5) |
| Enter | новая строка с отступом текущей (пробелы и табуляции до курсора) |
| Backspace, Del | удалить символ перед курсором, под курсором; при выделении — выделение |
| Ctrl+Y | удалить строку |
| Ins | вставка / замена |
| Tab | символ табуляции |
| F1 | справка |
| F2, Ctrl+S | записать; у текста без имени — «Сохранить как» |
| Shift+F2, F12 | «Сохранить как» (разд. 6.2) |
| F7 | поиск; F3, Ctrl+L — искать дальше (разд. 5.2) |
| F4 | замена |
| F9, Ctrl+G | переход на строку по номеру |
| F10, Esc | выход; если текст изменён — вопрос `[Y]es [N]o [Esc] Cancel` (Y и Enter — записать и выйти) |

Ввод символа, Enter и Tab заменяют выделение.

Модификаторы редактор берёт из событий клавиатуры (`CON_GETEV`, R2; «Системные вызовы», разд. 9.5). Веб-отладчик передаёт их для всех клавиш; эмулятор командной строки — только если терминал шлёт последовательности xterm с модификаторами (машина, разд. 9.2), поэтому у основных действий есть сочетания с Ctrl + буква. Ctrl+T, Ctrl+W, Ctrl+N не используются: в веб-отладчике их забирает браузер.

Редактор включает сырой режим с `NOBREAK`: Ctrl+C — копирование, а не завершение программы, и правки не теряются.

## 4. Выделение и буфер обмена

Выделение — отрезок текста от **якоря** до курсора. Движение с Shift начинает выделение в позиции курсора (якорь) или продолжает его; движение без Shift снимает выделение. Ctrl+A ставит якорь в начало текста, а курсор — в конец.

- **Копирование** (Ctrl+C) кладёт выделенный текст в буфер обмена; выделение остаётся.
- **Вырезание** (Ctrl+X) копирует и удаляет.
- **Вставка** (Ctrl+V) удаляет выделение, если оно есть, и вставляет буфер обмена; курсор — за вставкой.
- **Del, Backspace и ввод** при выделении удаляют его (ввод — и вставляет символ на его место).

Буфер обмена живёт до выхода из редактора; его длина не ограничена ничем, кроме памяти (разд. 7.6). Если для копии или вставки не хватает памяти, текст и буфер не меняются, а в строке состояния — `not enough memory`.

## 5. Отмена и поиск

### 5.1. Отмена

Ctrl+Z отменяет последний **шаг** правки и возвращает курсор туда, где он был перед шагом. Шаги:

- подряд набранный текст (символы без перемещения курсора между ними) — один шаг; то же — серия Backspace и серия Del;
- Enter, Ctrl+Y, вставка, вырезание, удаление выделения — по шагу на каждое действие; замена выделения вводом — один шаг вместе с набранным следом текстом;
- вся замена (F4), сколько бы вхождений она ни заменила, — один шаг.

Отменяется не больше **1000** последних шагов; журнал правок занимает не больше **256 КБ** (32 кадра) и не берёт кадр, если в машине их останется меньше 16. Когда места нет, из журнала уходят самые старые шаги. Если для самого текста не хватает кадров, журнал тоже отдаёт старые шаги: текст важнее отмены.

Удаление больше 253 952 байт (журнал без одного кадра) отменить нельзя: перед ним редактор спрашивает `Deleting N bytes cannot be undone. Continue?` (`[Y]es [N]o`, Enter не отвечает). Если шаг всё же не поместился в журнал, журнал очищается, а в строке состояния — `undo history lost`. Отменять нечего — `nothing to undo`. Повтора отменённого (redo) нет.

Отмена помечает текст изменённым (`*`), даже если вернула его к записанному.

### 5.2. Поиск и замена

**Поиск (F7)** — от курсора вперёд, без учёта регистра букв (латиница, кириллица, `Ё`, как сравниваются имена файлов). Найденное становится выделением, курсор — в его конец. F3 и Ctrl+L ищут то же дальше; без заданной строки спрашивают её. Ненайденное — `not found`.

**Замена (F4)** спрашивает строку поиска и строку замены и идёт от курсора (если есть выделение — от его начала): каждое вхождение показывается выделением с вопросом `[Y]es [N]o [A]ll [Esc] Stop`. A заменяет это и все дальнейшие без вопросов. Итог — `N replaced`. Строка курсора не попадает под окно вопроса: редактор сдвигает текст, чтобы она была третьей строкой экрана. Замена сначала вставляет новый текст и только потом удаляет найденный, поэтому при нехватке памяти найденное остаётся на месте.

## 6. Чтение и запись файла

### 6.1. Файл

**Концы строк.** Если в файле есть пары `\r\n`, при чтении они заменяются на `\n`, в строке состояния появляется `CRLF`, а при записи каждый `\n` снова пишется как `\r\n`. Одиночный `\r` остаётся в тексте как есть и записывается обратно. Файл, в котором одни строки кончаются `\r\n`, а другие — `\n`, после записи весь будет с `\r\n`.

**Запись (F2)** открывает файл с `O_WRITE | O_CREATE`, сначала увеличивает его вызовом `SETSIZE` до нового размера, затем пишет текст с начала и в конце укорачивает файл, если текст стал короче. Если места на томе не хватит, ошибка случится на `SETSIZE`, до записи данных, и прежнее содержимое файла останется целым. Время изменения ставит монитор, флаги файла не меняются.

**Ошибки** чтения и записи показываются красным окном с путём и текстом ошибки («Оболочка и утилиты», разд. 8.2):

- файл — каталог: `is a directory`;
- файл больше предела (разд. 7.6): `too large: N bytes, the editor holds M`;
- не хватило кадров при чтении: `not enough memory`;
- запись файла с RDONLY или на том только для чтения: `read-only`.

После ошибки открытия редактор завершается с кодом 1, после ошибки записи — продолжает работу с тем же текстом.

### 6.2. «Сохранить как»

Shift+F2 и F12 (а у текста без имени — и F2) открывают окно-обозреватель:

```text
┌────────────────────────────────── Save as ───────────────────────────────────┐
│ A:/data                                                                      │
│  ..                                                                  <DIR>   │
│  sub                                                                 <DIR>   │
│  hello.txt                                                            3895   │
│ ...                                                                          │
│ Name: hello2.txt                                                             │
│ Enter - save / open   Tab - list / name   Esc - cancel                       │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **Каталог** — сначала каталог текущего файла, у текста без имени — текущий каталог редактора (при запуске из fm — каталог активной панели). В списке — `..`, каталоги, затем файлы, по имени без учёта регистра; записей не больше 200 (иначе — пометка `(the list is cut)`).
- **Поле имени** — сначала имя текущего файла. Ввод символов и Backspace правят поле, Ctrl+U очищает его.
- **Стрелки, PgUp, PgDn, Home, End** двигают курсор списка; на файле его имя попадает в поле имени. Tab переключает между списком и полем.
- **Enter в списке на каталоге** (и на `..`) открывает каталог.
- **Enter на поле имени** (или на файле в списке): если имя — каталог или том (`sub`, `..`, `1:`, `A:/bin`), окно переходит туда; иначе имя — путь файла относительно каталога окна. Если файл уже есть — вопрос `The file exists. Overwrite it?` (`[Y]es [N]o`, Enter не отвечает). Затем текст записывается (разд. 6.1), и дальше редактор работает с новым файлом.
- **Esc** закрывает окно без записи. Если окно открылось при выходе с записью, редактор не выходит.

## 7. Устройство

| Файл | Содержание |
| --- | --- |
| `user/edit/edit.b16` | редактор целиком |
| `user/fm/scr.b16` | общий с fm: регистры дисплея, рамки, клавиатура (`getkey` с модификаторами `kmods`), диалоги |

Сборка: `tools/b16build.sh user/edit/edit.b16` (так же в `make system`). Поля заголовка заданы в `edit.b16`: `option max_top = PTOP` (`$A000`) и `option min_free = 4096`; та же константа `PTOP` — адрес окна B и предел, который `edit` проверяет при запуске.

### 7.1. Память

Собственная память процесса — до `$A000` (`max_top` = 40 КБ; сейчас код и данные — до `$6A7A`): код, данные, таблицы и стек. Сам текст, журнал правок, буфер обмена и список окна «Сохранить как» лежат в кадрах расширенной памяти (`XALLOC`, «Системные вызовы», разд. 7.6). Кадры читаются и меняются через два окна:

| Окно | Страница | Адреса | Назначение |
| --- | --- | --- | --- |
| A | 6 | `$C000–$DFFF` | блок текста, с которым идёт работа; источник вставки (текст, буфер обмена, журнал) |
| B | 5 | `$A000–$BFFF` | второй блок при переносе байтов между блоками; новые кадры вставки; запись в журнал и буфер обмена; список каталога окна «Сохранить как» |

Окна объявлены переменными `at`. Кадр ставится в окно вызовом `XMAP`, только если в окне сейчас другой кадр (редактор помнит кадр каждого окна по номеру, поэтому любая функция может поставить в окно свой кадр). Если память процесса оказалась выше `$A000`, редактор не запускается (`edit: not enough memory`). Кадры освобождает монитор при завершении процесса.

Пока редактор работает, fm остаётся в памяти со своими кадрами: у потомка свой процесс («Системные вызовы», разд. 2.1), и текст не делит память с панелями fm.

### 7.2. Блоки текста

Таблица блоков — номер кадра и длина каждого блока, по порядку текста; позиция текста — 32-битное число. Начала блоков не хранятся: редактор помнит последний найденный блок и его начало и от него идёт по таблице вперёд или назад. Последовательный проход по тексту поэтому стоит одного шага по таблице на блок.

| Величина | Значение |
| --- | --- |
| `FRAME` | 8192 — кадр; журнал и буфер обмена — потоки по целым кадрам |
| `BLK` | 8192 — наибольшая длина блока текста |
| `FILL` | 7168 — заполнение блоков при чтении файла и при вставке: запас 1 КБ для правки без деления |
| `MAXBLK` | 224 — блоков не больше |

Пустой блок бывает только единственным — у пустого текста.

- **Вставка** нескольких байт меняет один блок: хвост блока сдвигается внутри окна A. Вставка в начало блока идёт в хвост предыдущего, если там есть место, — без сдвига. Если в блоке нет места, он делится пополам: вторая половина переносится через окно B в новый кадр.
- **Удаление** отрезка освобождает целиком попавшие в него блоки, а в крайних сдвигает хвост. После удаления блок в позиции удаления сливается с соседом, если один из них короче `BLK / 4`, а вместе они не длиннее `FILL`.
- **Вставка потока любой длины** (`ins_stream`: вставка из буфера обмена, отмена удаления): блок курсора делится в позиции курсора, вставка собирается в новых кадрах (окно B) и только затем новые блоки встают в таблицу. Источник читается через окно A функцией `src_at`, которая ставит в окно кадр текста, буфера обмена или журнала. Пока вставка собирается, позиции текста не меняются. Если кадров не хватило, собранные кадры освобождаются, текст не меняется.
- **Строки.** Номер строки курсора и число строк хранятся и пересчитываются при правке и движении курсора (по числу `\n` в пройденном отрезке).
- **Экран** после клавиши перерисовывается целиком, только если сдвинулся текст, изменилось число строк или есть выделение; иначе — строка курсора и строка состояния.
- **Чтение файла** идёт прямо в окно A кусками по `FILL` байт; `\r\n` сжимаются на месте, а `\r` в конце куска решает следующий кусок. **Запись** пишет блоки прямо из окна A (с `\r\n` — через буфер на 512 байт).

### 7.3. Правка и журнал

Правка разделена на два уровня:

- `t_insb`, `t_delete`, `ins_stream` меняют текст, курсор, номер и число строк, начало экрана и якорь выделения, но журнала не касаются; их вызывает и отмена;
- `ed_insb`, `ed_delete`, `ed_stream` делают то же и пишут запись в журнал: удаление — до изменения текста (запись хранит удалённые байты), вставка — после.

Команда начинает правку вызовом `ed_begin(вид)`: вид 0 всегда начинает новый шаг; ввод (1), Backspace (2) и Del (3) продолжают шаг прошлой команды того же вида, если курсор с тех пор не двигался.

**Журнал** — поток записей `[jbeg, jend)` в кадрах `jfr` (до 32); `jf0` — смещение начала первого кадра в потоке. Запись:

| Смещение | Длина | Содержание |
| --- | --- | --- |
| 0 | 1 | вид: 1 — вставка, 2 — удаление |
| 1 | 1 | флаги: бит 0 — запись начинает шаг |
| 2 | 4 | позиция |
| 6 | 4 | длина |
| 10 | 4 | курсор перед шагом |
| 14 | длина | у удаления — удалённые байты |
| конец − 4 | 4 | длина всей записи |

По хвосту отмена идёт назад, по заголовку уход старых шагов идёт вперёд. Подряд набранный текст не плодит записей: новая вставка, продолжающая прошлую в том же шаге, увеличивает её длину. Отмена шага применяет его записи в обратном порядке — вставку удаляет, удаление вставляет обратно из журнала (`ins_stream` с источником-журналом) — и ставит курсор на место. Кадры за концом журнала после отмены освобождаются.

Ограничения журнала (`JSTEPS` = 1000 шагов, `JMAXF` = 32 кадра, `JRES` = 16 свободных кадров машины) соблюдаются уходом самых старых шагов: шаг, начатый первым, удаляется целиком, и кадры, оставшиеся целиком до начала журнала, освобождаются. Текущий шаг не уходит никогда; если места не хватает и ему одному, журнал очищается (`undo history lost`), и записи шага до конца пропускаются.

### 7.4. Буфер обмена

Буфер обмена — кадры, заполненные целиком (последний — частично), и длина. Копирование выделения освобождает прежний буфер, берёт кадры и копирует текст из окна A в окно B. Вставка — `ins_stream` из буфера обмена.

### 7.5. «Сохранить как»

Окно берёт кадр и ставит его в окно B: в нём лежат записи каталога (`READDIR`, до 200 по 40 байт), а порядок показа — байты в памяти процесса (сортировка вставками: каталоги первыми, затем по имени без учёта регистра). Переход по каталогам — `CHDIR` процесса редактора; после окна редактор возвращается в каталог, где был запущен. Путь файла строит `canon`: каталог, в котором лежит имя, должен существовать; полный путь — от `GETCWD` этого каталога.

### 7.6. Пределы

- Файл при открытии — не больше `(MAXBLK − 8) · FILL` = 1 548 288 байт; восемь блоков оставлены на правку и деление.
- Текст при правке ограничен числом блоков `MAXBLK` и свободными кадрами машины («Машина», разд. 7.6); журнал отдаёт им свои кадры. Когда их нет, вставка, копия и вставка из буфера отказывают с `not enough memory`, а текст остаётся прежним.
- Журнал — 1000 шагов и 256 КБ (разд. 5.1).
- Строка длиннее 65 535 столбцов показывается неверно (столбец — 16 бит).

## 8. Проверка

Сценарии в `tools/run_tests.py` — при всех расписаниях тиков, с проверкой целостности томов и возврата всех кадров:

- `edit` (`tests/scripts/edit.scn`): файл с `\r\n` — правка и запись с теми же концами строк; выделение Shift+↓, вырезание, вставка в конец текста, удаление выделения, режим замены, Del, отмена ввода, запись Ctrl+S; новый файл, строка в 100 знаков (сдвиг по горизонтали), поиск F7, F3 и Ctrl+L, переход на строку, выход с записью; F4 в fm и возврат в панели; Shift+F4 — текст без имени, запись через «Сохранить как» в каталоге панели, Shift+F2 — запись в подкаталог, F12 — перезапись с подтверждением.
- `editbig` (`tests/scripts/edit_big.scn`): файл 280 000 байт (40 блоков) — правка в конце и в начале, поиск, выделение 28 КБ до конца текста, копия и вставка в конец, отмена вставки и вставка заново, запись; файл 59 500 байт с `\r\n` — чтение и запись. Файлы создаёт `run_tests.py` в `out/`, а после прогона сверяет их содержимое на томе байт в байт (`fs16tool.py get`).
- `editundo` (`tests/scripts/edit_undo.scn`): пределы журнала — из 1200 отдельных шагов (Enter) отменяются последние 1000; удаление всего файла 280 000 байт спрашивает подтверждение, отказ оставляет текст; три удаления по ~100 КБ — самое старое уходит из журнала, отменяются два последних, затем `nothing to undo`.

Случайная проверка — `tests/edit/stress.py [первый сид [число сидов [число действий]]]`: случайные последовательности клавиш (символы, Backspace, Del, Enter с отступом, Ctrl+Y, стрелки, Home, End, Ctrl+B, Ctrl+E, выделение Shift+→, Ctrl+C, Ctrl+X, Ctrl+V, Del и ввод поверх выделения) против модели на Python со сборкой, где `BLK` = 512 и `FILL` = 448, — так деление и слияние блоков случаются на каждом шагу. Сверяется записанный файл; затем все шаги отменяются, и текст, записанный через F12, должен совпасть с исходным. Проверяются и возврат кадров, и целостность тома.

## 9. Ограничения и планы

- Нет повтора отменённого (redo).
- Нет переноса длинных строк по ширине экрана.
- Нет прямоугольного выделения.
- Буфер обмена — только внутри одного запуска редактора.
- В эмуляторе командной строки выделение Shift со стрелками работает, только если терминал передаёт модификаторы (машина, разд. 9.2).

## 10. Изменения

### Ревизия 2

- **Сборка программ (B16 ревизии 3).** Параметры образа (`max_top`, `min_free`) заданы в исходнике объявлениями `option`, обёртки вызовов подключает `sys.b16` строкой `include asm`; `max_top` совпадает с адресом окна B через константу `PTOP`; команда сборки — без ключей.
- **Выделение и буфер обмена** (разд. 3, 4): Shift с клавишами движения, Ctrl+A, Ctrl+C / Ctrl+X / Ctrl+V и Ctrl+Ins / Shift+Del / Shift+Ins; ввод заменяет выделение. Отметка блока F3, копия F5, перенос F6 и удаление F8 убраны: их заменяют выделение, буфер обмена и Del.
- **Отмена** (разд. 5.1, 7.3): Ctrl+Z, до 1000 шагов и 256 КБ журнала.
- **Поиск**: найденное — выделение, курсор — в его конце; F3 — искать дальше (разд. 5.2).
- **Текст без имени и «Сохранить как»** (разд. 1, 6.2, 7.5): `edit` без аргумента; Shift+F2 и F12 — окно-обозреватель.
- **Движение по словам** Ctrl+← и Ctrl+→, начало и конец текста Ctrl+Home и Ctrl+End.
- **Память** (разд. 7.1): процесс — до `$A000` (40 КБ); журнал, буфер обмена и список окна — в кадрах, по-прежнему через два окна.
