# Монитор CPU16: загрузка с диска. Ревизия 4

Документ описывает загрузку монитора с диска 0: код запуска в ПЗУ, код загрузки тома ФС16 и формат файла ядра `A:/sys/monitor.sys`. Загрузка заканчивается переходом на точку входа ядра `boot_entry`, состояние для которой задано в «Монитор CPU16: устройство ядра», разд. 8.3.

Разделы 1–6 нормативные, раздел 7 — инструменты и проверка.

## 2. Цепочка загрузки

| Шаг | Код | Где выполняется | Что делает |
| --- | --- | --- | --- |
| 1 | ПЗУ | `$0000…`, кадры 0–3, MMU выключен | читает секторы 1–3 диска 0 по адресу `$C000`, проверяет сигнатуру, переходит на `$C008` |
| 2 | код загрузки тома | `$C000–$C5FF`, кадр 6 | находит `/sys/monitor.sys`, раскладывает его по кадрам ядра, ставит карту ядра, переходит на точку входа из заголовка файла |
| 3 | `boot_entry` | страница 7, кадр 7 | векторы, данные ядра, `kmain` («Устройство ядра», разд. 8.3) |

**Память во время загрузки:**

| Кадры | Назначение |
| --- | --- |
| 0–3 | ПЗУ (в эмуляторе — образ ПЗУ в ОЗУ) |
| 6 | код загрузки тома `$C000–$C5FF`, его буферы `$D000–$D4FF`, стек ПЗУ и кода загрузки — вниз от `$E000` |
| 7 | резидентная часть ядра; таблица векторов |
| 8–11 | код ядра |
| 12 | данные ядра: заполняет `boot_entry` |

Код загрузки и стек не пересекаются с кадрами, которые заполняются: кадры 0–6 ядро в пул не включает («Устройство ядра», разд. 2.1).

## 3. ПЗУ

После сброса IP = 0, менеджер памяти выключен, IF = 0, таймер выключен («Машина», разд. 3, 7). Код ПЗУ:

1. ставит SP = `$E000` (стек в странице 6);
2. записывает все 16 векторов адресом своей процедуры сбоя;
3. ставит дисплей в режим телетайпа с курсором, ATTR = `$07`;
4. проверяет, что диск 0 подключён (DRIVES, бит 0);
5. читает 3 сектора диска 0 с LBA 1 по адресу `$C000`, дожидаясь BUSY = 0 опросом STATUS (IEN = 0), затем подтверждает команду (ACK);
6. проверяет заголовок кода загрузки (разд. 4.1);
7. переходит на `$C008` при выключенном менеджере памяти.

**Ошибки** — сообщение на английском на дисплей и останов (`CLI`, `WFI`):

| Ситуация | Сообщение |
| --- | --- |
| диск 0 не подключён | `ROM: no disk 0` |
| ошибка чтения | `ROM: disk 0 read error` |
| неверный заголовок кода загрузки | `ROM: disk 0 is not bootable` |
| недопустимая команда или прерывание | `ROM: fault` |

ПЗУ не зависит от ФС16: оно читает три фиксированных сектора. Код ПЗУ не длиннее 32 КБ (кадры 0–3); нынешний — 251 байт.

## 4. Код загрузки тома

### 4.1. Заголовок

Секторы 1–3 тома (ФС16, разд. 2), 1536 байт, ПЗУ читает по адресу `$C000`:

| Смещение | Размер | Содержимое |
| --- | --- | --- |
| 0 | 4 | сигнатура `"CXBT"` |
| 4 | 2 | версия кода загрузки: 1 |
| 6 | 2 | 0 |
| 8 | … | код; ПЗУ переходит на `$C008` |

Том, у которого секторы 1–3 — нули, не загрузочный (ФС16, разд. 2).

### 4.2. Действия

Код загрузки работает при выключенных прерываниях, с диском — опросом STATUS, как ПЗУ.

1. **Суперблок.** Читает сектор 0, проверяет сигнатуру `"FS16"`.
2. **Поиск файла.** От записи ROOT суперблока ищет в корне запись `sys` — каталог, в нём запись `monitor.sys` — файл. Имена сравниваются без учёта регистра (ФС16, разд. 7.1), все 32 байта поля NAME: каталог `SYS` и файл `Monitor.sys` тоже подходят.
3. **Менеджер памяти.** Включает карту: PAGE0–PAGE3 = кадры 0–3, PAGE4 — окно, PAGE5 = 5, PAGE6 = 6, PAGE7 = 7.
4. **Заголовок файла.** Читает сектор 0 файла и проверяет его (разд. 5).
5. **Сегмент кода.** Сектор j сегмента (j = 0, 1, …) читается через окно PAGE4 = кадр 8 + j / 16 по адресу `$8000` + (j mod 16) · 512.
6. **Резидентный сегмент.** Сектор j читается прямо по адресу `адрес сегмента + 512 · j` в странице 7.
7. **Карта ядра.** PAGE0–PAGE4 = кадры 8–12, PAGE5 = мусорный кадр 13; PAGE6 остаётся кадром 6, на котором выполняется код загрузки.
8. **Переход** на точку входа из заголовка файла. SP по-прежнему в странице 6, IF = 0: это состояние контракта `boot_entry`.

**Ограничения.** Код загрузки читает только прямые адреса записи и индексный кластер IND (ФС16, разд. 6). Поэтому каталоги `/` и `/sys` и файл `monitor.sys` не должны занимать больше 1034 кластеров каждый (2068 КБ). Каталоги просматриваются целиком: записи могут стоять в любом месте.

### 4.3. Ошибки

| Ситуация | Сообщение |
| --- | --- |
| на диске 0 нет правильного суперблока | `boot: no FS16 volume on disk 0` |
| нет `/sys` или `/sys/monitor.sys`, `sys` — не каталог, `monitor.sys` — каталог | `boot: no file A:/sys/monitor.sys` |
| неверный заголовок файла | `boot: bad file A:/sys/monitor.sys` |
| адрес кластера 0 внутри размера, нужен DIND | `boot: damaged volume or file too large` |
| ошибка чтения | `boot: disk 0 read error` |

Сообщения — на английском. После сообщения — останов (`CLI`, `WFI`).

## 5. Файл ядра `monitor.sys`

Сектор 0 файла — заголовок, дополненный нулями до 512 байт:

| Смещение | Размер | Поле | Содержимое |
| --- | --- | --- | --- |
| 0 | 4 | `magic` | `"CXMS"` |
| 4 | 2 | `version` | 1 |
| 6 | 2 | `entry` | адрес точки входа `boot_entry`, в резидентном сегменте |
| 8 | 2 | `code_len` | длина сегмента кода в байтах, не больше `$8000` |
| 10 | 2 | `res_addr` | адрес резидентного сегмента: `$E000` |
| 12 | 2 | `res_len` | длина резидентного сегмента в байтах |

Затем идут сегменты, каждый дополнен нулями до целого сектора:
1. **сегмент кода** — содержимое адресов `$0000` … `code_len − 1` карты ядра (код ядра и образцы начальных значений данных, до `__image_end`);
2. **резидентный сегмент** — содержимое адресов `res_addr` … `res_addr + res_len − 1`.

Сегмент кода раскладывается по кадрам 8, 9, … (страница k → кадр 8 + k), резидентный — в кадр 7. Хвосты последних секторов (до границы сектора) тоже попадают в память: в странице 7 это часть области резидентного кода, которую ядро не использует, в кадрах кода — адреса за `__image_end`.

Файлу удобно дать флаги SYSTEM и RDONLY, чтобы его не удалили случайно. Код загрузки флаги не проверяет.

## 6. Обновление и установка на работающей системе

Файл `monitor.sys` — обычный файл тома: новое ядро вступает в силу при следующей загрузке, если заменить файл. Если у файла флаг RDONLY, его снимают на время замены: `attr -r /sys/monitor.sys`, `cp новое.sys /sys/monitor.sys`, `attr +r /sys/monitor.sys`. Код загрузки в секторах 1–3 при этом не меняется: он находит файл по имени.

**Код загрузки** ставит утилита `sysboot X [файл]` (X — буква тома `A`–`H` или номер 0–7) («Оболочка и утилиты», разд. 6): она записывает файл кода загрузки — по умолчанию `A:/sys/fsboot.bin`, копию `out/fsboot.bin` на системном томе — в секторы 1–3 диска X вызовом `DISK_IO`. Монитор эти секторы не использует, поэтому их можно писать и на смонтированном на запись томе, в том числе на томе `A:` («Системные вызовы», разд. 9.8). `sysboot` проверяет заголовок файла (разд. 4.1) и наличие тома ФС16 на диске.

**Загрузочный диск на работающей системе** делается так:

    mkdir B:/sys
    mkdir B:/bin
    cp /sys/monitor.sys B:/sys
    cp /sys/shell.cx B:/sys
    cp /bin/ls.cx B:/bin            (и остальные нужные утилиты)
    sysboot B

Без `/sys/monitor.sys` на томе `sysboot` предупреждает, что диск не загрузится. Чтобы загрузиться с такого диска, его подключают как диск 0 (том `A:`).

## 7. Инструменты и проверка

| Файл | Назначение |
| --- | --- |
| `boot/rom.asm` | ПЗУ; собирается в `out/rom.bin` |
| `boot/fsboot.asm` | код загрузки тома, `--base $C000`; `out/fsboot.bin`, не больше 1536 байт |
| `tools/mksys.py` | `monitor.sys` из `monitor.bin` и карты памяти (символы `__image_end`, `resident_end`, `boot_entry`) |
| `tools/fs16tool.py boot IMG CODE` | записать код загрузки в секторы 1–3 тома; в спецификации тома — поле `"boot"` |
| `make system` | загрузочный том `out/system.img`: код загрузки, `/sys/monitor.sys`, `/sys/fsboot.bin`, оболочка, утилиты |

Запуск в эмуляторе — образ ПЗУ вместо образа монитора:

    ../cpu16/build/cpu16 --disk 0=out/system.img out/rom.bin

Сценарии стенда (`make test`):
- **boot, bootsh** — тест `tsys` и сценарий утилит под ядром, загруженным с диска, при всех расписаниях тиков;
- **nodisk, noboot, nomon, badmon** — сообщения ПЗУ и кода загрузки: нет диска, нет кода загрузки, нет `monitor.sys`, неверный `monitor.sys`;
- **sysboot** — загрузочный диск, подготовленный на работающей системе (`mkdir`, `cp`, `sysboot`), ошибки `sysboot`, установка кода загрузки на смонтированный том 0, затем загрузка со скопированного диска.

## 8. Изменения

### Ревизия 4

Пути — с буквой тома («Системные вызовы», ревизия 6): сообщения кода загрузки — `boot: no file A:/sys/monitor.sys` и `boot: bad file A:/sys/monitor.sys`; `sysboot` принимает том буквой (`sysboot B`) или, как прежде, номером. Сам код загрузки и формат диска не меняются.

### Ревизия 3

Поиск `/sys/monitor.sys` сравнивает имена без учёта регистра, как монитор (разд. 4; ФС16, ревизия 3). Код загрузки на уже подготовленных дисках нужно обновить утилитой `sysboot`: прежний находит файл, только если имена записаны строчными буквами.

### Ревизия 2

Установка кода загрузки с самой машины: утилита `sysboot`, копия кода загрузки `/sys/fsboot.bin` на системном томе (разд. 6, 7).

### Ревизия 1

Первая редакция. Вместе с ней в «Устройстве ядра» (разд. 8.3) точка входа `boot_entry` перенесена в резидентную часть и сама заполняет векторы.
