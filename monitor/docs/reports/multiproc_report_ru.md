## Как это выглядит для пользователя

- **Клавиши:** Ctrl+] — следующий сеанс по кругу, Ctrl+[ — предыдущий. Работают при любом режиме консоли, в том числе с `NOBREAK`, и программам не передаются.
- **Список сеансов:**
  ```
  0:/data> session
    0    80K  0:/sys/shell.cx > 0:/bin/cat.cx
  * 2    56K  0:/sys/shell.cx
  ```
- **Команда `session`:**
  - `session N` — перейти в сеанс N;
  - `session new [-b] [команда ...]` — новый сеанс с оболочкой или программой, в текущем каталоге; `-b` — без перехода;
  - `session kill [-f] [N]` — завершить сеанс. Без `-f` сеанс, где работает больше одного процесса, не завершается: `use kill -f`.
- **Конец сеанса:** когда завершается корень сеанса, сеанс закрывается и текущим становится следующий. Выход из последнего сеанса работает как раньше: код 0 — останов, иначе перезапуск оболочки.
- **Вызовы:** `SESS_INFO $70`, `SESS_NEW $71`, `SESS_SWITCH $72`, `SESS_KILL $73`. `SESS_INFO` возвращает сведения о каждом процессе цепочки: состояние, память, командную строку.

## Что стоит знать

- **Ctrl+[ в терминале.** В эмуляторе командной строки Ctrl+[ неотличима от Esc, поэтому там работает только Ctrl+]. При 2–3 сеансах этого хватает.
- **Веб-отладчик нужно поправить.** Его нет в архиве, а ядру нужен регистр SCRD. Без SCRD ядро будет сохранять пустые экраны. Правка та же, что в `cpu16_machine.hpp`:
  - словное чтение `$FF50` — символ | атрибут << 8, позиция сдвигается, как в координатном режиме;
  - байты `$FF50`/`$FF51` — символ и атрибут без сдвига.
- **Резидентная часть была почти полна** (свободно 20 байт, а не ~134, как в документе). Поэтому `sys_table` перенесена в код ядра, теперь резидентная часть занята до `$E394`.
- **Запас по объёму ядра:**
  - код ядра 27,0 КБ — документ советует подумать об оверлеях при 28 КБ;
  - данные 7,7 КБ из 8;
  - экраны, строки консоли и имена процессов лежат в отдельном кадре памяти на каждый сеанс.
- **Набранное до перехода отбрасывается.** События, набранные до завершения перехода, принадлежат прежнему сеансу и теряются.
- **Startup один раз.** Оболочка нового сеанса не выполняет проверку томов и `0:/sys/startup`; это делается только при запуске системы.
- **Ожидаемая строка в тесте fm.** Свободное место на томе стало 914K вместо 916K, потому что `shell.cx` вырос.

## Что проверено

- **`sess`** — все вызовы с ошибками и:
  - переход из вычислительного цикла с проверкой флагов между `CMP` и `JNZ` и регистров R4–R12, LR;
  - перезапуск `CON_GETEV`;
  - `SLEEP`, который досыпает только остаток;
  - восстановление экрана и режима дисплея;
  - `kill` своего сеанса;
  - работа после закрытия сеанса 0.
- **`session`** — команда оболочки.
- **`sessfm`** — fm в одном сеансе, оболочка в другом; снимок экрана после возврата показывает fm целиком.
