# Монитор CPU16: отчёт по этапу 4 — загрузка с диска

## 1. Что сделано

Загрузка по «Монитор CPU16: загрузка с диска» (ревизия 1): ПЗУ → код загрузки тома → `/sys/monitor.sys` → `boot_entry`.

| Часть | Файл | Размер |
| --- | --- | --- |
| ПЗУ: векторы сбоя, дисплей, чтение секторов 1–3 диска 0, проверка `"CXBT"` | `boot/rom.asm` | 251 байт |
| код загрузки тома: суперблок, поиск `/sys/monitor.sys` (прямые адреса и IND), сегмент кода в кадры 8.. через окно, резидентный сегмент в кадр 7, карта ядра | `boot/fsboot.asm` | 955 байт из 1536 |
| файл ядра `monitor.sys` из `monitor.bin` и карты памяти | `tools/mksys.py` | 24 064 байта |
| запись кода загрузки в секторы 1–3 | `tools/fs16tool.py boot`, поле `"boot"` спецификации тома | — |
| загрузочный системный том | `make system` → `out/system.img` | — |

**Изменения ядра:**
- точка входа `boot_entry` перенесена из начального кода (`boot.asm`, страница 6) в резидентную часть (страница 7) и сама заполняет векторы. Иначе загрузчик с диска, который выполняется в той же странице 6, не мог бы на неё перейти;
- `boot.asm` теперь только копирует код ядра в кадры и переходит на `boot_entry`;
- резидентная часть выросла на 74 байта (806 из 1276).

Изменения записаны в «Устройстве ядра», разд. 8.3: новый контракт `boot_entry` проще прежнего — векторы загрузчик не заполняет.

## 2. Проверка

`make test` проходит целиком: 15 сценариев, затем всё с `-fcopy-params`.

| Сценарий | Что проверяет |
| --- | --- |
| **boot** | тест `tsys` под ядром, загруженным с диска (через ПЗУ), при всех расписаниях тиков |
| **bootsh** | сценарий утилит (оболочка, утилиты, два тома) под ядром, загруженным с диска |
| **nodisk** | `ROM: no disk 0` |
| **noboot** | том ФС16 без кода загрузки: `ROM: disk 0 is not bootable` |
| **nomon** | код загрузки есть, файла нет: `boot: no file 0:/sys/monitor.sys` |
| **badmon** | `monitor.sys` - не файл ядра: `boot: bad file 0:/sys/monitor.sys` |

`monitor.sys` занимает 12 кластеров, поэтому загрузка проверяет и чтение через индексный кластер. Загрузка проверена и в обычном эмуляторе:

    cpu16/build/cpu16 --disk 0=out/system.img out/rom.bin

## 3. Ошибка, найденная по ходу

В коде загрузки заголовок `monitor.sys` сначала читался в отдельный буфер, который перекрывал переменные самого загрузчика (адреса текущей записи). Чтение целого сектора их затирало, и загрузка останавливалась с сообщением о повреждённом томе. Заголовок теперь читается в общий буфер сектора.

## 4. Что осталось

- **Установка кода загрузки с самой машины.** Секторы 1–3 диска 0 нельзя записать на работающей системе: `DISK_IO` не пишет на смонтированный диск. Пока код загрузки пишет инструмент хоста. Для утилиты установки понадобится либо разрешение `DISK_IO` писать секторы 1–3 смонтированного тома, либо отдельный вызов.
- **Вторая ревизия монитора** — `EXEC`, обработчики событий, расширенная память, отладчик.
- **История команд** в оболочке.
- **Список «на потом»** для компилятора.
