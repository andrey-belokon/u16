# Монитор CPU16, ревизия 2, шаг 3: структура проекта и SETMTIME

## 1. Структура проекта

Верхний уровень — три каталога:

| Каталог | Содержание |
| --- | --- |
| `b16c/` | компилятор B16 |
| `cpu16/` | эмулятор, ассемблер, веб-отладчик (с проверкой `--exec` вывода за `image_end`), документация машины и ассемблера |
| `monitor/` | всё, что относится к монитору: ядро, загрузка, программы, тесты, инструменты, готовый комплект `dist/`, документация `docs/` |

В `monitor/docs/` собраны все спецификации монитора: системные вызовы, устройство ядра, оболочка и утилиты, загрузка с диска, формат исполняемого файла, ФС16; отчёты — в `monitor/docs/reports/`. Пути сборки (`Makefile`, `tools/b16build.sh`, `tools/run_tests.py`) указывают на `../b16c` и `../cpu16`. Каталог `.git` в архив не входит.

## 2. SETMTIME

Новый вызов `$2C SETMTIME(путь, метка)` («Системные вызовы», ревизия 2, разд. 9.4): записывает MTIME файла, каталога или корня тома; 0 — метки нет. Метка проверяется по полям ФС16 (`INVAL` при недопустимых); устройство — `INVAL`, том только для чтения — `RDONLY`. Открытые дескрипторы сразу видят новое значение.

Новая утилита `touch [-t ГГГГ-ММ-ДД ЧЧ:ММ:СС] файл ...`: создаёт файл, если его нет, и ставит текущее или заданное время. Разбор даты перенесён в `ulib.b16` и общий с `date`.

## 3. Проверка

`make test` проходит целиком, в том числе с `-fcopy-params`. Новые проверки: в сценарии fs — `SETMTIME` файла, видимость через открытый дескриптор, корень, метка 0, недопустимая метка, устройство, том только на чтение, отсутствующий файл; в сценарии utils — `touch -t` существующего и нового файла и неверная дата. Веб-отладчик проходит свою сверку с `cpu16asm`.
