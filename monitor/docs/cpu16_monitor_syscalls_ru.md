# Монитор CPU16: системные вызовы. Ревизия 6

Ревизия 6 обозначает тома в путях буквами `A:`–`H:` (разд. 4.1). Ревизия 5 добавляет сеансы — несколько цепочек процессов со своими экранами и переход между ними (разд. 2.4, 9.9). Ревизия 4 добавляет модификаторы событий клавиатуры (Shift, Ctrl, Alt) в результат `CON_GETEV` (разд. 6.1, 9.5). Ревизия 3 делает имена файлов нечувствительными к регистру букв (разд. 4.1, 9.3, 9.4) и описывает событие Ctrl+Enter (разд. 6.1). Ревизия 2 добавила замену программы в процессе (`EXEC`), обработчики событий Ctrl+C и недопустимой команды (`ONEVENT`), изменение памяти процесса (`SETTOP`), расширенную память (`XALLOC`, `XFREE`, `XMAP`) и установку времени изменения (`SETMTIME`). Изменения — в разделе 11.

Документ описывает интерфейс монитора CPU16 для программ: модель системы, соглашение о системном вызове, имена файлов и устройств, работу с файлами, консолью и процессами, коды ошибок и сами вызовы. Устройство ядра монитора здесь не описывается.

Разделы 1–9 нормативные, раздел 10 — интерфейс для B16 и образец обёрток.

## 2. Модель системы

### 2.1. Цепочка процессов

Монитор не переключает процессы по таймеру. В каждый момент выполняется ровно один процесс — последний в цепочке:

- процесс запускает потомка вызовом `SPAWN` и ждёт его завершения внутри вызова;
- потомок завершается вызовом `EXIT` или возвратом по LR (формат CX16, разд. 8.1);
- родитель получает код завершения потомка как результат `SPAWN` и продолжает работу.

Первый процесс цепочки — оболочка (разд. 2.3). Цепочек может быть несколько, по одной на сеанс (разд. 2.4); процессов во всех цепочках вместе — не больше 16, включая оболочки.

Каждый процесс имеет собственную память (`$0000 … top − 1`, формат CX16, разд. 2), собственную таблицу дескрипторов (разд. 5.1) и собственный текущий каталог (разд. 4.3). Пока потомок работает, память, дескрипторы и регистры родителя не меняются.

### 2.2. Ресурсы машины

Защиты памяти и устройств нет, поэтому разделение ресурсов задано правилами. Нарушение правил — ошибка программы с неопределённым результатом.

| Ресурс | Программе |
| --- | --- |
| память `$0000 … top − 1` | своя, любой доступ |
| память `top … $DFFF`, страница 7 | запрещено |
| таблица векторов `$FF00–$FF1F` | запрещено: векторы принадлежат монитору; события таймера — через `TICKHOOK` (разд. 7.4) |
| вывод в дисплей: запись `$FF20`, регистры `$FF22–$FF26`; чтение экрана — регистр SCRD `$FF50` | **разрешено** (разд. 6.4) |
| клавиатура: чтение `$FF20`, `$FF21` | запрещено: события клавиатуры забирает монитор; ввод — через вызовы (разд. 6) |
| таймер `$FF29` | запрещено; частота тиков фиксирована, 50 Гц |
| часы реального времени | запрещено; время — через `TIME_GET`, `TIME_SET` |
| контроллер дисков | запрещено; сырые секторы — через `DISK_IO` |
| менеджер памяти | запрещено |
| прерывания (`CLI`, `STI`) | разрешено кратковременно (формат CX16, разд. 8.3) |
| `TRAP #9` | системный вызов (разд. 3) |
| `TRAP #10` | зарезервирован монитором для точек останова отладчика; программе запрещено |
| `TRAP #11` … `TRAP #15` | зарезервированы монитором; программе запрещено |

### 2.3. Старт и останов системы

При старте монитор монтирует все подключённые диски с ФС16 (разд. 5.3) и запускает оболочку — программу `A:/sys/shell.cx` с командной строкой `A:/sys/shell.cx`. Текущий каталог оболочки — `A:/`, дескрипторы 0, 1, 2 открыты на консоль.

Если диск 0 не смонтирован или оболочку не удалось запустить, монитор выводит сообщение на консоль и останавливает машину.

Когда завершается корень последнего сеанса (обычно оболочка; разд. 2.4):

- с кодом 0 — монитор выполняет `SHUTDOWN` (разд. 9.8): записывает всё на диски, размонтирует тома и останавливает машину;
- с любым другим кодом — монитор выводит сообщение с кодом и запускает оболочку заново.

### 2.4. Сеансы

**Сеанс** — цепочка процессов разд. 2.1 со своим экраном. Сеансов не больше 4, номера 0–3. Первый сеанс — 0 с оболочкой, остальные создаёт `SESS_NEW` (разд. 9.9).

Сеанс — не многозадачность. Выполняется только **текущий сеанс**: в нём — последний процесс его цепочки, как в разд. 2.1. Последний процесс другого сеанса **заморожен**: процессор его код не выполняет, тиков (`TICKHOOK`) и Ctrl+C он не получает, его вызов ожидания (разд. 3.4) не идёт. Время в нём при этом не стоит: `TICKS` и часы после возврата покажут, сколько прошло.

**Переход** в другой сеанс:
- **с клавиатуры:** Ctrl+] — следующий сеанс по кругу, Ctrl+[ — предыдущий. Эти клавиши монитор распознаёт всегда, при любом режиме консоли и `NOBREAK`, и программам их не передаёт. Распознаётся сканкод `[` или `]` с Ctrl в модификаторах (машина, разд. 2.6) и символ `$1D`: так Ctrl+] передаёт терминал. Ctrl+[ терминал передаёт как Esc, поэтому в эмуляторе командной строки работает только Ctrl+];
- **вызовом** `SESS_SWITCH` или `SESS_NEW` без `SN_BACK`: переход выполняется сразу после возврата из вызова, а вызвавший процесс получит результат, когда его сеанс снова станет текущим.

Переход прозрачен для программ:
- **процессор:** замороженный процесс продолжается ровно с того места, где был, с теми же регистрами и флагами;
- **ожидание:** вызов, который ждал (разд. 3.4), выполняется заново, когда процесс снова станет текущим. Он ничего не теряет: незаконченная строка строчного ввода — в сеансе, `SLEEP` ждёт оставшееся число тиков;
- **дисплей:** у каждого сеанса свой экран. При переходе монитор сохраняет содержимое экрана, CTRL, ATTR и позицию уходящего сеанса и восстанавливает их у нового. Новый сеанс начинается с пустого экрана в телетайпе, с курсором и ATTR = `$07`;
- **клавиатура:** события, набранные до перехода, отбрасываются: они были для прежнего сеанса.

**Процессы сеанса.** Корень сеанса, созданного `SESS_NEW`, — программа из командной строки вызова, обычно оболочка; его дескрипторы 0, 1, 2 открыты на консоль, текущий каталог — каталог вызвавшего процесса. Потомки — как в разд. 2.1. Память, файлы и тома общие для всех сеансов: открытый в одном сеансе файл виден другому, а удаление файла, открытого замороженным процессом, даёт `BUSY` (разд. 5.2).

**Конец сеанса:**
- корень сеанса завершился, а есть другие сеансы — сеанс закрывается, текущим становится следующий сеанс по кругу. Код завершения корня никто не получает;
- завершился корень **последнего** сеанса — как в разд. 2.3: останов при коде 0, иначе новая оболочка в том же сеансе;
- `SESS_KILL` завершает все процессы сеанса без уведомления, как выключение: закрываются дескрипторы, освобождается память;
- `SHUTDOWN` останавливает систему со всеми сеансами.

## 3. Соглашение о вызове

### 3.1. Вызов

Системный вызов — команда `TRAP #9`, за которой сразу следует слово с **номером вызова**:

```asm
        TRAP    #9
        .word   $12             ; READ
```

Монитор возвращает управление на адрес за словом номера.

**Аргументы** передаются в R0–R3 по правилу слотов B16 (B16, разд. 9.3):
- аргумент-слово занимает один регистр;
- аргумент `long`/`ulong` занимает два регистра подряд, младшее слово в первом.

Каждый вызов задаёт свои аргументы. Регистры R0–R3, которые вызов не использует как аргументы, на результат не влияют.

### 3.2. Результат

| Ресурс | После вызова |
| --- | --- |
| R0 | **код ошибки** (разд. 8); 0 — успех |
| ZF | 1, если R0 = 0; иначе 0 |
| R1–R3 | результаты вызова по правилу слотов; не используемые для результатов — не определены |
| R4–R12 (включая LR), SP | не меняются |
| IF | не меняется |
| CF, SF, OF | не определены |

Результаты в R1–R3 определены только при R0 = 0, если описание вызова не говорит иного. Например, `READ` и `WRITE` сообщают число переданных байт и при ошибке.

Вызов с неизвестным номером возвращает `NOSYS`.

### 3.3. Указатели и строки

- **Память процесса** — страницы, в которых стоит кадр процесса: собственные страницы ниже `top` и страницы с кадрами расширенной памяти (разд. 7.6), в том числе выше `top`.
- **Буфер** `[p, p + n)` должен целиком лежать в памяти процесса. Иначе вызов возвращает `FAULT` и ничего не делает. При n = 0 буфер не проверяется.
- **Строка** (путь, командная строка) — байты в кодировке машины с завершающим нулём. Строка должна лежать в памяти процесса вместе с нулём и быть не длиннее предела, указанного в вызове. Иначе — `FAULT` (выход за память) или `BADPATH`/`ARGS` (длина).
- **Адрес кода** (обработчики `TICKHOOK` и `ONEVENT`) должен быть чётным и лежать в памяти процесса, иначе `FAULT`.

Буфер, переданный вызову, не должен пересекаться с другим буфером того же вызова; результат такого вызова не определён.

### 3.4. Ожидание и прерывание вызова

Большинство вызовов выполняются сразу. Ждут только:
- чтение с консоли (`READ` консоли, `CON_GETEV` без `NOWAIT`);
- `SLEEP`;
- `SPAWN` (на время работы потомка).

Пока вызов ждёт, монитор обслуживает тики и клавиатуру.

Если во время ожидания нажата Ctrl+C и она действует как прерывание (разд. 6.3), ожидание заканчивается, а вызов возвращает `INTR`. Вызовы, которые не ждут, Ctrl+C не прерывает: они выполняются до конца, а прерывание действует после возврата (разд. 6.3).

Переход в другой сеанс (разд. 2.4) ожидание не завершает: вызов будет выполнен заново, когда процесс снова станет текущим, и программа этого не замечает. `SLEEP` при этом ждёт оставшееся число тиков, время в другом сеансе не считается. Вызов, который не ждёт, выполняется до конца, переход — после возврата.

### 3.5. Нумерация

Номера сгруппированы по 16:

| Номера | Группа |
| --- | --- |
| `$00–$0F` | процессы |
| `$10–$1F` | дескрипторы и ввод-вывод |
| `$20–$2F` | файловая система |
| `$30–$3F` | консоль |
| `$40–$4F` | память |
| `$50–$5F` | время |
| `$60–$6F` | система |
| `$70–$7F` | сеансы; `$7F` занят монитором |

Номера, которых нет в разд. 9.1, свободны для следующих ревизий и возвращают `NOSYS`.

## 4. Имена

### 4.1. Пути

Путь — строка не длиннее 255 байт без завершающего нуля. Он называет файл или каталог на томе, или устройство.

```text
путь      = [ префикс ] [ "/" ] шаги
префикс   = том ":"             том: буква A–H или цифра 0–7
          | "dev:"              устройство (разд. 4.2)
шаги      = шаг { "/" шаг } [ "/" ]
```

**Том** в префиксе — буква `A`–`H` в любом регистре: `A:` — том 0, `B:` — том 1 и так далее до `H:` — том 7. Для совместимости с путями прежних ревизий принимается и номер тома цифрой: `0:` равносильно `A:`, `7:` — `H:`. Пути, которые выдаёт монитор (`GETCWD`, сообщения), всегда содержат заглавную букву. Номер тома в вызовах (`MOUNT`, `VOLINFO`, `DISK_INFO` и др.) — по-прежнему число 0–7. Другой символ перед `:` (`I:`, `8:`) — не префикс тома, и путь даёт `BADNAME`.

**Начальная точка поиска:**

| Запись | Начало поиска |
| --- | --- |
| `X:/a/b`, `X:a/b` | корень тома X; `X:x` равносильно `X:/x` |
| `X:` | корень тома X |
| `/a/b` | корень тома текущего каталога |
| `a/b` | текущий каталог (разд. 4.3) |

**Шаги** разбираются по ФС16, разд. 7:
- `.` — пустой шаг;
- `..` — шаг назад по цепочке пути;
- повторные `/` равносильны одному;
- завершающий `/` допустим и смысла не меняет.

`..` в корне — ошибка `BADPATH`.

**Имя** в шаге — по ФС16, разд. 7: 1–32 байта, байты `$20` и выше, кроме `/` и `:`; имена `.` и `..` означают шаги. Имя длиннее 32 байт или с недопустимым байтом — ошибка `BADNAME`. Двоеточие допустимо только в префиксе: любое другое `:` в пути — `BADNAME`.

**Пределы:**
- путь длиннее 255 байт — `BADPATH`;
- после разбора `.` и `..` путь от корня тома содержит не больше 16 имён; более длинный — `BADPATH`;
- пустой путь (`""`) — `BADPATH`.

**Ошибки поиска:**

| Ситуация | Ошибка |
| --- | --- |
| том не смонтирован | `NODEV` |
| промежуточное имя не найдено | `NOENT` |
| промежуточное имя — файл, а не каталог | `NOTDIR` |
| последнее имя не найдено | `NOENT` |

Последняя ошибка возникает, если вызов не создаёт объект. Вызовы, которые создают объект, описывают это сами.

Имена сравниваются без учёта регистра букв (ФС16, разд. 7.1): `A:/BIN/LS.CX` и `A:/bin/ls.cx` — один файл. Регистр сохраняется: создание и переименование записывают последнее имя пути в том написании, в каком оно задано, а `READDIR` и `GETCWD` возвращают имена так, как они хранятся на диске. Например, если каталог называется `bin`, после `CHDIR` по пути `/BIN` вызов `GETCWD` вернёт `A:/bin`.

Префиксы `X:` и `dev:` и имена устройств (разд. 4.2) — не имена ФС16, правило на них не распространяется.

### 4.2. Устройства

Устройства называются путями с префиксом `dev:`:

| Путь | Устройство |
| --- | --- |
| `dev:con` | консоль: чтение — ввод с клавиатуры (разд. 6), запись — вывод на дисплей |
| `dev:nul` | пустое устройство: чтение сразу даёт конец файла, запись принимает и отбрасывает данные |

Другие имена после `dev:` — ошибка `NOENT`. Устройства можно открывать (`OPEN`) и запрашивать (`STAT`). Создавать, удалять, переименовывать их и делать текущим каталогом нельзя: это ошибка `INVAL`.

### 4.3. Текущий каталог

У каждого процесса один текущий каталог: том и путь от его корня.

- **Наследование.** Потомок получает копию текущего каталога родителя. `CHDIR` потомка на родителя не действует.
- **Вид.** `GETCWD` возвращает путь в виде `X:/a/b` с заглавной буквой тома, без завершающего `/`; корень — `X:/`.
- **Размонтированный том.** Если том текущего каталога размонтирован или диск отключён, пути без префикса тома дают `NODEV`, пока процесс не сменит каталог.
- **Удаление и переименование.** Каталог, который является текущим у какого-либо процесса цепочки или лежит на пути к такому каталогу, удалить и переименовать нельзя: `BUSY`.

## 5. Файлы и дескрипторы

### 5.1. Дескрипторы

Дескрипторы процесса — числа 0–15:

| Дескриптор | Назначение |
| --- | --- |
| 0 | стандартный ввод |
| 1 | стандартный вывод |
| 2 | стандартный вывод ошибок |

Других различий между дескрипторами нет. `OPEN` и `DUP` выдают наименьший свободный номер. Дескриптор вне 0–15 или не открытый — ошибка `BADF`.

**Наследование.** Потомок получает только дескрипторы 0, 1, 2, которые родитель назначает в `SPAWN` (разд. 7.1). Остальные дескрипторы родителя потомку не передаются.

**Закрытие при завершении.** При завершении процесса все его дескрипторы закрываются (разд. 7.2).

### 5.2. Открытые файлы и совместный доступ

Каждый `OPEN` создаёт новую запись открытого файла со своей позицией. `DUP` и наследование при `SPAWN` создают новый дескриптор на **ту же** запись: позиция у них общая. Запись закрывается, когда закрыт последний ссылающийся на неё дескриптор. Во всей системе одновременно открыто не больше 32 записей; при нехватке — ошибка `MFILE`.

**Совместный доступ:**
- один файл можно открыть несколько раз, в том числе одновременно на чтение и запись;
- изменения через одну запись сразу видны через другие: данные и размер общие;
- позиция каждой записи своя; если файл укоротили (`SETSIZE`), позиция другой записи за новым концом остаётся как есть: чтение с неё даёт конец файла, запись — `INVAL`.

**Открытые объекты.** Открытый файл или каталог нельзя удалить или переименовать: `BUSY`.

### 5.3. Тома

**Монтирование.** При старте монитор монтирует все подключённые диски с правильным суперблоком (ФС16, разд. 3). Позже это делает `MOUNT`.

| Состояние диска | Как монтируется |
| --- | --- |
| диск защищён от записи (RO в блоке INFO) | только на чтение |
| флаг DIRTY в суперблоке | только на чтение; при старте монитор выводит сообщение, `MOUNT` сообщает об этом флагом результата. Том проверяет и чинит программа (утилита `fsck`) через `DISK_IO`, затем том перемонтируется на запись (`MOUNT` с `MOUNT_REMOUNT`) |
| иначе | на запись; монитор ставит DIRTY (ФС16, разд. 10) |

Запись на том, смонтированный только на чтение, — ошибка `RDONLY`.

**Проверка тома с DIRTY.** На томе, смонтированном только на чтение, `DISK_IO` может писать секторы: монитор сам на такой том не пишет. После каждой записи монитор сбрасывает свой кеш секторов этого диска. Когда проверка закончена и DIRTY снят, `MOUNT` с флагом `MOUNT_REMOUNT` монтирует том заново, и он становится томом на запись. Так чинится и том 0, с которого загружены программы: открытых файлов на нём во время проверки нет, а текущий каталог перемонтирование не мешает.

**Размонтирование** (`UNMOUNT`, `SHUTDOWN`) записывает отложенные изменения, снимает DIRTY и выполняет FLUSH диска. Том, на котором есть открытые файлы или текущий каталог какого-либо процесса цепочки, размонтировать нельзя: `BUSY`.

**Отключение диска.** Перед каждым обращением к тому монитор проверяет, подключён ли диск. Если диск отключён (возможно у дисков REMOVABLE, машина, разд. 6):
- том помечается потерянным;
- все обращения к нему, в том числе через открытые дескрипторы, возвращают `NODEV`; `CLOSE` таких дескрипторов работает;
- том остаётся в таблице до `UNMOUNT`, который в этом случае ничего не записывает. После подключения диска его снова монтируют `MOUNT`.

### 5.4. Запись на диск

Монитор выполняет операции ФС16 в порядке её разд. 9–10. Гарантии для программы:

- данные, переданные `WRITE`, записаны на диск до возврата из вызова;
- размер файла и его адреса в записи каталога записаны до возврата из вызова, изменившего их (`WRITE`, `SETSIZE`, `OPEN` с `TRUNC`);
- метка времени изменения (MTIME) файла обновляется при каждом изменении его данных или размера (`WRITE`, `SETSIZE`, `OPEN` с `O_TRUNC`) и записывается на диск вместе с записью каталога до возврата из вызова; MTIME каталога — при создании, удалении и переименовании записей в нём;
- освобождения кластеров в карте могут быть отложены до `SYNC`, `UNMOUNT` или `SHUTDOWN` (ФС16, разд. 10). Если машину выключить раньше, освобождённые кластеры утекут, но том останется целостным.

`SYNC` записывает всё отложенное и выполняет FLUSH всех томов, смонтированных на запись.

## 6. Консоль

### 6.1. Режимы ввода

Клавиатурой владеет монитор: на каждом тике он перекладывает события из очереди клавиатуры в свой буфер на 256 событий. Лишние события отбрасываются.

Режим ввода задаёт `CON_MODE` — набор битов:

| Бит | Имя | Значение |
| --- | --- | --- |
| 0 | `RAW` | 0 — строчный режим (разд. 6.2), 1 — сырой |
| 1 | `NOECHO` | в строчном режиме не выводить вводимые символы |
| 2 | `NOBREAK` | Ctrl+C — обычный символ, а не прерывание (разд. 6.3) |

Режим принадлежит процессу. Новый процесс начинает в режиме 0 (строчный, с эхом, Ctrl+C прерывает). Когда потомок завершается, монитор восстанавливает режим родителя.

**Строчный режим.** `READ` с консоли получает строку, набранную и отредактированную пользователем (разд. 6.2).

**Сырой режим.** `READ` с консоли:
- ждёт хотя бы одно событие с ненулевым символом;
- возвращает символы всех доступных таких событий (не больше заказанного);
- эха и редактирования нет; события без символа (стрелки, F1–F12) отбрасываются.

**Ctrl+Enter** — событие с символом 0 и сканкодом `$1C` (машина, разд. 2.6). Строчный режим его игнорирует, сырой `READ` отбрасывает; отличить её от Enter можно только через `CON_GETEV`.

Для полного доступа к событиям, включая сканкоды и модификаторы, служит `CON_GETEV`. Он работает в любом режиме и берёт следующее событие из буфера монитора. Символы, уже попавшие в незаконченную строку строчного режима, `CON_GETEV` не получает.

### 6.2. Строчный ввод

Монитор накапливает строку до 255 символов и отдаёт её `READ` после Enter.

| Клавиша | Символ | Действие |
| --- | --- | --- |
| символы `$20` и выше, Tab | | добавляются в строку; при полной строке игнорируются |
| Backspace | `$08` | удаляет последний символ строки, на экране стирает его (`\b`, пробел, `\b`) |
| Ctrl+U | `$15` | удаляет всю строку, на экране стирает её |
| Enter | `$0A` | завершает строку: в неё добавляется `\n`, выводится перевод строки |
| Ctrl+Z в начале строки | `$1A` | конец файла: `READ` возвращает 0 байт |
| Ctrl+C | `$03` | разд. 6.3 |
| прочие управляющие символы и события без символа | | игнорируются |

Ctrl+Z не в начале строки игнорируется.

`READ` возвращает не больше заказанного числа байт. Остаток строки отдаётся следующими `READ`, и новая строка не начинается, пока не прочитана предыдущая.

### 6.3. Ctrl+C

Если в режиме процесса не установлен `NOBREAK`, Ctrl+C — **прерывание**. Монитор распознаёт его на тике, в любой момент работы процесса:

1. Буфер событий и незаконченная строка отбрасываются; монитор выводит `^C` и перевод строки.
2. Если процесс выполняется вне монитора, он завершается с кодом `$8001` (разд. 7.2).
3. Если процесс ждёт в вызове (разд. 3.4), вызов возвращает `INTR`, после чего процесс завершается с кодом `$8001`.
4. Если процесс выполняет вызов, который не ждёт, вызов выполняется до конца, после чего процесс завершается с кодом `$8001`.

Если процесс установил **обработчик Ctrl+C** (`ONEVENT`, разд. 7.5), в пп. 2–4 вместо завершения вызывается обработчик: в п. 2 — сразу, в пп. 3 и 4 — после возврата из вызова (п. 3 — с результатом `INTR`).

Прерывание действует на выполняющийся, то есть последний процесс цепочки. Его родитель получает код `$8001` как обычный код завершения и продолжает работу.

Если `NOBREAK` установлен, Ctrl+C — обычное событие с символом `$03`:
- в сыром режиме оно доставляется как любое другое;
- в строчном режиме оно отменяет строку: строка отбрасывается, монитор выводит `^C` и перевод строки, а ожидающий `READ` возвращает `INTR`.

Так оболочка, установив `NOBREAK`, отменяет набранную команду, но сама не завершается.

### 6.4. Вывод и дисплей

`WRITE` в консоль выводит байты в регистр DATA подряд, без преобразований (машина, разд. 2.3). В режиме телетайпа `\n` переводит строку.

Программа может сама управлять дисплеем: писать в DATA, CTRL, ATTR, COL, ROW, CMD. Это быстрее вызовов и нужно полноэкранным программам. Прямой вывод обходит перенаправление стандартного вывода: он всегда попадает на экран.

Эхо строчного ввода и сообщения монитора выводятся в DATA при текущем состоянии CTRL и ATTR. Если программа перевела дисплей в координатный режим, эхо будет выводиться по его правилам.

Когда потомок завершается, монитор восстанавливает CTRL и ATTR, какие были при его запуске. Содержимое экрана и позиция не восстанавливаются.

Экран можно прочитать регистром SCRD (машина, разд. 2.2): словное чтение `$FF50` даёт символ и атрибут ячейки в позиции и сдвигает позицию. При переходе между сеансами экран, CTRL, ATTR и позицию сохраняет и восстанавливает монитор (разд. 2.4), программам для этого ничего делать не нужно.

## 7. Процессы

### 7.1. Запуск потомка

`SPAWN` получает командную строку (не длиннее 255 байт) и три дескриптора родителя для стандартных потоков потомка.

1. **Разбор.** Командная строка разбирается по формату CX16, разд. 5.2. Первое слово — путь к файлу программы (разд. 4.1). Монитор не ищет программу по каталогам и не добавляет расширение: это делает оболочка. `argv[0]` — первое слово командной строки как есть.
2. **Загрузка.** Файл загружается по формату CX16, разд. 9.1; ошибки загрузки — коды разд. 8. При любой ошибке потомок не создаётся, а родитель получает ошибку.
3. **Стандартные потоки.** Дескрипторы 0, 1, 2 потомка ссылаются на те же записи открытых файлов, что указанные дескрипторы родителя (разд. 5.2). Значение `$FFFF` означает «тот же дескриптор родителя»: 0, 1 или 2 соответственно.
4. **PIB.** Флаги перенаправления в PIB (формат CX16, разд. 4) монитор ставит сам:
   - бит 0 — если дескриптор 0 потомка не консоль;
   - бит 1 — если дескриптор 1 не консоль.
5. **Окружение потомка:** копия текущего каталога родителя; режим консоли 0; обработчика тика и обработчиков событий нет.
6. **Возврат.** Родитель ждёт в вызове, пока потомок не завершится. Затем `SPAWN` возвращает R0 = `OK` и R1 = код завершения потомка — даже если потомок завершён монитором (коды `$8000` и выше).

Если цепочка уже содержит 16 процессов, `SPAWN` возвращает `NOPROC`.

### 7.2. Завершение и коды

Процесс завершается:
- вызовом `EXIT` с кодом в R0;
- возвратом по LR, полученному при запуске (процедура выхода по адресу `$E000`, формат CX16, разд. 8.1), с кодом в R0;
- монитором (Ctrl+C, недопустимая команда).

При завершении монитор:
1. закрывает все дескрипторы процесса;
2. сбрасывает обработчик тика и обработчики событий;
3. восстанавливает режим консоли, CTRL и ATTR родителя (разд. 6.1, 6.4);
4. освобождает память процесса;
5. возвращает управление родителю из его `SPAWN`.

**Коды завершения:**

| Код | Значение |
| --- | --- |
| `$0000` | успех |
| `$0001–$7FFF` | коды программы |
| `$8000–$FFFF` | зарезервированы монитором |
| `$8001` | прерван Ctrl+C |
| `$8008` | недопустимая команда |
| `$8009` | прочие причины, по которым процесс завершил монитор |

Программа не должна сама завершаться с кодом из диапазона `$8000–$FFFF`. Монитор такой код не проверяет и передаёт родителю как есть.

### 7.3. Недопустимая команда

Если процесс выполняет недопустимую команду (процессор, ERRCMD), монитор:
- выводит на консоль, минуя перенаправление, сообщение `monitor: illegal instruction at $XXXX`;
- завершает процесс с кодом `$8008`.

Если процесс установил обработчик недопустимой команды (`ONEVENT`, разд. 7.5), вместо этого вызывается обработчик; сообщения нет.

### 7.4. Обработчик тика

`TICKHOOK` устанавливает обработчик тика процесса.

Монитор вызывает обработчик **после своей обработки тика**, но только если тик прервал процесс вне монитора. Тики, пришедшие, пока процесс выполнял вызов или ждал в нём, обработчику не передаются и потом не наверстываются.

Вызов обработчика выглядит так же, как вход в обработчик прерывания:
- на стеке процесса `[SP]` — FLAGS, `[SP+2]` — адрес прерванной команды;
- IF = 0;
- регистры содержат значения прерванной программы.

Обработчик сохраняет все регистры, которые меняет, и завершается командой `IRET`. На B16 это `interrupt fn` (B16, разд. 9.5).

Правила для обработчика:
- работать недолго, меньше одного тика; тики, пришедшие во время его работы, сливаются (машина, разд. 3);
- **не выполнять системные вызовы**: результат не определён;
- при входе в обработчик процессор уже положил 4 байта на стек процесса; сам обработчик кладёт на стек столько, сколько использует. Стек программы должен это выдерживать в любой момент.

Обработчик принадлежит процессу: у потомка его нет, пока потомок работает, обработчик родителя не вызывается, а при завершении процесса обработчик сбрасывается.

### 7.5. Обработчики событий

`ONEVENT` устанавливает обработчик одного из событий процесса:

| Событие | Константа | Когда вызывается | Адрес в кадре |
| --- | --- | --- | --- |
| Ctrl+C | `EVT_BREAK` | вместо завершения с `$8001` (разд. 6.3) | прерванное место: команда, на которой пришёл тик, или адрес за вызовом |
| недопустимая команда | `EVT_BADINSN` | вместо завершения с `$8008` (разд. 7.3) | первое слово недопустимой команды (процессор, разд. 8.4) |

Вызов обработчика выглядит так же, как вход в обработчик прерывания:
- на стеке процесса `[SP]` — FLAGS, `[SP+2]` — адрес из таблицы;
- IF = 0;
- регистры содержат значения прерванной программы. Если Ctrl+C пришла во время вызова, R0–R3 содержат результат вызова (п. 3 разд. 6.3 — код `INTR`), а FLAGS в кадре — флаги после вызова, с ZF по R0.

Обработчик сохраняет регистры, которые меняет, и завершается командой `IRET` (на B16 — `interrupt fn`), и тогда программа продолжается с адреса в кадре. Обработчик недопустимой команды, который хочет пропустить или эмулировать команду, сам увеличивает адрес в кадре на её длину; иначе `IRET` выполнит ту же команду снова. Обработчик может и не возвращаться, например вызвать `EXIT`.

В отличие от обработчика тика, **в обработчике событий можно выполнять системные вызовы**: он вызывается как обычный код программы.

Требования к стеку: при доставке Ctrl+C после вызова монитор сам кладёт на стек процесса кадр возврата из вызова, а затем выходит в обработчик со вторым кадром — всего 8 байт ниже SP. Если их нет (SP меньше 8 или больше `top`), процесс завершается с `$8001`, как без обработчика.

Ctrl+C, пришедшая во время работы обработчика, ждёт выхода из него: обработчик выполняется при IF = 0. Если обработчик сам разрешил прерывания или ждёт в вызове, новая Ctrl+C снова вызовет обработчик.

Обработчики принадлежат процессу: потомок их не наследует, пока потомок работает, обработчики родителя не действуют, а при `EXEC` и завершении процесса они сбрасываются. При `NOBREAK` Ctrl+C — обычное событие, и обработчик Ctrl+C не вызывается.

### 7.6. Память процесса и расширенная память

**Собственная память** — `top / $2000` кадров в страницах 0 … `top`/$2000 − 1 (формат CX16, разд. 6). `SETTOP` увеличивает или уменьшает её целыми страницами.

**Расширенная память** — кадры сверх собственных: `XALLOC` выдаёт обнулённый кадр, `XMAP` ставит его в любую из страниц 0–6, `XFREE` возвращает системе. Так программа работает с памятью больше 56 КБ, переключая кадры в одной-двух страницах-окнах.

- **Номер кадра** — его номер в машине (14–255). Программа получает его от `XALLOC` и передаёт в `XMAP` и `XFREE`; чужие кадры и свои собственные эти вызовы не принимают.
- **Окно.** Страница, в которую поставлен кадр расширенной памяти, — память процесса (разд. 3.3), даже если она выше `top`; в ней могут лежать буферы вызовов, стек и код. Ставить кадр в страницу, где выполняется код или лежит стек, — забота программы: смена действует сразу после возврата из `XMAP`.
- **Без защиты.** Писать в регистры менеджера памяти напрямую по-прежнему нельзя (разд. 2.2): монитор хранит карту процесса сам и восстанавливает её при каждом выходе из вызова.
- **Владение.** Кадры расширенной памяти принадлежат процессу: потомок их не получает, при `EXIT` и `EXEC` они освобождаются вместе с собственной памятью.
- **Предела на процесс нет.** Если свободных кадров не осталось, `XALLOC`, `SETTOP` и запуск программ (`SPAWN`, `EXEC`) возвращают `NOMEM`.

### 9.2. Процессы

#### `$00` EXIT — завершить процесс

```text
fn sys_exit(code: uint)
```

R0 = код. Завершает процесс (разд. 7.2) и не возвращается.

#### `$01` SPAWN — запустить потомка

```text
fn sys_spawn(cmd: ptr byte, fin: uint, fout: uint, ferr: uint): (uint, uint)
```

R0 = командная строка, R1–R3 — дескрипторы родителя для потоков 0, 1, 2 потомка (`$FFFF` — тот же номер). Результат: R1 = код завершения потомка.

Запускает потомка и ждёт его завершения (разд. 7.1).

Ошибки: `BADF` (дескриптор), `ARGS` (строка длиннее 255 байт, число аргументов, кавычка), ошибки загрузки (разд. 8), `NOPROC`.

#### `$02` EXEC — заменить программу в процессе

```text
fn sys_exec(cmd: ptr byte): uint
```

R0 = командная строка (не длиннее 255 байт). Загружает программу так же, как `SPAWN` (разд. 7.1, пп. 1–2), но в тот же процесс, вместо вызвавшей программы. При успехе не возвращается: управление получает новая программа в начальном состоянии формата CX16 (разд. 8.1).

**Сохраняются:** место процесса в цепочке (родитель получит код завершения новой программы), все открытые дескрипторы, текущий каталог.

**Сбрасываются:** память (новая программа получает свою, старая освобождается), режим консоли (0), обработчик тика и обработчики событий. Флаги PIB ставятся по дескрипторам 0 и 1 процесса.

**Память.** Новая программа загружается до освобождения старой: при неудаче вызывающая программа продолжается и получает код ошибки. Поэтому на время загрузки нужны свободные кадры для обеих: `NOMEM` возможен, даже если после освобождения старой памяти новой программе её бы хватило.

Ошибки: `ARGS`, `FAULT`, ошибки загрузки (разд. 8).

#### `$03` ONEVENT — обработчик события

```text
fn sys_onevent(ev: uint, h: ptr interrupt fn()): (uint, ptr interrupt fn())
```

R0 = событие (`EVT_BREAK`, `EVT_BADINSN`), R1 = адрес обработчика (разд. 7.5) или 0 — убрать. Результат: R1 = прежний обработчик этого события или 0.

Ошибки: `INVAL` (неизвестное событие), `FAULT` (адрес не меньше `top` или нечётный).

### 9.3. Дескрипторы и ввод-вывод

**Режимы открытия** (аргумент `mode` вызова `OPEN`):

| Бит | Имя | Значение |
| --- | --- | --- |
| 0 | `O_READ` | чтение |
| 1 | `O_WRITE` | запись |
| 2 | `O_CREATE` | создать файл, если его нет |
| 3 | `O_TRUNC` | укоротить до 0; требует `O_WRITE` |
| 4 | `O_EXCL` | с `O_CREATE`: ошибка, если файл уже есть |
| 5 | `O_APPEND` | каждая запись — в конец файла |

#### `$10` OPEN — открыть

```text
fn sys_open(path: ptr byte, mode: uint, attr: uint): (uint, uint)
```

R0 = путь, R1 = режим, R2 = флаги нового файла (`A_RDONLY`, `A_HIDDEN`, `A_SYSTEM`; используются только при создании). Результат: R1 = дескриптор, наименьший свободный.

**Объекты:**
- **Файл** открывается с `O_READ` и (или) `O_WRITE`. Позиция — 0.
- **Каталог** открывается только с `O_READ`, без прочих битов. Читается вызовом `READDIR`.
- **Устройство** (`dev:con`, `dev:nul`) — с `O_READ` и (или) `O_WRITE`, прочие биты игнорируются.

**Создание.** С `O_CREATE`, если последнего имени пути нет, создаётся пустой файл с флагами `attr` и MTIME = текущее время (ФС16, разд. 9). Последнее имя ищется без учёта регистра (разд. 4.1): если есть файл, имя которого отличается только регистром, открывается он, а его имя не меняется. Новый файл с `A_RDONLY` остаётся открытым на запись через этот дескриптор, если в `mode` есть `O_WRITE`.

**`O_APPEND`.** Перед каждой записью позиция ставится в конец файла. Чтение идёт с текущей позиции.

Ошибки:
- `INVAL` — нет ни `O_READ`, ни `O_WRITE`, или `O_TRUNC` без `O_WRITE`;
- `NOENT` — нет файла и нет `O_CREATE`;
- `EXIST` — `O_CREATE | O_EXCL`, а файл есть;
- `ISDIR` — каталог с `O_WRITE`, `O_CREATE` или `O_TRUNC`;
- `RDONLY` — `O_WRITE` для файла с флагом RDONLY, создание в каталоге с RDONLY, запись на том только для чтения;
- `NOSPC` — нет места для новой записи каталога;
- `MFILE`, `NODEV`, `IO`.

#### `$11` CLOSE — закрыть

```text
fn sys_close(h: uint): uint
```

Закрывает дескриптор. Все изменения файла уже записаны на диск вызовами, которые их сделали (разд. 5.4), поэтому закрытие ничего не пишет. Ошибки: `BADF`, `IO` (дескриптор закрыт и в этом случае).

#### `$12` READ — читать

```text
fn sys_read(h: uint, buf: ptr, n: uint): (uint, uint)
```

R0 = дескриптор, R1 = буфер, R2 = число байт. Результат: R1 = прочитано, в том числе при ошибке.

| Объект | Поведение |
| --- | --- |
| файл | читает с позиции не больше n байт и сдвигает позицию; в конце файла — 0 |
| консоль | по режиму ввода (разд. 6.1–6.2); ждёт ввода |
| `dev:nul` | 0 |

Ошибки: `BADF` (не открыт на чтение), `ISDIR` (каталог), `INTR`, `NODEV`, `IO`.

#### `$13` WRITE — писать

```text
fn sys_write(h: uint, buf: ptr, n: uint): (uint, uint)
```

R0 = дескриптор, R1 = буфер, R2 = число байт. Результат: R1 = записано, в том числе при ошибке.

| Объект | Поведение |
| --- | --- |
| файл | пишет с позиции, при необходимости увеличивая файл; сдвигает позицию. Данные и размер на диске до возврата (разд. 5.4) |
| консоль | вывод (разд. 6.4) |
| `dev:nul` | R1 = n |

Если места не хватило, записывается сколько поместилось, вызов возвращает `NOSPC`. Позиция за концом файла (после чужого `SETSIZE`, разд. 5.2) — `INVAL`.

Ошибки: `BADF` (не открыт на запись), `ISDIR`, `NOSPC`, `RDONLY`, `INVAL`, `NODEV`, `IO`.

#### `$14` SEEK — позиция

```text
fn sys_seek(h: uint, off: long, whence: uint): (uint, ulong)
```

R0 = дескриптор, R1:R2 = смещение, R3 = отсчёт: 0 — от начала, 1 — от текущей позиции, 2 — от конца файла. Результат: R1:R2 = новая позиция. `SEEK(h, 0, 1)` сообщает текущую позицию.

- Новая позиция должна быть в пределах 0 … размер файла включительно, иначе `INVAL` и позиция не меняется. Дыр в файлах ФС16 нет.
- **Каталог.** Допустим только `SEEK(h, 0, 0)`: следующий `READDIR` начнёт с первой записи.
- **Консоль и `dev:nul`.** Позиции нет: `INVAL`.

Ошибки: `BADF`, `INVAL`.

#### `$15` DUP — копия дескриптора

```text
fn sys_dup(h: uint, target: uint): (uint, uint)
```

R0 = дескриптор, R1 = нужный номер или `$FFFF`. Результат: R1 = новый дескриптор на ту же запись открытого файла (разд. 5.2).

- При `target = $FFFF` выдаётся наименьший свободный номер.
- Иначе дескриптор `target`, если открыт, сначала закрывается.
- `target = h` — ничего не делает.

Ошибки: `BADF`, `MFILE`.

#### `$16` HINFO — вид дескриптора

```text
fn sys_hinfo(h: uint): (uint, uint, uint)
```

Результат: R1 = вид (0 — файл, 1 — каталог, 2 — консоль, 3 — `dev:nul`), R2 = режим открытия (биты `O_…`). Ошибки: `BADF`.

#### `$17` SETSIZE — изменить размер файла

```text
fn sys_setsize(h: uint, size: ulong, flags: uint): uint
```

R0 = дескриптор, R1:R2 = новый размер, R3 = флаги: бит 0 `SZ_ZERO` — заполнить добавленные байты нулями. Позиция дескриптора не меняется, кроме случая уменьшения ниже неё: тогда позиция ставится на новый конец.

**Уменьшение.** Лишние кластеры освобождаются в порядке ФС16, разд. 9 («Обрезка»).

**Увеличение.** Файлу добавляются кластеры до нового размера в порядке ФС16, разд. 9 («Добавление кластера»), запись каталога пишется один раз в конце:
- без `SZ_ZERO` данные новых кластеров на диск не пишутся. Байты от прежнего конца файла до нового **не определены**: в них может оказаться что угодно, в том числе данные удалённых файлов. Вызов быстрый: он пишет только карту, индексные кластеры и запись каталога;
- с `SZ_ZERO` монитор записывает нули во все байты от прежнего конца до нового, включая хвост последнего прежнего кластера. Это стоит записи каждого добавленного сектора.

Если места не хватает, размер не меняется: уже выделенные кластеры освобождаются, и вызов возвращает `NOSPC`. Новый размер больше 2^27 − 1 — тоже `NOSPC`.

При равном размере вызов ничего не делает.

Ошибки: `BADF` (не открыт на запись), `INVAL` (объект не файл, лишние биты флагов), `NOSPC`, `RDONLY`, `NODEV`, `IO`.

#### `$18` FSTAT — сведения об открытом файле

```text
fn sys_fstat(h: uint, st: ptr Stat): uint
```

Заполняет `Stat` (разд. 10.2) по текущему состоянию открытого объекта. Ошибки: `BADF`, `NODEV`.

### 9.4. Файловая система

#### `$20` STAT — сведения о файле

```text
fn sys_stat(path: ptr byte, st: ptr Stat): uint
```

Заполняет `Stat` (разд. 10.2): первые 40 байт записи каталога ФС16 — имя, размер с флагами, MTIME.
- Для корня тома имя пустое, стоит флаг DIR.
- Для устройства — имя устройства (`con`, `nul`), размер 0, флагов нет, MTIME 0.

Ошибки: только ошибки пути, `NODEV`, `IO`.

#### `$21` DELETE — удалить

```text
fn sys_delete(path: ptr byte): uint
```

Удаляет файл или пустой каталог (ФС16, разд. 9).

Ошибки:
- `RDONLY` — флаг RDONLY у объекта или у каталога, в котором он лежит; том только для чтения;
- `NOTEMPTY`;
- `BUSY` — открыт или текущий каталог (разд. 4.3, 5.2);
- `INVAL` — корень или устройство;
- `NODEV`, `IO`.

#### `$22` RENAME — переименовать, переместить

```text
fn sys_rename(old: ptr byte, new: ptr byte): uint
```

Переименовывает объект или перемещает его в другой каталог того же тома (ФС16, разд. 9). MTIME самого объекта не меняется. Флаг RDONLY у объекта переименованию не мешает.

**Смена регистра.** Если `new` называет тот же объект, что и `old` (например, `readme` → `README`), вызов меняет только написание имени: NAME записи заменяется последним именем `new`. Это не ошибка `EXIST`. Если написание совпадает побайтно, вызов успешен и ничего не меняет.

Ошибки:
- `EXIST` — `new` уже есть и это другой объект (имена сравниваются без учёта регистра);
- `XDEV` — пути на разных томах;
- `INVAL` — каталог в собственный подкаталог, корень или устройство;
- `RDONLY` — RDONLY у каталога-источника или каталога-приёмника; том только для чтения;
- `BUSY` — объект открыт или текущий каталог;
- `NOSPC`, `NODEV`, `IO`.

#### `$23` MKDIR — создать каталог

```text
fn sys_mkdir(path: ptr byte): uint
```

Создаёт пустой каталог. Ошибки: `EXIST` (объект с таким именем без учёта регистра уже есть), `RDONLY`, `NOSPC`, `INVAL` (устройство), `NODEV`, `IO`.

#### `$24` CHDIR — сменить текущий каталог

```text
fn sys_chdir(path: ptr byte): uint
```

Ошибки: `NOTDIR` (путь называет файл), `INVAL` (устройство), `NODEV`, `IO`.

#### `$25` GETCWD — текущий каталог

```text
fn sys_getcwd(buf: ptr byte, n: uint): (uint, uint)
```

Записывает в буфер путь текущего каталога в виде разд. 4.3 с завершающим нулём. Результат: R1 = длина пути без нуля. Ошибки: `INVAL` (не хватает n байт; буфер не меняется).

#### `$26` READDIR — следующая запись каталога

```text
fn sys_readdir(h: uint, st: ptr Stat): (uint, uint)
```

R0 = дескриптор каталога, открытого `OPEN`. Заполняет `Stat` следующей занятой записью каталога. Результат: R1 = 1, если запись есть; 0 — записи кончились (`Stat` не меняется).

Записи выдаются в порядке на диске, свободные пропускаются, записи с HIDDEN и SYSTEM не пропускаются. Если каталог меняется во время перебора, каждая запись, не менявшаяся за это время, выдаётся ровно один раз.

Ошибки: `BADF`, `NOTDIR` (дескриптор не каталога), `NODEV`, `IO`.

#### `$27` SETATTR — изменить флаги

```text
fn sys_setattr(path: ptr byte, attr: uint): uint
```

Устанавливает флаги RDONLY, HIDDEN, SYSTEM объекта: биты `A_RDONLY`, `A_HIDDEN`, `A_SYSTEM` (разд. 10.2). Флаг DIR не меняется; другие биты — `INVAL`. Снять RDONLY этим вызовом можно. MTIME не меняется.

Ошибки: `INVAL` (корень, устройство, лишние биты), `RDONLY` (том только для чтения), `NODEV`, `IO`.

#### `$28` VOLINFO — сведения о томе

```text
fn sys_volinfo(drv: uint, vi: ptr VolInfo): uint
```

Заполняет `VolInfo` (разд. 10.2): метка, серийный номер, число кластеров, свободные кластеры, флаги монтирования. Ошибки: `NODEV`, `IO`.

#### `$29` MOUNT — смонтировать

```text
fn sys_mount(drv: uint, flags: uint): (uint, uint)
```

R0 = диск 0–7, R1 = флаги: бит 0 `MOUNT_RDONLY` — только чтение, бит 1 `MOUNT_REMOUNT` — перемонтировать. Монтирует том (разд. 5.3). Результат: R1 = флаги `VolInfo.flags`; по ним видно, смонтирован ли том только на чтение и почему.

**`MOUNT_REMOUNT`** — для уже смонтированного тома: отложенные изменения записываются (если том на запись), кеш секторов диска сбрасывается, суперблок читается заново и том монтируется так же, как при первом монтировании. Текущие каталоги процессов на томе остаются действительными. Если монтирование заново не удалось, том остаётся размонтированным. Нужен после проверки тома (разд. 5.3).

Ошибки: `NODEV` (нет диска; для `MOUNT_REMOUNT` — том не смонтирован или потерян), `BUSY` (уже смонтирован без `MOUNT_REMOUNT`; с `MOUNT_REMOUNT` — на томе есть открытые файлы или каталоги), `INVAL` (лишние биты), `NOTFS`, `IO`.

#### `$2A` UNMOUNT — размонтировать

```text
fn sys_unmount(drv: uint): uint
```

Ошибки: `NODEV` (не смонтирован), `BUSY` (разд. 5.3), `IO`.

#### `$2B` SYNC — записать отложенное

```text
fn sys_sync(): uint
```

Записывает отложенные изменения всех томов и выполняет FLUSH (разд. 5.4). Ошибки: `IO`.

#### `$2C` SETMTIME — установить время изменения

```text
fn sys_setmtime(path: ptr byte, t: ulong): uint
```

R0 = путь, R1:R2 = метка времени в формате ФС16 (разд. 5.1 ФС16) или 0 — метки нет. Записывает MTIME объекта: файла, каталога или корня тома. Флаги объекта и RDONLY не мешают. Открытые дескрипторы объекта сразу видят новое значение; следующее изменение данных или размера файла поставит MTIME заново (разд. 5.4).

Ошибки: `INVAL` (недопустимое поле метки, устройство), `RDONLY` (том только для чтения), `NODEV`, `IO`.

### 9.5. Консоль

#### `$30` CON_MODE — режим консоли

```text
fn sys_con_mode(mode: uint): (uint, uint)
```

R0 = новый режим (биты разд. 6.1) или `$FFFF` — только узнать. Результат: R1 = прежний режим. Незаконченная строка строчного режима при смене режима отбрасывается. Ошибки: `INVAL` (лишние биты).

#### `$31` CON_GETEV — событие клавиатуры

```text
fn sys_con_getev(flags: uint): (uint, uint, uint)
```

R0 = флаги: бит 0 `NOWAIT` — не ждать. Результат: R1 = событие (символ в младшем байте, сканкод в старшем), R2 = модификаторы события: бит 0 Shift, бит 1 Ctrl, бит 2 Alt (регистр MODS машины, разд. 2.6). Ждёт события, если буфер пуст.

Модификаторы монитор запоминает при каждом событии в буфере, поэтому они относятся именно к нему, даже если программа забирает события позже. Какие сочетания вообще доходят до машины, зависит от эмулятора (машина, разд. 9.2, 9.3): терминал Unix, например, у символов модификаторы не передаёт. Программе с сочетаниями вида Shift+стрелка стоит иметь и запасные клавиши. Вызов с двумя целями (`e, ev = sys_con_getev(0)`) по-прежнему допустим: лишний результат отбрасывается.

Ctrl+C отдаётся как событие, только если установлен `NOBREAK` (разд. 6.3).

Ошибки: `AGAIN` (`NOWAIT`, событий нет), `INTR`, `INVAL`.

#### `$32` CON_FLUSH — сбросить ввод

```text
fn sys_con_flush(): uint
```

Отбрасывает буфер событий и незаконченную строку строчного режима.

### 9.6. Память

#### `$40` MEMINFO — сведения о памяти

```text
fn sys_meminfo(): (uint, uint, uint, uint)
```

Результат:
- R1 = `top` процесса;
- R2 = число свободных кадров памяти в системе (по 8 КБ);
- R3 = число кадров расширенной памяти процесса.

#### `$41` SETTOP — изменить память процесса

```text
fn sys_settop(top: uint): uint
```

R0 = новый `top`, кратный `$2000`, от `$2000` до `$E000`. Новые собственные страницы получают обнулённые кадры, лишние кадры освобождаются. Страница, в которой стоит кадр расширенной памяти, остаётся с ним; собственный кадр за ней появляется или освобождается как у остальных. Поле `top` в PIB обновляется. Данные и стек выше нового `top` при уменьшении теряются — перенести их заранее забота программы.

Ошибки: `INVAL` (значение), `NOMEM` (не хватает свободных кадров; память не меняется).

#### `$42` XALLOC — кадр расширенной памяти

```text
fn sys_xalloc(): (uint, uint)
```

Выделяет процессу обнулённый кадр (разд. 7.6). Результат: R1 = номер кадра. Ошибки: `NOMEM`.

#### `$43` XFREE — вернуть кадр

```text
fn sys_xfree(f: uint): uint
```

Возвращает системе кадр расширенной памяти f. Страницы, в которых он стоит, получают то, что в них было бы без `XMAP`: собственный кадр ниже `top`, иначе ничего (обращение к ним из вызовов — `FAULT`). Ошибки: `INVAL` (кадр не принадлежит процессу как кадр расширенной памяти).

#### `$44` XMAP — поставить кадр в страницу

```text
fn sys_xmap(page: uint, f: uint): (uint, uint)
```

R0 = страница 0–6, R1 = номер кадра расширенной памяти или `XM_OWN` (`$FFFF`) — вернуть странице собственный кадр (выше `top` — убрать кадр). Результат: R1 = кадр, стоявший в странице: номер кадра расширенной памяти или `XM_OWN`, если там был собственный кадр или ничего. Один кадр можно поставить в несколько страниц.

Ошибки: `INVAL` (страница больше 6, кадр не принадлежит процессу как кадр расширенной памяти).

### 9.7. Время

#### `$50` TIME_GET — текущее время

```text
fn sys_time_get(): (uint, ulong)
```

Результат: R1:R2 = время в формате метки ФС16 (разд. 5.1): R1 — время суток, R2 — дата. Значения можно сравнивать как `ulong`. Если часы не установлены, результат — то, что показывают часы машины (машина, разд. 8).

#### `$51` TIME_SET — установить время

```text
fn sys_time_set(t: ulong): uint
```

R0:R1 = время в формате ФС16. Ошибки: `INVAL` (недопустимое значение поля, в том числе 0).

#### `$52` TICKS — число тиков

```text
fn sys_ticks(): (uint, ulong)
```

Результат: R1:R2 = число тиков с запуска монитора, по модулю 2^32. Счётчик идёт всегда, в том числе во время вызовов, но тики, пришедшие при IF = 0 в программе, могут слиться (формат CX16, разд. 8.3).

#### `$53` SLEEP — ждать

```text
fn sys_sleep(n: uint): uint
```

Ждёт n тиков (не меньше n − 1 полных интервалов по 20 мс). При n = 0 возвращается сразу. Ошибки: `INTR`.

#### `$54` TICKHOOK — обработчик тика

```text
fn sys_tickhook(h: ptr interrupt fn()): (uint, ptr interrupt fn())
```

R0 = адрес обработчика (разд. 7.4) или 0 — отключить. Результат: R1 = прежний обработчик или 0. Ошибки: `FAULT` (адрес не меньше `top`).

### 9.8. Система

#### `$60` DISK_INFO — сведения о диске

```text
fn sys_disk_info(drv: uint, info: ptr): (uint, uint)
```

R0 = диск 0–7, R1 = буфер на 32 байта для блока INFO (машина, разд. 6.3). Результат: R1 = состояние: бит 0 — смонтирован, бит 1 — смонтирован только на чтение. Ошибки: `NODEV` (диск не подключён или номер больше 7), `IO`.

#### `$61` DISK_IO — чтение и запись секторов

```text
fn sys_disk_io(req: ptr DiskReq): uint
```

R0 = адрес запроса `DiskReq` (разд. 10.2). Читает или записывает `count` секторов (1–255) диска `drive` начиная с `lba`. Буфер — `512·count` байт в памяти процесса.

Вызов нужен программам проверки и форматирования томов:
- с несмонтированным диском можно и читать, и писать;
- с томом, смонтированным только на чтение, — тоже: после записи монитор сбрасывает кеш секторов этого диска (разд. 5.3);
- с томом, смонтированным на запись, — только читать: запись — `BUSY`;
- **секторы 1–3** (код загрузки тома, ФС16, разд. 2) можно писать всегда, даже на томе, смонтированном на запись: монитор их не использует. Запрос, который выходит за сектор 3, подчиняется общему правилу.

Ошибки:
- `INVAL` — операция, `count`, сектор за концом диска;
- `NODEV`;
- `RDONLY` — диск защищён;
- `BUSY`;
- `IO`.

#### `$62` SYSINFO — сведения о системе

```text
fn sys_sysinfo(si: ptr SysInfo): uint
```

Заполняет `SysInfo` (разд. 10.2).

#### `$63` SHUTDOWN — остановить систему

```text
fn sys_shutdown()
```

Выполняет `SYNC`, размонтирует все тома, выводит сообщение и останавливает машину. Не возвращается. Ошибки записи выводятся на консоль, но останов не отменяют. Процессы всех сеансов завершаются без уведомления (разд. 2.4).

### 9.9. Сеансы

Сеанс задаётся номером 0–3 или `SAME` — сеанс вызывающего процесса. Номер больше 3 — `INVAL`, номер сеанса, которого нет, — `NOENT`.

#### `$70` SESS_INFO — сведения о сеансе

```text
fn sys_sess_info(s: uint, k: uint, pi: ptr ProcInfo): (uint, uint, uint, uint)
```

R0 = сеанс, R1 = номер процесса в цепочке (0 — корень), R2 = адрес `ProcInfo` (разд. 10.2) или 0. Результат: R1 = флаги сеанса (`SF_CUR` — текущий), R2 = число процессов в цепочке, R3 = номер сеанса (так программа узнаёт свой сеанс по `SAME`). Если R2 ≠ 0, монитор заполняет `ProcInfo` k-го процесса: номер описателя, состояние (`PS_RUN` — выполняется, `PS_WAIT` — ждёт потомка, `PS_SUSP` — заморожен), `top`, кадры собственной и расширенной памяти, начало командной строки, с которой процесс запущен (`SPAWN`, `EXEC`, `SESS_NEW`).

Список всех сеансов — вызовы для s = 0, 1, 2, 3 с `pi` = 0; `NOENT` пропускается.

Ошибки: `INVAL` (сеанс, k не меньше числа процессов), `NOENT`.

#### `$71` SESS_NEW — новый сеанс

```text
fn sys_sess_new(cmd: ptr byte, flags: uint): (uint, uint)
```

R0 = командная строка корня сеанса (как у `SPAWN`, разд. 7.1) или 0 — оболочка `A:/sys/shell.cx`. R1 = флаги: `SN_BACK` — остаться в текущем сеансе. Монитор занимает свободный номер (наименьший), загружает программу (ошибки загрузки — как у `SPAWN`), открывает ей дескрипторы 0–2 на консоль и даёт текущий каталог вызывающего процесса. Без `SN_BACK` сразу после возврата текущим становится новый сеанс (разд. 2.4). Результат: R1 = номер сеанса.

Ошибки: `INVAL` (флаги), `ARGS`, ошибки загрузки, `NOMEM` (в том числе на экран сеанса — кадр памяти), `NOPROC` (все 4 сеанса заняты или в системе уже 16 процессов).

#### `$72` SESS_SWITCH — перейти в сеанс

```text
fn sys_sess_switch(s: uint): uint
```

Текущим становится сеанс s — сразу после возврата из вызова. Вызов возвращает результат, когда сеанс вызывающего процесса снова станет текущим. Переход в свой сеанс ничего не делает. Ошибки: `INVAL`, `NOENT`.

#### `$73` SESS_KILL — завершить сеанс

```text
fn sys_sess_kill(s: uint, flags: uint): uint
```

Завершает все процессы сеанса s и закрывает его (разд. 2.4). Без флага `SK_FORCE` сеанс, в котором работает больше одного процесса, не завершается (`BUSY`): так оболочка с запущенным редактором не пропадает случайно. Если s — свой сеанс, вызов не возвращается, текущим становится следующий сеанс по кругу.

Ошибки: `INVAL` (сеанс, флаги), `NOENT`, `BUSY` (несколько процессов без `SK_FORCE`; единственный сеанс системы — его завершают выходом из корня).

## 10. Интерфейс для B16

### 10.1. Подключение

Модуль `sysdefs.b16` содержит константы, структуры (через `abi.b16`) и прототипы вызовов. Модуль `sys.asm` содержит обёртки: каждая — три слова. `sys.b16` подключает оба: `sysdefs.b16` строкой `include`, `sys.asm` — строкой `include asm` (B16, разд. 3.2, 10.4), поэтому обёртки попадают в образ до `__image_end`. Программе достаточно одной строки:

```text
include "sys.b16"
```

```text
b16c prog.b16 -o prog.s
```

`sysdefs.b16` без `sys.b16` нужен коду, который вызывает обёртки, уже лежащие в другом образе: так оверлеи BScript пользуются обёртками резидентной части `bsvm`.

Обёртка — функция B16 с той же раскладкой регистров (B16, разд. 9.3), поэтому она ничего не переставляет:

```asm
sys_read:
        TRAP    #9
        .word   $12
        RET
sys_seek:
        TRAP    #9
        .word   $14
        RET
```

Номер вызова — слово сразу за `TRAP #9` (разд. 3.1). Монитор сохраняет LR (разд. 3.2), поэтому `RET` после вызова возвращает в программу. Код ошибки — первый результат и одновременно ZF, поэтому ассемблерный код может проверять результат переходом `JNZ` сразу после вызова.

```text
assert sizeof(SysInfo) == 16, "SysInfo"

struct ProcInfo {
    pid: uint                       // номер описателя процесса
    state: uint                     // PS_...
    top: uint                       // граница собственной памяти
    frames: uint                    // кадров: собственная и расширенная память
    cmd: [PI_CMDLEN]byte            // начало командной строки запуска, с нулём
}
assert sizeof(ProcInfo) == 64, "ProcInfo"
```

Размер файла получают как `st.size & SIZE_MASK`, флаги — как `uint(st.size >> 16) & $F800`.

### 10.4. Пример

```text
include "sys.b16"

var buf: [512]byte

// Копирует файл argv[1] в стандартный вывод.
fn main(argc: int, argv: ptr ptr byte): int {
    if argc < 2 { return 1 }
    var e: uint
    var h: uint
    e, h = sys_open(argv[1], O_READ, 0)
    if e != OK { return 2 }
    loop {
        var n: uint
        e, n = sys_read(h, &buf[0], 512)
        if e != OK || n == 0 { break }
        e, n = sys_write(STDOUT, &buf[0], n)
        if e != OK { break }
    }
    e = sys_close(h)
    return 0
}
```

## 11. Изменения

### Ревизия 6

- **Интерфейс для B16** (разд. 10.1): объявления вынесены в `sysdefs.b16`; `sys.b16` подключает их и обёртки `sys.asm` строкой `include asm` (B16 ревизии 3), ключ `--asm sys.asm` больше не нужен.
- **Буквы томов** (разд. 4.1): префикс тома в пути — `A:`–`H:` в любом регистре. Цифры `0:`–`7:` по-прежнему принимаются. `GETCWD` и сообщения монитора пишут заглавную букву: прежние программы, которые разбирали цифру в начале пути от `GETCWD`, нужно поправить. Номера томов в вызовах не меняются. Оболочка запускается как `A:/sys/shell.cx`. `SYSINFO.version` = `$0600`.

### Ревизия 5

- **Сеансы** (разд. 2.4, 9.9): до 4 цепочек процессов, у каждой свой экран; выполняется только текущий сеанс, остальные заморожены. Переход — Ctrl+] и Ctrl+[ или вызовом. Новые вызовы `SESS_INFO`, `SESS_NEW`, `SESS_SWITCH`, `SESS_KILL`, структура `ProcInfo`; номер `$7F` занят монитором.
- Предел 16 процессов — на все сеансы вместе (разд. 2.1); останов при выходе из корня — только у последнего сеанса (разд. 2.3).
- Ожидающие вызовы при переходе выполняются заново, `SLEEP` — на остаток (разд. 3.4).
- Чтение экрана регистром SCRD разрешено программам (разд. 2.2, 6.4; машина, ревизия 9).
- `SysInfo`: поля `reserved` стали `session` и `max_sess`, `depth` — цепочка своего сеанса. `SYSINFO.version` = `$0500`.

### Ревизия 4

- **Модификаторы событий** (разд. 6.1, 9.5; машина, ревизия 8, разд. 2.6): `CON_GETEV` возвращает в R2 Shift, Ctrl и Alt события. Прежние программы не меняются: R2 они не читают.
- `SYSINFO.version` = `$0400`.

### Ревизия 3

- **Имена без учёта регистра** (разд. 4.1; ФС16, ревизия 3, разд. 7.1): поиск, создание (`OPEN` с `O_CREATE`, `MKDIR`) и проверка `EXIST` сравнивают имена без учёта регистра. Регистр сохраняется при записи, `READDIR` и `GETCWD` возвращают хранимое написание. `RENAME` в то же имя другим регистром меняет написание (разд. 9.4).
- **Ctrl+Enter** (разд. 6.1; машина, ревизия 7, разд. 2.6): событие с символом 0 и сканкодом `$1C`, доступно через `CON_GETEV`.
- `SYSINFO.version` = `$0300`. Программа, которой важно сравнение имён, может проверить старший байт: при значении 3 и выше регистр не учитывается.
- Префиксы томов и устройств и имена устройств не меняются.

### Ревизия 2

- **`EXEC`** (`$02`, разд. 9.2): замена программы в процессе с сохранением места в цепочке, дескрипторов и текущего каталога.
- **`ONEVENT`** (`$03`, разд. 7.5, 9.2): обработчики Ctrl+C и недопустимой команды вместо завершения процесса; в них можно выполнять системные вызовы.
- Разд. 6.3, 7.1, 7.2, 7.3 — ссылки на обработчики событий; разд. 10.2, 10.3 — константы `EVT_BREAK`, `EVT_BADINSN` и прототипы.
- **`SETMTIME`** (`$2C`, разд. 9.4): установка времени изменения файла или каталога.
- **`DISK_IO`** (разд. 9.8): запись секторов 1–3 разрешена на любом томе, в том числе смонтированном на запись — для установки кода загрузки с самой машины; запись на том, смонтированный только на чтение, — для проверки тома (разд. 5.3).
- **`SETTOP`, `XALLOC`, `XFREE`, `XMAP`** (`$41–$44`, разд. 7.6, 9.6): изменение собственной памяти и расширенная память; `MEMINFO` в R3 сообщает число кадров расширенной памяти.
- Разд. 3.3: память процесса — страницы с его кадрами, в том числе окна выше `top`; адреса обработчиков проверяются так же.

### Ревизия 1

Уточнения по итогам реализации: проверка тома с DIRTY — `DISK_IO` пишет на том, смонтированный только на чтение, `MOUNT_REMOUNT` (разд. 5.3, 9.4, 9.8, 10.2); сообщения монитора — на английском (разд. 7.3); MTIME файла обновляется при каждом изменении данных или размера, а не при закрытии (разд. 5.4, 9.3).

Первая редакция. Модель цепочки процессов без вытеснения. Вызовы процессов, дескрипторов, файловой системы, консоли, памяти (только сведения), времени, обработчика тика и сырых секторов диска.

Зарезервированы для следующей ревизии:
- `$02` — замена образа процесса;
- `$03` — обработчики событий (Ctrl+C, недопустимая команда);
- `$41–$44` — изменение `top` и расширенная память;
- `TRAP #10` — отладчик.
