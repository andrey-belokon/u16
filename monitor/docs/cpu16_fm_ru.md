# Монитор CPU16: файловый менеджер fm. Ревизия 6

`fm` — экранный файловый менеджер в духе Norton Commander: две панели с содержимым каталогов, командная строка и клавиши F1–F10. Это обычная программа формата CX16 на B16 (`A:/bin/fm.cx`), она пользуется только системными вызовами.

Раздел 1–5 — описание для пользователя, раздел 6 — устройство программы, раздел 7 — проверка, раздел 9 — изменения.

## 1. Запуск

    fm [путь]

Левая панель показывает текущий каталог, правая — `путь` (по умолчанию тоже текущий каталог). F10 завершает fm с кодом 0; текущим каталогом оболочки остаётся тот, что был до запуска (у fm свой процесс).

Экран рисуется прямым выводом в дисплей в координатном режиме («Системные вызовы», разд. 6.4). Эмулятор командной строки `cpu16` координатный вывод в stdout не передаёт, поэтому работать с fm удобно в веб-отладчике (окно «Display»).

## 2. Экран

```text
╔══════════ A:/data ═════╤════════╗╔═══ B:/ ═══ ... ╗   заголовок: каталог панели; активная выделена
║        Name        │  Size  │  Date  ║               шапка столбцов
║..                  │      Up│        ║               ".." - шаг вверх (кроме корня тома)
║sub                 │  Folder│18.10.26║               каталоги - первыми, белым
║hello.txt           │    3895│--.--.--║               файлы - по имени без учёта регистра
╟────────────────────┴────────┴────────╢
║hello.txt                        23:38║               полное имя и время записи под курсором
╚═══ 74028 in 4 files, 828K free ═════╝               файлы каталога и свободное место, или итог отметок
A:/data> _                                             командная строка
1Help   2Drive  3View   4Edit   5Copy   6RenMov 7Mkdir  8Delete 9Attr   10Quit
```

- Имя длиннее 20 знаков обрезается знаком `}`; целиком оно видно в строке сведений.
- В столбце Size у `..` написано `Up`, у каталога — `Folder`; у `..` столбец Date пуст.
- Нижняя рамка: если отметок нет — суммарный размер и число файлов каталога (подкаталоги не считаются; от 10 000 000 байт — в КБ с буквой `K`) и свободное место тома (`(ro)` — том только для чтения); если есть — число и размер отмеченных.
- Размер больше 99 999 999 байт показывается в КБ с буквой `K`.
- Цвета: каталоги — белые, программы `.cx` — зелёные, файлы с HIDDEN или SYSTEM — серые, отмеченные — жёлтые.
- Записи без метки времени показываются прочерками.
- В панели не больше 204 записей; если каталог больше, в нижней рамке написано `list truncated`.

## 3. Клавиши

| Клавиша | Действие |
| --- | --- |
| ↑ ↓ PgUp PgDn Home End | курсор |
| Tab | другая панель |
| Enter | каталог — войти; `.cx` — запустить; `.bs` — запустить сценарий BScript (`A:/bin/bs.cx`), `.bsc` — скомпилированный сценарий (`A:/bin/bsvm.cx путь --`); на другом файле — ничего (просмотр — F3); при непустой командной строке — выполнить её |
| Ins | отметить запись и перейти к следующей |
| `+` `-` `*` | (при пустой командной строке) отметить все файлы, снять все отметки, обратить отметки |
| F1 | справка |
| F2 | выбор тома для активной панели (стрелки и Enter или буква тома; цифра 0–7 тоже годится) |
| F3 | файл — просмотр (разд. 4); каталог — его размер (разд. 5) |
| F4 | файл — в редактор `A:/bin/edit.cx` (разд. 3, «Текстовый редактор edit») |
| Shift+F4 | редактор без файла: новый текст, имя спрашивается при записи |
| F5 | копировать |
| F6 | переименовать или переместить |
| F7 | создать каталог |
| F8 | удалить |
| F9 | флаги RDONLY, HIDDEN, SYSTEM |
| F10 | выйти |
| Ctrl+R | перечитать панели |
| Ctrl+Enter | имя под курсором — в командную строку (см. ниже) |
| Ctrl+E, Ctrl+X | предыдущая и следующая команда (8 последних) |
| Esc, Ctrl+U | очистить командную строку |
| Backspace | стереть символ командной строки |

**Командная строка.** `cd путь`, `X:` (смена тома: буква `A`–`H` или цифра) и `exit` fm выполняет сам. Любая другая строка записывается в `A:/tmp/.fmcmd` и выполняется сценарием оболочки `A:/sys/shell.cx A:/tmp/.fmcmd` в каталоге активной панели, поэтому работают поиск программ, перенаправления, конвейеры и встроенные команды оболочки. Если файл записать нельзя, строка передаётся `SPAWN` как есть.

**Ctrl+Enter** — событие с символом 0 и сканкодом Enter `$1C` («Машина», ревизия 7, разд. 2.6); Enter — символ `$0A`. fm вставляет в командную строку имя под курсором (в кавычках, если в нём есть пробел или знак оболочки) и пробел; на `..` клавиша ничего не делает. Ctrl+Enter работает в веб-отладчике (в окне и панели дисплея) и в эмуляторе командной строки в консоли Windows; терминалы Unix обычно передают её как Enter («Машина», разд. 9.2).

**Запуск программ.** Перед запуском экран переводится в обычный телетайп. После завершения программы fm пишет `--- fm: press any key ---` и ждёт клавишу: экранную память прочитать нельзя, и показать вывод программы после перерисовки панелей было бы нечем. Затем обе панели перечитываются.

**Редактор (F4)** — отдельная программа `A:/bin/edit.cx`, которой fm передаёт полный путь файла под курсором (в кавычках, если в нём есть пробел или знак оболочки); на каталоге и `..` клавиша ничего не делает. Редактор полноэкранный, поэтому fm не пишет строку команды и не ждёт клавишу после него, а сразу перечитывает панели. Если редактор не запустился (например, файла `A:/bin/edit.cx` нет), fm пишет `fm: A:/bin/edit.cx: текст ошибки` и ждёт клавишу. Свой процесс даёт редактору свою память: текст не делит её с панелями fm («Текстовый редактор edit», разд. 7.1). **Shift+F4** открывает редактор без файла в каталоге активной панели: текст пишется в файл через окно «Сохранить как» редактора, начальный каталог окна — каталог панели. Новый файл с готовым именем создаёт и команда `edit имя` в командной строке fm. Shift fm узнаёт из модификаторов события (`CON_GETEV`, R2; «Системные вызовы», разд. 9.5): в эмуляторе командной строки сочетание доходит, только если терминал шлёт для Shift+F4 последовательность xterm (машина, разд. 9.2).

## 4. Просмотр (F3)

Текст показывается с переносом длинных строк, табуляция — до столбца, кратного 8, `\r` пропускается. Файл не загружается целиком: читается только окно от позиции верхней строки, поэтому размер файла не ограничен памятью. Если среди первых 256 байт много управляющих символов, файл сразу открывается в шестнадцатеричном виде.

| Клавиша | Действие |
| --- | --- |
| ↑ ↓ PgUp PgDn Home End | прокрутка |
| F4 | текст / шестнадцатеричный вид |
| Esc, F3, F10, `q` | выход |

В верхней строке — путь, позиция верхней строки, размер и процент просмотренного.

## 5. Операции

Операции F5, F6, F8, F9 применяются к отмеченным записям, а если отметок нет — к записи под курсором (`..` не выбирается).

**Копирование (F5).** Назначение по умолчанию — каталог другой панели; его можно исправить. Путь отсчитывается от каталога активной панели.

- Если назначение — существующий каталог, объекты копируются в него под своими именами.
- Иначе назначение — новое имя; так можно копировать только один объект.
- Каталоги копируются с содержимым. Копия получает время изменения и флаги оригинала.
- Существующий файл назначения — вопрос `[Y]es [N]o [A]ll [Esc] Cancel`.
- Копия в самого себя — ошибка `same file`; каталог внутрь самого себя — ошибка `destination is inside the directory`. Пути сравниваются без учёта регистра букв, как имена файлов («Системные вызовы», разд. 4.1): копия `a` в `A` того же каталога — тоже `same file`.
- Недописанная копия (ошибка или прерывание) удаляется.

**Перемещение (F6)** — `RENAME`; между томами — копирование и удаление источника. Если при копировании что-то пропущено, источник не удаляется.

- **Смена регистра имени.** Если назначение называет сам объект в другом регистре букв (`readme` → `README`), это переименование, а не перемещение: имя получает введённое написание. Для каталога так же — назначение `DIR` у каталога `dir` не считается каталогом, в который его перемещать.
- **Существующее назначение.** Файл назначения — вопрос `[Y]es [N]o [A]ll [Esc] Cancel`; при согласии он удаляется перед перемещением. Сам источник в другом регистре букв назначением не считается и не удаляется.

**Удаление (F8).** Одно подтверждение на всю операцию; каталоги удаляются с содержимым. Ответ — только клавишей `Y`/`y` (удалить) или `N`/`n` (отказаться; Esc — тоже отказ), Enter не отвечает. Для объекта с RDONLY — вопрос `[Y]es [N]o [A]ll [Esc] Cancel`, тоже без Enter; при согласии флаг снимается.

**Размер каталога (F3 на каталоге).** fm обходит каталог со всеми подкаталогами (Esc — прервать) и показывает окно: число файлов и подкаталогов, суммарный размер файлов в байтах и место на томе — кластеры данных, индексные кластеры IND, DIND и второго уровня (ФС16, разд. 6) у файлов и каталогов, включая сам каталог.

**Создание каталога (F7).** Имя, совпадающее с существующим без учёта регистра букв (`NEWDIR` при `newdir`), — ошибка `already exists`: в каталоге не может быть двух таких имён (ФС16, разд. 7.1).

**Флаги (F9).** Клавиши R, H, S переключают флаги в окне, Enter устанавливает их всем выбранным объектам.

**Ошибки.** Ошибка с объектом показывается окном с путём и текстом ошибки («Оболочка и утилиты», разд. 8.2): Enter или S — пропустить объект, Esc — прервать операцию. Esc во время копирования, перемещения и удаления спрашивает, прервать ли операцию. Нажатия, сделанные во время операции, не теряются: fm откладывает их и обрабатывает после неё.

После операции обе панели перечитываются; курсор остаётся на той же записи, если она есть (имя ищется без учёта регистра, поэтому после смены регистра курсор не сбрасывается). Панель, каталог которой исчез, поднимается к ближайшему существующему каталогу.

## 6. Устройство

| Файл | Содержание |
| --- | --- |
| `user/fm/fm.b16` | панели, командная строка, клавиши, выбор тома, справка, `main` |
| `user/fm/scr.b16` | регистры дисплея, рамки, клавиатура и очередь отложенных событий, диалоги |
| `user/fm/view.b16` | просмотрщик |
| `user/fm/ops.b16` | копирование, перемещение, удаление, каталоги, флаги |

Сборка: `tools/b16build.sh user/fm/fm.b16` (так же в `make system`). Поля заголовка заданы в `fm.b16`: `option max_top = EWIN` (`$A000`) и `option min_free = 4096`; та же константа `EWIN` — адрес массива записей панелей.

**Память.** Собственная память процесса — до `$A000` (`max_top` = 40 КБ). Записи панелей (`[2][204]Stat`, 16 320 байт) лежат в двух кадрах расширенной памяти: при запуске fm выделяет их `XALLOC` и ставит в страницы 5 и 6 (`XMAP`), а массив объявлен переменной `at $A000`. Без двух свободных кадров fm не запускается (`fm: not enough memory`, код 1). Кадры освобождаются монитором при завершении.

Статические данные вместе с `min_free` (4 КБ под стек) должны кончаться не выше `$A000`, иначе монитор отведёт процессу память до `$C000` и страница 5 будет занята. Поэтому буфер копирования — 3,5 КБ (7 секторов за чтение), а не 4 КБ; окно просмотрщика — первые 2 КБ того же буфера; буферы путей (`spath`, `dpath`, `cdst`, `inbuf`, `cwdbuf`) — по 256 байт: путь не длиннее 255 байт («Системные вызовы», разд. 4.1), и `GETCWD` получает размер 256; командная строка запуска `clbuf` — 276 байт (путь редактора, пробел, путь до 255 байт в кавычках, 0); порядок показа записей `ord` — байты (записей не больше 204). Запас до `$A000` после ревизии 4 — 442 байта: новое в fm должно быть малым, крупное — отдельной программой, как редактор.

**Каталоги.** Панель хранит путь в виде `GETCWD` (`X:/a/b`, буква тома заглавная). Переход в каталог — `CHDIR` в каталог панели, затем `CHDIR` в имя и `GETCWD`, так что разбор `..` и проверки пути выполняет монитор. Текущий каталог процесса — каталог активной панели.

**Обход дерева** при копировании и удалении не держит каталоги открытыми: имена каталога читаются в пул (4 КБ), дескриптор закрывается, затем обрабатывается каждое имя. Глубина ограничена только длиной пути («Системные вызовы», разд. 4.1), а не числом дескрипторов; пути собираются в двух буферах, к которым на каждом уровне добавляется и потом отрезается имя.

**Клавиатура** — сырой режим с `NOBREAK`, события `CON_GETEV`. Ctrl+Enter отличается от Enter только сканкодом: символ 0, сканкод `$1C` (`K_ENTER` в `scr.b16`). Во время операции fm проверяет Esc вызовом `CON_GETEV` с `NOWAIT`; остальные события откладываются в очередь на 16 событий и отдаются первыми.

## 7. Проверка

Вызов редактора по F4 и Shift+F4 проверяет сценарий `edit` («Текстовый редактор edit», разд. 8). Сценарий `fm` в `tools/run_tests.py` (`tests/scripts/fm.scn`): Ctrl+Enter (имя в командную строку), копирование файла на том `B:`, создание каталога и отказ `already exists` для того же имени в другом регистре, удаление каталога, переименование и смена регистра имени, отказ `same file` при копии в себя в другом регистре, просмотр, команда `ls` из командной строки, выход. Сценарий ждёт текста на экране и сверяет снимки экрана; для этого стенд `kmon` понимает строки

    screen "текст" steps N ...          ждать текст на экране (в том числе координатный вывод)
    after "текст" steps N dump          напечатать экран (dumpa - вместе с атрибутами)

Снимки печатаются в stdout после вывода консоли, в UTF-8. Для ручной отладки — `tests/fm/run.sh СЦЕНАРИЙ` (тома `out/fmt0.img` и `out/fmt1.img` по `out/fmt*.json`) и `tests/fm/show.py`.

## 8. Ограничения и планы

- Нет показа экрана программ после возврата (Ctrl+O): экранная память недоступна для чтения.
- Нет сортировки по размеру и времени, краткого режима панели, поиска файла.
- Не больше 204 записей в панели.

## 9. Изменения

### Ревизия 6

- **Сборка программ (B16 ревизии 3).** Параметры образа (`max_top`, `min_free`) заданы в исходнике объявлениями `option`, обёртки вызовов подключает `sys.b16` строкой `include asm`; `max_top` и адрес записей панелей — одна константа `EWIN`; команда сборки — без ключей.
- Тома обозначаются буквами («Системные вызовы», ревизия 6): заголовки панелей и список F2 — `A:`, `B:`…; выбор тома в списке — буквой в любом регистре или, как прежде, цифрой; в командной строке — `B:` или `1:`.

### Ревизия 5

- Enter на `.bs` запускает сценарий BScript через `A:/bin/bs.cx`, на `.bsc` — скомпилированный сценарий через `A:/bin/bsvm.cx путь --` («BScript», разд. 11.4).
- Enter на файле, который не является программой или сценарием, ничего не делает; просмотр — по F3.

### Ревизия 4

- **Shift+F4 — редактор без файла** (разд. 3). Модификаторы события `getkey` (`scr.b16`) берёт из `CON_GETEV` и хранит в `kmods`; события, отложенные во время операции (`poll_esc`), хранятся вместе с модификаторами.
- **Память** (разд. 6): буферы путей — 256 байт вместо 260, `clbuf` — 276 вместо 300, `ord` — байты вместо слов (408 байт). Запас до `$A000` — 442 байта.

### Ревизия 3

- **F4 — редактор** (разд. 3): файл под курсором открывается в отдельной программе `A:/bin/edit.cx`; после неё fm не ждёт клавишу. `exec_child` получил признак полноэкранной программы; запуск `.cx` по Enter и вызов редактора — одна функция `run_entry`.
- **Буферы путей операций** — 260 байт вместо 300 (разд. 6): иначе образ с F4 не помещался под `$A000`.

### Ревизия 2

- **Ctrl+Enter** (разд. 3, 6): событие с символом 0 и сканкодом `$1C` («Машина», ревизия 7). Прежнее распознавание по символу `$0D` удалено: такого события Ctrl+Enter не даёт, а `$0D` со сканкодом `$32` — это Ctrl+M.
- **Имена без учёта регистра** (разд. 5; «Системные вызовы», ревизия 3): проверки `same file` и «каталог внутрь самого себя» сравнивают пути без учёта регистра; F6 меняет регистр имени файла и каталога; перемещение не удаляет источник, совпадающий с назначением без учёта регистра; F7 с тем же именем в другом регистре — `already exists`; курсор после перечитывания ищется без учёта регистра; сортировка учитывает `Ё`.
- **Буфер копирования** — 3,5 КБ (разд. 6).

### Ревизия 1

Первая редакция.
