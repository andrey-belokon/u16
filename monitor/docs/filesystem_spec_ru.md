# Файловая система ФС16 — спецификация

Ревизия 3 · Oct 19, 2026 · @Андрей

## 1. Назначение и соглашения

ФС16 — файловая система для дисков до 128 МБ с 16-битными номерами кластеров. Метаданные файла хранятся прямо в записи каталога, адреса данных — по схеме «прямые + косвенный + двойной косвенный», свободное место — битовой картой.

| Параметр | Значение |
| --- | --- |
| Блок (сектор диска) | 512 байт |
| Кластер | 4 блока = 2048 байт |
| Номер кластера | 16 бит, 0 означает «нет кластера» |
| Единица выделения | кластер |
| Запись каталога | 64 байта, 32 записи в кластере |
| Индексный кластер | 1024 номера кластеров |

Соглашения:

- Все многобайтовые поля — little-endian, как у процессора и контроллера дисков.
- Смещения и номера считаются с 0. Словные поля лежат по чётным смещениям.
- Строки (имена, метка) записаны в кодировке машины и дополнены нулями до длины поля. Завершающий ноль не обязателен: строка может занимать поле целиком.
- Неиспользуемые байты служебных структур равны 0 при записи и не проверяются при чтении.
- Кластер N занимает секторы 4N…4N+3. LBA первого сектора занимает 18 бит: LBA\_LO = N << 2, LBA\_HI = N >> 14. По терминологии контроллера диск больше 32 МБ не является «маленьким», поэтому драйвер всегда пишет LBA\_HI.

## 2. Разметка диска

Диск делится на три области: кластер 0, битовая карта с кластера 1 и область данных до конца тома. Фиксированного места у корневого каталога нет: его запись хранится в суперблоке, а данные выделяются из общей области.

| Кластеры | Секторы | Содержимое |
| --- | --- | --- |
| 0 | 0 | суперблок (разд. 3) |
| 0 | 1…3 | код загрузки, 1536 байт; если том не загрузочный — нули |
| 1 … B | 4 … 4B+3 | битовая карта (разд. 4) |
| B+1 … N−1 | — | область данных: данные файлов, каталогов и индексные кластеры |

Размеры:

- N — число кластеров тома: N = min(⌊секторов / 4⌋, 65535). Секторы за кластером N−1 не используются.
- B — число кластеров карты: B = ⌈N / 16384⌉, то есть от 1 до 4. Один кластер карты (16384 бита) описывает 32 МБ.
- Минимальный том — 3 кластера (12 секторов): кластер 0, один кластер карты и один кластер данных.
- Номер 0 никогда не встречается как адрес данных, потому что кластер 0 служебный. Это и даёт ему значение «нет кластера».

## 3. Суперблок

Суперблок занимает сектор 0 и описывает том целиком, включая запись корневого каталога. Начало карты фиксировано (кластер 1), поэтому отдельного поля для него нет.

| Смещение | Размер | Поле | Содержимое |
| --- | --- | --- | --- |
| 0 | 4 | MAGIC | байты $46 $53 $31 $36 («FS16») |
| 4 | 2 | VERSION | 1 |
| 6 | 2 | CLUSTERS | N, число кластеров тома, 3…65535 |
| 8 | 2 | MAPLEN | B, число кластеров карты |
| 10 | 2 | FREE | число свободных кластеров |
| 12 | 2 | HINT | кластер, с которого начинать поиск свободного |
| 14 | 2 | FLAGS | бит 0 DIRTY — том смонтирован на запись; остальные биты 0 |
| 16 | 4 | SERIAL | серийный номер тома, задаётся при форматировании |
| 20 | 16 | LABEL | метка тома, до 16 символов |
| 36 | 64 | ROOT | запись корневого каталога (формат — разд. 5) |
| 100 | 410 | — | нули |
| 510 | 2 | CHECKSUM | сумма всех 256 слов сектора по модулю 2^16 равна 0 |

Правила:

- В записи ROOT имя состоит из нулей, стоит флаг DIR. У пустого только что отформатированного тома размер корня 0 и все адреса равны 0.
- FREE и HINT — подсказки. Источник истины — карта; проверка тома пересчитывает их. HINT вне области данных трактуется как B+1.
- Изменение любого поля пересчитывает CHECKSUM: его значение равно дополнению суммы остальных 255 слов до 0.
- При монтировании проверяются MAGIC, VERSION = 1, CHECKSUM, 4N ≤ числа секторов диска, B = ⌈N / 16384⌉ и флаг DIR у ROOT. При несовпадении том не монтируется.
- Метка тома не связана с меткой из блока INFO контроллера: та принадлежит носителю, эта — файловой системе и переезжает вместе с образом.

## 4. Битовая карта

Карта хранит по одному биту на каждый номер кластера от 0 до 16384·B − 1: 1 — кластер занят, 0 — свободен.

- Кластеру c соответствует бит c & 7 байта c >> 3 карты. Это то же, что бит c & 15 слова c >> 4: карту можно обрабатывать как байтами, так и словами.
- Байт карты k лежит в секторе 4 + (k >> 9) по смещению k & 511. Один сектор карты описывает 4096 кластеров.
- Всегда заняты (бит = 1): кластер 0, кластеры карты 1…B и все номера от N до конца карты. Поэтому внутри слова карты не нужно сравнивать номер с N: биты за концом тома равны 1 и свободными не окажутся.
- Занят любой кластер, на который ссылается какая-либо запись (данные или индекс), включая запись ROOT.
- Поиск свободного идёт от HINT вперёд до N (номера строго меньше N) с переходом к B+1. До конца карты поиск не доходит: при B = 4 конец карты — номер 65536, а он не помещается в 16 бит. Сказанное выше про биты за концом тома не значит, что поиск может выйти за N: оно лишь освобождает от сравнения номера с N внутри слова.
- Рекомендуемый способ поиска — пропускать слова, равные $FFFF. После выделения HINT ставится на выделенный кластер + 1, чтобы файлы росли подряд.
- Размер карты: для диска 128 МБ — 8 КБ. Рассчитывать на кеширование её целиком не нужно: достаточно держать в памяти один сектор.

## 5. Запись каталога

Запись занимает 64 байта: 32 — имя, 4 — размер с флагами, 4 — дата и время изменения, 24 — адреса: 10 прямых, один косвенный и один двойной косвенный. Резервных байтов нет.

| Смещение | Размер | Поле | Содержимое |
| --- | --- | --- | --- |
| 0 | 32 | NAME | имя, 1…32 символа, дополнено нулями; NAME\[0\] = 0 — запись свободна |
| 32 | 4 | SIZE | биты 0–26 — размер в байтах, биты 27–31 — флаги |
| 36 | 4 | MTIME | дата и время последнего изменения: слово +36 — время, слово +38 — дата (разд. 5.1) |
| 40 | 20 | DIRECT\[0…9\] | прямые адреса: кластеры данных 0…9 файла |
| 60 | 2 | IND | косвенный индексный кластер: кластеры данных 10…1033 |
| 62 | 2 | DIND | двойной косвенный: кластеры данных от 1034 |

Флаги в старших битах SIZE:

| Бит SIZE | Бит слова +34 | Имя | Значение |
| --- | --- | --- | --- |
| 31 | 15 | DIR | запись — каталог |
| 30 | 14 | RDONLY | запись и удаление запрещены |
| 29 | 13 | HIDDEN | не показывать в обычном списке |
| 28 | 12 | SYSTEM | системный файл |
| 27 | 11 | — | 0 |

Пояснения:

- На 16-битной машине удобно читать SIZE двумя словами. Слово +32 — младшие 16 бит размера. В слове +34 биты 0–10 — старшие биты размера (маска $07FF), биты 11–15 — флаги (маска $F800).
- 27 бит размера дают до 128 МБ − 1 байт, что больше ёмкости любого тома.
- У свободной записи все 64 байта равны 0.
- MTIME файла меняется при любом изменении его данных или размера. MTIME каталога меняется при создании, удалении и переименовании записей в нём. Переименование или перемещение файла его собственный MTIME не меняет.
- Время создания не хранится.

### 5.1. Кодирование даты и времени

Метка занимает два слова: младшее — время суток с точностью до секунды в 12-часовом формате, старшее — дата и признак AM/PM. Время локальное, по часам машины; часовой пояс не хранится.

Младшее слово (время):

| Биты | Поле | Диапазон |
| --- | --- | --- |
| 12–15 | час | 0…11 |
| 6–11 | минута | 0…59 |
| 0–5 | секунда | 0…59 |

Старшее слово (дата):

| Биты | Поле | Диапазон |
| --- | --- | --- |
| 10–15 | год − 2025 | 0…63, то есть 2025…2088 |
| 6–9 | месяц | 1…12 |
| 1–5 | день | 1…31 |
| 0 | PM | 0 — до полудня, 1 — после |

Правила:

- Час 0 означает 12: полночь — AM, час 0; полдень — PM, час 0; 23:59:59 — PM, 11:59:59.
- Поля расположены от старших к младшим (год, месяц, день, AM/PM, час, минута, секунда). Поэтому две метки сравниваются как беззнаковые 32-битные числа: сначала старшие слова, при равенстве — младшие.
- Значение 0 (оба слова нулевые) означает «время неизвестно»: месяц 0 недопустим и в настоящей дате не встречается.
- Предел формата — 31 декабря 2088 года.

## 6. Адресация данных файла

Байт файла со смещением pos лежит в кластере данных с номером k = pos >> 11 внутри файла. Поскольку pos < 2^27, k всегда помещается в 16 бит, и вся дальнейшая арифметика 16-битная.

```text
k = pos >> 11                      ; кластер файла
if k < 10:     c = DIRECT[k]
elif k < 1034: c = IND[k - 10]     ; IND — индексный кластер
else:          j = k - 1034
               t = DIND[j >> 10]   ; кластер второго уровня
               c = t[j & 1023]
s      = (pos >> 9) & 3            ; сектор в кластере
LBA_LO = (c << 2) | s
LBA_HI = c >> 14
offset = pos & 511                 ; байт в секторе
```

Индексный кластер — это массив из 1024 16-битных номеров кластеров. Элемент i лежит в секторе i >> 8 этого кластера по смещению (i & 255) · 2. Для одного адреса достаточно прочитать один сектор, а не весь кластер.

Правила размещения:

- У файла размером size ровно C = ⌈size / 2048⌉ кластеров данных, и все они выделены. Дырок (невыделенных кластеров внутри файла) нет.
- Адреса кластеров с номерами k ≥ C равны 0 — и в записи, и в индексных кластерах.
- IND ≠ 0 тогда и только тогда, когда C > 10. DIND ≠ 0 тогда и только тогда, когда C > 1034; тогда в DIND заняты ⌈(C − 1034) / 1024⌉ первых элементов.
- Хвост последнего кластера за концом файла не определён. При чтении он не выдаётся, при росте файла перезаписывается.

Чего стоит индекс на разных размерах файла:

| Размер файла | Кластеров данных | Индексных кластеров | Чтений индекса на сектор |
| --- | --- | --- | --- |
| до 20 КБ | 1…10 | 0 | 0 |
| до 2068 КБ | 11…1034 | 1 | 1 |
| до ≈128 МБ (весь том) | до ≈ 65500 | до 2 + 63 = 65 | 2 |

## 7. Каталоги

Каталог — это файл с флагом DIR, содержимое которого — массив 64-байтных записей. Данные каталога адресуются так же, как данные файла (разд. 6).

**Размер.** Размер каталога всегда кратен 2048: каталог состоит из целых кластеров по 32 записи. Пустой каталог может иметь размер 0 и не занимать ни одного кластера. Если свободной записи нет, каталог растёт на один кластер, заполненный нулями. Кластеры в середине каталога не освобождаются; последние кластеры из одних свободных записей реализация может отрезать.

**Цена индекса.** Каталог адресуется как файл, поэтому каталог больше 10 кластеров (больше 320 записей) занимает ещё и индексный кластер IND, а больше 1034 кластеров — ещё и DIND с кластерами второго уровня (разд. 6). Индексные кластеры записей не вмещают: каталог из 21 кластера, включая IND, содержит не более 640 записей, а не 672.

**Корень.** Запись корневого каталога — поле ROOT суперблока. В самом корне записи для него нет.

**Имена.**

- Длина — от 1 до 32 байт. Допустимы байты $20 и выше, кроме «/» (разделитель пути) и «:» (отделяет префикс тома в путях монитора, см. ниже). Имя с «:» недопустимо: монитор отказывает таким именам, и файл с «:» в имени был бы для него недоступен — его нельзя ни открыть, ни удалить.
- Имена «.» и «..» запрещены: они зарезервированы за путями (смысл — в «Пути и переход вверх»).
- Имена сравниваются **без учёта регистра букв** (разд. 7.1). В одном каталоге имена уникальны в этом смысле: `Readme`, `README` и `readme` — одно имя.
- Регистр сохраняется: NAME хранит имя в том написании, в каком его задали при создании или последнем переименовании. Поиск по любому написанию находит эту запись.
- Порядок записей не определён. Новая запись занимает первую свободную.

**Пути и переход вверх.** Записей «.» и «..» на диске нет, и обратных ссылок на родителя тоже. Обратная ссылка всё равно не даёт доступа к родителю: его адреса лежат в записи дедушки. Поэтому реализация хранит текущий каталог как цепочку от корня, а «..» в пути обрабатывает как шаг назад по цепочке. Зато перемещение каталога не требует правок внутри него.

Путь делится на шаги по «/». Правила разбора:

- «.» — пустой шаг: остаться в текущем каталоге;
- «..» — шаг назад по цепочке;
- повторные «/» равносильны одному: пустые шаги между ними пропускаются;
- завершающий «/» допустим и не меняет смысла пути: «/w/» называет то же, что «/w».

Префикс тома «X:» в ФС16 не входит: его смысл определяет спецификация монитора (п. 4.1). Для ФС16 путь — это только шаги внутри одного тома, а двоеточие в именах запрещено именно ради этого префикса.

**Адрес записи.** Файл однозначно определяется положением своей записи: кластер каталога (16 бит) и номер записи в нём, 0…31. Запись ROOT имеет адрес «кластер 0». Реализация держит этот адрес для каждого открытого файла, чтобы обновлять размер и адреса.

### 7.1. Сравнение имён

Два имени равны, если равны их байты после приведения каждого байта функцией fold. Она меняет только заглавные буквы на строчные:

| Заглавные | Строчные | fold |
| --- | --- | --- |
| `A–Z` (`$41–$5A`) | `a–z` (`$61–$7A`) | +$20 |
| `А–Я` (`$C0–$DF`) | `а–я` (`$E0–$FF`) | +$20 |
| `Ё` (`$B3`) | `ё` (`$A3`) | $A3 |
| остальные байты | — | без изменений |

```text
fold(b) = b + $20,  если $41 ≤ b ≤ $5A или $C0 ≤ b ≤ $DF
        = $A3,      если b = $B3
        = b         иначе
```

- Приведение не меняет длину. Поэтому сравнивать можно как раньше, всё 32-байтное поле NAME: нули дополнения проходят через fold без изменений.
- «Е» и «Ё» — разные буквы: `ёж` и `еж` — разные имена. Псевдографика, значки и знаки препинания сравниваются как есть.
- Таблица — часть формата: все реализации (монитор, загрузчик, проверка тома, утилиты хоста) обязаны приводить одинаково. Иначе одна сочла бы имена равными, а другая — нет.

## 8. Инварианты целостности

Том целостен, если выполнены все правила ниже. Проверка тома (разд. 10) проверяет именно их.

1. Каждый кластер области данных либо свободен, либо ссылается ровно один раз — из записи или из индексного кластера. Общих кластеров у файлов нет.
2. Бит карты равен 1 тогда и только тогда, когда кластер системный, лежит за концом тома или на него есть ссылка. FREE равно числу нулевых битов.
3. Все ненулевые адреса лежат в области данных, то есть в пределах B+1 … N−1.
4. Адреса соответствуют размеру по правилам разд. 6: ровно C кластеров данных, дальше нули, IND и DIND заданы только когда нужны.
5. Размер каталога кратен 2048. У каждой записи либо все 64 байта равны 0, либо имя допустимо (разд. 7) и уникально в каталоге без учёта регистра (разд. 7.1). Имя с «:» недопустимо; проверка тома сообщает о нём. Два имени, равные без учёта регистра, — тоже нарушение; проверка тома переименовывает лишние (разд. 10, п. 6).
6. Дерево каталогов — дерево: каждый каталог, кроме корня, описан ровно одной записью. Каждая запись достижима от ROOT. Вместе с правилом 1 это исключает циклы и «потерянные» поддеревья.

## 9. Основные операции

Ни одна операция не копирует данные файла: рост и обрезка меняют только адреса, перемещение — только запись. Ниже операции перечислены с порядком записи на диск (его смысл — в разд. 10).

**Поиск по пути.** Путь делится на шаги по «/» и разбирается по правилам разд. 7 (пустые шаги, «.» и «..»). Для каждого имени записи текущего каталога просматриваются по сектору (8 записей) или по кластеру (32 записи) до совпадения NAME без учёта регистра (разд. 7.1). Промежуточное имя должно указывать на каталог.

**Чтение.** Адрес каждого кластера вычисляется по разд. 6. Соседние кластеры файла с идущими подряд номерами можно читать одной командой READ: до 255 секторов за раз, в пределах буфера.

**Добавление кластера k = C в конец файла:**

1. Выделить кластер данных и, если нужно, новые индексные кластеры: IND при k = 10, DIND и первый кластер второго уровня при k = 1034, новый кластер второго уровня при (k − 1034) & 1023 = 0. Не хватило места — откатить уже выделенное и вернуть ошибку «диск заполнен».
2. Пометить выделенные кластеры в карте и записать карту.
3. Записать данные; новые индексные кластеры записать сразу с адресом и нулями.
4. Записать адрес в уже существующий индексный кластер (один сектор), если он меняется.
5. Записать запись каталога с новыми SIZE, MTIME и адресами.

Шаг 5 можно не выполнять после каждого кластера, а отложить до конца операции записи (например, одного вызова, добавляющего несколько кластеров): запись каталога пишется один раз, с итоговыми SIZE, MTIME и адресами, и не позже возврата из операции. Порядок «карта → данные → индекс → запись каталога» при этом сохраняется. Если сбой случится до записи каталога, в ней останется старый размер: добавленные кластеры утекут, но общими не станут (разд. 10); проверка тома обнулит адреса за размером.

**Обрезка до размера size'.** Пусть C' = ⌈size' / 2048⌉.

1. Определить все кластеры, которые будут освобождены: кластеры данных с номерами k ≥ C', кластер IND при C' ≤ 10, кластер DIND при C' ≤ 1034 и кластеры второго уровня, в которых не останется адресов. Запомнить их номера (в памяти) до любого обнуления: после обнуления на диске эти адреса прочитать уже негде.
2. Записать запись каталога с новыми SIZE и MTIME и обнулёнными лишними адресами (в том числе IND и DIND, если они больше не нужны).
3. Обнулить лишние адреса в остающихся индексных кластерах и записать их. Для кластера второго уровня, который освобождается целиком, сначала записать кластер DIND с обнулённым элементом, ссылающимся на него.
4. Освободить в карте запомненные кластеры. Кластер данных освобождается после записи индекса без ссылки на него; кластер второго уровня — после записи DIND с обнулённым элементом; кластеры IND и DIND — после записи записи каталога без ссылки на них (шаг 2).

Смысл порядка тот же, что и везде: кластер освобождается только после того, как исчезла последняя ссылка на него.

**Создание.** Проверить, что в каталоге нет имени, равного новому без учёта регистра, и записать в первую свободную запись имя, флаги, SIZE = 0 и MTIME = текущее время. Свободной записи нет — сначала добавить каталогу кластер. Новый каталог создаётся так же, с флагом DIR, и кластеров не занимает.

**Удаление.** Файл с RDONLY не удаляется, каталог удаляется только пустым (все записи свободны). Порядок: запомнить адреса, обнулить и записать запись, затем освободить все её кластеры (данные и индексы) в карте.

**Переименование и перемещение.** Новое имя проверяется на уникальность без учёта регистра среди записей каталога-приёмника; запись самого объекта при этой проверке не учитывается. Поэтому переименование, меняющее только регистр (`readme` → `README`), допустимо. В пределах каталога меняется только NAME. При перемещении в другой каталог 64 байта сначала записываются в новую запись, потом старая обнуляется. Каталог нельзя переместить в его же подкаталог: реализация проверяет это по цепочке пути назначения.

## 10. Порядок записи и проверка тома

Кластер помечается занятым до первой ссылки на него и освобождается после удаления последней. Тогда сбой посреди операции в худшем случае оставляет утёкшие кластеры (заняты, но никем не используются) и никогда не отдаёт один кластер двум файлам. Исключение — перемещение: после сбоя может остаться две записи одного файла, зато данные не теряются.

Из этого правила следует асимметрия карты:

- **Выделение** записывается в карту сразу, до первой ссылки на кластер. Откладывать его нельзя: иначе после сбоя кластер, на который уже ссылается запись или индекс, оказался бы в карте свободным и мог бы достаться второму файлу.
- **Освобождение** можно откладывать: запись освобождённых битов карты разрешено держать в кеше до размонтирования (или до вытеснения сектора, сброса, следующей записи этого сектора). Освобождать поздно безопасно: в худшем случае после сбоя кластер утечёт, а проверка тома его вернёт.
- **Запись каталога** при росте файла допускается откладывать до конца операции (разд. 9, «Добавление кластера»), но не раньше записи карты, данных и индекса.

**Монтирование на запись:**

1. Прочитать и проверить суперблок (разд. 3).
2. Если DIRTY = 1, том не был корректно размонтирован: выполнить проверку тома или смонтировать только для чтения.
3. Поставить DIRTY = 1, записать суперблок, выполнить FLUSH.

**Размонтирование:** записать всё из кеша, FLUSH, записать суперблок с актуальными FREE и HINT и DIRTY = 0, снова FLUSH. FREE и HINT в процессе работы можно держать только в памяти: это подсказки.

**Проверка тома:**

1. Обойти дерево от ROOT и построить в памяти новую карту (до 8 КБ), отмечая каждый кластер, на который есть ссылка.
2. Адрес вне области данных или уже отмеченный кластер: обрезать файл перед этим кластером. Если с него файл начинается, это дубль после перемещения, и запись обнуляется.
3. Несоответствие SIZE и адресов: SIZE уменьшить до числа реально выделенных кластеров, лишние адреса обнулить.
4. Записать новую карту поверх старой, пересчитать FREE. Утёкшие кластеры при этом освобождаются сами.
5. Имя с «:» (разд. 8, п. 5): сообщить о записи и не менять её. Исправить имя может утилита хоста.
6. Имена, равные без учёта регистра (разд. 8, п. 5): первая по порядку записей каталога запись группы остаётся как есть, каждая следующая получает новое уникальное имя и сообщение о переименовании. Новое имя — прежнее с числом 2, 3, … в конце: берётся наименьшее число, при котором имя не совпадает без учёта регистра ни с одной другой записью каталога; если имя с числом длиннее 32 байт, прежнее имя укорачивается. Например, из `readme` и `ReadMe` вторая становится `ReadMe2`, а если в каталоге уже есть `readme2` — `ReadMe3`. Такие группы возможны на томах, записанных до ревизии 3; без переименования лишние записи были бы недоступны по имени, и их нельзя было бы ни открыть, ни удалить.

## 11. Пределы

| Величина | Значение |
| --- | --- |
| Максимальный том | 65535 кластеров = 134 215 680 байт (128 МБ − 2 КБ) |
| Минимальный том | 3 кластера = 6 КБ |
| Служебная область | 1 + B кластеров, от 4 КБ до 10 КБ |
| Максимальный файл | область данных минус индексные кластеры; формат допускает до 2^27 − 1 байт |
| Файл без индексных кластеров | до 20 КБ (10 кластеров) |
| Файл с одним индексным кластером | до 2068 КБ (1034 кластера) |
| Длина имени | 1…32 байта |
| Записей в кластере каталога | 32 (8 в секторе) |
| Записей в каталоге | ограничено только местом на томе; каталог больше 320 записей занимает ещё и индексный кластер (разд. 7) |
| Минимальный расход на непустой файл | 2 КБ данных + 64 байта записи |
| Пустой файл или каталог | только 64 байта записи |

Не входит в версию 1: время создания, жёсткие ссылки, файлы с дырами, копия суперблока.

Изменения ревизии 3:

1. **Регистр букв в именах** (разд. 7, 7.1, 8, 9, 10). Имена сравниваются без учёта регистра по таблице fold (латиница, `А–Я`, `Ё`); в каталоге не может быть двух имён, равных в этом смысле. Регистр при хранении сохраняется. Переименование, меняющее только регистр, допустимо. Проверка тома переименовывает лишние записи таких групп: к имени добавляется число 2, 3, … (разд. 10, п. 6).
2. **Новый разд. 7.1** — правило сравнения имён и таблица приведения.
3. **Формат на диске не меняется**, VERSION остаётся 1. Тома ревизии 2 монтируются как есть; если на них есть имена, различающиеся только регистром, проверка тома переименует лишние.

Изменения ревизии 2:

1. **Двоеточие в именах** (разд. 7, 8, 10). Имена с «:» недопустимы; проверка тома сообщает о них, но не меняет.
2. **Пути** (разд. 7, 9). «.» — пустой шаг, повторные «/» равносильны одному, завершающий «/» допустим и смысла не меняет. Префикс тома «X:» в ФС16 не входит.
3. **Порядок при обрезке** (разд. 9). Освобождаемые адреса запоминаются до обнуления; кластер второго уровня освобождается после записи DIND с обнулённым элементом, IND и DIND — после записи каталога без ссылки на них.
4. **Предел поиска по карте** (разд. 4). Поиск свободного идёт до N, а не до конца карты; «не проверяет границы» относится только к сравнению номера с N внутри слова.
5. **Отложенная запись каталога** (разд. 9, 10). Запись каталога можно записывать один раз в конце операции, сохраняя порядок «карта → данные → индекс → запись каталога».
6. **Отложенная запись освобождений** (разд. 10). Запись освобождённых битов карты можно откладывать до размонтирования, запись выделенных — нельзя.
7. **Цена каталога с IND** (разд. 7, 11). Каталог больше 320 записей занимает ещё и индексный кластер.
