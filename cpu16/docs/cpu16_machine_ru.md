## 1. Карта памяти

Адресное пространство процессора — 64 КБ. Адреса в этом разделе логические, то есть те, что видит процессор. Физическая память — до 2 МБ, логические адреса отображаются на неё менеджером памяти (разд. 7). Пока менеджер выключен, физический адрес равен логическому.

| Адреса | Назначение |
|---|---|
| `$0000–$FEFF` | память (в эмуляторах — вся ОЗУ) |
| `$FF00–$FF1F` | таблица векторов прерываний (обычная память, спецификация процессора, разд. 8) |
| `$FF20–$FFFF` | **окно устройств**, в нём: |
| `$FF20–$FF29` | — консоль, дисплей, клавиатура, таймер (разд. 2–4) |
| `$FF2A–$FF2E` | — часы реального времени (разд. 8) |
| `$FF2F` | — свободен (зарезервирован для будущих устройств) |
| `$FF30–$FF3B` | — контроллер дисков (разд. 6) |
| `$FF3C` | — MODS: модификаторы клавиатуры (разд. 2.6) |
| `$FF3D–$FF3F` | — свободны (зарезервированы для контроллера дисков) |
| `$FF40–$FF48` | — менеджер памяти (разд. 7) |
| `$FF49–$FF4F` | — свободны (зарезервированы для менеджера памяти) |
| `$FF50–$FF51` | — SCRD: чтение экрана (разд. 2.2) |
| `$FF52–$FFFF` | — свободны (зарезервированы для будущих устройств) |

После сброса выполнение начинается с адреса `$0000`, все регистры процессора равны 0, менеджер памяти выключен. Рекомендуемое деление памяти для программ — ПЗУ `$0000–$7FFF`, ОЗУ `$8000–$FEFF`, стек вниз от `$FF00` — описано во «Введении», разд. 6.

**Окно устройств `$FF20–$FFFF` — не память.** Весь диапазон целиком отдан шине устройств, есть там устройство или нет:

- **Выбор по логическому адресу.** Обращение к окну узнаётся по логическому адресу до преобразования менеджером памяти и в физическую память не попадает ни при каком значении EN и PAGE7 (разд. 7.5).
- **Свободные адреса.** Чтение адреса, где нет устройства, даёт 0, запись в него игнорируется. Байты памяти по таким адресам не хранятся.
- **Совместимость.** Программы не должны обращаться к свободным адресам: в будущих ревизиях там могут появиться устройства. Нули при чтении — гарантия того, что обращение не повредит память, а не способ хранить данные.
- **Векторы — память.** Таблица векторов `$FF00–$FF1F` лежит ниже окна. Это обычная память, она преобразуется через PAGE7. Стек, растущий вниз от `$FF00`, окна не задевает.

**Порты байтовые.** Каждый регистр устройства занимает один байт, к нему обращаются командами `LDZX`, `LDSX`, `STB`. Обращение словом по чётному адресу A — одно обращение к паре регистров: A даёт младший байт слова, A + 1 — старший. Если один из двух адресов свободен, его половина слова при чтении равна 0, а при записи отбрасывается. Где словное обращение допустимо:

- консоль: только чтение слова по `$FF20` (разд. 2.6); событие клавиатуры при нём забирается один раз; чтение слова по `$FF50` (SCRD, разд. 2.2) — одно обращение: ячейка читается и позиция сдвигается один раз;
- часы: чтение и запись слова по `$FF2A` и `$FF2C` (разд. 8.2);
- контроллер дисков: чтение и запись слова по любому чётному адресу его регистров (разд. 6.1);
- менеджер памяти: чтение и запись слова по любому чётному адресу его регистров (разд. 7.2).

Других словных обращений к консоли и часам программы делать не должны. В эмуляторах такое обращение выполняется как два байтовых: сначала по A, затем по A + 1 (разд. 9).

## 2. Консоль и дисплей

Консоль, дисплей и клавиатура — одно устройство. Вывод идёт на экран 80×25 знакомест, ввод приходит из клавиатуры.

### 2.1. Экран

- 80 столбцов, 25 строк; столбцы и строки нумеруются с 0, позиция (0, 0) — левый верхний угол.
- Каждое знакоместо (ячейка) хранит **символ** (байт в кодировке машины, разд. 5) и **атрибут** (цвет и оформление, разд. 2.4).
- **Позиция** — текущая ячейка вывода. Она же — видимый курсор.
- Экранная память находится внутри устройства и в адресное пространство процессора не входит. Прочитать её можно регистром SCRD (разд. 2.2).

### 2.2. Регистры

| Адрес | Имя | Чтение | Запись |
|---|---|---|---|
| `$FF20` | DATA | символ следующего события клавиатуры, 0 если событий нет; слово — символ и сканкод (разд. 2.6) | вывод символа (разд. 2.3) |
| `$FF21` | SCAN | сканкод следующего события клавиатуры (событие забирается целиком) | — |
| `$FF22` | CTRL | режим | режим |
| `$FF23` | ATTR | текущий атрибут | текущий атрибут |
| `$FF24` | COL | столбец позиции | столбец позиции (больше 79 — становится 79) |
| `$FF25` | ROW | строка позиции | строка позиции (больше 24 — становится 24) |
| `$FF26` | CMD | 0 | команда (разд. 2.5) |
| `$FF27` | COLS | ширина экрана: 80 | — |
| `$FF28` | ROWS | высота экрана: 25 | — |
| `$FF3C` | MODS | модификаторы последнего забранного события клавиатуры (разд. 2.6) | — |
| `$FF50` | SCRD | символ ячейки в позиции; слово — ячейка целиком, см. ниже | — |
| `$FF51` | — | атрибут ячейки в позиции | — |

Запись в регистры, которые доступны только для чтения, ничего не делает.

**CTRL:**

| Бит | Имя | Значение |
|---|---|---|
| 0 | TTY | 1 — режим телетайпа, 0 — координатный режим |
| 1 | CURSOR | 1 — курсор виден |
| 2 | ATTRMODE | 1 — режим атрибутов |
| 3–7 | — | 0 |

**Состояние после сброса:**
- CTRL = `%011`: телетайп, курсор виден;
- ATTR = `$07`: белый на чёрном;
- позиция (0, 0);
- экран заполнен пробелами с атрибутом `$07`;
- очередь клавиатуры пуста, MODS = 0.

**SCRD — чтение экрана.** Словное чтение `$FF50` (`LD R0, [$FF50]`) даёт ячейку в позиции: символ в младшем байте, атрибут в старшем — и сдвигает позицию так же, как запись в координатном режиме (разд. 2.3): после столбца 79 — начало следующей строки, после последней ячейки экрана — (0, 0), при любом CTRL. Так весь экран читается 2000 чтениями слова подряд с позиции (0, 0). Байтовое чтение `$FF50` даёт символ, `$FF51` — атрибут той же ячейки; позиция при этом не меняется. Запись в SCRD ничего не делает.

```asm
        LD      R1, #0
        STB     [$FF24], R1             ; COL = 0
        STB     [$FF25], R1             ; ROW = 0
        LD      R1, #2000
@cell:  LD      R2, [$FF50]             ; символ | атрибут << 8, позиция - на следующую
        ST      [R0++], R2
        SUB     R1, #1
        JNZ     @cell                   ; позиция снова (0, 0)
```

Восстановить экран из такого снимка можно в координатном режиме: для каждой ячейки записать атрибут в ATTR и символ в DATA. После последней ячейки позиция переходит в (0, 0), прокрутки нет.

MODS лежит вне диапазона `$FF20–$FF29`, потому что адреса за ним уже заняты часами и контроллером дисков; это регистр консоли, как и остальные регистры таблицы. Он занял первый адрес резерва контроллера дисков: у `$FF2F` словное чтение по чётному адресу `$FF2E` захватывало бы регистр часов.

### 2.3. Вывод: запись в DATA

Что происходит при записи байта в DATA, зависит от CTRL. Режим атрибутов важнее остальных.

**Режим телетайпа (TTY = 1, ATTRMODE = 0)** — поведение обычной консоли:

| Байт | Действие |
|---|---|
| `$0A` (`\n`) | позиция на начало следующей строки |
| `$0D` (`\r`) | позиция на начало текущей строки |
| `$08` (`\b`) | позиция на столбец назад (в столбце 0 ничего не происходит); символ не стирается |
| `$09` (`\t`) | позиция на следующий столбец, кратный 8; за концом строки — начало следующей |
| `$00` | ничего |
| остальные | символ записывается в позицию с атрибутом ATTR, позиция сдвигается на столбец; после столбца 79 — начало следующей строки |

Если переход на следующую строку выводит за строку 24, экран прокручивается вверх на строку (нижняя строка заполняется пробелами с атрибутом ATTR), а позиция остаётся в строке 24.

**Координатный режим (TTY = 0, ATTRMODE = 0):** любой байт, включая `$00` и управляющие коды, записывается в позицию как символ с атрибутом ATTR. Позиция сдвигается на столбец; после столбца 79 она переходит на начало следующей строки, после последней ячейки экрана — в (0, 0). Прокрутки нет.

**Режим атрибутов (ATTRMODE = 1, TTY не важен):** записанный байт становится **атрибутом** ячейки в позиции, символ не меняется. Позиция сдвигается так же, как в координатном режиме. Так можно выделить цветом или инверсией часть экрана, не перерисовывая текст.

### 2.4. Атрибут и палитра

```text
   7      6      5    4    3     2    1    0
| INV  | UNDL | фон (0..7)     | текст (0..7)   |
```

- **Текст** и **фон** — номера цветов палитры.
- **INV** (инверсия) меняет местами цвета текста и фона.
- **UNDL** (подчёркивание) рисует под символом линию цветом текста.

| Код | Цвет | RGB | Код | Цвет | RGB |
|---|---|---|---|---|---|
| 0 | чёрный | `#000000` | 4 | красный | `#C50F1F` |
| 1 | синий | `#0037DA` | 5 | жёлтый | `#C19C00` |
| 2 | зелёный | `#13A10E` | 6 | серый | `#767676` |
| 3 | голубой | `#3A96DD` | 7 | белый | `#CCCCCC` |

Атрибут удобно собирать выражением `ФОН << 3 | ТЕКСТ`. Примеры:

| Атрибут | Выражение | Вид |
|---|---|---|
| `$07` | `0 << 3 \| 7` | белый на чёрном |
| `$0F` | `1 << 3 \| 7` | белый на синем |
| `$0D` | `1 << 3 \| 5` | жёлтый на синем |
| `$87` | `$80 \| $07` | инверсия: чёрный на белом |
| `$47` | `$40 \| $07` | белый на чёрном, подчёркнутый |

### 2.5. Команды: запись в CMD

| Код | Действие |
|---|---|
| 1 | очистить экран; позиция в (0, 0) |
| 2 | очистить от позиции до конца строки |
| 3 | очистить от позиции до конца экрана |
| 4 | прокрутка вверх на строку, внизу пустая строка |
| 5 | прокрутка вниз на строку, вверху пустая строка |

Очищенные и новые ячейки заполняются пробелами с текущим атрибутом ATTR. Команды 2–5 позицию не меняют. Неизвестные коды не делают ничего.

### 2.6. Ввод: клавиатура

Клавиатура складывает **события** в очередь. Каждое событие — пара: **символ** (байт в кодировке машины) и **сканкод** (номер клавиши, разд. 2.7). Чтение регистров забирает событие из очереди:

| Обращение | Результат | Событие |
|---|---|---|
| байт `$FF20` (`LDZX R0, [$FF20]`) | символ | забирается |
| слово `$FF20` (`LD R0, [$FF20]`) | символ в младшем байте, сканкод в старшем | забирается |
| байт `$FF21` (`LDZX R0, [$FF21]`) | сканкод | забирается, символ теряется |

Если очередь пуста, результат 0. Регистра готовности нет, а ожидание — это опрос в цикле или по прерыванию таймера.

- **Символ** зависит от раскладки и Shift: клавиша S даёт `s`, `S`, `ы` или `Ы`. Сканкод от раскладки не зависит.
- Особые символы:
  - Enter — `$0A` (`\n`, как в потоке консоли);
  - Ctrl+Enter — символ 0 и сканкод Enter `$1C`: клавиша без символа, как стрелки. Так программа, читающая слово, отличает её от Enter. Ctrl+Enter строку не завершает и в поток символов не попадает;
  - Backspace — `$08`, Tab — `$09`, Esc — `$1B`;
  - Ctrl + буква — `$01..$1A`.
- У клавиш без символа (стрелки, F1–F12, Home и т. п.) символ равен 0.
- Если символа клавиши нет в кодировке машины, символ равен 0, а сканкод сохраняется.
- Клавиши-модификаторы (Shift, Ctrl, Alt) отдельных событий не дают. Удержание клавиши повторяет событие, отпускание не сообщается.
- **Модификаторы события** хранятся вместе с ним. Регистр MODS (`$FF3C`) показывает модификаторы события, которое последним забрало чтение DATA или SCAN; чтение MODS событие не забирает. Пока программа не забрала новое событие, MODS не меняется; чтение из пустой очереди ставит MODS = 0.

  | Бит | Модификатор |
  |---|---|
  | 0 | Shift |
  | 1 | Ctrl |
  | 2 | Alt |
  | 3–7 | 0 |

  Так программа отличает Shift+стрелку от стрелки и Shift+F4 от F4: у клавиш без символа модификаторы видны только в MODS. Байт `$FF3D` читается как 0, слово `$FF3C` — MODS в младшем байте. Запись в MODS ничего не делает.

  ```asm
          LD      R0, [$FF20]             ; событие: символ | сканкод << 8
          LDZX    R1, [$FF3C]             ; его модификаторы
  ```

  Сочетания, которые забирает хост (браузер, терминал), машина не получает; какие модификаторы передают эмуляторы — в разд. 9.2, 9.3.
- Очередь вмещает 256 событий; лишние отбрасываются.
- Байт 0 в символе неотличим от «событий нет». Программе, которой важны специальные клавиши (в том числе Ctrl+Enter), надо читать слово.

Совместимость с прежней консолью полная: запись байта выводит символ (в телетайпе), чтение байта даёт символ или 0.

## 3. Таймер

| Адрес | Имя | Чтение | Запись |
|---|---|---|---|
| `$FF29` | TIMER | бит 0 — таймер включён | бит 0: 1 — включить, 0 — выключить |

После сброса таймер выключен.

Включённый таймер каждые **20 мс реального времени** (50 Гц) выставляет запрос **IRQ0**. Дальше действуют общие правила прерываний процессора (спецификация, разд. 8): запрос принимается при IF = 1 и будит `WFI`.

- **Время реальное.** Сколько команд процессор выполнит за 20 мс, зависит от скорости эмулятора и хоста. Программа, которой важна скорость событий (анимация, игра), должна считать тики, а не команды.
- **Тики не накапливаются.** Запрос IRQ0 — один флаг. Если предыдущий запрос ещё не принят (IF = 0 или обработчик слишком долгий), новый тик сливается с ним.
- **Порядок включения:** сначала заполнить вектор IRQ0 (и остальную таблицу), затем включить таймер, затем `STI`.
- **`WFI` при включённом таймере — ожидание, а не остановка:** следующий тик разбудит процессор.
- **Висящий запрос IRQ0.** Выключение таймера не снимает запрос, который уже выставлен, но ещё не принят: он остаётся в ожидании. При IF = 0 такой запрос будит `WFI` каждый раз, не входя в обработчик, поэтому последовательность «выключить таймер, `CLI`, `WFI`» машину не останавливает: `WFI` тут же просыпается, и программа остаётся в цикле `WFI` / `JMP`.
- **Остановка программы:** выключить таймер, затем `STI` и `CLI` — чтобы обработчик принял висящий запрос и снял его, — и только потом `WFI`. После этого запросов нет, таймер выключен, и `WFI` останавливает процессор. Вектор IRQ0 при этом должен быть заполнен обработчиком, который возвращается по `IRET` (в примере — `on_tick`; для остановки подходит и пустой обработчик из одного `IRET`). Эмулятор считает программу завершённой, когда процессор в `WFI`, запросов нет, таймер выключен и нет команды диска, которая выставит IRQ1 (BUSY = 1 при IEN = 1, разд. 6.5).

```asm
        .equ    TIMER, $FF29
        LD      R0, #on_tick
        ST      [$FF00 + 2*0], R0       ; вектор IRQ0
        LD      R0, #1
        STB     [TIMER], R0             ; таймер включён
        STI
        ...
halt:   LD      R0, #0
        STB     [TIMER], R0             ; таймер выключен
        STI                             ; принять висящий запрос IRQ0:
        CLI                             ;   обработчик выполнится и вернётся
@stop:  WFI                             ; запросов нет: процессор останавливается
        JMP     @stop
```

Если запрос IRQ0 не висит, `STI` и `CLI` ничего не меняют, поэтому рецепт безопасен всегда.

Кнопка IRQ 0 в веб-отладчике выставляет тот же запрос, что и таймер.

### 5.1. Строки в исходниках

Исходники пишутся в UTF-8. Ассемблер перекодирует строковые (`.ascii`, `.asciz`) и символьные (`'Ё'`) литералы в кодировку машины. Символ, которого в ней нет, — ошибка ассемблирования. Escape-последовательности (`\n`, `\x41`) задают байт напрямую, без перекодировки.

### 5.2. Кодировка в эмуляторе командной строки

- Байты, выводимые в телетайпе, эмулятор переводит в UTF-8 для терминала, включая псевдографику и значки.
- Ввод из stdin в UTF-8 переводится в кодировку машины. Символы, которых нет в таблице, отбрасываются.
- Последовательности клавиш терминала (стрелки, Home, End, Del, F1–F12) эмулятор распознаёт и превращает в события со сканкодом и символом 0.

## 6. Контроллер дисков

Контроллер обслуживает до 8 дисков с номерами 0..7. Диск — последовательность секторов по **512 байт**. Номер сектора (LBA) 32-битный, так что диск может содержать до 2^32 секторов.

Диски размером не более 2^16 секторов называются **маленькими**: номера их секторов умещаются в 16 бит. Структура данных на диске — дело программ (файловой системы). Сам контроллер маленькие и большие диски не различает, для него различие сводится к значениям старшего слова LBA.

Обмен идёт **прямым доступом к памяти (DMA)**: контроллер сам копирует секторы между диском и памятью. Процессор задаёт параметры, запускает команду и ждёт её завершения.

### 6.1. Регистры

| Адрес | Имя | Чтение | Запись |
|---|---|---|---|
| `$FF30` | STATUS / CMD | состояние | команда (разд. 6.3) |
| `$FF31` | ERROR | код ошибки последней команды (разд. 6.4) | — |
| `$FF32` | DISK | номер выбранного диска | номер диска; учитываются биты 0–2 |
| `$FF33` | COUNT | оставшееся число секторов | число секторов 0..255 |
| `$FF34–$FF35` | ADDR | текущий адрес в памяти | адрес буфера |
| `$FF36–$FF37` | LBA_LO | текущий сектор, младшее слово | номер сектора, младшее слово |
| `$FF38–$FF39` | LBA_HI | текущий сектор, старшее слово | номер сектора, старшее слово |
| `$FF3A` | CTRL | режим | режим |
| `$FF3B` | DRIVES | маска подключённых дисков: бит n — диск n | — |
| `$FF3D–$FF3F` | — | 0 (зарезервированы) | игнорируется |

**Словное обращение.** Все регистры контроллера можно читать и писать словом по чётному адресу: младший байт слова соответствует регистру по этому адресу, старший — регистру по следующему. Так ADDR, LBA_LO и LBA_HI задаются одной командой `ST`, а пара DISK и COUNT — одним словом:

```asm
        LD      R0, #4 << 8 | 1          ; COUNT = 4, DISK = 1
        ST      [$FF32], R0
```

Чтение регистров контроллера побочных эффектов не имеет. Чтение слова по `$FF30` даёт STATUS в младшем байте и ERROR в старшем. При записи слова по `$FF30` младший байт выполняется как команда, а старший (ERROR, только чтение) игнорируется.

**CTRL:**

| Бит | Имя | Значение |
|---|---|---|
| 0 | IEN | 1 — запрос IRQ1 по завершении команды (разд. 6.5) |
| 1–7 | — | 0 |

CTRL можно писать в любой момент, в том числе пока команда выполняется (BUSY = 1). Биты 1–7 при записи отбрасываются и читаются как 0.

**STATUS:**

| Бит | Имя | Значение |
|---|---|---|
| 0 | BUSY | команда выполняется |
| 1 | ERR | последняя команда завершилась с ошибкой (ERROR ≠ 0) |
| 2 | DONE | команда завершена и не подтверждена (разд. 6.5) |
| 3 | PRESENT | диск, выбранный в DISK, подключён |
| 4 | RO | диск, выбранный в DISK, защищён от записи |
| 5–7 | — | 0 |

BUSY и ERR стоят в младших битах, чтобы их проверка помещалась в короткую константу: `TEST R0, #1`.

**Состояние после сброса:**
- все регистры, кроме DRIVES, равны 0;
- команда не выполняется, IEN = 0;
- DRIVES отражает подключённые диски.

Сброс машины диски не отключает.

### 6.2. Выполнение команды

1. Программа заполняет регистры параметров и пишет код команды в CMD.
2. Контроллер выставляет BUSY = 1, сбрасывает DONE и обнуляет ERROR, затем проверяет параметры. Если проверка не прошла, команда сразу завершается с ошибкой и данные не передаются (порядок проверок — ниже).
3. Секторы передаются по одному. После каждого сектора LBA (32 бита) увеличивается на 1, ADDR — на 512, COUNT уменьшается на 1.
4. По завершении BUSY = 0 и DONE = 1. Если команда завершилась с ошибкой, ERR = 1, а код ошибки — в ERROR.

**Порядок проверок.** Проверки выполняются по порядку; код в ERROR определяет первая не пройденная проверка:

| Шаг | Проверка | Ошибка | Какие команды |
|---|---|---|---|
| 1 | код команды 1..4 | BADCMD | все, кроме ACK |
| 2 | диск, выбранный в DISK, подключён | NODISK | READ, WRITE, INFO, FLUSH |
| 3 | COUNT = 0 — команда сразу завершается успешно | — | READ, WRITE |
| 4 | диск не защищён от записи | READONLY | WRITE |
| 5 | LBA + COUNT не больше числа секторов | RANGE | READ, WRITE |
| 6 | ADDR + 512·COUNT − 1 ≤ `$FF1F` (у INFO — ADDR + 31 ≤ `$FF1F`) | BADADDR | READ, WRITE, INFO |

- Суммы в шагах 5 и 6 вычисляются без переполнения, а не по модулю 2^32 и 2^16: LBA + COUNT занимает до 33 бит, ADDR + 512·COUNT − 1 — до 18 бит.
- Из шага 3 следует, что READ и WRITE с COUNT = 0 на подключённом диске успешны всегда, даже на защищённом диске и при любых LBA и ADDR.

**Регистры продвигаются по ходу обмена.** Чтобы прочитать следующие секторы, достаточно снова задать COUNT и повторить команду: LBA и ADDR уже указывают дальше. Если ошибка ввода-вывода прервала обмен, COUNT показывает, сколько секторов не передано. Если после успешной команды нужно снова прочитать тот же сектор, LBA надо записать заново.

**Время выполнения** зависит от реализации. Эмулятор может выполнить команду мгновенно, отладчик — с задержкой. Программа обязана дождаться BUSY = 0, опросом STATUS или по IRQ1. Обмен происходит между командами процессора.

**Пока BUSY = 1:**
- запись в CMD (включая ACK) и в регистры параметров (DISK, COUNT, ADDR, LBA) игнорируется; запись в CTRL действует;
- чтение регистров показывает ход обмена;
- программа не должна обращаться к буферу: его содержимое не определено.

**Буфер** занимает логические адреса от ADDR до ADDR + 512·COUNT − 1 и должен целиком лежать в `$0000–$FF1F`. Таблицу векторов можно читать и писать через диск, окно устройств — нельзя: DMA никогда не обращается к адресам `$FF20–$FFFF`.

**Буфер и менеджер памяти.** Адрес буфера логический. При включённом менеджере (разд. 7) каждое обращение DMA преобразуется через регистры PAGE так же, как обращение процессора. Чтобы прочитать данные в любой кадр, его ставят в одну из страниц. Пока BUSY = 1, программа не должна менять MMU_CTRL и регистры PAGE страниц, которые перекрывает буфер: в какой кадр попадут данные, не определено.

**Загрузка кода.** Запись DMA — обычная запись данных в память. Если в буфер прочитан код, выполненный переход после ожидания служит точкой синхронизации (спецификация процессора, разд. 11), и код исполнится в новом виде.

### 6.3. Команды

| Код | Команда | Действие |
|---|---|---|
| 0 | ACK | сбросить DONE и снять запрос IRQ1; ERR и ERROR не меняются |
| 1 | READ | прочитать COUNT секторов, начиная с LBA, в память по ADDR |
| 2 | WRITE | записать COUNT секторов из памяти по ADDR на диск, начиная с LBA |
| 3 | INFO | записать 32-байтный блок сведений о диске в память по ADDR |
| 4 | FLUSH | дописать на носитель данные, ещё не сохранённые при прежних WRITE |
| 5–255 | — | ошибка BADCMD |

- Команда ACK выполняется сразу и BUSY не выставляет.
- При COUNT = 0 команды READ и WRITE завершаются успешно, ничего не передав.
- INFO и FLUSH используют только DISK (INFO — ещё ADDR) и регистров параметров не меняют.
- ACK при BUSY = 1 игнорируется, как любая запись в CMD.
- После успешной WRITE данные уже видны следующим READ. FLUSH нужна только для гарантии сохранности на носителе (в эмуляторе — в файле образа).

**Блок INFO (32 байта):**

| Смещение | Размер | Содержимое |
|---|---|---|
| 0 | 4 | число секторов (32 бита, little-endian) |
| 4 | 1 | флаги: бит 0 RO (защита от записи), бит 1 REMOVABLE (диск можно подключать и отключать во время работы), бит 2 SMALL (маленький диск: не более 2^16 секторов) |
| 5 | 11 | 0 (резерв) |
| 16 | 16 | метка диска: строка с завершающим нулём в кодировке машины, до 15 символов; байты после нуля равны 0 |

Флаг SMALL избавляет от проверки граничного случая: у диска ровно из 2^16 секторов старшее слово размера равно 1, но диск маленький.

### 6.4. Ошибки

| Код | Имя | Причина |
|---|---|---|
| 0 | OK | ошибки нет |
| 1 | NODISK | выбранный диск не подключён |
| 2 | BADCMD | неизвестная команда |
| 3 | RANGE | LBA + COUNT больше числа секторов диска |
| 4 | BADADDR | буфер выходит за `$FF1F` (разд. 6.2, шаг 6) |
| 5 | READONLY | WRITE на защищённый диск |
| 6 | IO | ошибка носителя (в эмуляторе — ошибка файла образа или отключение диска во время команды) |

Ошибки 1–5 обнаруживаются до начала обмена, и регистры параметров при них не меняются. Ошибка 6 может возникнуть посреди обмена: регистры показывают место сбоя — LBA и ADDR указывают на сектор, который не удалось передать, COUNT включает его.

ERR и ERROR держатся до начала следующей команды (кроме ACK): ACK их не сбрасывает.

### 6.5. Прерывание

Запрос **IRQ1** держится, пока DONE = 1 и IEN = 1 (запрос по уровню, спецификация процессора, разд. 8.2). Обработчик снимает запрос командой ACK. Новая команда тоже сбрасывает DONE. Если не подтвердить завершение, после `IRET` обработчик будет вызван снова.

Запрос таймера IRQ0 имеет более высокий приоритет.

Команда может завершиться сразу после записи в CMD, ещё до следующей команды процессора. Поэтому ожидание через `STI` / `WFI` содержит гонку: прерывание может прийти между `STI` и `WFI`, и `WFI` заснёт навсегда. Надёжный способ — ждать при IF = 0. При IF = 0 команда `WFI` просыпается по запросу, не входя в обработчик, а следующая за ней `STI` сразу даёт обработчику выполниться (разд. 6.6, второй пример).

### 6.6. Примеры

Драйвер маленьких дисков с ожиданием опросом:

```asm
        .equ    DK_CMD,    $FF30
        .equ    DK_STATUS, $FF30
        .equ    DK_ERROR,  $FF31
        .equ    DK_DISK,   $FF32
        .equ    DK_COUNT,  $FF33
        .equ    DK_ADDR,   $FF34
        .equ    DK_LBA_LO, $FF36
        .equ    DK_LBA_HI, $FF38
        .equ    DK_CTRL,   $FF3A
        .equ    DK_DRIVES, $FF3B
        .equ    DK_ACK,    0
        .equ    DK_READ,   1
        .equ    DK_WRITE,  2
        .equ    DK_INFO,   3
        .equ    DK_FLUSH,  4
        .equ    DK_BUSY,   $01

; Вход:  R0 = диск, R1 = LBA, R2 = адрес буфера, R3 = число секторов
; Выход: R0 = код ошибки, ZF = 1 при успехе.
; R4 используется и сохраняется в стеке.
disk_read:
        PUSH    R4
        LD      R4, #DK_READ
        JMP     disk_io
disk_write:
        PUSH    R4
        LD      R4, #DK_WRITE
disk_io:                                ; R4 = команда, сохранённый R4 в стеке
        STB     [DK_DISK], R0
        STB     [DK_COUNT], R3
        ST      [DK_ADDR], R2
        ST      [DK_LBA_LO], R1
        LD      R0, #0
        ST      [DK_LBA_HI], R0          ; маленький диск: старшее слово 0
        STB     [DK_CMD], R4
@wait:  LDZX    R0, [DK_STATUS]
        TEST    R0, #DK_BUSY
        JNZ     @wait
        LDZX    R0, [DK_ERROR]
        POP     R4
        CMP     R0, #0
        RET
```

Примеры следуют соглашению о вызовах: аргументы и результат передаются в R0–R3, эти регистры вызов не сохраняет, остальные подпрограмма обязана сохранить.

Драйвер всегда пишет LBA_HI. Регистры продвигаются, и после чтения последнего сектора диска из 2^16 секторов в LBA_HI окажется 1, поэтому полагаться на прежнее значение нельзя.

Ожидание по IRQ1 без гонки. Вектор IRQ1 заполнен, IEN = 1, параметры заданы:

```asm
; Вход: R1 = код команды. Портит R0.
disk_start_wait:
        CLI
        LD      R0, #0
        STB     [dk_done], R0
        STB     [DK_CMD], R1            ; запуск
@wait:  LDZX    R0, [dk_done]
        CMP     R0, #0
        JNZ     @done
        WFI                             ; IF = 0: проснуться по запросу, не входя в обработчик
        STI                             ; запрос принимается сразу после STI
        CLI
        JMP     @wait
@done:  STI
        RET

disk_irq:                               ; вектор IRQ1: ST [$FF00 + 2*1], ...
        PUSH    R0
        LD      R0, #DK_ACK
        STB     [DK_CMD], R0            ; снять запрос
        LD      R0, #1
        STB     [dk_done], R0
        POP     R0
        IRET

dk_done: .byte  0
```

Пока программа ждёт, `WFI` будят и тики таймера. Цикл просто проверяет флаг ещё раз.

Этот вариант рассчитан на программу, которая работает при IF = 1: он завершается `STI`. Код, который работает при IF = 0 (например, ядро монитора), после каждого ожидания должен вернуть IF = 0 сам, поэтому ему нужен вариант без завершающего `STI`. Вектор IRQ1 заполнен, IEN = 1, параметры заданы, IF = 0:

```asm
; Вход: R1 = код команды. Портит R0. IF = 0 на входе и на выходе.
disk_start_wait0:
        LD      R0, #0
        STB     [dk_done], R0
        STB     [DK_CMD], R1            ; запуск
@wait:  LDZX    R0, [dk_done]
        CMP     R0, #0
        JNZ     @done
        WFI                             ; IF = 0: проснуться по запросу, не входя в обработчик
        STI                             ; запрос принимается сразу после STI
        CLI                             ; IF снова 0
        JMP     @wait
@done:  RET                             ; IF = 0, как на входе
```

Обработчик `disk_irq` тот же, что в предыдущем примере. Проверка флага стоит до `WFI`, поэтому завершение, пришедшее сразу после записи в CMD, не теряется: цикл выходит, не засыпая. Если запрос пришёл раньше, чем процессор дошёл до `WFI`, `WFI` при IF = 0 просыпается сразу. Команда `CLI` в начале не нужна: IF уже равен 0. Если вызывающий код может работать и при IF = 1, он сохраняет флаги (`PUSH FLAGS`) и сам выполняет `CLI` до вызова, а после вызова возвращает их (`POP FLAGS`).

## 7. Менеджер памяти

Менеджер памяти (MMU) расширяет физическую память до **2 МБ**. Он стоит между процессором и памятью. Процессор не меняется: он по-прежнему работает с 16-битными **логическими** адресами, а менеджер преобразует их в 21-битные **физические**.

### 7.1. Страницы и кадры

Логическое пространство делится на 8 **страниц** по 8 КБ, физическое — на 256 **кадров** по 8 КБ. Каждой странице соответствует регистр PAGEp, который хранит номер кадра.

| Логические адреса | Страница | Регистр |
|---|---|---|
| `$0000–$1FFF` | 0 | PAGE0 |
| `$2000–$3FFF` | 1 | PAGE1 |
| `$4000–$5FFF` | 2 | PAGE2 |
| `$6000–$7FFF` | 3 | PAGE3 |
| `$8000–$9FFF` | 4 | PAGE4 |
| `$A000–$BFFF` | 5 | PAGE5 |
| `$C000–$DFFF` | 6 | PAGE6 |
| `$E000–$FFFF` | 7 | PAGE7 |

```text
логический адрес:  | p:3     | смещение:13 |
физический адрес:  | PAGEp:8 | смещение:13 |     21 бит
```

Пример: при PAGE6 = 20 логический адрес `$C010` соответствует физическому 20 · `$2000` + `$0010` = `$28010`.

- Один кадр можно отобразить в несколько страниц сразу.
- Двухсловная команда может лежать на границе страниц: каждое слово преобразуется по своей странице.
- Слова выровнены, поэтому одно слово границу страниц не пересекает.

### 7.2. Регистры

| Адрес | Имя | Чтение | Запись |
|---|---|---|---|
| `$FF40` + p | PAGEp | номер кадра страницы p | номер кадра 0..255 |
| `$FF48` | MMU_CTRL | режим | режим |
| `$FF49–$FF4F` | — | 0 (зарезервированы для расширения менеджера) | игнорируется |

**MMU_CTRL:**

| Бит | Имя | Значение |
|---|---|---|
| 0 | EN | 1 — менеджер включён, 0 — выключен |
| 1–7 | — | 0; при записи отбрасываются |

- Регистры доступны байтом, а также словом по чётному адресу (разд. 1): `ST [$FF40], R0` задаёт PAGE0 и PAGE1 одной командой.
- Чтение побочных эффектов не имеет.
- Регистры PAGE можно читать и писать при любом значении EN.

**Состояние после сброса:**
- EN = 0, менеджер выключен;
- значения PAGE0..PAGE7 **не определены** (в эмуляторах они равны 0, разд. 9, но программы на это полагаться не должны).

### 7.3. Режимы

**Выключен (EN = 0).** Физический адрес равен логическому: процессор видит первые 64 КБ физической памяти, то есть кадры 0..7. Регистры PAGE на обращения не влияют, поэтому карту можно подготовить заранее. В этом режиме машина совпадает с машиной ревизии 2. Программе, которой менеджер не нужен, о нём знать не надо.

**Включён (EN = 1).** Обращение по логическому адресу страницы p идёт в кадр PAGEp (разд. 7.1).

**Перед включением программа обязана записать все восемь регистров PAGE.** После сброса их значения не определены, и менеджер их не инициализирует. Настройка карты — ответственность программы, которая включает менеджер.

Выключение (запись EN = 0) разрешено и возвращает режим, в котором физический адрес равен логическому.

DMA контроллера дисков подчиняется тем же правилам, что и процессор (разд. 6.2).

### 7.4. Когда изменения вступают в силу

- **Данные.** Запись в PAGEp или MMU_CTRL действует со следующей команды. Сама записывающая команда, включая её второе слово, исполняется по прежнему отображению.
- **Выборка команд.** Изменение отображения равносильно изменению кода (спецификация процессора, разд. 11). Новое отображение гарантированно действует после точки синхронизации: выполненного перехода, `CALL`, `RET`, `TRAP`, `IRET` или входа в прерывание. До неё каждое слово команды из затронутой страницы может быть взято как по старому, так и по новому отображению.
- **Безопасное переключение.** Страница, в которой исполняется код, меняющий отображение, должна отображаться на тот же кадр до и после изменения.
  - При включении это значит PAGEp = p для страницы p, где лежит код включения.
  - Чтобы сменить содержимое собственной страницы, надо перейти в код в другой странице (трамплин).

### 7.5. Что не преобразуется

**Окно устройств `$FF20–$FFFF`** выбирается по логическому адресу до преобразования и целиком принадлежит устройствам (разд. 1):

- Устройства, в том числе регистры менеджера, видны при любых EN и PAGE7.
- Свободные адреса окна читаются как 0 при любом отображении: они не ведут в кадр страницы 7.
- Байты со смещениями `$1F20–$1FFF` кадра, стоящего в странице 7, через эту страницу недоступны ни процессору, ни DMA. Через другую страницу они доступны как обычная память.
- При EN = 0 в странице 7 стоит кадр 7, поэтому физические адреса `$0FF20–$0FFFF` недоступны вовсе. Чтобы обратиться к ним, нужно включить менеджер и поставить кадр 7 в другую страницу.

**Таблица векторов `$FF00–$FF1F`** — обычная память, она преобразуется через PAGE7. Векторы, код обработчиков и их стек должны быть отображены всякий раз, когда прерывание может быть принято. ERRCMD не маскируется, поэтому вектор 8 должен быть действителен всегда.

Рекомендуется общая страница 7 — векторы, стек, данные ядра — с одним и тем же кадром во всех картах.

**Прерывание отображение не меняет.** Обработчик, который меняет карту, обязан её восстановить. Вся карта читается четырьмя словами:

```asm
        .equ    MMU_PAGE, $FF40

        LD      R0, [MMU_PAGE+0]         ; PAGE0, PAGE1
        PUSH    R0
        LD      R0, [MMU_PAGE+2]         ; PAGE2, PAGE3
        PUSH    R0
        LD      R0, [MMU_PAGE+4]         ; PAGE4, PAGE5
        PUSH    R0
        LD      R0, [MMU_PAGE+6]         ; PAGE6, PAGE7
        PUSH    R0
```

### 7.6. Физическая память

- Физическое пространство — 2 МБ, кадры 0..255.
- При EN = 0 физические адреса `$00000–$0FFFF` образуют 64-килобайтное пространство ревизии 2; из них процессору доступны `$00000–$0FF1F`, остальное закрыто окном устройств (разд. 7.5).
  - В железной реализации, по рекомендации «Введения», кадры 0–3 (`$0000–$7FFF`) могут быть ПЗУ с кодом запуска, кадры 4–7 — ОЗУ.
  - Состав остальных кадров определяет реализация.
- В эмуляторах все 2 МБ — ОЗУ.
- Защиты памяти нет: менеджер только перераспределяет адреса.

### 7.7. Загрузка и включение

Предварительный сценарий для железной реализации:

1. **Сброс.** IP = 0, менеджер выключен. Процессор исполняет код запуска из ПЗУ.
2. **Код ПЗУ:**
   - ставит SP;
   - записывает векторы, начиная с ERRCMD (спецификация процессора, разд. 9);
   - читает загрузчик с диска в ОЗУ;
   - передаёт ему управление.
3. **Загрузчик:**
   - записывает все регистры PAGE;
   - включает менеджер;
   - загружает систему в нужные кадры и переходит в неё.

Программа в ПЗУ, которой менеджер не нужен, его не включает.

Пример включения. Загрузчик работает в странице 4, стек и векторы лежат в странице 7. Страницы 0–3 получают ОЗУ вместо ПЗУ, страницы 4–7 отображаются на свои кадры:

```asm
        .equ    MMU_PAGE, $FF40
        .equ    MMU_CTRL, $FF48
        .equ    MMU_EN,   $01

; Портит R0.
mmu_init:
        LD      R0, #9 << 8 | 8          ; PAGE0 = 8, PAGE1 = 9
        ST      [MMU_PAGE+0], R0
        LD      R0, #11 << 8 | 10        ; PAGE2 = 10, PAGE3 = 11
        ST      [MMU_PAGE+2], R0
        LD      R0, #5 << 8 | 4          ; PAGE4 = 4 (код загрузчика), PAGE5 = 5
        ST      [MMU_PAGE+4], R0
        LD      R0, #7 << 8 | 6          ; PAGE6 = 6, PAGE7 = 7 (векторы, стек)
        ST      [MMU_PAGE+6], R0
        LD      R0, #MMU_EN
        STB     [MMU_CTRL], R0           ; менеджер включён
        RET                              ; переход — точка синхронизации
```

ПЗУ после включения остаётся доступным: достаточно поставить его кадр в какую-нибудь страницу.

## 8. Часы реального времени

Часы хранят местные дату и время с точностью до секунды и идут независимо от процессора. Значение записано в формате метки времени файловой системы ФС16 («Файловая система ФС16», разд. 5.1), поэтому его можно без преобразований положить в поле MTIME записи каталога.

Программа не обращается к часам напрямую. Обмен идёт через регистры TIME и DATE: команда READ копирует в них текущее значение часов, команды записи переносят значение из них в часы.

### 8.1. Формат значения

Значение занимает 32 бита, little-endian: младшее слово TIME — время, старшее слово DATE — дата и признак PM.

```text
TIME:   15      12  11            6  5             0
      | час 0..11 | минута 0..59    | секунда 0..59   |

DATE:   15          10  9       6  5        1    0
      | год − 2025     | месяц    | день       | PM |
```

- **Время 12-часовое.** Час 0 означает 12: полночь — AM, час 0; полдень — PM, час 0; 23:59:59 — PM, 11:59:59. Час в 24-часовой записи равен час + 12 · PM.
- **Признак PM** относится ко времени суток, но лежит в младшем бите слова DATE.
- **Диапазон** — с 1 января 2025 года AM 0:00:00 по 31 декабря 2088 года PM 11:59:59.
- **Сравнение.** Поля идут от старших к младшим, и два значения сравниваются как беззнаковые 32-битные числа.
- **Время местное.** Часовой пояс и признак летнего времени не хранятся.

**Допустимое время суток:** час 0..11, минута и секунда 0..59; PM любой. **Допустимая дата:** год любой (0..63), месяц 1..12, день от 1 до числа дней в месяце. В феврале високосного года 29 дней; в диапазоне 2025–2088 високосны годы, кратные 4. Значение допустимо, если допустимы и время суток, и дата.

Значение часов всегда допустимо (разд. 8.3, 8.4). В частности, часы никогда не показывают 0: в метке ФС16 это «время неизвестно», а месяц 0 недопустим.

### 8.2. Регистры

| Адрес | Имя | Чтение | Запись |
|---|---|---|---|
| `$FF2A–$FF2B` | TIME | время | время |
| `$FF2C–$FF2D` | DATE | дата и PM | дата и PM |
| `$FF2E` | STATUS / CMD | состояние | команда (разд. 8.3) |

- **TIME и DATE — регистры данных.** Их чтение и запись побочных эффектов не имеют и на часы не влияют: с часами регистры связаны только через команды. Значения в них хранятся как есть, без проверки.
- **Словное обращение.** TIME и DATE доступны байтом и словом по `$FF2A` и `$FF2C` (разд. 1). CMD — только байтом.

**STATUS:**

| Бит | Имя | Значение |
|---|---|---|
| 0 | ERR | последняя команда записи отклонена: значение в регистрах недопустимо |
| 1–7 | — | 0 |

**Состояние после сброса:**
- TIME = 0, DATE = 0, ERR = 0;
- значение и ход часов сброс не меняет (разд. 8.4).

### 8.3. Команды

| Код | Команда | Действие |
|---|---|---|
| 1 | READ | скопировать текущее значение часов в TIME и DATE |
| 2 | WRITE | установить дату и время: время суток из TIME и бита PM регистра DATE, дату из DATE |
| 3 | WRITE_TIME | установить только время суток: из TIME и бита PM регистра DATE; дата не меняется |
| 4 | WRITE_DATE | установить только дату: год, месяц и день из DATE (бит PM не учитывается); время суток не меняется |
| 0, 5–255 | — | ничего не делают |

- **Выполнение сразу.** Команда выполняется при записи в CMD; её результат виден уже следующей команде процессора. Ожидать завершения не нужно.
- **READ** копирует все четыре байта одновременно, поэтому время и дата в регистрах относятся к одному моменту, даже если между чтением слов часы перешли через полночь. ERR команда не меняет.
- **Проверка при записи.** Команда записи проверяет то, что устанавливает: WRITE — значение целиком, WRITE_TIME — время суток, WRITE_DATE — дату (разд. 8.1).
  - Значение допустимо — часы устанавливаются, ERR = 0.
  - Значение недопустимо — **часы не меняются**: сохраняют прежнее значение и продолжают идти. ERR = 1.
- **Доля секунды.** WRITE и WRITE_TIME её сбрасывают: следующая секунда наступит ровно через 1 с после команды. WRITE_DATE долю секунды не трогает, и ход секунд не сбивается.
- Команды записи и неизвестные коды не меняют TIME и DATE; неизвестные коды не меняют и ERR.

**Порядок работы:**
- чтение — команда READ, затем чтение TIME и DATE;
- установка — запись TIME и DATE, затем команда WRITE, затем проверка ERR;
- установка только времени или только даты — запись нужного регистра и команда WRITE_TIME или WRITE_DATE. Для WRITE_TIME в регистре DATE должен стоять нужный бит PM: проще всего выполнить READ и поменять в словах только нужные поля.

### 8.4. Ход часов

- Каждую секунду реального времени значение увеличивается на одну секунду с переносами: AM 11:59:59 → PM 0:00:00 (полдень), PM 11:59:59 → AM 0:00:00 следующего дня, последний день месяца → 1-е число следующего. Длины месяцев и високосные годы учитываются.
- **Часы идут по кругу:** за 31 декабря 2088 года PM 11:59:59 следует 1 января 2025 года AM 0:00:00. Метки, записанные до и после такого перехода, при сравнении дают неверный порядок.
- **Начальное значение не определено.** После включения машины часы могут показывать любую допустимую дату и время и сразу идут. Признака «часы не установлены» нет: программа, которой важно настоящее время, получает его у пользователя или из другого источника и устанавливает командой WRITE.
- **Сброс машины** значение и ход часов не меняет.
- Точность хода определяет реализация.
- Прерываний часы не выставляют. Смену секунды программа узнаёт опросом, например в обработчике таймера.

**Прерывания.** Регистры TIME, DATE и бит ERR у часов одни на всех. Если обработчик прерывания обращается к часам, основная программа должна работать с ними при IF = 0: от команды READ до чтения обоих регистров и от записи регистров до проверки ERR. Иначе обработчик, вызванный посередине, перезапишет регистры.

### 8.5. Примеры

Чтение и установка часов. Значение в R0 (время) и R1 (дата) лежит в формате MTIME: R0 пишется в слово +36 записи каталога, R1 — в слово +38.

```asm
        .equ    RTC_TIME,       $FF2A
        .equ    RTC_DATE,       $FF2C
        .equ    RTC_CMD,        $FF2E
        .equ    RTC_STATUS,     $FF2E
        .equ    RTC_READ,       1
        .equ    RTC_WRITE,      2
        .equ    RTC_WRITE_TIME, 3
        .equ    RTC_WRITE_DATE, 4
        .equ    RTC_ERR,        $01

; Выход: R0 = время, R1 = дата.
rtc_get:
        PUSH    FLAGS                   ; критическая секция: READ и чтение
        CLI                             ;   регистров без обработчика между ними
        LD      R0, #RTC_READ
        STB     [RTC_CMD], R0           ; значение часов → TIME, DATE
        LD      R0, [RTC_TIME]
        LD      R1, [RTC_DATE]
        POP     FLAGS
        RET

; Вход:  R0 = время, R1 = дата.
; Выход: R0 = 0 и ZF = 1 — часы установлены;
;        R0 = 1 — значение недопустимо, часы не изменились.
rtc_set:
        PUSH    FLAGS
        CLI
        ST      [RTC_TIME], R0
        ST      [RTC_DATE], R1
        LD      R0, #RTC_WRITE
        STB     [RTC_CMD], R0
        LDZX    R0, [RTC_STATUS]        ; бит 0 — ERR, остальные 0
        POP     FLAGS
        CMP     R0, #0
        RET
```

Если обработчики прерываний к часам не обращаются, `PUSH FLAGS`, `CLI` и `POP FLAGS` не нужны.

Час в 24-часовой записи:

```asm
; Вход: R0 = время, R1 = дата. Выход: R0 = час 0..23.
rtc_hour24:
        SHR     R0, #12                 ; час 0..11
        TEST    R1, #1                  ; PM?
        JZ      @am
        ADD     R0, #12
@am:    RET
```

## 9. Эмуляторы

### 9.1. Общее для эмуляторов

Эмулятор командной строки и веб-отладчик реализуют машину одинаково. Их совпадение проверяется сверкой на случайных программах. Ниже — решения, которые документ оставляет реализации, и то, как их приняли оба эмулятора.

| Что | Как |
|---|---|
| память | 2 МБ ОЗУ, при запуске заполнена нулями |
| менеджер памяти после сброса | EN = 0, PAGE0..PAGE7 = 0 |
| свободные адреса окна устройств | чтение 0, запись игнорируется (разд. 1) |
| словные обращения к окну, кроме описанных в разд. 1 | как два байтовых обращения: сначала по A, затем по A + 1. Например, запись слова в `$FF20` выводит младший байт, старший уходит в SCAN и отбрасывается |
| изменённый код и смена отображения | действуют сразу, с ближайшей выборки слова команды (спецификация процессора, разд. 11, допускает и это) |
| ограниченно непредсказуемые кодировки команд | ERRCMD (спецификация процессора, разд. 6.3) |
| опрос устройств | тик таймера и ход команды диска с задержкой проверяются между командами процессора раз в 256 команд и при каждом ожидании в `WFI`; поэтому IRQ0 и завершение такой команды становятся видны программе с запаздыванием до 256 команд |
| команда диска без задержки | выполняется целиком при записи в CMD; DONE и запрос IRQ1 видны уже следующей команде процессора |
| метка диска | имя файла без каталога, первые 15 символов; символы, которых нет в кодировке машины, и управляющие символы заменяются на `?` |
| начальное значение часов | местное время хоста при запуске; если оно вне 2025–2088 — 1 января 2025 года AM 0:00:00. Между запусками значение не сохраняется |
| ход часов | равномерный, по монотонным часам хоста, от запуска или последней установки. Перевод часов хоста и переход на летнее время на часы машины не влияют |
| команда READ | значение вычисляется в момент записи в CMD; опроса между командами часы не требуют |
| часы при сбросе машины | идут дальше; TIME, DATE и ERR равны 0 |

### 9.2. Эмулятор командной строки `cpu16`

| Что | Как |
|---|---|
| вывод в телетайпе | в stdout (UTF-8) |
| координатный вывод | в stdout не попадает; ключ `--screen` печатает содержимое экрана по завершении |
| ввод | stdin, без ожидания: если ввода нет, чтение даёт 0. С терминала Unix строка приходит после Enter. Обычно терминал передаёт Ctrl+Enter как Enter, и эмулятор их не различает; если терминал шлёт для Ctrl+Enter последовательность `ESC [13;5u` (протокол CSI u) или `ESC [27;5;13~` (xterm с modifyOtherKeys), эмулятор превращает её в событие со сканкодом `$1C` и символом 0 и MODS = Ctrl. Модификаторы других клавиш эмулятор берёт из последовательностей xterm: `ESC [1;mX` вместо `ESC [X` и `ESC O X` (стрелки, Home, End, F1–F4), `ESC [n;m~` вместо `ESC [n~` (PgUp, PgDn, Ins, Del, F5–F12), где m − 1 — сумма Shift 1, Alt 2, Ctrl 4; терминал шлёт их для Shift-, Ctrl- и Alt-сочетаний с клавишами без символа. У символов терминал модификаторы не передаёт: их MODS = 0, в том числе у Ctrl + буква (символ `$01..$1A` всё равно различим). В консоли Windows клавиши читаются сразу, по одной: Enter даёт `$0A`, Ctrl+Enter — событие со сканкодом `$1C` и символом 0 (разд. 2.6), стрелки, Home, End, PgUp, PgDn, Ins, Del и F1–F12 — события со сканкодом и символом 0, буквы — в Юникоде, независимо от кодовой страницы консоли. Модификаторы в консоли Windows: Ctrl-, Shift- и Alt-сочетания F1–F12, Ctrl со стрелками, Home, End, PgUp, PgDn, Ins, Del — по кодам консоли; Shift с остальными клавишами без символа — по состоянию клавиши Shift (`GetKeyState`) |
| таймер | реальные 20 мс; в `WFI` эмулятор спит до следующего тика |
| диски | ключ `--disk N=файл[:ro]`, N = 0..7; можно повторять (см. ниже) |
| команды диска | выполняются мгновенно, при записи в CMD; BUSY программа не видит |
| завершение | процессор в `WFI`, запросов нет, таймер выключен и нет команды диска, которая выставит IRQ1 (разд. 3) |
| образ программы | плоский файл не больше 64 КБ; загружается по адресу из ключа `-l` (по умолчанию 0). После сброса менеджер выключен, поэтому это и логический, и физический адрес. Байты образа, попавшие на адреса `$FF20–$FFFF`, процессору не видны |
| часы | ключ `--rtc ДД.ММ.ГГГГTЧЧ:ММ:СС` задаёт начальное значение вместо времени хоста (24-часовая запись, эмулятор переводит её в формат разд. 8.1). Недопустимая дата или год вне 2025–2088 — ошибка запуска. Ключ нужен для воспроизводимых запусков и сверки эмуляторов |
| другие ключи | `-t` — трассировка, `-n N` — не больше N команд, `--strict-align` — сообщения о словных обращениях и переходах по нечётному адресу, `--selftest` — встроенные тесты |

Диски командной строки:

```text
./cpu16 --disk 0=sys.img --disk 1=data.img:ro prog.bin
```

- **Образ** — плоский файл секторов, сектор n лежит со смещения 512·n. Размер файла должен быть кратен 512, иначе это ошибка запуска. Число секторов равно размеру файла, делённому на 512.
- **Суффикс `:ro`** защищает диск от записи. Файл, который не удаётся открыть на запись, тоже подключается только для чтения.
- **Метка** — по правилу разд. 9.1.
- **Запись** идёт в файл образа. FLUSH и завершение эмулятора сбрасывают данные на носитель хоста.
- Флаг REMOVABLE у дисков командной строки равен 0.
- **Ошибки запуска:** номер диска вне 0..7, повтор номера, файл не открывается, размер не кратен 512. Эмулятор сообщает об ошибке и программу не запускает.

### 9.3. Веб-отладчик

| Что | Как |
|---|---|
| консоль (внизу) | журнал телетайпного вывода с прокруткой назад; ввод с клавиатуры, когда консоль в фокусе |
| дисплей | кнопка «Display» рядом с консолью: отдельное окно браузера, а если окна запрещены (например, во встроенном просмотре в чате) — панель справа во всю высоту; в обоих есть полноэкранный режим |
| программа рисует на закрытом дисплее | кнопка «Display» подсвечивается |
| клавиши в фокусе дисплея | все уходят программе, кроме Pause/Break (пауза отладчика) |
| Ctrl+Enter | в фокусе консоли и дисплея — событие со сканкодом `$1C` и символом 0 (разд. 2.6); действие браузера по умолчанию подавляется |
| Ctrl+[ и Ctrl+] | в фокусе консоли и дисплея — события со сканкодами `$1A` и `$1B`, символом 0 и MODS = Ctrl (ими монитор переключает сеансы); остальные сочетания с Ctrl в фокусе консоли остаются браузеру и отладчику |
| модификаторы | MODS — состояние Shift, Ctrl и Alt в момент нажатия (`KeyboardEvent`); сочетания, которые браузер не отдаёт странице (например, Ctrl+T, Ctrl+W, Ctrl+N), программа не получает |
| таймер | реальные 20 мс, пока программа выполняется; при паузе и пошаговом выполнении таймер стоит, пропущенные тики не накапливаются |
| диски | вкладка «Disks» рядом с консолью: подключить образ с компьютера (или перетащить файл `.img`, `.dsk` на страницу), создать пустой образ заданного числа секторов, скачать образ, включить и снять защиту от записи, отключить диск; там же видны текущие регистры контроллера |
| подключение во время работы | разрешено, DRIVES меняется сразу; у всех дисков отладчика флаг REMOVABLE = 1; отключение во время команды завершает её ошибкой IO |
| время команды диска | 1 мс реального времени на сектор (INFO и FLUSH — 1 мс целиком), поле «Time per sector» на вкладке «Disks»; 0 — команда выполняется при записи в CMD, как в эмуляторе командной строки. Ошибки проверки (разд. 6.2) завершают команду сразу при любой задержке |
| обмен на паузе | при паузе и пошаговом выполнении обмен стоит; при продолжении отсчёт текущего сектора начинается заново |
| `WFI` в ожидании диска | если выполняется команда при IEN = 1, `WFI` — ожидание, а не остановка; строка состояния показывает «Running (WFI, disk)» |
| хранение образов | в памяти страницы; изменения сохраняются только скачиванием образа, изменённый образ помечен «modified»; FLUSH всегда успешна |
| менеджер памяти | раздел «Memory manager» в панели регистров: бит EN, регистры PAGE0..PAGE7 (правка двойным щелчком) и физические адреса страниц |
| часы | раздел «Clock» в панели регистров: значение часов в виде даты и времени (24-часовая запись), регистры TIME, DATE и ERR. Правка значения двойным щелчком устанавливает часы, недопустимое значение не принимается; кнопка «Host time» ставит местное время хоста. Часы идут и на паузе, и при пошаговом выполнении: в отличие от таймера, это время, а не тики |
| просмотр памяти | по логическим или по физическим (21 бит) адресам, кнопка «Logical / Physical». В логическом режиме окно устройств показывает текущие значения регистров без побочных эффектов (событие клавиатуры не забирается) и не редактируется. Дизассемблер и точки останова работают по логическим адресам |
| сброс и пересборка | сброс машины: процессор, устройства, регистры контроллера дисков, менеджер памяти, регистры часов; подключённые диски и ход часов остаются |

В полноэкранном режиме клавишу Esc забирает браузер, чтобы выйти из него. Программам не стоит делать Esc единственным способом выхода.

## 10. Изменения

### Ревизия 9

- **Регистр SCRD** (`$FF50–$FF51`, разд. 2.2): чтение символа и атрибута ячейки экрана в позиции; словное чтение сдвигает позицию, как запись в координатном режиме. Нужен монитору, чтобы сохранять экран сеанса. Прежние программы не меняются: адреса были свободны и читались как 0.
- **Веб-отладчик** (разд. 9.3): в фокусе консоли программе передаются и Ctrl+[, Ctrl+] (раньше — только Ctrl+Enter из сочетаний с Ctrl).

Ссылки на разделы в описании каждой ревизии даны в нумерации этой ревизии.

### Ревизия 8

- **Регистр MODS** (`$FF3C`, разд. 1, 2.2, 2.6, 4; резерв контроллера дисков — теперь `$FF3D–$FF3F`): модификаторы Shift, Ctrl и Alt события, которое последним забрала программа. Раньше модификаторы не сообщались вовсе, и Shift+стрелку нельзя было отличить от стрелки.
- **Эмуляторы** (разд. 9.2, 9.3): веб-отладчик передаёт модификаторы всех клавиш; эмулятор командной строки — из последовательностей xterm с модификаторами и из кодов консоли Windows; Ctrl+Enter даёт MODS = Ctrl.
- **Совместимость полная:** формат события и остальные регистры не меняются; адрес `$FF3C` раньше читался как 0.

### Ревизия 7

- **Ctrl+Enter** (разд. 2.6, 9.2, 9.3): раньше давала то же событие, что Enter (`$0A`, `$1C`), и программа не могла её распознать. Теперь это событие с символом 0 и сканкодом `$1C`, как у клавиш без символа. В эмуляторе командной строки Ctrl+Enter различается в консоли Windows и в терминалах, которые шлют для неё `ESC [13;5u` или `ESC [27;5;13~`; остальные терминалы Unix передают Ctrl+Enter как Enter.
- **Совместимость:** программа, читающая байт `$FF20`, Ctrl+Enter больше не видит; раньше та завершала строку как Enter. Остальные клавиши не меняются.

### Ревизия 6

Источник правок — отчёт о прототипе B (разд. 6, п. 1 и 4). Ссылки на разделы даны в нумерации этой ревизии; нумерация разделов не менялась.

- **Рецепт остановки** (разд. 3): последовательность «выключить таймер, `CLI`, `WFI`» остановку не гарантировала. Запрос IRQ0, выставленный до выключения таймера, остаётся висеть и при IF = 0 будит `WFI` снова и снова, не входя в обработчик; эмулятор при этом не завершается. Теперь рецепт такой: выключить таймер, `STI` / `CLI` (обработчик принимает висящий запрос), затем `WFI`. Обновлены список правил и пример.
- **Ожидание IRQ1 при IF = 0** (разд. 6.6): к примеру ожидания, который завершается `STI` и рассчитан на код при IF = 1, добавлен второй пример для кода при IF = 0. Цикл проверяет флаг, затем `WFI` / `STI` / `CLI`, завершающего `STI` нет, IF после ожидания остаётся равным 0.
- **Упоминания «Введения»:** в самом документе рецепт остановки приведён только в разд. 3; запись ревизии 1 о «стандартной остановке во «Введении»» сохранена как историческая и снабжена ссылкой на это уточнение. Текст «Введения» (справочник B16, разд. 9.2, и формат исполняемых файлов) в этот файл не входит: в справочнике B16 `__halt` уже описан по новому рецепту (`STI`, затем `CLI`, затем `WFI`), в формате исполняемых файлов (разд. 8.3) рецепт упомянут в прежней форме и требует отдельной правки.
- **Совместимость:** поведение машины и эмуляторов не меняется, правятся только рекомендации. Программы, остановка которых строилась по прежнему рецепту, продолжают работать, если у них не было висящего запроса IRQ0; при его наличии они не останавливались и раньше.

### Ревизия 5

- **Часы реального времени** (разд. 8) — новое устройство по адресам `$FF2A–$FF2E`.
  - Значение — метка времени ФС16: слово TIME (12-часовое время с точностью до секунды) и слово DATE (год 2025–2088, месяц, день, PM).
  - Обмен через регистры TIME и DATE и регистр команд: READ копирует значение часов в регистры, WRITE, WRITE_TIME и WRITE_DATE устанавливают часы целиком, только время суток или только дату.
  - Недопустимое значение не устанавливается: часы сохраняют прежнее значение и идут дальше, в STATUS ставится ERR.
  - Начальное значение не определено, но всегда допустимо. Часы идут по кругу: за 2088 годом следует 2025. Сброс машины часы не меняет.
- **Карта памяти** (разд. 1): адреса `$FF2A–$FF2E` заняты часами, свободными остаются `$FF2F` и `$FF50–$FFFF`; добавлены словные обращения к часам.
- **Сводка регистров** (разд. 4) дополнена регистрами часов.
- **Эмуляторы** (разд. 9): начальное значение часов — местное время хоста, ход равномерный; ключ `--rtc` эмулятора командной строки; раздел «Clock» веб-отладчика.
- **Нумерация разделов:** «Эмуляторы» стали разделом 9 (подразделы 9.1–9.3), «Изменения» — разделом 10. Разделы 1–7 сохранили номера.
- **Совместимость:** программы ревизии 4 работают без изменений. Адреса `$FF2A–$FF2E` в ревизии 4 были свободны, и программы не должны были к ним обращаться.

### Ревизия 4

- **Окно устройств** (разд. 1, 7.5): весь диапазон `$FF20–$FFFF` принадлежит устройствам, есть там устройство или нет. Свободный адрес окна читается как 0, запись в него игнорируется; памяти по таким адресам нет ни при каком отображении. В ревизии 3 разд. 1 говорил, что зарезервированные адреса в эмуляторах ведут себя как обычная память, а разд. 7.5 — что окно в память не попадает; ревизия 4 устраняет это противоречие.
- **Карта памяти** (разд. 1): границы занятых регистров уточнены — контроллер дисков `$FF30–$FF3B`, менеджер памяти `$FF40–$FF48`; остальные адреса их диапазонов зарезервированы за ними. Описаны словные обращения, захватывающие свободный адрес.
- **Контроллер дисков** (разд. 6.1–6.4): порядок проверок команды — BADCMD, NODISK, (COUNT = 0 — успех), READONLY, RANGE, BADADDR; суммы в проверках вычисляются без переполнения. Запись в CTRL действует и при BUSY = 1, ACK при BUSY = 1 игнорируется. Уточнены место сбоя при ошибке IO, время жизни ERR и ERROR и заполнение метки в блоке INFO.
- **Менеджер памяти** (разд. 7.2, 7.5, 7.6): свободные адреса `$FF49–$FF4F` читаются как 0; физические адреса `$0FF20–$0FFFF` при EN = 0 недоступны.
- **Эмуляторы** (разд. 8): новый разд. 8.1 собирает общие для обоих эмуляторов решения — нули в памяти при запуске, PAGE = 0 после сброса, словные обращения к окну, опрос устройств, метку диска. В эмуляторе командной строки: полное условие завершения, размер и адрес загрузки образа, ключи, ошибки ключа `--disk`, ввод в консоли Windows (Enter — `$0A`). В веб-отладчике: 1 мс на сектор по умолчанию вместо 0, поведение на паузе, «Running (WFI, disk)», вкладка «Disks» и раздел «Memory manager», просмотр окна устройств, сброс.
- **Нумерация разделов:** в разделе 8 подразделы «Эмулятор командной строки» и «Веб-отладчик» стали 8.2 и 8.3. Остальные разделы сохранили номера.
- **Совместимость:** программы ревизии 3 работают без изменений, если не обращаются к зарезервированным адресам, а этого им и раньше делать не полагалось.

### Ревизия 3

- **Менеджер памяти** (разд. 7) — новое устройство по адресам `$FF40–$FF4F`.
  - Логическое пространство делится на 8 страниц по 8 КБ, каждая отображается на один из 256 кадров физической памяти (всего 2 МБ).
  - Регистры PAGE0..PAGE7 и MMU_CTRL. После сброса менеджер выключен, значения PAGE не определены; программа, включающая менеджер, обязана заполнить их все.
  - Окно устройств `$FF20–$FFFF` не преобразуется. Таблица векторов преобразуется через PAGE7.
  - Изменение отображения для выборки команд подчиняется точке синхронизации (спецификация процессора, разд. 11).
- **Карта памяти** (разд. 1): адреса раздела логические; описано физическое пространство; адреса `$FF40–$FF4F` заняты менеджером, резервными остаются `$FF2A–$FF2F` и `$FF50–$FFFF`.
- **Контроллер дисков** (разд. 6.2): адрес буфера логический и при включённом менеджере преобразуется через него; пока команда выполняется, отображение страниц буфера менять нельзя.
- **Сводка регистров** (разд. 4) дополнена регистрами менеджера.
- **Эмуляторы** (разд. 8): 2 МБ ОЗУ, панель менеджера в веб-отладчике.
- **Нумерация разделов:** «Эмуляторы» стали разделом 8, «Изменения» — разделом 9. Разделы 1–6 сохранили номера.
- **Совместимость:** программы ревизии 2 работают без изменений. После сброса менеджер выключен, и машина ведёт себя как в ревизии 2. Адреса `$FF40–$FF4F` в ревизии 2 были зарезервированы.

### Ревизия 2

- **Контроллер дисков** (разд. 6) — новое устройство по адресам `$FF30–$FF3F`.
  - До 8 дисков, сектор 512 байт, номер сектора 32-битный (до 2^32 секторов). Диски не более 2^16 секторов называются маленькими.
  - Обмен идёт через DMA. Команды: ACK, READ, WRITE, INFO, FLUSH. Коды ошибок — в регистре ERROR.
  - Регистры LBA, ADDR и COUNT продвигаются по ходу обмена.
  - Завершение команды отмечается флагом DONE и может выставлять запрос IRQ1 (по уровню, снимается командой ACK).
- **Карта памяти** (разд. 1): адреса `$FF30–$FF3F` заняты контроллером дисков, резервными остаются `$FF2A–$FF2F` и `$FF40–$FFFF`.
- **Словное обращение к устройствам** (разд. 1) описано общим правилом: слово по чётному адресу A — одно обращение к паре регистров A и A + 1. Для консоли ничего не изменилось: по-прежнему допустимо только чтение слова по `$FF20`. Для регистров контроллера дисков допустимы чтение и запись слова.
- **Завершение программы** (разд. 3): эмулятор не завершает работу на `WFI`, пока выполняется команда диска, которая выставит IRQ1 (BUSY = 1 при IEN = 1).
- **Сводка регистров** (разд. 4) дополнена регистрами контроллера дисков.
- **Эмуляторы:**
  - в эмуляторе командной строки появился ключ `--disk N=файл[:ro]`;
  - в веб-отладчике появилась панель дисков.
- **Нумерация разделов:** «Эмуляторы» стали разделом 7, «Изменения» — разделом 8. Разделы 1–5 сохранили номера, поэтому внешние ссылки на них (например, на кодировку, разд. 5) остаются верными.
- **Совместимость:** программы ревизии 1 работают без изменений. Адреса `$FF30–$FF3F` в ревизии 1 были зарезервированы, и программы не должны были их использовать.

### Ревизия 1

Изменения относительно прежнего поведения машины (консоль на порту `$FF20` без других устройств):

- **Порт `$FF20`:** запись и чтение байта работают как раньше. Добавлены чтение слова (символ и сканкод) и регистры `$FF21–$FF29`.
- **Таймер** — новое устройство, по умолчанию выключен, существующих программ не касается.
- **Ассемблер** перекодирует строковые литералы в кодировку машины. Раньше байты копировались как есть (UTF-8). Программы со строками только на ASCII не меняются.
