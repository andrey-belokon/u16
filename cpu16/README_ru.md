# CPU16

Минималистичный 16-битный процессор с микропрограммной реализацией в виду. В проект входят:
- описание архитектуры (ревизия 6), машины и языка ассемблера;
- эмулятор и ассемблер на C++;
- веб-отладчик;
- стандартная библиотека и примеры программ.

## С чего начать

1. Прочитайте `docs/cpu16_intro_ru.md`. Подробности ищите в спецификации и справочнике ассемблера.
2. Откройте веб-отладчик `../webdbg/cpu16_debugger.html` в браузере (он лежит на верхнем уровне проекта, в каталоге `webdbg/`). Демо-программа уже собрана: F9 — выполнить, F7 — шаг. Пример из `examples/` можно вставить на вкладку «Source» и собрать по Ctrl+B.

## Описание машины

Документ «Машина CPU16: память и устройства» (`cpu16_machine_ru.md`) ведётся в проекте и в архив не входит, чтобы не расходиться с актуальной версией.

Эмуляторы и отладчик в этом архиве реализуют его ревизию 5:
- 2 МБ физической памяти и менеджер памяти: 8 страниц по 8 КБ, регистры `$FF40–$FF48`; после сброса менеджер выключен, PAGE0..PAGE7 = 0;
- консоль, дисплей и клавиатура на портах `$FF20–$FF28`, таймер `$FF29` (IRQ0);
- часы реального времени `$FF2A–$FF2E`: значение в формате метки времени ФС16, обмен через регистры TIME и DATE и команды READ, WRITE, WRITE_TIME, WRITE_DATE;
- контроллер дисков `$FF30–$FF3B`: до 8 дисков по 512 байт в секторе, DMA, IRQ1 по уровню;
- кодировка.

Окно устройств `$FF20–$FFFF` выбирается по логическому адресу до преобразования и целиком принадлежит устройствам: адрес, где нет устройства, читается как 0, запись в него игнорируется. Таблица векторов `$FF00–$FF1F` — обычная память.

Решения, которые спецификация оставляет эмуляторам (в ревизии 5 они записаны в разд. 9 документа):
- **Порядок проверок команды диска:** BADCMD → NODISK → (COUNT = 0 — успех) → READONLY → RANGE → BADADDR.
- **Время команд:** в эмуляторе командной строки команда выполняется целиком при записи в CMD; в отладчике — 1 мс на сектор (INFO и FLUSH — 1 мс целиком), настраивается на вкладке «Disks», на паузе и при пошаговом выполнении обмен стоит.
- **Часы:** начальное значение — местное время хоста (вне 2025–2088 — 1 января 2025 года 0:00:00), секунды машины меняются вместе с секундами хоста; ход — по монотонным часам хоста, перевод часов хоста на машину не влияет; сброс машины обнуляет регистры TIME, DATE и ERR, а часы идут дальше.
- **Образ программы** — не больше 64 КБ; он загружается по адресу `-l` (по умолчанию 0), который после сброса и логический, и физический.

## Сборка

Нужны `g++` с поддержкой C++17 и Python 3. Для тестов — Node.js, для сценариев интерфейса — Playwright с Chromium.

```
make                    # build/cpu16, build/cpu16asm и ../webdbg/cpu16_debugger.html
make examples           # все примеры -> build/examples/*.bin
```

Без `make`:

```
g++ -std=c++17 -O2 -o cpu16 tools/cpu16.cpp
g++ -std=c++17 -O2 -o cpu16asm tools/cpu16asm.cpp
python3 ../webdbg/build.py
```

## Запуск

```
build/cpu16asm examples/snake.asm -o snake.bin -l snake.lst -m snake.map
build/cpu16 snake.bin
```

- **Карта памяти.** `-m файл.map` пишет размещение всех объектов образа: адрес, размер, тип (code, data, bss, выравнивание), место в исходнике, сводку по видам памяти и по файлам, список объектов по размеру и константы (формат — «Справочник ассемблера», разд. 17.4). По ней удобно следить за бюджетом памяти и находить объект по адресу из трассировки.
- **Место в исходнике компилятора.** Директива `.line "файл", N` (или `.line N` в том же файле) задаёт место всех следующих строк ассемблерного текста до следующей `.line`: сообщения об ошибках, карта памяти и столбец листинга указывают на исходную программу (например, B16). В сообщениях указана и строка ассемблерного текста: `kernel.b16:120 (kernel.asm:345): error: ...`; ключ `--no-line` отключает `.line` совсем. Ключи `cpu16asm`, форматы листинга, карты и сообщений собраны в «Справочнике ассемблера», разд. 17.
- **Вывод и ввод.** Эмулятор выводит текст консоли в stdout и читает клавиатуру из stdin. Стрелки и функциональные клавиши терминала превращаются в сканкоды, а их сочетания с Shift, Ctrl и Alt, переданные последовательностями xterm, — ещё и в модификаторы регистра MODS («Машина», разд. 2.6, 9.2).
- **Дисплей.** Изображение 80×25 видно только в веб-отладчике; ключ `--screen` печатает итоговый экран по завершении.
- **Диски:** `--disk N=файл[:ro]` подключает образ диска N (0..7), ключ можно повторять. Размер файла должен быть кратен 512; `:ro` или файл, который не открывается на запись, — защита от записи. Метка диска — имя файла. Пример — `examples/disk_demo.asm`.
- **Часы:** `--rtc ДД.ММ.ГГГГTЧЧ:ММ:СС` задаёт начальное значение вместо местного времени хоста (формат ключа задан документом «Машина CPU16», разд. 9.2; 24-часовая запись, 2025–2088). Нужен для воспроизводимых запусков. Пример — `examples/clock.asm`.
- **Завершение:** процессор в WFI, запросов нет, таймер выключен и нет команды диска, которая выставит IRQ1.
- **Другие ключи:** `-t` — трассировка, `-n N` — ограничение числа шагов, `--strict-align` — сообщения о невыровненных обращениях.

```
python3 -c "open('demo.img','wb').write(bytes(64*512))"
build/cpu16asm examples/disk_demo.asm -o disk_demo.bin
build/cpu16 --disk 0=demo.img disk_demo.bin
```

### Исполняемые файлы для монитора

Формат исполняемого файла описан в документе «Монитор CPU16: формат исполняемого файла и запуск программ» (`cpu16_exec_format_ru.md`, ревизия 2, ведётся в проекте). Программа под монитором получает управление с разрешёнными прерываниями; на голой машине, как и после сброса, IF = 0. Заголовок пишется в исходнике вручную, неинициализированные данные — директивой `.reserve` в конце программы (в файл они не попадают). Ключ ассемблера `--exec` проверяет заголовок готового образа:

```
build/cpu16asm --exec examples/calc_exec.asm -o calc_exec.bin
build/cpu16 calc_exec.bin              # файл CX16 запускается и на голой машине
```

Пример — `examples/calc_exec.asm`, заготовка для своей программы — `docs/skeleton_exec.asm`. Обе программы работают и под монитором, и на голой машине.

## Тесты

```
make test               # эмулятор, ассемблер, библиотека, «Введение», сверка отладчика с C++
make test-ui            # сценарии веб-отладчика в headless Chromium
```

Что проверяется:
- **Эмулятор:** встроенный самотест (`build/cpu16 --selftest`).
- **Ассемблер:** тесты с запуском программ в эмуляторе, `.reserve`, проверка заголовка `--exec`, запуск `calc_exec.asm` и `skeleton_exec.asm` на голой машине и с имитацией запуска монитором по ревизии 2 формата (IF = 1, векторы монитора, тик таймера между командами программы, начиная с первой).
- **Стандартная библиотека:** граничные значения и сотни случайных случаев 32-битной арифметики.
- **«Введение»:** все программы из документа собираются, запускаются и дают напечатанный там вывод.
- **«Машина CPU16»:** примеры драйвера дисков, ожидания по IRQ1, включения менеджера памяти и работы с часами выполняются в эмуляторе с образами дисков и ключом `--rtc`; ошибки запуска `--disk` и `--rtc`; `disk_demo.asm` и `clock.asm`. Фрагменты встроены в тест; `make test MACHINE_DOC=путь/к/cpu16_machine_ru.md` дополнительно сверяет их с документом.
- **Веб-отладчик:**
  - JS-движок сверяется с C++-эмулятором на случайных программах, включая все устройства, таймер, часы (с начальными значениями у границ переносов), диски (мгновенные и с задержкой) и менеджер памяти;
  - дизассемблер проверяется круговым тестом через ассемблер;
  - JS-ассемблер сверяется с C++-ассемблером побайтно на общем корпусе исходников, включая сообщения проверки заголовка.
