# BScript для CPU16: фаза 1

Язык сценариев BScript («BScript: язык сценариев для CPU16», версия 1.1, `docs/bscript_spec_ru.md`): компилятор, виртуальная машина и загрузчик сценариев. Все три программы написаны на B16 и работают под монитором CPU16.

| Программа | Назначение |
| --- | --- |
| `A:/bin/bsc.cx` | компилятор: `bsc [-l] source.bs [-o out.bsc]`, `bsc --run cache.bsc source.bs [args...]` |
| `A:/bin/bsvm.cx` | виртуальная машина: `bsvm program.bsc [script-path] [args...]`; оверлеи — в `A:/bin/bsvm.ovl` рядом |
| `A:/bin/bs.cx` | загрузчик: `bs script.bs [args...]` — компилирует при необходимости (кеш `.bsc`) и запускает |

Оболочка монитора (ревизия 4) находит сценарии `имя.bs` при поиске программы, так что `A:/bin/backup.bs` запускается командой `backup`.

## Сборка и проверка

    make            out/bsc.bin out/bsvm.bin out/bsvm.ovl out/bs.bin (нужны ../b16c/b16c и ../cpu16/build/cpu16asm)
    make test       tests/*.bs в стенде ../monitor/out/kmon: вывод сравнивается с tests/*.out
    make examples   примеры examples/*.bs с эталонами examples/expected/*.out
    make stress     проверочные сборки bsvm: сборка мусора перед каждым выделением (правило 12.3)
                    и расширенный режим сразу при ближней куче 2 КБ (дальняя память, 12.10)
    python3 tools/run_tests.py --update [имя ...]     переписать эталоны

`make system` и `make dist` в `../monitor` собирают BScript и кладут `bsc.cx`, `bsvm.cx`, `bsvm.ovl`, `bs.cx` в `/bin` системного тома.

`tools/vmrun.py` выполняет команды оболочки на временном томе со всеми инструментами:

    python3 tools/vmrun.py -f prog.bs:/t/prog.bs "bs /t/prog.bs" "bsc -l /t/prog.bs"

## Каталоги

| Каталог | Содержание |
| --- | --- |
| `common/` | `bsdefs.b16` — формат `.bsc`, коды команд, номера встроенных функций и методов; `util.b16` — пути, строки |
| `bsc/` | компилятор: лексер `lex.b16`, таблицы `sym.b16`, выражения `expr.b16`, операторы `stmt.b16`, встроенные функции `builtins.b16`, буферы в расширенной памяти `xbuf.b16`, листинг `list.b16`, главный файл `bsc.b16` |
| `vm/` | VM. Резидентная часть: типы `types.b16`, куча, сборщик и функции доступа `heap.b16`, словари `map.b16`, значения `value.b16`, потоки и файлы `io.b16`, интерпретатор `interp.b16`, команды `ops.b16`, частые встроенные функции и методы `lib.b16`, `libstr.b16`, менеджер оверлеев `ovl.b16`, загрузка `bsvm.b16`. Оверлеи: `ov_fs.b16` (fs, path), `ov_sys.b16` (proc, time, редкие методы, сообщения об ошибках), `ov_gc.b16` (редкие части дальней памяти, `fail`, `error()`), `ov_init.b16` (загрузчик), общие функции `ov_common.b16` |
| `bs/` | загрузчик сценариев |
| `examples/` | примеры сценариев и программ (`examples/README_ru.md`) с эталонами вывода |
| `tests/` | тесты: программа `.bs` и эталон `.out`; первая строка `// run: команда` задаёт запуск. `tests/inc/`, `tests/data/` — подключаемые файлы и данные |
| `bench/` | программы измерений (спецификация, 13.2) |
| `docs/` | спецификация языка версии 1.1, «Формат байт-кода BScript» |
| `tools/` | `build.sh`, `mkovl.py` (сборка оверлеев), `vmrun.py`, `run_tests.py`, `stress.sh` (`gc`, `far`, `both`), `profile.py` (профиль по функциям через `kmon --profile`) |

## Устройство

**Компилятор.** Код, константы и таблица строк — в кадрах расширенной памяти через окно на странице 6 (`bsc/xbuf.b16`). Предварительный проход собирает глобальные имена, сигнатуры функций и константы; второй — однопроходный рекурсивный спуск с генерацией кода. Описатель выражения откладывает выдачу констант и l-значений, что даёт свёртку констант и цели присваивания без дерева. Функции стоят в коде верхнего уровня на месте объявления, код верхнего уровня обходит их переходом. Компилятор держит весь модуль в памяти и пишет `.bsc` через временный файл с переименованием.

**VM.** Значения — 4 байта (разд. 12.2), объекты — в куче за таблицей handles; сборщик mark-compact с явным стеком пометки и повторным просмотром кучи при его переполнении, с правилом временных корней для встроенных функций. Вся библиотека обращается к объектам только через функции кучи (правило 12.3, `vm/heap.b16`); `make stress` проверяет это сборкой мусора перед каждым выделением. Константы модуля — статические объекты прямо в памяти модуля. Таблица строк не загружается: место ошибки ищется в файле `.bsc`, когда оно нужно. Буферы потоков и файлов закреплены, обработчик Ctrl+C записывает их и завершает процесс с `$8001`.

**Оверлеи** (разд. 12.9). Страница 6 — окно. Обычно в нём стоит кадр модуля: таблица функций, код байт-кода и кадры вызовов. Редкий и долгий код библиотеки собран по адресу окна и лежит в `bsvm.ovl`: `fs` (fs, path), `sys` (proc, time, редкие методы, сообщения об ошибках), `gc` (редкие части дальней памяти). Частые функции строк, массивов, словарей и файлов резидентны. Вызов функции оверлея ставит в окно его кадр (загружается при первом вызове), по возврату — прежний кадр; вложенные вызовы допускаются. Загрузчик — оверлей `init` на странице 5, выполняется один раз. `tools/mkovl.py` находит резидентные функции, которые вызывают оверлеи (только они попадают в образ), строит заглушки входов, объявления резидентной части для оверлеев и файл оверлеев.

**Дальняя память** (разд. 12.10). Когда ближней кучи не хватает, VM переходит в расширенный режим: страница 5 становится окном данных, новые объекты создаются в ближней куче, выжившие переносятся в кадры расширенной памяти в безопасных точках между командами; барьер записи запоминает дальние контейнеры со ссылками на ближние объекты; полная сборка сжимает кадры. Массивы и словари больше 4 КБ хранятся кусками. Предел — 1 МБ, не больше 32 512 объектов. Стек B16 перенесён за блок аргументов, чтобы страница 5 была свободна.

**Загрузчик.** Кеш годен, если версия, путь главного исходника и MTIME всех исходников совпадают; тогда `EXEC` в `bsvm`, иначе в `bsc --run`. Для каталога только для чтения кеш лежит в `A:/tmp`.

## Измерения и пределы

Подробно — спецификация, разд. 12.1, 12.9, 12.10 и 13.2.

| Величина | Значение |
| --- | --- |
| `bsvm` | резидентная часть 27,6 КБ образ, 32,3 КБ с данными; оверлеи 21,1 КБ (`fs` 5,5, `sys` 6,6, `gc` 5,6, `init` 3,3 КБ) |
| `bsc` | 31,4 КБ образ, 44 КБ ближней памяти; код, константы и таблица строк — в расширенной памяти; компиляция около 9,4 тыс. команд на строку |
| ближняя куча VM | около 11,8 КБ у небольшого сценария; около 3,6 КБ в расширенном режиме |
| дальняя память | до 1 МБ (127 кадров), не больше 32 512 объектов; строка там — до 7674 байт |
| модуль | код до 32 КБ, константы до 16 КБ (пределы `bsc`, 12.6); модуль до 8 КБ — в одном кадре, крупнее — код в нескольких кадрах; крупные константы — в кадрах |
| коллекции | массив до 32 767 элементов, словарь до 16 384 ключей |
| вложенность в `bsc` | 24 уровня выражений, 32 блока |
| вызовы | 100 кадров, стек значений 384 |
| файлы | 8 открытых файлов программы, буфер 192 байта |
| скорость | около 59 команд CPU16 на команду байт-кода; вызов функции оверлея — около 100 команд сверху (быстрый путь `XMAP` в мониторе), в примерах это меньше 0,5 % времени; расширенный режим медленнее обычного примерно в 1,6 раза при работе с объектами в разных кадрах |
