## 1. Назначение и статус

BScript — небольшой динамический язык для сценариев, которые запускаются из оболочки монитора CPU16: перебор файлов, обработка текстов, запуск программ и разбор их результатов. Программа компилируется в байт-код и выполняется виртуальной машиной. Все три инструмента написаны на B16 и работают на самой машине CPU16.

**Статус.** Нормативное описание фазы 1, версия языка 1.1. Каждое утверждение документа проверяется набором тестов `tests/*.bs` и примерами `examples/*.bs`. Расхождение документа и реализации считается ошибкой одного из них и исправляется в обоих.

**Совместимость.** Будущие версии языка обязаны компилировать и выполнять программы этой версии без изменений, а их виртуальная машина — выполнять байт-код формата 1.

**Нормативные слова.** «Ошибка компиляции» — `bsc` отвергает программу (11.2). «Ошибка выполнения» — `bsvm` останавливает программу с кодом 125 (6.5). «Завершается ошибкой» — вызов возвращает значение `error`, которое можно перехватить (6.4).

### 1.2. Обзор языка

- значения: `null`, `bool`, `int` (16 бит со знаком), строки, массивы, словари, файлы, ошибки;
- функции с несколькими результатами, необязательные аннотации типов с проверкой при выполнении;
- ошибки как значения `error`, которые поднимаются по вызовам сами и перехватываются лишней переменной слева;

- интерполяция строк, `include`;
- библиотека: строки, массивы, словари, текстовые файлы, пути, запуск программ с перенаправлением и захватом вывода.

## 2. Лексическая структура

### 2.1. Исходный текст

Исходный текст — последовательность байтов в кодировке машины CPU16. Пробельные символы — пробел, табуляция и возврат каретки (CR); перевод строки (LF) имеет особый смысл (2.3). Пары CR LF допустимы.

Комментарии, как в B16:

- `// ...` — до конца строки;
- `/* ... */` — блочный, не вкладывается. Переводы строк внутри блочного комментария не завершают оператор.

Текст разбивается на лексемы слева направо, каждый раз выбирается самая длинная возможная лексема. Исключение — конец подстановки `|}` в интерполированной строке (2.8).

### 2.2. Идентификаторы и зарезервированные имена

```
IDENT = буква { буква | цифра } .
буква = "A"…"Z" | "a"…"z" | "_" .
цифра = "0"…"9" .
```

Регистр букв значим. Длина идентификатора — до 62 символов, иначе ошибка компиляции `name too long`. Имена, начинающиеся с `__`, зарезервированы реализацией. Имя `_` означает «отбросить значение» и допустимо только как цель множественного присваивания (5.3).

**Ключевые слова:**

```
break    case     const    continue default  else     fail     false
fn       for      if       in       include  loop     null     return
switch   true     var      while
```

**Зарезервированные имена** нельзя объявлять как переменную, константу или функцию (ошибка `reserved name: имя`):

- `enum`, `record`, `static`, `defer` — оставлены для будущих версий;
- имена пространств библиотеки: `io`, `fs`, `path`, `proc`, `str`, `time`, `errors`. Имя `str` одновременно — глобальная функция `str(x)`: `str.` начинает обращение к пространству, `str(` — вызов функции;
- `args` — предопределённая глобальная переменная (3.2);
- имена глобальных встроенных функций (9.1).

**Имена типов** (`int`, `bool`, `string`, `array`, `map`, `file`, `error`, `value`) — обычные идентификаторы, которые имеют смысл только в аннотации типа (4.3). Объявлять переменные с такими именами не запрещено, но не рекомендуется; `error` при этом остаётся встроенной функцией и объявлен быть не может.

### 2.3. Конец оператора

Правило совпадает с B16 (разд. 2.3) с поправкой на набор лексем BScript. Перевод строки становится лексемой `EOS` (конец оператора), если последняя лексема строки — одна из:

- идентификатор, число, символьный литерал, строка или интерполированная строка;
- `true`, `false`, `null`;
- `)`, `]` или `}`;
- `++` или `--`;
- `break`, `continue` или `return`.

Исключения:

- если первая непустая лексема после перевода строки (пропуская пустые строки и комментарии `//`) — `else`, `EOS` не вставляется;
- внутри круглых `( )` и квадратных `[ ]` скобок `EOS` не вставляется;
- внутри словарного литерала `{ ... }` синтаксический анализатор пропускает `EOS` между элементами.

Конец файла после такой лексемы тоже даёт `EOS`. Точка с запятой `;` всегда означает `EOS`; несколько `EOS` подряд допустимы. Перед закрывающей `}` блока `EOS` не обязателен: `if bad { return 1 }` — верная запись.

Следствие: выражение переносится только после знака операции, запятой или открывающей скобки.

### 2.4. Числа

```
NUMBER = десятичное
       | "$" шестн { шестн }
       | ("0x" | "0X") шестн { шестн }
       | ("0b" | "0B") двоичн { двоичн } .
```

- **Десятичное число** — от 0 до 32767. Число 32768 допустимо только как операнд унарного минуса: `-32768`. Иначе — ошибка компиляции `number too large`.
- **Шестнадцатеричное и двоичное число** — от 0 до `$FFFF`; оно задаёт 16-битный образ значения `int`: `$FFFF` равно −1, `$8000` равно −32768.
- Сразу за числом не может стоять буква, цифра другой системы или `_`.

Отрицательных литералов нет: `-1` — унарный минус, применённый к литералу (константное выражение).

### 2.5. Символьные литералы

Символьный литерал — один символ или escape-последовательность в апострофах: `'A'`, `'\n'`, `'Ж'`. Его значение — код символа в кодировке машины, тип `int` (0…255). Пустой литерал `''` и литерал из нескольких символов — ошибка компиляции.

Символьный литерал нужен, когда сравнивают байты: `s[i] == ','` — сравнение двух `int`. Запись `s[i] == ","` сравнивает число со строкой и всегда даёт `false` (4.4).

### 2.6. Escape-последовательности

Одинаковы для символьных литералов, строк и интерполированных строк:

| Последовательность | Код |
| --- | --- |
| `\n` | 10 |
| `\r` | 13 |
| `\t` | 9 |
| `\e` | 27 |
| `\0` | 0 |
| `\\`, `\'`, `\"`, `` \` ``, `\{` | символ после `\` |
| `\xH`, `\xHH` | байт с этим шестнадцатеричным кодом |

Другие последовательности после `\` — ошибка компиляции.

### 2.7. Строки

Строка — символы и escape-последовательности в двойных кавычках `"..."` или в обратных апострофах `` `...` ``. Обе записи дают одинаковые строки. Внутри обратных апострофов двойные кавычки и апострофы пишутся без экранирования, внутри двойных кавычек — апострофы и обратные апострофы:

```text
var a = `строка "без" экранирования`
var b = "it's ok"
```

Перевод строки внутри строки — ошибка компиляции. Строковый литерал — до 512 байт (`string too long`). Строка может содержать любые байты, включая 0: длина хранится явно. Строки неизменяемы.

Длинный текст собирается конкатенацией с переносом после `+`; конкатенация литералов вычисляется при компиляции (до 1024 байт):

```text
var help = "usage: tool [-v] file\n" +
           "  -v  verbose\n"
```

### 2.8. Интерполированные строки

Интерполированная строка начинается с `$"` или `` $` `` и содержит подстановки `{|выражение|}`. Кавычки работают так же, как у обычных строк:

```text
println($"{|name|}: {|count|} lines")
```

- Значение каждой подстановки преобразуется в текст, как `str(x)` (9.1).
- Внутри подстановки допустимо любое выражение, кроме другой интерполированной строки. Обычные строки внутри подстановки допустимы: `{|m["key"]|}`.
- Подстановка не может содержать перевод строки. Пустая подстановка `{||}` — ошибка `empty substitution`; подстановок в одной строке — не больше 255.
- **Конец подстановки.** В начале каждой лексемы внутри подстановки, вне скобок и строк, лексер сначала проверяет пару символов `|}`. Если она есть, подстановка закончена. Поэтому `{|a || b|}` — это `a || b`, а `{|flags | 1|}` — это `flags | 1`.
- Чтобы получить в тексте `{|` буквально, пишут `\{|`. Пара `|}` вне подстановки — обычный текст.

Интерполированная строка компилируется в одну конкатенацию и создаёт одну новую строку. Разделитель `{|...|}` выбран, чтобы фигурные скобки в тексте (например, JSON) не требовали экранирования: `` $`{"name": "{|name|}"}` `` — правильная строка.

### 2.9. Знаки операций и разделители

```
+   -   *   /   %   &   |   ^   ~   !   <<  >>  >>>
==  !=  <   >   <=  >=  &&  ||  ??  ++  --
=   +=  -=  *=  /=  %=  &=  |=  ^=  <<= >>= >>>=
(   )   [   ]   {   }   ,   ;   :   .
```

Любой другой символ вне комментария, строки и символьного литерала — ошибка компиляции.

## 3. Структура программы

### 3.1. Два вида программы

Программа — главный файл и файлы, подключённые `include`. На верхнем уровне файла стоят директивы `include`, объявления (`const`, `var`, `fn`) и, в сценарии, операторы.

**Программа с `main`.** Если в программе объявлена функция `main`, на верхнем уровне допустимы только объявления и `include`; оператор там — ошибка компиляции `statements are not allowed at top level of a program with main`. Выполнение:

1. инициализаторы глобальных переменных выполняются в порядке текста (с учётом порядка подключения файлов);
2. вызывается `main`.

`main` объявляется одним из способов, другая сигнатура — ошибка `invalid signature of main`:

```text
fn main() { ... }
fn main(): int { ... }
fn main(args: array) { ... }
fn main(args: array): int { ... }
```

Результат `main` — код завершения процесса (0…32767). Без результата или при значении `null` код — 0.

**Сценарий.** Если функции `main` нет, операторы верхнего уровня всех файлов выполняются по порядку вместе с инициализаторами глобальных переменных. `return` на верхнем уровне завершает сценарий; его единственное значение — код завершения. `return` без значения и конец текста дают код 0.

### 3.2. Аргументы

Глобальная переменная `args` объявлена в обоих видах программы: массив строк с аргументами командной строки, без имени программы и без пути сценария. Параметр `args` функции `main` — тот же массив. Путь сценария, как его передали загрузчику, сообщает `proc.script()` (10.7).

### 3.3. Глобальные и локальные имена

- Глобальные переменные, константы и функции образуют одно пространство имён. Повторное объявление — ошибка компиляции.
- **Функции** видят все глобальные имена программы независимо от порядка текста: компилятор собирает объявления предварительным проходом. Функцию можно вызвать до её объявления.
- **Код верхнего уровня** сценария может обращаться к глобальной переменной или константе только после её объявления по тексту; иначе — ошибка `used before declaration: имя`.
- Глобальная переменная, к которой функция обратилась до выполнения её инициализатора, равна `null`.
- `var` внутри блока на верхнем уровне сценария (например, в теле `if`) объявляет локальную переменную этого блока, а не глобальную.
- Функции объявляются только на верхнем уровне (`functions can be declared only at top level`).

### 3.4. `include`

```text
include "lib/strings.bs"
```

- Директива стоит в начале файла, до первого объявления или оператора (`include must come before declarations and statements`).
- Путь — относительно каталога файла с директивой, если он не абсолютный (с томом `X:` — буква `A`–`H` или цифра `0`–`7` — или начальным `/`).
- **Повторное подключение** того же файла пропускается. Файлы сравниваются по нормализованному абсолютному пути без учёта регистра (как `path.equal`, 10.6), поэтому циклическое подключение безвредно.
- Подключение текстовое: имена подключённого файла попадают в общее пространство программы.
- Глубина вложенности `include` — не больше 8, общее число файлов программы — не больше 32.

## 4. Значения и типы

### 4.1. Типы значений

| Тип | `type(x)` | Описание |
| --- | --- | --- |
| null | `"null"` | отсутствие значения |
| bool | `"bool"` | `true`, `false` |
| int | `"int"` | целое со знаком, 16 бит: −32768…32767 |
| string | `"string"` | неизменяемая последовательность байтов |
| array | `"array"` | изменяемый массив значений |
| map | `"map"` | изменяемый словарь со строковыми ключами |
| file | `"file"` | открытый текстовый файл (10.5) |
| error | `"error"` | ошибка: код, текст, объект (6.2) |

Строки, массивы, словари, файлы и ошибки — объекты кучи. Переменная хранит ссылку на объект: присваивание и передача в функцию не копируют объект. Копию делает `clone()`. Память освобождается сборщиком мусора; программа её явно не освобождает.

Длина строки и число элементов массива — не больше 32767, ключей словаря — не больше 16 384. Превышение — ошибка выполнения `too large` (у функций, которые читают данные извне, — ошибка `errors.TOOBIG`, 6.6).

### 4.2. Целые числа

- Сложение, вычитание и умножение выполняются по модулю 2^16; переполнение не обнаруживается.
- `/` округляет к нулю; `%` имеет знак делимого: `a == (a / b) * b + a % b`.
- Деление и остаток на 0 — ошибка выполнения. `-32768 / -1` равно −32768, `-32768 % -1` равно 0.
- `~`, `&`, `|`, `^` работают с 16-битным образом.
- `a << n` — сдвиг влево; `a >> n` — арифметический сдвиг вправо; `a >>> n` — логический сдвиг вправо. При n ≥ 16 результат `<<` и `>>>` равен 0, а `>>` — 0 или −1 по знаку a. Отрицательное n — ошибка выполнения.
- Сравнения `<`, `<=`, `>`, `>=` — знаковые. Беззнаковый образ выводит `str.hex(n, w)` (10.2).

### 4.3. Аннотации типов

Аннотации необязательны у переменных и параметров и обязательны у результатов функций (5.1).

```text
var name: string = "x"
fn count(lines: array, mark: string): int { ... }
```

Допустимые имена: `int`, `bool`, `string`, `array`, `map`, `file`, `error` и `value` (любой тип); другое имя — ошибка `type name expected`.

Аннотация проверяется при выполнении: при присваивании переменной, при входе в функцию для параметров и при возврате для результатов. Несовпадение — ошибка выполнения `type mismatch: T expected, got U`. Значение `null` допустимо для любой аннотации.

### 4.4. Равенство и порядок

- `a == b` истинно, если у значений один тип и:
    - для `int`, `bool` — одно значение;
    - для строк — одинаковые байты;
    - для массивов, словарей и файлов — один и тот же объект;
    - для ошибок — один код (6.2);
    - `null == null` истинно.
- Значения разных типов **не равны**, ошибки нет. Поэтому `x == null` и `cfg["port"] == 80` безопасны для любого `x`.
- `<`, `<=`, `>`, `>=` допустимы для двух `int` (знаковое сравнение) и для двух строк (побайтово: байты как числа 0…255, более короткий префикс меньше). Иначе — ошибка выполнения.

### 4.5. Логические значения

Условия `if` и `while`, операнды `&&`, `||` и `!` должны быть `bool`. Неявного приведения нет: `if count { }` — ошибка выполнения `bool expected, got int`; нужно `if count != 0 { }`.

## 5. Объявления и функции

### 5.1. Функции

```text
fn name(p1: T1, p2, ...): R1, R2 {
    ...
}
```

- Параметров — не больше 16, результатов — не больше 8. Ошибка в число результатов не входит (6.4).
- Типы результатов обязательны: по ним компилятор знает число результатов. Тип `value` — любой.
- Число аргументов проверяется при компиляции (`wrong number of arguments for имя`). Необязательных параметров и переменного числа аргументов у функций программы нет; у встроенных функций — есть (разд. 9–10).
- Вложенных функций и функций как значений нет: имя функции без вызова — ошибка `functions are not values: имя`.
- Рекурсия допустима; глубина — до 100 вызовов, дальше ошибка выполнения `stack overflow` (разд. 12).

**Завершение функции.** Функция с результатами должна завершаться оператором `return` или `fail`. Компилятор проверяет, что конец тела недостижим: тело оканчивается оператором, который «завершает выполнение»:

- `return` или `fail`;
- `if` с `else`, в котором обе ветки завершают выполнение;
- `loop` без относящегося к нему `break`;
- `switch` с `default`, в котором все ветки завершают выполнение.

Иначе — ошибка компиляции `missing return in function имя`. Проверка относится только к объявленным функциям: код верхнего уровня сценария может закончиться без `return`.

### 5.2. Переменные и константы

```text
var count = 0
var name: string
var a, b = split_pair(s)
const LIMIT = 100
const GREETING = "hello"
```

- `var` без инициализатора даёт `null`.
- Область видимости локальной переменной — от объявления до конца блока. Повторное объявление в том же блоке — ошибка; во вложенном блоке допустимо и скрывает внешнее.
- `const` задаёт имя для константного выражения: литералов, других констант, арифметических и битовых операций над `int` и `+` над строками; другое — ошибка `constant expression expected`. Константы допустимы на верхнем уровне и в блоках.

### 5.3. Несколько результатов

```text
fn divmod(a: int, b: int): int, int {
    return a / b, a % b
}

var q, r = divmod(17, 5)
q, r = divmod(20, 3)
var _, rest = divmod(9, 4)
```

- Справа от множественного объявления или присваивания стоит ровно один вызов функции. Число целей равно числу результатов или на одну больше: лишняя последняя цель перехватывает ошибку вызова (6.4). Обмен `a, b = b, a` не поддерживается.
- Целью может быть переменная, элемент `a[i]`, `m[k]` или `_`. Целей — не больше 9.
- `return f()` допустим, если число результатов `f` равно числу результатов текущей функции. `return x, f()` при многозначной `f` — ошибка.
- Вызов многозначной функции там, где нужно одно значение, — ошибка `function returns several results`; функции без результата — `function has no result`.
- Вызов как оператор отбрасывает все результаты; ошибка вызова при этом поднимается дальше (6.4).

## 6. Ошибки

### 6.1. Два вида ошибок

**Ожидаемые ошибки** — отсутствие файла, нет места на томе, неверное число в тексте, ошибка, о которой сообщила сама программа. Это значения типа `error`. Они возникают в функциях библиотеки или по оператору `fail`, поднимаются по цепочке вызовов и могут быть перехвачены (6.4).

**Ошибки выполнения** — ошибки самой программы: неверный тип операнда, выход индекса за границы, деление на ноль. Они не перехватываются и останавливают программу (6.5).

### 6.2. Значение `error`

Значение `error` неизменяемо:

| Метод | Описание |
| --- | --- |
| `e.code() → int` | код: коды монитора, коды BScript или коды программы (6.6) |
| `e.text() → string` | текст ошибки: `"no such file or directory"` |
| `e.object() → string` | объект ошибки — обычно путь — или `null` |
| `e.where() → string` | место возникновения `файл:строка` или `null` у констант `errors.*` |

- `str(e)` — `объект: текст`, а без объекта — `текст`.
- **Равенство** ошибок — по коду: `err == errors.NOENT` истинно для любой ошибки «нет файла», с любым объектом.
- `error(text[, object[, code]]) → error` создаёт значение без возбуждения. Код по умолчанию — 100 (`errors.FAIL`).

### 6.3. Оператор `fail`

`fail` завершает текущую функцию ошибкой; в смысле 5.1 он завершает выполнение, как `return`.

| Запись | Возбуждаемая ошибка |
| --- | --- |
| `fail text` | `error(text)`: код `errors.FAIL`, без объекта |
| `fail text, object` | `error(text, object)` |
| `fail text, object, code` | `error(text, object, code)` |
| `fail e` | значение `e` типа `error` как есть |
| `fail e, object` | копия `e` с другим объектом: `fail errors.NOENT, name` |

- Первый операнд — строка или `error`, иначе ошибка выполнения. `object` — строка или `null`, `code` — `int`.
- `fail` записывает в ошибку место `файл:строка`, если его ещё нет. При `fail e` место не меняется.
- Коды 1…999 зарезервированы монитором и BScript. Программы задают свои коды от 1000.

### 6.4. Распространение и перехват

Любой вызов — функции программы, встроенной функции, метода, функции пространства — может завершиться ошибкой.

**Перехват.** Если вызов стоит справа от объявления или присваивания и целей на одну больше, чем результатов, последняя цель получает ошибку или `null` при успехе. При ошибке остальные цели получают `null`.

```text
var text, err = fs.read_text(name)     // 1 результат + ошибка
var err2 = fs.remove(tmp)              // 0 результатов + ошибка
var code, out, perr = proc.capture("ls", [])
var t, _ = fs.read_text(name)          // ошибка отброшена явно
```

Перехват возможен только у вызова, стоящего справа целиком; вызов внутри выражения (`fs.read_text(p).lines()`) не перехватывается.

**Распространение.** Неперехваченная ошибка завершает текущую функцию той же ошибкой, без результатов. Так ошибка поднимается до вызова, который её перехватывает, или до верхнего уровня.

**Верхний уровень.** Ошибка, дошедшая до верхнего уровня сценария или вышедшая из `main`, выводится в поток 2 как `имя: объект: текст` (`имя` — `proc.name()`), буферы записываются, программа завершается с кодом 1. Это формат сообщений утилит оболочки: сценарий без единой проверки ведёт себя как правильная утилита.

**Ресурсы.** Открытые файлы функций, через которые прошла ошибка, остаются открытыми до сборки мусора или завершения программы (10.5).

```text
fn load_config(name: string): map {
    var cfg = {}
    for line in fs.read_text(name).lines() {   // ошибка чтения уходит вызывающему
        var i = line.find("=")
        if i < 0 {
            fail $`bad line "{|line|}"`, name
        }
        cfg[line.slice(0, i).trim()] = line.slice(i + 1).trim()
    }
    return cfg
}

var cfg, err = load_config("app.cfg")
if err == errors.NOENT {
    cfg = {}                                  // нет файла — настройки по умолчанию
} else if err != null {
    fail err
}
```

### 6.5. Ошибки выполнения

Ошибка выполнения выводит в поток 2

```text
bsvm: файл:строка: in function имя: текст
```

для кода верхнего уровня — без части `in function имя: `. Файл — абсолютный путь исходника. Затем записываются буферы открытых файлов, процесс завершается с кодом 125. Ошибки выполнения — в том числе `assert` (9.1), `out of memory` и `stack overflow`.

## 7. Выражения

### 7.1. Приоритет

Порядок совпадает с B16 (разд. 6.1) с добавлением `in`, `??` и `>>>`.

| Уровень | Операции | Ассоциативность |
| --- | --- | --- |
| 1 (высший) | `f(...)` `a[i]` `x.m(...)` `ns.f(...)` | слева направо |
| 2 | унарные `-` `+` `~` `!` | справа налево |
| 3 | `*` `/` `%` | слева направо |
| 4 | `+` `-` | слева направо |
| 5 | `<<` `>>` `>>>` | слева направо |
| 6 | `&` | слева направо |
| 7 | `^` | слева направо |
| 8 | `\|` | слева направо |
| 9 | `==` `!=` `<` `>` `<=` `>=` `in` | неассоциативны |
| 10 | `&&` | слева направо |
| 11 | `\|\|` | слева направо |
| 12 (низший) | `??` | справа налево |

Битовые операции связывают сильнее сравнений: `x & M == 0` означает `(x & M) == 0`. Цепочка сравнений `a < b < c` — ошибка `comparisons cannot be chained`. Присваивание — оператор, а не выражение. Вложенность выражений (скобки, аргументы, литералы) — до 24 уровней.

### 7.2. Операции

- **Арифметические и битовые** — над двумя `int` (4.2). Иначе — ошибка выполнения, кроме `+` для двух строк.
- **`+` для строк** — новая строка из байтов левой и правой. `"a" + 1` — ошибка выполнения: число преобразуется явно, `str(n)`, или через интерполяцию.
- **`&&`, `||`** вычисляются по короткой схеме; операнды — `bool`.
- **`a in b`:**
    - `b` — массив: есть ли элемент, равный `a` (4.4);
    - `b` — словарь: есть ли ключ `a` (`a` — строка);
    - `b` — строка: входит ли строка `a` в `b` как подстрока;
    - иначе — ошибка выполнения.
- **`a ?? b`** — `a`, если оно не `null`, иначе `b`. `b` вычисляется, только если `a` равно `null`.
- Выражения из литералов и констант вычисляются при компиляции; на смысл программы это не влияет.

### 7.3. Индексирование

- `a[i]` для массива: `i` — `int`, 0 ≤ i < длины, иначе ошибка выполнения `index out of range`. Отрицательных индексов от конца нет.
- `s[i]` для строки: байт как `int` (0…255), с теми же правилами для `i`. Запись `s[i] = ...` — ошибка: строки неизменяемы.
- `m[k]` для словаря: `k` — строка; значение или `null`, если ключа нет. Присваивание `m[k] = v` добавляет или заменяет элемент.

### 7.4. Литералы массивов и словарей

```text
var a = [1, 2, 3]
var empty = []
var m = {"name": "x", "size": 10}
var nested = {
    "list": [1, 2],
    "flags": {"v": true},
}
```

Каждый литерал создаёт новый объект. Ключи словарного литерала — выражения типа `string`; повторный ключ заменяет предыдущее значение. Запятая после последнего элемента допустима.

### 7.5. Методы и пространства

`x.m(args)` вызывает встроенный метод значения `x` (разд. 9); набор методов определяется типом значения при выполнении. Метода нет у типа — ошибка выполнения `no method m for type`.

У всех типов метод с данным именем принимает одно и то же число аргументов, поэтому компилятор проверяет число аргументов метода. Имя, которого нет ни у одного типа, — ошибка компиляции `unknown method`.

`ns.f(args)` вызывает функцию пространства (разд. 10); `ns` — одно из зарезервированных имён (2.2). Константы пространств записываются так же: `errors.NOENT`, `proc.BREAK`.

Полей у значений нет: `x.name` без скобок — ошибка компиляции `values have no fields` (кроме констант пространств).

## 8. Операторы

### 8.1. Блоки и простые операторы

Блок — последовательность операторов в фигурных скобках. Фигурные скобки у `if`, `else`, циклов и `switch` обязательны. Вложенность блоков — до 32 уровней, циклов — до 32.

Простые операторы:

- объявление `var` или `const` (5.2);
- присваивание `цель = выражение`, составное присваивание `цель op= выражение` (8.2), множественное присваивание (5.3);
- `цель++`, `цель--` — только как отдельный оператор, цель должна содержать `int`;
- вызов функции или метода;
- `return`, `fail` (6.3), `break`, `continue`.

Другие выражения как операторы — ошибка компиляции `expression is not a statement` (`x + 1` в отдельной строке).

### 8.2. Присваивание

Цель присваивания — переменная, элемент массива `a[i]` или элемент словаря `m[k]`; другое — ошибка `cannot assign to this expression`.

Составные присваивания: `+=`, `-=`, `*=`, `/=`, `%=`, `&=`, `|=`, `^=`, `<<=`, `>>=`, `>>>=`. Запись `a[i] += 1` вычисляет `a` и `i` один раз. Для строк `s += t` — конкатенация.

### 8.3. `if`

```text
if count == 0 {
    println("empty")
} else if count == 1 {
    println("one")
} else {
    println("many")
}
```

Условие — выражение типа `bool`. В условии `if`, `while`, `for` и `switch` открывающая фигурная скобка начинает блок, поэтому словарный литерал там пишется в скобках: `if m == ({}) { }` (иначе ошибка `map literal in a condition must be in parentheses`).

### 8.4. Циклы

```text
while i < n { ... }

loop {
    ...
    if done { break }
}

for line in lines { ... }
for i, line in lines { ... }
```

- `while` проверяет условие перед каждой итерацией. `loop` — бесконечный цикл, из которого выходят `break`, `return` или `fail`.
- `for v in e` перебирает элементы массива или байты строки (как `int`). `e` вычисляется один раз. Вариант с двумя именами даёт индекс (`int`, от 0) и значение. Переменные цикла — новые локальные переменные тела.
- Если длина перебираемого массива изменилась во время цикла, следующая итерация — ошибка выполнения `array changed during iteration`. Запись в элементы без изменения длины допустима.
- Словари перебираются через `m.keys()` или `m.values()`, которые возвращают новый массив.
- `break` и `continue` относятся к ближайшему охватывающему циклу, в том числе внутри `switch`; вне цикла — ошибка `break or continue outside a loop`.

### 8.5. `switch`

```text
switch cmd {
case "add", "plus":
    total += n
case "clear":
    total = 0
case limit_name():
    println("limit")
default:
    eprintln($"unknown command: {|cmd|}")
}
```

- Селектор вычисляется один раз.
- **Метки** — любые выражения. Ветки проверяются по порядку сверху вниз, метки внутри ветки — слева направо, сравнением `==` (4.4). Метки вычисляются только до первого совпадения, поэтому порядок побочных эффектов определён. Метки разных типов допустимы.
- Повтор константной метки (литерала или константы) — ошибка `duplicate case label`; проверяются первые 64 константные метки оператора. Повторы вычисляемых меток не проверяются.
- **Ветка** начинается после `:` и продолжается до следующего `case`, `default` или закрывающей `}`. Каждая ветка — отдельная область видимости. Проваливания в следующую ветку нет; пустая ветка ничего не делает.
- `default` — не больше одного (`several default clauses`), в любом месте; выполняется, если ни одна метка не подошла.
- **`break` и `continue` внутри `switch` относятся к охватывающему циклу**, а не к `switch`, в отличие от C:

```text
for line in lines {
    switch line {
    case "":
        continue          // следующая строка
    case "end":
        break             // выход из цикла for
    }
    handle(line)
}
```

### 8.6. `return`

`return` с числом значений, равным числу результатов функции (`wrong number of return values`). На верхнем уровне сценария — `return` или `return код` (3.1).

## 9. Встроенные функции и методы

Квадратные скобки в сигнатуре обозначают необязательный аргумент, `→` — результаты. Неверный тип аргумента — ошибка выполнения.

### 9.1. Глобальные функции

| Функция | Описание |
| --- | --- |
| `type(x) → string` | имя типа (4.1) |
| `str(x) → string` | текст значения: `int` — десятичное число, `bool` — `true`/`false`, `null` — `null`, строка — она сама, массив — `<array N>`, словарь — `<map N>`, файл — `<file>`, ошибка — `объект: текст` |
| `error(text[, object[, code]]) → error` | новая ошибка без возбуждения (6.2) |
| `assert(cond[, msg])` | при `cond == false` — ошибка выполнения `assertion failed: msg` |
| `min(a, b) → int`, `max(a, b) → int` | для двух `int` |
| `abs(x) → int` | модуль; `abs(-32768)` — ошибка выполнения |
| `print(x)`, `eprint(x)` | то же, что `io.print`, `io.eprint` (10.3) |
| `println([x])`, `eprintln([x])` | то же, что `io.println`, `io.eprintln`; без аргумента выводят только `\n` |

### 9.2. Методы строк

Аргументы `start`, `end` задают полуоткрытый интервал байтов `[start, end)`; выход за `0…len` — ошибка выполнения.

| Метод | Описание |
| --- | --- |
| `s.len() → int` | длина в байтах |
| `s.slice(start[, end]) → string` | подстрока; `end` по умолчанию — длина |
| `s.find(sub[, from]) → int` | позиция первого вхождения не раньше `from`, −1 — нет |
| `s.contains(sub) → bool` | то же, что `sub in s` |
| `s.starts_with(p) → bool`, `s.ends_with(p) → bool` | префикс, суффикс |
| `s.split(sep) → array` | части между вхождениями `sep` (не пустого): `"a,,b".split(",")` → `["a", "", "b"]`, `"".split(",")` → `[""]` |
| `s.lines() → array` | делит по `\n`, у каждой строки отрезает конечный `\r`, последнюю пустую часть отбрасывает; `"".lines()` → `[]` |
| `s.replace(old, new) → string` | все вхождения `old` (не пустого) заменены на `new` |
| `s.trim() → string` | без начальных и конечных пробелов, табуляций, `\r`, `\n` |
| `s.upper() → string`, `s.lower() → string` | регистр латиницы и кириллицы по таблице fold ФС16 (разд. 7.1): `A–Z`, `А–Я`, `Ё` ↔ `a–z`, `а–я`, `ё` |
| `s.equal_fold(t) → bool` | равенство после `lower()` обеих строк |
| `s.repeat(n) → string` | `n` копий, n ≥ 0 |
| `s.pad_left(w[, ch]) → string`, `s.pad_right(w[, ch]) → string` | дополнение до ширины `w` байтом `ch` (`int`, по умолчанию пробел); длинная строка не обрезается |
| `s.to_int() → int` | разбор числа (ниже) |

**`to_int`** принимает, с необязательными пробелами по краям: десятичное число с необязательным `-` или `+` (−32768…32767); `$`, `0x`, `0X` и шестнадцатеричные цифры или `0b`, `0B` и двоичные (0…`$FFFF`, как 16-битный образ). Иначе — ошибка `errors.NUMBER`, объект — разбираемая строка.

### 9.3. Методы массивов

| Метод | Описание |
| --- | --- |
| `a.len() → int` | число элементов |
| `a.push(v)` | добавить в конец |
| `a.pop() → value` | убрать и вернуть последний; у пустого массива — ошибка выполнения |
| `a.insert(i, v)` | вставить перед позицией `i`, 0 ≤ i ≤ len |
| `a.remove(i) → value` | убрать и вернуть элемент `i` |
| `a.slice(start[, end]) → array` | новый массив из элементов `[start, end)` |
| `a.clear()` | удалить все элементы |
| `a.clone() → array` | неглубокая копия |
| `a.contains(v) → bool` | то же, что `v in a` |
| `a.index_of(v) → int` | позиция первого элемента, равного `v`, или −1 |
| `a.reverse()` | развернуть на месте |
| `a.sort()` | по возрастанию на месте (4.4); все элементы — `int` или все — строки, иначе ошибка выполнения. Сортировка неустойчивая (быстрая, медиана трёх) и не требует дополнительной памяти кучи |

### 9.4. Методы словарей

Ключи — строки. Порядок перебора (`keys`, `values`) — порядок первой вставки ключа; удаление и повторная вставка ставят ключ в конец.

| Метод | Описание |
| --- | --- |
| `m.len() → int` | число элементов |
| `m.has(k) → bool` | то же, что `k in m` |
| `m.get(k[, default]) → value` | значение или `default` (по умолчанию `null`) |
| `m.set(k, v)` | то же, что `m[k] = v` |
| `m.delete(k) → bool` | удалить; `false`, если ключа не было |
| `m.keys() → array`, `m.values() → array` | новые массивы |
| `m.clone() → map` | неглубокая копия |

Значение `null` хранится как обычное: после `m.set("a", null)` выражение `m.has("a")` истинно, а `m["a"]` равно `null`.

### 9.5. Методы файлов и ошибок

Методы `file` — в 10.5, методы `error` — в 6.2.

## 10. Библиотека

### 10.1. Общие правила

- Пути — строки в форме монитора: необязательный том `X:` (буква `A`–`H` в любом регистре или цифра `0`–`7`) или `dev:`, имена через `/`, `.` и `..`. Пути длиннее 255 байт или глубже 16 имён — `errors.BADPATH`.
- Имена файлов сравниваются без учёта регистра (ФС16, разд. 7.1); так же работают `path.equal`, `fs.copy` и защита `include`.
- Функции, которые обращаются к монитору, при неудаче завершаются ошибкой (6.4). Её объект — путь неудачной операции (у `rename` и `copy` — тот из двух путей, на котором она произошла; у `proc` — имя программы или путь перенаправления).
- Ниже указаны только обычные результаты; ошибку можно перехватить у любого вызова, который её возвращает.
- Лимиты монитора: 16 дескрипторов на процесс, из них три — стандартные потоки, и 32 открытых файла на систему. VM открывает дескрипторы сверх нужных программе только кратковременно внутри одной функции (`fs.list`, `fs.copy`, `proc.capture`).

### 10.2. `str`

| Функция | Описание |
| --- | --- |
| `str.join(a, sep) → string` | элементы массива строк через `sep`; не строка в массиве — ошибка выполнения |
| `str.from_byte(b) → string` | строка из одного байта, 0 ≤ b ≤ 255 |
| `str.hex(n[, width]) → string` | 16-битный образ заглавными цифрами без префикса, с нулями слева до `width`: `str.hex(-1)` → `"FFFF"`, `str.hex(10, 4)` → `"000A"` |

### 10.3. `io` — стандартные потоки

| Функция | Описание |
| --- | --- |
| `io.print(x)`, `io.println([x])` | `str(x)` в поток 1; `println` добавляет `\n` |
| `io.eprint(x)`, `io.eprintln([x])` | то же в поток 2 |
| `io.read_line() → string` | следующая строка потока 0 без `\n` и конечного `\r`; `null` в конце ввода |
| `io.read_all() → string` | остаток потока 0; длиннее 32767 байт — `errors.TOOBIG` |
| `io.flush()` | записать буферизованный вывод |

**Буферизация.** Вывод в потоки 1 и 2 буферизуется. Буфер записывается: при `\n`, если поток — консоль; при `io.flush()`; перед `io.read_line`, `io.read_all`, `proc.run` и `proc.capture`; при завершении программы, в том числе по ошибке выполнения и Ctrl+C. Ошибки записи в потоки 1 и 2 не сообщаются; программа, которой они важны, пишет через файл.

### 10.4. `fs` — файлы и каталоги

| Функция | Описание |
| --- | --- |
| `fs.read_text(path) → string` | содержимое файла целиком; длиннее 32767 байт — `errors.TOOBIG` |
| `fs.write_text(path, text)` | создать или заменить файл |
| `fs.append_text(path, text)` | дописать в конец, создать при отсутствии |
| `fs.open(path, mode) → file` | открыть текстовый файл (10.5) |
| `fs.exists(path) → bool` | есть ли файл, каталог или устройство; любая ошибка — `false` |
| `fs.is_dir(path) → bool`, `fs.is_file(path) → bool` | то же с проверкой вида |
| `fs.list(dir) → array` | записи каталога (ниже) |
| `fs.mkdir(path)` | создать каталог |
| `fs.remove(path)` | удалить файл или пустой каталог |
| `fs.rename(old, new)` | переименовать или переместить в пределах тома |
| `fs.copy(src, dst)` | копировать файл (ниже) |
| `fs.cwd() → string` | текущий каталог процесса |
| `fs.chdir(path)` | сменить текущий каталог; действует и на запущенные затем программы |

**`fs.list`** возвращает массив словарей в порядке записей на диске, включая скрытые и системные: `"name"` — имя; `"dir"` — `true` для каталога; `"hidden"`, `"system"`, `"rdonly"` — флаги. Размер и время изменения не сообщаются. Каталог читается целиком и закрывается до возврата.

**`fs.copy`** копирует байты `src` в `dst`, создавая или заменяя `dst`. Если `dst` — существующий каталог, копия получает имя `src` в нём. Если `src` и `dst` — один файл (нормализованные абсолютные пути равны без учёта регистра) — `errors.SAMEFILE`, файл не меняется. Каталог как `src` — `errors.ISDIR`. Время изменения копии — текущее.

### 10.5. Текстовые файлы

| Режим `fs.open` | Описание |
| --- | --- |
| `"r"` | чтение |
| `"w"` | запись с начала; файл создаётся или укорачивается |
| `"a"` | дописывание в конец; файл создаётся при отсутствии |

Другая строка режима — ошибка выполнения. Каталог — `errors.ISDIR`. Открытых файлов программы — не больше 8 (`errors.MFILE`); перед этой ошибкой VM запускает сборку мусора, которая закрывает недостижимые файлы, и повторяет попытку.

| Метод | Описание |
| --- | --- |
| `f.read_line() → string` | следующая строка без `\n` и конечного `\r`; `null` в конце файла; длиннее 32767 байт — `errors.TOOBIG` |
| `f.read_all() → string` | остаток файла; длиннее 32767 байт — `errors.TOOBIG` |
| `f.write(s)` | записать строку (буферизованно) |
| `f.flush()` | записать буфер на диск |
| `f.close()` | записать буфер и закрыть; повторное закрытие ничего не делает |
| `f.path() → string` | путь, с которым файл открыт |

- Чтение у файла, открытого на запись, и запись у файла, открытого на чтение, — ошибка выполнения. Любой метод, кроме `close` и `path`, у закрытого файла завершается ошибкой `errors.CLOSED`.
- Ошибка записи (например, `errors.NOSPC`) может проявиться не в этом `write`, а в следующем `write`, `flush` или `close`. Ошибка `close` по умолчанию поднимается дальше, поэтому не теряется.
- Недостижимый файл закрывается при сборке мусора с записью буфера; ошибка при этом теряется. При завершении программы все открытые файлы закрываются с записью буферов.
- Позиционирования, размера и двоичного чтения нет.

### 10.6. `path`

Функции работают с текстом путей и не обращаются к диску.

| Функция | Описание |
| --- | --- |
| `path.join(a, b) → string` | `b`, если он абсолютный; иначе `a + "/" + b` без удвоения `/` |
| `path.basename(p) → string` | последнее имя: `"A:/a/b.txt"` → `"b.txt"` |
| `path.dirname(p) → string` | без последнего имени: `"A:/a/b.txt"` → `"A:/a"`, `"b.txt"` → `"."`, `"A:/x"` → `"A:/"` |
| `path.extension(p) → string` | расширение последнего имени с точкой (`".txt"`) или `""`; имя, начинающееся с точки, расширением не считается |
| `path.normalize(p) → string` | убирает `.`, повторные и конечные `/`, сокращает `имя/..`; ведущие `..` относительного пути сохраняются; регистр не меняет |
| `path.is_absolute(p) → bool` | есть том или начальный `/` |
| `path.equal(a, b) → bool` | `normalize` обоих и сравнение без учёта регистра; относительные пути — как есть, без текущего каталога |
| `path.match(pattern, name) → bool` | `*` — любые байты, кроме `/`, `?` — один байт, остальное — буквально без учёта регистра |

### 10.7. `proc` — процессы

| Функция | Описание |
| --- | --- |
| `proc.run(name, args[, redirect]) → int` | запустить программу и дождаться её; результат — код завершения |
| `proc.capture(name, args[, redirect]) → int, string` | то же; вывод потока 1 возвращается строкой |
| `proc.which(name) → string` | путь программы по правилам поиска или `null` |
| `proc.exit(code)` | завершить программу с кодом 0…32767; буферы записываются |
| `proc.script() → string` | путь сценария, как его передали `bsvm` |
| `proc.name() → string` | имя для сообщений: последнее имя пути сценария без расширения |

**Поиск программы** (`run`, `capture`, `which`) повторяет правила оболочки:

- `name` с `/` или `:` — путь как есть, затем с `.cx`, затем с `.bs`;
- иначе по очереди текущий каталог и `A:/bin`, в каждом `name`, `name.cx`, `name.bs`; имена сравнивает монитор без учёта регистра.

Найденный файл `.bs` запускается как `A:/bin/bs.cx путь args...`. Программа не найдена — `errors.NOENT`.

**Командная строка** собирается из найденного пути и элементов `args` (массив строк). Пустой аргумент или аргумент с пробелом или табуляцией заключается в кавычки. Аргумент с двойной кавычкой, строка длиннее 255 байт или больше 32 слов — `errors.ARGS`.

**Перенаправление** — необязательный словарь `redirect`:

| Ключ | Значение |
| --- | --- |
| `"stdin"` | путь файла для потока 0 потомка |
| `"stdout"` | путь файла для потока 1 (у `capture` недопустим) |
| `"stderr"` | путь файла для потока 2 |
| `"append"` | `true` — `stdout` и `stderr` дописываются, а не заменяются |

Неизвестный ключ или значение не того типа — ошибка выполнения. Ошибка открытия файла — ошибка вызова, программа не запускается. Если `stdout` и `stderr` — один путь, оба потока пишутся в один файл.

**`capture`** направляет поток 1 потомка во временный файл `A:/tmp/bs-NNNN.out` (каталог создаётся при отсутствии), после завершения читает и удаляет его. Вывод длиннее 32767 байт — `errors.TOOBIG`.

**Коды завершения.** Код потомка возвращается как `int`; коды монитора `$8000` и выше выглядят отрицательными:

| Константа | Код | Значение |
| --- | --- | --- |
| `proc.BREAK` | `$8001` (−32767) | потомок прерван Ctrl+C |
| `proc.BADINSN` | `$8008` (−32760) | потомок остановлен за недопустимую команду |

Если потомок завершился с `proc.BREAK`, сценарий тоже завершается с кодом `$8001`; `run` в этом случае не возвращается. Ошибки запуска (`NOENT`, `NOEXEC`, `NOMEM`, `NOPROC`, `ARGS` …) — ошибки вызова с объектом — именем программы. Ненулевой код потомка ошибкой не считается.

### 10.8. `time`

| Функция | Описание |
| --- | --- |
| `time.sleep(ticks)` | пауза в тиках таймера монитора (50 Гц, 20 мс); 0 ≤ ticks ≤ 32767 |

Константы — значения `error` таблицы 6.6, без объекта. Других функций у пространства нет.

## 11. Инструменты и запуск

### 11.1. Состав

| Программа | Назначение |
| --- | --- |
| `A:/bin/bsc.cx` | компилятор: исходник → файл байт-кода `.bsc` |
| `A:/bin/bsvm.cx` | виртуальная машина: выполняет `.bsc`; оверлеи — в `A:/bin/bsvm.ovl` рядом |
| `A:/bin/bs.cx` | загрузчик сценариев: компилирует при необходимости и запускает |

### 11.2. `bsc`

```text
bsc [-l] source.bs [-o out.bsc]
bsc --run cache.bsc source.bs [args...]
```

- Без `-o` результат — `source.bsc` в каталоге исходника. `-l` выводит в поток 1 листинг байт-кода.
- `--run` (используется `bs`) компилирует в `cache.bsc` и при успехе выполняет `EXEC` в `A:/bin/bsvm.cx cache.bsc source.bs args...`.
- **Сообщения:** `файл:строка:столбец: текст` в поток 2. Компилятор останавливается на первой ошибке.
- **Коды завершения:** 0 — успех, 1 — ошибка в программе, 2 — ошибка вызова или ввода-вывода.
- `.bsc` пишется во временный файл рядом и переименовывается в конце, поэтому прерванная компиляция не оставляет испорченного кеша.

### 11.3. `bsvm`

```text
bsvm program.bsc [script-path] [args...]
```

- `script-path` — путь исходника для `proc.script()` и сообщений; без него используется путь из заголовка `.bsc`. Чтобы при ручном запуске без пути сценария передать аргументы, первым пишут `--`: `bsvm prog.bsc -- a b`.
- **Коды завершения:** код программы (3.1); 1 — необработанная ошибка (6.4); 125 — ошибка выполнения (6.5); 126 — файл `.bsc` не найден, испорчен, другой версии, нет `bsvm.ovl` или памяти под него; `$8001` — Ctrl+C.

### 11.4. `bs` и оболочка

```text
bs script.bs [args...]
```

1. Вычисляет абсолютный нормализованный путь сценария.
2. Выбирает кеш: `script.bsc` рядом с исходником; если каталог только для чтения — `A:/tmp/имя.bsc`.
3. Кеш годен, если он правильной версии, путь главного исходника в нём равен пути сценария (без учёта регистра) и у каждого исходника (главного и подключённых) совпадает MTIME.
4. Годный кеш — `EXEC` в `bsvm`, иначе — `EXEC` в `bsc --run`. В цепочке процессов всегда одна программа, и вся память достаётся ей.

Служебные слова (`bs` или `bsc --run` и пути) входят в предел командной строки 255 байт и 32 слов, поэтому сценарию остаётся меньше, чем обычной программе.

**Оболочка** (ревизия 4) при поиске программы после `имя.cx` проверяет `имя.bs` и запускает найденный файл через `bs`: сценарий `A:/bin/backup.bs` вызывается просто как `backup`, перенаправления оболочки действуют. Явно названный `prog.bsc` оболочка запускает как `bsvm путь -- args...` без проверки кеша. Файловый менеджер fm (ревизия 5) по Enter запускает `.cx`, `.bs` и `.bsc`.

### 11.5. Ctrl+C

- Во время работы потомка Ctrl+C получает потомок; сценарий завершается по правилу 10.7.
- Во время работы самой VM обработчик записывает буферы потоков и открытых файлов и завершает процесс с кодом `$8001`.
- Компилятор и `bs` обработчика не ставят: их прерывание не оставляет испорченных файлов.

### 11.6. Формат `.bsc`

Файл `.bsc` (сигнатура `"BSC1"`, версия формата 1) содержит заголовок, таблицу исходников (абсолютные пути и MTIME, первым — главный файл), константы, таблицу функций, байт-код стековой машины и таблицу строк для сообщений об ошибках. Кодирование описано в документе «Формат байт-кода BScript», версия 1.

## 12. Пределы реализации

Программа, которая превышает предел компилятора, отвергается с сообщением из таблицы; предел VM при выполнении — ошибка выполнения. Пределы измерены на реализации фазы 1; как устроены куча, оверлеи и дальняя память, описано в «BScript — устройство виртуальной машины» (`bscript_vm_ru.md`).

| Величина | Предел | Сообщение |
| --- | --- | --- |
| код модуля | 32 КБ | `program too large` |
| константы | 16 КБ, 512 строк | `constants too large`, `too many constants` |
| функции; глобальные имена | 160; 160 | `too many functions`, `too many global names` |
| локальные переменные функции | 250 слотов, 96 имён одновременно | `too many local variables`, `too many local names` |
| параметры; результаты; цели присваивания | 16; 8; 9 | `too many parameters`, `too many results`, `too many targets` |
| идентификатор | 62 символа | `name too long` |
| строковый литерал; константное выражение-строка | 512; 1024 байта | `string too long`, `constant string too long` |
| вложенность выражений | 24 уровня | `expression nested too deep` |
| вложенность блоков; циклов | 32; 32 | `blocks nested too deep`, `loops nested too deep` |
| `include`: глубина; число файлов | 8; 32 | — |
| строка; массив | 32 767 байт; 32 767 элементов | `too large` |

## Приложение А. Грамматика

Нотация: `{ x }` — повторение 0 и более раз, `[ x ]` — необязательная часть, `|` — выбор. `EOS` — конец оператора (2.3). Лексемы — в кавычках или заглавными.

```
program     = { include } { toplevel } .
include     = "include" STRING EOS .
toplevel    = constdecl | vardecl | fndecl | statement .

fndecl      = "fn" IDENT "(" [ params ] ")" [ ":" types ] block .
params      = param { "," param } .
param       = IDENT [ ":" TYPE ] .
types       = TYPE { "," TYPE } .
TYPE        = IDENT .              (* int bool string array map file error value *)

constdecl   = "const" IDENT "=" expr EOS .
vardecl     = "var" names [ ":" TYPE ] [ "=" expr ] EOS .
names       = IDENT { "," IDENT } .

block       = "{" { statement } "}" .
statement   = constdecl | vardecl | simple EOS | ifstmt | whilestmt
            | loopstmt | forstmt | switchstmt | returnstmt | failstmt
            | "break" EOS | "continue" EOS | EOS .
simple      = target { "," target } "=" expr
            | target assignop expr
            | target ( "++" | "--" )
            | call .
target      = IDENT | "_" | postfix index .
assignop    = "+=" | "-=" | "*=" | "/=" | "%=" | "&=" | "|=" | "^="
            | "<<=" | ">>=" | ">>>=" .

ifstmt      = "if" expr block [ "else" ( ifstmt | block ) ] .
whilestmt   = "while" expr block .
loopstmt    = "loop" block .
forstmt     = "for" IDENT [ "," IDENT ] "in" expr block .
switchstmt  = "switch" expr "{" { EOS } { caseclause } "}" .
caseclause  = ( "case" expr { "," expr } | "default" ) ":" { statement } .
failstmt    = "fail" expr [ "," expr [ "," expr ] ] EOS .
returnstmt  = "return" [ expr { "," expr } ] EOS .

expr        = orexpr [ "??" expr ] .
orexpr      = andexpr { "||" andexpr } .
andexpr     = cmpexpr { "&&" cmpexpr } .
cmpexpr     = bitor [ cmpop bitor ] .
cmpop       = "==" | "!=" | "<" | "<=" | ">" | ">=" | "in" .
bitor       = bitxor { "|" bitxor } .
bitxor      = bitand { "^" bitand } .
bitand      = shift { "&" shift } .
shift       = additive { ( "<<" | ">>" | ">>>" ) additive } .
additive    = term { ( "+" | "-" ) term } .
term        = unary { ( "*" | "/" | "%" ) unary } .
unary       = ( "-" | "+" | "~" | "!" ) unary | postfix .
postfix     = primary { index | "." IDENT [ args ] | args } .
index       = "[" expr "]" .
args        = "(" [ expr { "," expr } ] ")" .
call        = postfix .            (* последний элемент — args *)
primary     = NUMBER | CHAR | STRING | ISTRING | "true" | "false" | "null"
            | IDENT | "(" expr ")" | arraylit | maplit .
arraylit    = "[" [ expr { "," expr } [ "," ] ] "]" .
maplit      = "{" [ expr ":" expr { "," expr ":" expr } [ "," ] ] "}" .
```

Ограничения, которые грамматика не выражает:

- `EOS` перед `}` можно опустить (2.3); `EOS` после `}` составного оператора разбирается как пустой оператор;
- `"." IDENT` без `args` допустим только после имени пространства (`errors.NOENT`);
- `args` после `primary` допустим только для имени функции;
- несколько имён в `vardecl` и несколько целей в `simple` — только с одним вызовом справа; целей столько же, сколько результатов, или на одну больше (5.3, 6.4);
- `ISTRING` разбирается лексером вместе с подстановками (2.8);
- в условии `if`, `while`, `for`, `switch` словарный литерал без скобок недопустим (8.3).
