# Формат байт-кода BScript. Версия 1

Документ дополняет «BScript: язык сценариев для CPU16», версия 1.0, разд. 12.5 (план работ, 13.1). Он описывает файл `.bsc`, который пишет компилятор `bsc` и выполняет виртуальная машина `bsvm`, и команды байт-кода. Общие определения реализации — `common/bsdefs.b16`.

Все многобайтовые поля — младшим байтом вперёд.

## 1. Файл `.bsc`

| Часть | Размер |
| --- | --- |
| заголовок | 32 байта |
| таблица исходников | `srcsz` (чётный) |
| константы | `constsz` (чётный) |
| функции | `funcsz` (чётный) |
| код | `codesz` (чётный) |
| таблица строк | `linesz` |

Части идут подряд, без промежутков. `bsvm` читает таблицу исходников и константы в ближнюю память, функции и код — в кадр модуля; таблицу строк он не загружает, а читает из файла, когда нужно место ошибки (разд. 5).

### 1.1. Заголовок

| Смещение | Поле | Значение |
| --- | --- | --- |
| 0 | сигнатура | `"BSC1"` |
| 4 | `version` | 1 |
| 6 | `flags` | 0 |
| 8 | `entry` | номер функции входа; в версии 1 всегда 0 |
| 10 | `nglobals` | число глобальных переменных; глобальная 0 — `args` |
| 12 | `nfiles` | число исходников |
| 14 | `srcsz` | размер таблицы исходников |
| 16 | `nconst` | число констант |
| 18 | `constsz` | размер констант |
| 20 | `nfunc` | число функций |
| 22 | `funcsz` | размер таблицы функций |
| 24 | `codesz` | размер кода |
| 26 | `linesz` | размер таблицы строк |
| 28 | резерв | 0 |

Виртуальная машина отвергает файл с другой сигнатурой или версией (код завершения 126).

### 1.2. Таблица исходников

Для каждого файла программы, первым — главный: MTIME (4 байта, метка времени ФС16), длина пути (1 байт), абсолютный нормализованный путь. При нечётном общем размере — байт 0. Таблицей пользуются `bs` (годность кеша, разд. 11.4 спецификации) и сообщения об ошибках.

### 1.3. Константы

Каждая константа — строка в формате объекта кучи VM, чтобы виртуальная машина использовала её прямо в памяти модуля, без копирования:

| Слово | Значение |
| --- | --- |
| 0 | тип: 3 (строка); VM добавляет флаг «статический объект» |
| 1 | длина строки в байтах |
| 2 | 0; VM записывает сюда номер handle |

Затем байты строки и, при нечётной длине, байт выравнивания. Константы нумеруются с 0 в порядке файла. Константа 0 — пустая строка (имя функции верхнего уровня).

### 1.4. Функции

`nfunc` записей по 10 байт, затем блок аннотаций.

| Смещение | Поле |
| --- | --- |
| 0 | номер константы с именем функции |
| 2 | смещение кода функции от начала кода |
| 4 | число параметров (байт) |
| 5 | число локальных слотов, включая параметры (байт) |
| 6 | число результатов (байт) |
| 7 | 1 — у параметров или результатов есть аннотации, которые нужно проверять |
| 8 | смещение аннотаций в блоке: сначала параметры, затем результаты, по байту |

Функция 0 — неявная функция верхнего уровня: операторы сценария вместе с инициализаторами глобальных переменных, а в программе с `main` — инициализаторы и вызов `main`. Пользовательские функции получают номера с 1 в порядке объявления.

Аннотации: 0 — нет, 1 — `bool`, 2 — `int`, 3 — `string`, 4 — `array`, 5 — `map`, 6 — `file`, 7 — `error`, 15 — `value`. Значение `null` проходит любую аннотацию.

### 1.5. Код

Код всех функций — одна последовательность. Код верхнего уровня начинается со смещения 0, тело каждой функции стоит в нём на месте объявления, и код верхнего уровня обходит его переходом `jmp`.

**Кадры кода.** Код делится на кадры по 8 КБ (смещения `$0000–$1FFF`, `$2000–$3FFF`, ...): VM, которой модуль не помещается в один кадр, держит код в нескольких кадрах расширенной памяти и ставит нужный в окно (спецификация, 12.1). Поэтому команда не пересекает границу кадра: если до границы меньше 7 байт, компилятор ставит `jmp` на начало следующего кадра, а остаток до границы заполняет нулями. Переходы и вызовы задают смещение в коде целиком и могут вести в другой кадр.

## 2. Значения

Значение — 4 байта, разд. 12.2 спецификации: слово 0 — образ или handle, слово 1 — тег.

| Тег | Тип |
| --- | --- |
| `$8000` | null |
| `$8001` | bool (0/1) |
| `$8002` | int |
| `$8010` | строка |
| `$8011` | массив |
| `$8012` | словарь |
| `$8013` | файл |
| `$8014` | ошибка |

## 3. Команды

Стековая машина. Локальные слоты функции — на стеке значений с базы кадра. `s8`, `u8`, `u16`, `s16` — операнды; смещение перехода `s16` отсчитывается от конца команды.

### 3.1. Загрузка и запись

| Код | Команда | Операнды | Действие |
| --- | --- | --- | --- |
| `$01` | `null` | | положить null |
| `$02` | `true` | | |
| `$03` | `false` | | |
| `$04` | `int8` | s8 | целое −128…127 |
| `$05` | `int16` | u16 | целое |
| `$06` | `str` | u16 | константа-строка |
| `$07` | `ldl` | u8 | локальный слот |
| `$08` | `stl` | u8 | снять в локальный слот |
| `$09` | `ldg` | u16 | глобальная переменная |
| `$0A` | `stg` | u16 | снять в глобальную |
| `$0B` | `pop` | | |
| `$0C` | `dup` | | |
| `$0D` | `dup2` | | повторить два верхних значения |
| `$0E` | `popn` | u8 | снять n значений |
| `$0F` | `chkt` | u8 | проверить аннотацию вершины (`type mismatch`) |

### 3.2. Операции

`$10`–`$1A`: `add sub mul div mod and or xor shl shr ushr` — два операнда. `add` складывает две строки. `$1B neg`, `$1C not` (bool), `$1D bnot`, `$1E pos` (проверка int) — один операнд.

`$20`–`$26`: `eq ne lt le gt ge in` — результат bool.

### 3.3. Переходы

| Код | Команда | Действие |
| --- | --- | --- |
| `$28` | `jmp s16` | переход |
| `$29` | `jf s16` | снять bool; false — переход |
| `$2A` | `jt s16` | снять bool; true — переход |
| `$2B` | `jfk s16` | вершина bool: false — переход, значение остаётся; иначе снять (`&&`) |
| `$2C` | `jtk s16` | то же для true (`||`) |
| `$2D` | `jnn s16` | вершина не null — переход, значение остаётся; иначе снять (`??`) |
| `$2E` | `chkb` | вершина должна быть bool |

Не bool там, где нужен bool, — ошибка выполнения.

### 3.4. Вызовы

| Код | Команда | Операнды |
| --- | --- | --- |
| `$30` | `call` | u16 функция, u8 режим |
| `$31` | `callb` | u8 встроенная функция, u8 число аргументов, u8 режим |
| `$32` | `callm` | u8 метод, u8 число аргументов, u8 режим |
| `$33` | `ret` | u8 число значений |
| `$34` | `fail` | u8 число операндов 1…3 |
| `$35` | `errc` | u8 код: значение `errors.*` |

Аргументы лежат на стеке по порядку; у `callm` ниже аргументов — получатель. Номера встроенных функций (`B_*`) и методов (`M_*`) заданы в `bsdefs.b16`.

**Режим вызова** — байт:

| Режим | Смысл |
| --- | --- |
| `$80` | оператор-вызов: результаты отбрасываются, ошибка поднимается |
| `$40 + n` | ровно n значений без перехвата: вызов в выражении (n = 1), `return f()` |
| `n` (1…9) | n целей присваивания: n = числу результатов — без перехвата; n = результатов + 1 — последняя цель получает ошибку или null |

Для функций программы и встроенных функций компилятор проверяет совпадение режима с числом результатов; для методов тип получателя неизвестен, и проверку делает VM (ошибка выполнения `wrong number of results`).

**`ret n`** кладёт n результатов на место аргументов вызова и применяет режим. В функции 0 `ret` завершает программу: 0 значений или null — код 0, иначе значение должно быть неотрицательным int.

**Ошибки** (разд. 12.7 спецификации). Неудачная встроенная функция и `fail` ставят регистр текущей ошибки. Если вызов в текущей функции перехватывает ошибку, на месте результатов оказываются null и ошибка. Иначе VM снимает кадры, пока не встретит вызов с перехватом. Ошибка, вышедшая из функции 0, выводится как `имя: объект: текст`, код 1.

**`fail n`**: операнды — текст или ошибка, объект (строка или null), код. Место `файл:строка` записывается в новую ошибку; `fail e` с одним операндом передаёт ошибку без изменений.

### 3.5. Элементы и литералы

| Код | Команда | Действие |
| --- | --- | --- |
| `$38` | `getidx` | `c i → c[i]` |
| `$39` | `setidx` | `c i v →`: `c[i] = v` |
| `$3A` | `setidxd u8` | `v` снять; `c` и `i` лежат под d значениями ниже `v` — для множественного присваивания |
| `$3B` | `arr u16` | n значений → новый массив |
| `$3C` | `map u16` | n пар ключ–значение → новый словарь |
| `$3D` | `concat u8` | n значений → `str()` каждого, одна новая строка (интерполяция) |

Множественное присваивание `a[i], m[k] = f()`: компилятор кладёт на стек пары контейнер–индекс целей, затем вызов, затем записывает результаты с последнего: переменная — `stl`/`stg`, элемент — `setidxd`, где глубина d — число значений между парой цели и записываемым значением; в конце `popn` снимает пары.

### 3.6. Цикл `for`

`for` использует три скрытых слота s, s+1, s+2: коллекция, индекс, длина при входе.

| Код | Команда | Действие |
| --- | --- | --- |
| `$3E` | `forinit u8` | снять массив или строку в слот s, индекс 0, длину |
| `$3F` | `fornext1 u8 s16` | индекс ≥ длины — переход; иначе положить элемент, индекс + 1 |
| `$40` | `fornext2 u8 s16` | то же, перед элементом — индекс |

Если длина массива изменилась, `fornext` — ошибка выполнения `array changed during iteration`.

### 3.7. `switch`

Отдельной команды нет. Селектор сохраняется в скрытом слоте, каждая метка сравнивается командами `ldl`, метка, `eq`, `jt`/`jf`; ветка `default` получает управление после последней неудачной проверки.

## 4. Кадры и память VM

Кадр вызова: адрес возврата, база локальных слотов, номер функции, режим вызова. Таблица функций, код и таблица кадров лежат в кадре модуля — кадре расширенной памяти в окне (страница 6, спецификация 12.9), если вместе с 800 байтами таблицы кадров умещаются в 8 КБ; иначе таблица функций и таблица кадров — в ближней памяти, а код — в нескольких кадрах (разд. 1.5). Таблица исходников — в ближней памяти; константы — тоже, а если после них осталось бы меньше 6 КБ кучи, — в кадрах расширенной памяти как статические объекты (спецификация, 12.10). Параметры занимают первые слоты, остальные слоты при входе — null. Глубина вызовов — до 100 кадров, стек значений — 384 значения; при переполнении — ошибка выполнения `stack overflow`.

## 5. Таблица строк

Поток записей в порядке возрастания смещения кода:

| Запись | Размер | Смысл |
| --- | --- | --- |
| `0, файл u8, смещение u16, строка u16` | 6 байт | абсолютная запись |
| `dкод (1…255), dстрока s8` | 2 байта | смещение и строка относительно предыдущей записи, тот же файл |

Место команды — последняя запись со смещением не больше смещения команды. VM ищет его, только когда нужно: сообщение об ошибке выполнения, `e.where()`, вывод необработанной ошибки.

## 6. Листинг

`bsc -l` выводит таблицу функций и команды по смещениям, например:

```text
fn sq params 1 locals 1 results 1 at 000A
000A  ldl 0
000C  ldl 0
000E  mul
000F  ret 1
```
