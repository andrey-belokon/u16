Монитор CPU16: формат исполняемого файла и запуск программ. Ревизия 1 (проект)

Документ описывает формат исполняемого файла для монитора CPU16, блок сведений о процессе (PIB), размещение аргументов командной строки и состояние программы при запуске. Машина описана в документе «Машина CPU16: память и устройства» (ревизия 3), процессор — в спецификации «Архитектура 16-битного процессора» (ревизия 6), язык ассемблера — в «Справочнике ассемблера».

Разделы 1–8 нормативные: слова «должен», «запрещено» обязательны для монитора и программ. Раздел 9 — рекомендации по реализации, раздел 10 — планируемые изменения инструментов. Они не нормативные.

Файловая система, системные вызовы, коды завершения, EXEC и SPAWN описываются отдельно. Здесь они упоминаются только там, где нужны для запуска.

1. Обзор

Программа хранится в файле как плоский образ памяти с адреса $0000, как его выводит ассемблер. Отличие от «голого» образа одно: сразу за начальным переходом лежит заголовок — 12 слов со сведениями для загрузчика.

Загрузчик монитора:

  1. проверяет заголовок и выделяет программе память;
  2. читает образ с адреса $0000 и обнуляет неинициализированные данные;
  3. кладёт разобранную командную строку (блок аргументов) сразу за статическими данными программы;
  4. записывает PIB поверх заголовка: после загрузки заголовок больше не нужен;
  5. передаёт управление на $0000.

Перемещения кода нет. Каждый процесс получает собственное адресное пространство через менеджер памяти и всегда загружается с адреса $0000.

Термины:

Термин Значение
образ содержимое файла от адреса $0000 до image_end
bss неинициализированные статические данные image_end … bss_end; в файле не хранятся, загрузчик их обнуляет
bss_end′ bss_end, округлённый вверх до чётного
блок аргументов массив argv и строки аргументов, начиная с bss_end′
top верхняя граница памяти, выделенной процессу; кратна $2000
PIB блок сведений о процессе по адресам $0004–$001B

2. Адресное пространство процесса

Монитор работает при включённом менеджере памяти. Страница 7 ($E000–$FFFF) общая для всех процессов: в ней лежат ядро монитора, таблица векторов и окно устройств. Процессу доступны страницы 0–6.

Адреса Назначение
$0000 … top − 1 память процесса
top … $DFFF не выделены; обращаться к ним запрещено
$E000–$FFFF ядро монитора, векторы, устройства
  • top не больше $E000.
  • Защиты памяти нет. Обращение за top и запись в страницу 7 — ошибка программы с неопределённым результатом.

3. Файл программы

3.1. Структура

Смещение в файле Содержимое
$0000–$0003 начальный переход JMP #start
$0004–$001B заголовок
$001C … image_end − 1 код и инициализированные данные
image_end … необязательные дополнительные данные; загрузчик их не читает

Файл — образ памяти: байт со смещением A загружается по адресу A.

3.2. Заголовок

Все поля — слова. Порядок байтов машинный: младший байт по меньшему адресу.

Адрес Поле Значение
$0000 переход $C873 — код команды JMP #выр
$0002 start адрес точки входа
$0004 magic 4 байта "CX16": $43 $58 $31 $36
$0008 version версия формата, 1
$000A flags 0
$000C image_end длина образа в байтах
$000E bss_end конец статических данных
$0010 min_free минимум свободной памяти под стек и кучу, байт
$0012 max_top желаемая верхняя граница памяти; 0 — максимум
$0014–$001B резерв 4 слова, должны быть равны 0

Начальный переход записывается в абсолютной форме JMP #start. Только она гарантированно занимает два слова, так что заголовок всегда начинается с $0004.

3.3. Требования к заголовку

Загрузчик отклоняет файл, если нарушено хотя бы одно условие:

  1. слово по $0000 равно $C873, байты $0004–$0007 равны "CX16";
  2. version = 1;
  3. flags = 0 (неизвестный бит — отказ, а не игнорирование);
  4. резервные слова равны 0;
  5. $001C ≤ image_end ≤ bss_end ≤ $E000;
  6. start чётный и $001C ≤ start < image_end;
  7. min_free чётный;
  8. длина файла не меньше image_end.

max_top проверке не подлежит: значения больше $E000 ограничиваются этим адресом (разд. 6).

4. Блок сведений о процессе (PIB)

После загрузки по адресам $0004–$001B лежит PIB. Поля version и bss_end стоят на тех же смещениях, что в заголовке.

Адрес Поле Значение
$0004 magic 4 байта "CXPB": $43 $58 $50 $42
$0008 version версия PIB, 1
$000A flags бит 0 — стандартный ввод перенаправлен, бит 1 — стандартный вывод перенаправлен; остальные 0
$000C argc число аргументов, не меньше 1
$000E bss_end значение из заголовка
$0010 argv адрес массива argv[0..argc]
$0012 args_end первый байт за блоком аргументов (чётный)
$0014 top верхняя граница выделенной памяти
$0016–$001B резерв 3 слова, равны 0
  • Монитор PIB после запуска не читает и не изменяет. Программа может использовать эту память как угодно.
  • Метки программы, попавшие в $0004–$001B, после загрузки указывают на поля PIB. Читать свой заголовок во время работы программа не должна.
  • Сигнатура позволяет определить способ запуска: "CXPB" по $0004 — программу запустил монитор; "CX16" — её запустили прямо из файла на голой машине (разд. 8).

5. Аргументы командной строки

5.1. Блок аргументов

Блок лежит с адреса bss_end′ по args_end − 1. По возрастанию адресов:

  1. массив argv[0..argc] — по слову на элемент: адреса строк, argv[argc] = 0;
  2. строки аргументов в порядке номеров, каждая с завершающим нулём, вплотную друг к другу;
  3. при нечётной общей длине — один байт 0 для выравнивания.

Поле argv в PIB всегда равно bss_end′. Программы всё равно должны брать адрес из PIB или из R1.

Блок — обычная память процесса. Монитор его не охраняет. Программа, которой аргументы нужны, должна прочитать или скопировать их до того, как займёт эту память под кучу (разд. 7).

5.2. Разбор

Командную строку разбирает монитор. Правила одинаковы для оболочки и для запуска из программы.

  • Разделители — пробел ($20) и табуляция ($09). Несколько разделителей подряд равны одному, начальные и конечные игнорируются.
  • Кавычки. Текст в двойных кавычках "…" входит в слово целиком, вместе с разделителями. Сами кавычки в аргумент не попадают. Кавычки могут стоять внутри слова: a"b c"d даёт ab cd. Незакрытая кавычка — ошибка. Экранирования нет: включить двойную кавычку в аргумент нельзя.
  • Пустой аргумент "" допустим и даёт строку нулевой длины.
  • argv[0] — имя файла программы в том виде, в каком его открыл загрузчик, с расширением.
  • Перенаправления ввода и вывода обрабатывает оболочка до запуска. В блок аргументов они не попадают.
  • Ограничения: командная строка не длиннее 255 байт, аргументов вместе с argv[0] не больше 32. При нарушении программа не запускается.

Исходная строка программе не передаётся: только разобранные аргументы.

6. Выделение памяти

Пусть B — размер блока аргументов в байтах: 2·(argc + 1) плюс длины строк с нулями, с округлением вверх до чётного. Обозначим через ⌈x⌉ округление вверх до кратного $2000.

Величина Формула
потребность need ⌈bss_end′ + B + min_free⌉
желание want $E000, если max_top = 0 или max_top > $E000; иначе ⌈max_top⌉
top меньшее из want и объёма доступной памяти, но не меньше need
  • Если need больше $E000 или больше доступной памяти, программа не запускается.
  • Если want меньше need, берётся need.
  • Вычисления выполняются без переполнения: промежуточные суммы, превысившие $E000, означают отказ.

Процесс получает top / $2000 кадров в страницах 0 … top/$2000 − 1. Все выделенные кадры обнулены, кроме того, что записал загрузчик. Свободная память процесса — args_end … top − 1. Стек начинается с top и растёт вниз.

7. Память процесса после загрузки

Адреса Содержимое
$0000–$0003 JMP #start
$0004–$001B PIB
$001C … image_end − 1 образ из файла
image_end … bss_end − 1 bss, нули
bss_end′ … args_end − 1 блок аргументов
args_end … SP свободно
… top − 1 стек

Свободная память ограничена снизу bss_end′, если программа уже прочитала аргументы, или args_end, если хочет их сохранить. Куча растёт вверх, стек вниз. Столкновение не обнаруживается.

8. Состояние при запуске

8.1. Под монитором

Ресурс Значение
IP $0000
R0 argc
R1 argv
SP top
LR адрес процедуры выхода в мониторе
FLAGS 0, прерывания запрещены
остальные регистры 0

Процедура выхода завершает программу с кодом из R0. Поэтому программа, которая вернула стек и LR в исходное состояние, может закончить работу командой RET. Остальные способы завершения определяет спецификация системных вызовов.

8.2. На голой машине

Файл в этом формате можно запустить эмулятором без монитора: JMP #start перешагнёт заголовок. В этом случае по $0004 лежит "CX16", PIB и аргументов нет, регистры равны 0 (в том числе SP), менеджер памяти выключен.

Программа, рассчитанная на оба режима, должна проверить сигнатуру до первого обращения к стеку (разд. 9.3). Программа только для монитора может считать запуск без монитора ошибкой своего пользователя.

9. Рекомендации по реализации

9.1. Загрузчик

Порядок работы:

  1. Найти файл и прочитать его первый сектор в буфер ядра. Скопировать поля заголовка в переменные ядра: дальше образ затрёт заголовок.
  2. Проверить заголовок (разд. 3.3).
  3. Разобрать командную строку во временный буфер ядра и вычислить B.
  4. Вычислить need, want, top (разд. 6) и выделить кадры. На любом отказе до этого шага выделенные ресурсы освобождаются, и вызывающий получает ошибку.
  5. Отобразить кадры процесса в страницы 0 … top/$2000 − 1 и обнулить их.
  6. Прочитать образ DMA прямо в память процесса.
  7. Записать блок аргументов с bss_end′, затем PIB.
  8. Установить регистры (разд. 8.1) и перейти на $0000.

Где выполняется загрузчик. Код загрузчика лежит в общей странице 7, поэтому страницы 0–6 можно переключать на кадры нового процесса без трамплина. Переход на $0000 служит точкой синхронизации и для смены отображения, и для кода, прочитанного DMA.

Чтение образа. Образ читается целыми секторами: ⌈image_end / 512⌉ секторов с адреса $0000. Последний сектор может захватить до 511 байт за image_end, но они не выходят за top, потому что top кратна 8 КБ, а 8 КБ кратны 512. Байты image_end … ⌈image_end/512⌉·512 − 1 после чтения нужно обнулить снова: там могут оказаться дополнительные данные файла или мусор за концом файла.

Обнуление. Кадры нужно обнулять целиком, а не только bss: иначе процесс увидит данные предыдущего владельца. Удобный порядок — обнулить кадры до чтения образа. Тогда после чтения остаётся дочистить только хвост последнего сектора.

Страницы за top. Их тоже нужно на что-то отобразить, потому что у менеджера памяти нет признака «страница отсутствует». Рекомендуется отдельный «мусорный» кадр, общий для всех процессов: ошибочная запись за top портит только его, а не чужую память.

Арифметика. Суммы считаются в 16 битах. Перед каждым сложением в разд. 6 проверяйте перенос (CF) или сравнивайте слагаемые с $E000 заранее. Округление (x + $1FFF) & $E000 переполняется при x > $E000, поэтому проверка границы должна идти до него.

Ошибки загрузки. Монитор должен различать как минимум:

Ошибка Причина
не найден файла нет
не исполняемый файл нарушено условие разд. 3.3, кроме версии
неподдерживаемая версия version ≠ 1
ошибка аргументов длина строки, число аргументов, незакрытая кавычка
не хватает памяти need больше $E000 или больше свободных кадров
ошибка ввода-вывода ошибка диска при чтении

Числовые коды определит спецификация системных вызовов.

9.2. Стартовый код программы

  • Сначала прочитать аргументы, затем инициализировать кучу. Начало кучи — bss_end′ (поле bss_end в PIB, округлённое до чётного), если аргументы скопированы, или args_end, если программа хранит указатели из argv.
  • Верхняя граница кучи — текущий SP минус запас под стек. Монитор об этом запасе не знает: min_free лишь гарантирует, что память есть.
  • Адрес возврата из LR нужно сохранить, если программа собирается завершаться через RET после вызовов.
  • min_free выбирается с запасом на глубину стека. Для небольших утилит достаточно 1–4 КБ, для компилятора — сколько нужно его таблицам, если они в куче.
  • Программа, которой нужна вся память, задаёт max_top = 0. Маленькая утилита задаёт max_top, равный need, чтобы не занимать кадры, нужные другим процессам.

9.3. Определение способа запуска

        .equ    PIB_MAGIC, $0004

start:  LD      R4, [PIB_MAGIC+2]
        CMP     R4, #'P' | 'B' << 8     ; "CXPB": вторая половина
        JZ      @under_monitor
        LD      SP, #$FF00              ; голая машина: стек свой
        ...
@under_monitor:
        ...

Достаточно сравнить второе слово сигнатуры: первое у заголовка и PIB совпадает ("CX").

9.4. Пример программы

Программа выводит аргументы по одному в строке прямо в консоль и завершается командой RET с кодом 0. Данных у неё нет, поэтому image_end и bss_end совпадают. Метки перед .align получают значение счётчика (Справочник ассемблера, правило «Метки и выравнивание»), поэтому так удобно обозначить конец образа.

        .equ    CON_DATA, $FF20

        .org    0
        JMP     #start
        .ascii  "CX16"
        .word   1, 0                    ; version, flags
        .word   image_end, bss_end
        .word   512                     ; min_free
        .word   $2000                   ; max_top: хватит одной страницы
        .word   0, 0, 0, 0              ; резерв

start:  LD      R2, R1                  ; R2 = argv
@arg:   LD      R3, [R2++]              ; очередной указатель
        CMP     R3, #0
        JZ      @done
@ch:    LDZX    R4, [R3++]
        CMP     R4, #0
        JZ      @eol
        STB     [CON_DATA], R4
        JMP     @ch
@eol:   LD      R4, #10
        STB     [CON_DATA], R4
        JMP     @arg
@done:  LD      R0, #0                  ; код завершения
        RET                             ; LR = процедура выхода

image_end:
bss_end:
        .align  2

9.5. Проверка загрузчика

Минимальный набор случаев:

  • каждое условие разд. 3.3 по отдельности: неверный код перехода, магия, версия, флаги, ненулевой резерв, image_end < $001C, bss_end < image_end, bss_end > $E000, нечётный и выходящий за образ start, файл короче image_end;
  • image_end, кратный 512, и не кратный;
  • bss_end нечётный: блок аргументов начинается с bss_end + 1;
  • max_top = 0, меньше need, больше $E000;
  • need ровно $E000 и на байт больше;
  • командная строка 255 и 256 байт, 32 и 33 аргумента, пустой аргумент "", кавычки внутри слова, незакрытая кавычка;
  • данные после image_end в файле не попадают в память;
  • память выделенных кадров нулевая, кроме образа и блока аргументов;
  • PIB заполнен целиком, резерв нулевой;
  • регистры при входе соответствуют разд. 8.1.

10. Планируемые изменения инструментов

Ассемблер и компилятор B16 пока не меняются. Формат уже можно использовать: заголовок пишется в исходном тексте вручную, а bss_end приравнивается к image_end — неинициализированные данные тогда хранятся в файле нулями.

Ассемблер.

  • Директива резервирования памяти без вывода, например .reserve n. Она сдвигает счётчик адреса, не выводя байтов. Если зарезервированные области стоят в конце программы, файл заканчивается на image_end, а bss в нём не хранится.
  • Явное правило для метки в самом конце текста: она получает значение счётчика.
  • Возможно, необязательная проверка заголовка при выводе образа (магия, image_end равен длине вывода).

Компилятор B16.

  • Порядок области данных (спецификация B16, разд. 9.1): код, инициализированные глобальные переменные и строковые литералы, затем глобальные переменные без инициализатора в резервируемой области.
  • Стартовый код для монитора (разд. 9.2 спецификации B16): заголовок вместо голого начала, стек не устанавливается, выход через процедуру из LR. Выбор целевой среды — ключом вида --target bare|os.
  • Передача argc и argv в main и код завершения из main.
  • Значение min_free по умолчанию и способ его задать.
