# B16: компилятор для CPU16 (ревизия 6)

B16 — язык уровня B/C для 16-битного процессора CPU16. Каждая конструкция отображается на предсказуемую короткую последовательность команд. `b16c` — компилятор в одном файле на C99 без зависимостей. Он выдаёт текст для ассемблера `cpu16asm`, а результат запускается в эмуляторе `cpu16`.

- **`docs/B16_guide_ru.md`** — руководство программиста: как думать на B16, во что компилируется каждая конструкция, соглашение о вызовах, прерывания, ассемблер, приёмы и подводные камни. Начинайте с него.
- **`docs/B16_reference_ru.md`** — справочник языка (ревизия 3; что изменилось в каждой ревизии — раздел 14): синтаксис и семантика, двоичный интерфейс, а в разделе 13 — реализация `b16c`: все ключи командной строки, раскладка образа, отбор функций, диагностика, ограничения.
- **Этот файл** — краткая справка.

## Сборка и запуск

```
make                                       # или: cc -O2 -o b16c b16c.c (под Windows: g++ -x c++ -O2 -o b16c b16c.c)
./run.sh examples/universal/hello.b16      # b16c -I lib -> cpu16asm -> cpu16
./run.sh examples/bare/screen.b16 --screen # ключи после файла передаются cpu16
B16FLAGS=-s ./run.sh examples/universal/sort.b16  # ключи компилятора через B16FLAGS
make test CPU16ASM=../cpu16/build/cpu16asm CPU16=../cpu16/build/cpu16 CPU16SRC=../cpu16/tools
make fuzz CPU16ASM=../cpu16/build/cpu16asm CPU16=../cpu16/build/cpu16
```

```
b16c [ключи] prog.b16
  -o файл  -I каталог  -a  -s  -Werror  -w  -Wmaybe-uninit  -fcopy-params  -n (устарел)
  параметры образа, переопределяющие option и include asm исходного текста:
  --target std|kernel  --code АДРЕС  --data АДРЕС  --min-free N  --max-top N  --asm файл
```

Параметры образа (цель, адреса кода и данных, поля заголовка CX16) задаются в главном файле объявлениями `option`, ассемблерные модули — строками `include asm` (справочник, разд. 3.2, 3.6). Все ключи, значения по умолчанию, коды завершения, раскладка образа в каждой цели и правила отбора функций описаны в одном месте — `docs/B16_reference_ru.md`, раздел 13.

Программа с `main` собирается в исполняемый файл CX16: заголовок, стартовый код, функции, рантайм, инициализированные данные, затем `__image_end` и неинициализированные переменные в `.reserve` до `__bss_end`. Образ проходит `cpu16asm --exec` и запускается и монитором, и эмулятором на голой машине. Под монитором стартовый код вызывает `main(argc, argv)` и возвращает её код завершения по LR; на голой машине он ставит `SP = $FF00`, вектор ERRCMD на остановку, остальные векторы на пустую заглушку, обнуляет bss, а после `main` останавливает процессор.

В образ попадают только функции, достижимые из `main`, функций `export`, обработчиков прерываний, инициализаторов глобальных переменных и `asm`-блоков.

## Язык в одном экране

```
include "console.b16"                 // в начале строки; каждый файл один раз

const N = 10                          // константа времени компиляции
var count: uint                       // глобальная: всегда в памяти
var tbl: [4]int = {1, 2, 3}           // остаток нулями
var msg = "текст"                     // [6]byte, кодировка машины
var CONSOLE at $FF20: byte            // порт по фиксированному адресу
struct Node { next: ptr Node; key: int; tag: byte }
struct Key { scan: byte; name: ptr byte }
var keys: [2]Key = { { $48, "^" }, { .scan = $50, .name = "v" } }
static fn helper() { }                // видна только в своём файле
export fn entry(): int { return 1 }   // точка входа для ассемблера
extern fn memfill(p: ptr byte, n: uint, v: byte)  // определена в ассемблере
assert sizeof(Node) == 6

fn divmod(a, b: uint): uint, uint { return a / b, a % b }
interrupt fn on_tick() { count++ }    // сохраняет регистры, выходит через IRET

fn main(): int {
    var q, r: uint
    q, r = divmod(100, 7)             // несколько результатов
    _, r = divmod(5, 2)               // ненужный пропускается
    var p: ptr Node = 0
    if p != 0 && p.key > 0 { p = p.next } else if q == 0 { r++ }
    while r != 0 { r-- }
    loop { if q > 3 { break }; q++ }
    atomic { count = 0 }              // PUSH FLAGS / CLI ... POP FLAGS
    goto done
done:
    puts("ok\n")
    return 0
}
```

**Типы.**

| Тип | Размер | Знак |
|---|---|---|
| `byte` | 1 | беззнаковый |
| `char` | 1 | знаковый |
| `uint` | 2 | беззнаковый |
| `int` | 2 | знаковый |
| `ulong` | 4 | беззнаковый |
| `long` | 4 | знаковый |
| `ptr T`, `ptr` | 2 | беззнаковый |

Кроме скаляров есть массивы `[N]T`, структуры `struct`, указатели на функции `ptr fn(T…): R…` (до 4 результатов) и на обработчики `ptr interrupt fn()`. Типы указателей проверяются строго: `ptr T` присваивается только `ptr T`, целое указателю — только константа 0; `ptr` без типа элемента совместим с любым указателем на данные. Вычисления над `byte`, `char`, `int`, `uint` и указателями 16-битные, над `long` и `ulong` — 32-битные (пара регистров, цепочки `ADD`/`ADC`, `SUB`/`SBC`; умножение, деление и сдвиг по переменной — вызовы рантайма). Более узкое целое расширяется до `long`/`ulong` неявно по знаку своего типа, сужение — только приведением. Знаковые и беззнаковые операнды нельзя смешивать только в `< > <= >= / %`; нетипизированные константы считаются точно, подстраиваются под второй операнд, и значение, не помещающееся в тип, — ошибка. Приведения: `int(x)`, `uint(x)`, `long(x)`, `ulong(x)`, `byte(x)`, `char(x)`, `ptr T(x)`, `ptr(x)`. Есть `sizeof(T)` и `offsetof(S, поле)`.

**Операторы.** `var`, `if`/`else if`/`else`, `while`, `loop`, `break`, `continue`, `return` (до 4 значений), множественное присваивание, `goto` с метками `имя:`, `atomic { }`, `asm { }`. Тела всегда в фигурных скобках, условия без скобок. Конец оператора — перевод строки или `;`, как в Go.

**Приоритеты** (от сильного к слабому):

1. `() [] . x++ x--`;
2. унарные `- ~ ! * & ++ --`;
3. `* / %`;
4. `+ -`;
5. `<< >>`;
6. `&`;
7. `^`;
8. `|`;
9. сравнения (без цепочек);
10. `&&`;
11. `||`;
12. присваивания.

Битовые операции связывают сильнее сравнений: `x & M == 0` значит `(x & M) == 0`.

**goto.** Метки видны во всей функции. Прыгать внутрь `atomic` запрещено. Выход из `atomic` через `goto`, `break`, `continue` или `return` восстанавливает FLAGS.

**Встроенные функции.** `mulhu(a, b)`, `ror(x, n)`, `xchb(p, v)`, `di()`, `ei()`, `wfi()`, `trap(n)`. 32-битные значения — типы `long` и `ulong` с обычными операторами, без встроенных функций.

**Соглашение о вызовах.**

- аргументы 1–4 и результаты 1–4 передаются в R0–R3, остальные аргументы — в стеке справа налево, снимает вызывающий;
- R0–R3 и LR портятся, R4–R11 сохраняет вызываемая функция;
- листовая функция возвращается командой `RET`, нелистовая — `POP IP`.

## Вывод

Вывод соответствует справочнику ассемблера и рассчитан на карту памяти `cpu16asm -m`:

- каждая функция, глобальная переменная, строковый литерал (`функция.s<n>`), функция рантайма и часть стартового кода — объект с глобальной меткой, метки внутри функции локальные, `@L<n>`;
- перед кодом каждой строки B16 — `.line "файл.b16", N`, перед стартовым кодом и рантаймом — `.line` без аргументов: карта, листинг и сообщения ассемблера указывают строки B16;
- инициализированные данные — `.word`, `.byte`, `.space`, неинициализированные — `.reserve`;
- константы, адреса `at`-переменных, смещения полей `S.поле` и размеры `S.sizeof` структур — `.equ`;
- `static`-имена — `файл.имя`;
- переходы пишутся мнемониками `Jxx`, короткую или длинную форму выбирает ассемблер; используются псевдокоманды `PUSH`, `POP`, `RET`, `CLI`, `STI`.

Имена, совпадающие с мнемониками и регистрами, выводятся с префиксом `__` (функция `neg` становится меткой `__neg`). Строки и символьные литералы перекодируются из UTF-8 в кодировку машины. Имена директив и мнемоник собраны в начале `b16c.c`.

## Проверка

- **`make test`** компилирует все тесты и примеры, ассемблирует их с проверкой заголовка `--exec` и картой памяти, запускает в `cpu16 --strict-align` и сравнивает вывод с эталонами. Для `screen` сравнивается снимок экрана, для `echo` ввод берётся из `echo.txt`. Если доступны исходники инструментов CPU16 (`CPU16SRC`, по умолчанию `../cpu16/tools`), собирается `tests/monrun`, и каждая программа запускается ещё дважды: на голой машине с памятью, заполненной мусором, и с имитацией монитора (IF = 1, IRQ0 каждые 7 команд, выход по LR с проверкой кода завершения). Отдельно проверяются модуль ядра и сообщения компилятора.
- **`make fuzz`** генерирует 140 программ, в каждой по 62 случайных выражения и присваивания над регистровыми, глобальными и косвенными операндами, включая двумерные массивы, указатель на массив и умножение и деление на константы. 40 программ — с выражениями глубины 6, где не хватает регистров. Результаты сравниваются с эталонным вычислителем.

## Сообщения компилятора

Сообщения выводятся на английском, в формате `файл:строка: error: текст` и `файл:строка: warning: текст` (как у ассемблера). Так они читаются в любой консоли, в том числе в Windows без UTF-8. После ошибки разбор продолжается со следующего оператора или объявления, за запуск выводится до 20 ошибок. Предупреждения: неиспользуемые переменные, параметры и метки (кроме имён на `_`), чтение до присваивания, сравнение беззнакового с отрицательной константой, неиспользуемое значение выражения, прототип без определения (кроме `extern fn`). Ошибка — функция с результатами, которая может дойти до конца без `return`. Комментарии в генерируемом `.s` остаются на русском.

## Ограничения

- Нет анализа времени жизни: каждая переменная занимает свой регистр на всю функцию, в листовой функции регистровых переменных не больше девяти, остальные уходят в стек. В нелистовой функции параметры копируются в R4+.
- Временные значения переживают вызов внутри выражения через `PUSH`/`POP`. Если регистров для выражения не хватает, компилятор перегенерирует этот участок с промежуточными значениями в стеке: код длиннее, но ошибки нет.
- Нет `switch`, `for`, структур по значению, плавающей точки, макросов, оптимизации хвостовых вызовов.
- Глобальные переменные библиотек остаются в образе, даже если не используются.
