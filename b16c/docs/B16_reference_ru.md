# Спецификация языка B16

Ревизия 3 · Oct 23, 2026 · @Андрей (первая ревизия: Oct 8, 2026; вторая: Oct 16, 2026)

## 1. Введение

B16 — компилируемый язык системного программирования для 16-битного процессора CPU16 (ревизия 6). Документ определяет синтаксис и семантику языка, а также двоичный интерфейс, которому следует сгенерированный код. Это **третья ревизия** спецификации (не путать с ревизией 6 процессора CPU16); в ней параметры образа (цель, адреса кода и данных, поля заголовка CX16) и ассемблерные модули задаются в исходном тексте, подробно — в разделе 14. Эталонная реализация — компилятор `b16c`: его поведение, которое язык оставляет на усмотрение реализации, ключи командной строки и ограничения собраны в разделе 13.

Спецификация не описывает архитектуру процессора, ассемблер, устройства машины и монитор. Для них есть отдельные документы:

| Документ | Что из него используется |
| --- | --- |
| «Архитектура 16-битного процессора», ревизия 6 | система команд, регистры, прерывания |
| «Справочник ассемблера» | ассемблер `cpu16asm`, которому компилятор передаёт свой вывод |
| «Машина CPU16: память и устройства», ревизия 6 | адреса устройств, таймер, рецепт остановки (9.2) |
| «Монитор CPU16: формат исполняемого файла и запуск программ», ревизия 3 | формат CX16, PIB, состояние при запуске (9.1, 9.2, 13.3) |
| «Монитор CPU16: системные вызовы», ревизия 1 | интерфейс монитора для программ цели `std` |

Неформальное введение в язык с примерами — «B16: руководство программиста».

### Нотация

Грамматика записана в расширенной форме Бэкуса–Наура:

| Запись | Значение |
| --- | --- |
| `Имя = ... .` | правило |
| `"текст"` | лексема, записанная буквально |
| `A \| B` | одна из альтернатив |
| `[ A ]` | необязательная часть |
| `{ A }` | повторение ноль или более раз |
| `( A )` | группировка |

Имена лексем записываются заглавными буквами: `IDENT`, `NUMBER`, `STRING`, `EOS` (конец оператора, раздел 2.3).

### Термины

- **Ошибка** — нарушение правил, которое реализация обязана диагностировать; программа не транслируется.
- **Неопределённое поведение** — конструкция, для которой язык не задаёт результат; реализация не обязана её диагностировать.
- **Зависит от реализации** — поведение, которое реализация выбирает и документирует.
- **Скаляр** — значение типов `byte`, `char`, `uint`, `int`, `long`, `ulong` или указателя (раздел 4).
- **Слово** — 16 бит, **байт** — 8 бит, **двойное слово** — 32 бита (два слова, младшее первым). Вычисления над значениями типов `byte`, `char`, `uint`, `int` и указателями выполняются над словами, над значениями `long` и `ulong` — над двойными словами.

## 2. Лексическая структура

### 2.1. Исходный текст

Исходный текст — последовательность символов в кодировке UTF-8. Пробельные символы — пробел, табуляция и возврат каретки (CR); перевод строки (LF) имеет особый смысл (2.3). Пары CR LF допустимы.

Комментарии бывают двух видов:

- `// ...` — до конца строки;
- `/* ... */` — блочный, не вкладывается. Переводы строк внутри блочного комментария не завершают оператор.

### 2.2. Лексемы

Текст разбивается на лексемы слева направо, каждый раз выбирается самая длинная возможная лексема. Виды лексем: идентификаторы, ключевые слова, числа, символьные литералы, строки, знаки операций и разделители.

### 2.3. Конец оператора

Перевод строки становится лексемой `EOS` (конец оператора), если последняя лексема строки — одна из:

- идентификатор, число, символьный литерал или строка;
- `)`, `]` или `}`;
- `++` или `--`;
- `break`, `continue` или `return`;
- `byte`, `char`, `int`, `uint`, `long`, `ulong` или `ptr`.

Поэтому тип элемента указателя нельзя переносить на следующую строку: `var p: ptr` в конце строки — нетипизированный указатель (4.2).

Исключение: если первая непустая лексема после перевода строки (пропуская пустые строки и комментарии `//`) — `else`, лексема `EOS` не вставляется. Конец файла после такой лексемы тоже даёт `EOS`. Явная точка с запятой `;` всегда означает `EOS`; несколько `EOS` подряд допустимы.

Следствие: перенос выражения допустим только после знака операции, запятой или открывающей скобки.

### 2.4. Идентификаторы и ключевые слова

```
IDENT = буква { буква | цифра } .
буква = "A"…"Z" | "a"…"z" | "_" .
цифра = "0"…"9" .
```

Регистр букв значим. Имена, начинающиеся с `__`, зарезервированы реализацией и не могут объявляться в программе. Имя `_` в выражениях означает «отбросить значение» и допустимо только слева в множественном присваивании (7.8).

Ключевые слова зарезервированы:

```
asm      assert   atomic   at       break    byte     char     const
continue else     export   extern   fn       goto     if       include
int      interrupt long    loop     offsetof ptr      return   sizeof
static   struct   uint     ulong    var      while
```

Слово `option` не зарезервировано: оно имеет смысл только в начале объявления верхнего уровня (3.6), а в остальных местах — обычный идентификатор. Так же не зарезервированы имена параметров образа (`target`, `code`, `data`, `min_free`, `max_top`) и значения `std`, `kernel`.

Имена встроенных функций (`mulhu`, `ror`, `xchb`, `di`, `ei`, `wfi`, `trap`) не зарезервированы. Но идентификатор из этого списка, за которым следует `(`, всегда означает вызов встроенной функции (раздел 8).

### 2.5. Числа

```
NUMBER = десятичное | "$" шестн { шестн } | ("0x" | "0X") шестн { шестн } | ("0b" | "0B") двоичн { двоичн } .
```

Значение числа — от 0 до 4294967295 ($FFFFFFFF), большее значение — ошибка. Число — нетипизированная константа (4.7); тип ему придаёт контекст, а при отсутствии контекста — значение (5.3). Сразу за числом не может стоять буква, цифра другой системы или `_`. Отрицательных литералов нет: `-1` — это унарный минус, применённый к литералу (константное выражение, 6.10).

### 2.6. Символьные литералы

Символьный литерал — один символ или escape-последовательность в апострофах: `'A'`, `'\n'`, `'Ж'`. Его значение — код символа в кодировке машины CPU16. Символ исходника, которого нет в кодировке машины, — ошибка. Символьный литерал — нетипизированная целая константа (4.7), как и число.

| Последовательность | Код |
| --- | --- |
| `\n` | 10 |
| `\r` | 13 |
| `\t` | 9 |
| `\e` | 27 |
| `\0` | 0 |
| `\\`, `\'`, `\"` | символ после `\` |
| `\xH`, `\xHH` | байт с этим шестнадцатеричным кодом, без перекодировки |

Другие последовательности после `\` — ошибка.

### 2.7. Строки

Строка — последовательность символов и escape-последовательностей в кавычках. Перевод строки внутри строки — ошибка. Символы перекодируются в кодировку машины по тем же правилам, что и символьные литералы. Строка длиной n символов задаёт массив `[n+1]byte` с нулевым байтом в конце (6.3). Строковый литерал в выражении — объект только для чтения: запись в него — неопределённое поведение (12.1). Изменяемый текст объявляют массивом, инициализированным строкой: глобальным `var s = "..."` (тип `[n+1]byte`) или локальным `var s: [N]byte = "..."` (N не меньше n+1; собственная копия, 5.3). Локальная `var s = "..."` без типа — не массив, а `ptr byte` на литерал; писать в неё нельзя.

### 2.8. Знаки операций и разделители

```
+   -   *   /   %   &   |   ^   ~   !   <<  >>
==  !=  <   >   <=  >=  &&  ||  ++  --
=   +=  -=  *=  /=  %=  &=  |=  ^=  <<= >>=
(   )   [   ]   {   }   ,   ;   :   .
```

Любой другой символ вне комментария, строки и символьного литерала — ошибка.

## 3. Структура программы

### 3.1. Единица трансляции

Программа — один исходный файл вместе с файлами, которые он подключает через `include`. После подстановки получается единица трансляции: последовательность объявлений верхнего уровня, разделённых `EOS`.

```
Программа = { Объявление | EOS } .
Объявление = ОбъявлениеКонстанты | [ "static" ] ОбъявлениеПеременной | ОбъявлениеСтруктуры
           | ОбъявлениеФункции | Проверка | Параметр .
```

Операторы вне функций недопустимы. `Параметр` — параметр образа, он допустим только в главном файле (3.6).

### 3.2. include

Строка вида

```
include "путь"
```

заменяется текстом указанного файла. `include` распознаётся, только если стоит первым на строке (перед ним допустимы пробелы и табуляции). После закрывающей кавычки допустим только комментарий `//`. Внутри блочного комментария `include` не действует. Слово `include` в любом другом месте — ошибка.

Правила поиска и подключения:

1. Абсолютный путь используется как есть.
2. Относительный путь ищется сначала относительно каталога включающего файла, затем по очереди в каталогах поиска, заданных реализации (`b16c -I`).
3. Каждый файл подключается не более одного раза. Повторный `include` того же файла (определяется по каноническому пути) игнорируется.
4. Вложенность `include` — не более 16 уровней.
5. Ненайденный файл — ошибка.

Диагностика указывает имя и строку того файла, в котором находится ошибочный текст.

**Ассемблерный модуль.** Строка вида

```
include asm "путь"
```

подключает к образу ассемблерный модуль (10.4): текст файла не подставляется, а реализация выводит его в образ до `__image_end`. Строка распознаётся по тем же правилам, что `include`: первой на строке, вне блочного комментария, после кавычки — только комментарий `//`. Файл ищется по правилам 1 и 2; ненайденный файл — ошибка. Строка допустима в любом файле единицы трансляции: библиотека, которой нужен модуль, подключает его сама (`sys.b16` монитора подключает `sys.asm`). Повторное подключение того же модуля (по каноническому пути) игнорируется, в том числе совпадение с модулем, заданным реализации извне (`b16c --asm`). Модули выводятся в порядке первого появления в единице трансляции; предел числа модулей задаёт реализация (13.8).

### 3.3. Порядок объявлений

Область видимости объявления верхнего уровня — вся единица трансляции, включая текст до объявления. Функцию можно вызывать, а глобальную переменную использовать в теле функции выше по тексту, чем они объявлены. Прототип (5.5) для этого не нужен.

Исключение — контексты, вычисляемые при разборе объявлений:

- имя константы в константном выражении (размер массива, адрес `at`, значение другой константы) должно быть объявлено раньше по тексту;
- структура, которая используется по значению (как тип поля или глобальной переменной), должна быть определена раньше по тексту. Указатель `ptr S` допустим и на структуру, определённую позже;
- инициализатор глобальной переменной без явного типа (`var x = ...`) может ссылаться только на объявления выше по тексту. Инициализатор переменной с явным типом может ссылаться на любые объявления;
- значение параметра образа `option` (3.6) — константное выражение и подчиняется первому правилу.

### 3.4. Точка входа

Функция `main` — точка входа программы. Её допустимые объявления:

```
fn main()
fn main(): int
fn main(argc: uint, argv: ptr ptr byte)
fn main(argc: uint, argv: ptr ptr byte): int
```

Имена параметров произвольны, другие сочетания параметров и результатов — ошибка. `argc` — число аргументов командной строки, `argv` — массив из `argc` указателей на строки и завершающего 0; `argv[0]` — имя программы. Результат — код завершения; без результата программа завершается с кодом 0. `main` не может быть `static`.

Реализация добавляет стартовый код (9.2), который вызывает `main`. Программа без `main` и код без стартового кода (ядро, модули для ассемблера) транслируются в цели `kernel`: `option target = kernel` (3.6).

### 3.5. Достижимость функций

В образ попадают только достижимые функции. Корни достижимости:

- `main`;
- функции с пометкой `export` (5.5);
- все обработчики прерываний (`interrupt fn`);
- функции, имена которых встречаются в инициализаторах глобальных переменных.

Функция достижима, если на неё ссылается достижимая функция: вызовом, взятием адреса или упоминанием имени в тексте `asm`-блока. Глобальные переменные в образ попадают всегда.

### 3.6. Параметры образа

```
Параметр = "option" IDENT "=" ( КонстантноеВыражение | IDENT ) EOS .
```

Параметр образа задаёт, как программа раскладывается в памяти и запускается. `option` — контекстное слово (2.4): объявление верхнего уровня, начинающееся с идентификатора `option`, — параметр образа. Параметры:

| Имя | Значение | По умолчанию | Цель | Действие |
| --- | --- | --- | --- | --- |
| `target` | `std` или `kernel` | `std` | — | `std` — исполняемый файл CX16 с заголовком и стартовым кодом (9.2), нужна `main` (3.4); `kernel` — код без заголовка и стартового кода (ядро, модули для ассемблера), `main` — обычная функция |
| `code` | адрес, чётный, `$0000`…`$FFFE` | 0 | `kernel` | начало кода |
| `data` | адрес, чётный, `$0000`…`$FFFE` | сразу за кодом | обе | начало области всех глобальных переменных; начальные значения инициализированных лежат образцом рядом с кодом (9.1) |
| `min_free` | чётное, 0…`$E000` | 2048 | `std` | поле `min_free` заголовка CX16: память под стек и кучу сверх bss |
| `max_top` | 0…`$FFFF` | 0 | `std` | поле `max_top` заголовка CX16: желаемая верхняя граница памяти процесса, 0 — вся доступная |

Значение `target` записывается именем, остальных — константным выражением (6.10); константы в нём должны быть объявлены выше по тексту (3.3). Так одно значение служит и параметром, и адресом в программе:

```
const PTOP = $A000              // память процесса - до PTOP, выше - окна кадров
option max_top = PTOP
option min_free = 4096
var WB at PTOP: [8192]byte
```

Правила:

1. Параметры допустимы только в **главном файле** — том, что подан на вход реализации. В файле, подключённом через `include`, параметр — ошибка: библиотека не меняет раскладку программы, которая её подключила. Ассемблерные модули библиотека подключает сама строкой `include asm` (3.2).
2. Каждый параметр задаётся не более одного раза.
3. Место параметра в главном файле значения не имеет: действуют все параметры файла сразу. Принято писать их в начале файла.
4. Неизвестное имя, значение вне диапазона, нечётный адрес — ошибка.
5. Параметр, не относящийся к цели, — ошибка: `code` при цели `std` (код цели `std` всегда начинается с 0, там стоит заголовок), `min_free` и `max_top` при цели `kernel` (заголовка нет).

Реализация может принимать те же параметры извне (ключи `b16c`, 13.2); значение, заданное извне, имеет приоритет над параметром исходного текста.

Пример — ядро монитора:

```
option target = kernel
option code = $0004             // по $0000 - переход из monitor.asm
option data = $8000             // данные и bss - со страницы 4
include asm "klib.asm"
```

## 4. Типы

```
Тип = "byte" | "char" | "uint" | "int" | "long" | "ulong"
    | "ptr" [ Тип ]                           (* без типа - нетипизированный указатель *)
    | "[" КонстантноеВыражение "]" Тип
    | IDENT                                   (* имя структуры *)
    | "fn" "(" [ Тип { "," Тип } ] ")" [ ":" Результаты ]
    | "interrupt" "fn" "(" ")" .
Результаты = Тип { "," Тип } | "(" Тип { "," Тип } ")" .
```

### 4.1. Скалярные типы

| Тип | Размер, байт | Диапазон | Знаковость |
| --- | --- | --- | --- |
| `byte` | 1 | 0…255 | беззнаковый |
| `char` | 1 | −128…127 | знаковый |
| `uint` | 2 | 0…65535 | беззнаковый |
| `int` | 2 | −32768…32767 | знаковый |
| `ulong` | 4 | 0…4294967295 | беззнаковый |
| `long` | 4 | −2147483648…2147483647 | знаковый |
| `ptr T`, `ptr` | 2 | адрес 0…$FFFF | беззнаковый |

`byte` и `char` называются **байтовыми** типами, `uint`, `int` и указатели — **словными**, `long` и `ulong` — **двухсловными** (**широкими**). Значение байтового типа при чтении расширяется до слова: `byte` — нулями, `char` — знаковым битом. При записи в объект байтового типа сохраняется младший байт. Значение байтового типа в выражении имеет **продвинутый** тип: `byte` → `uint`, `char` → `int`.

Объект двухсловного типа занимает 4 байта, выравнивается по слову; младшее слово лежит по меньшему адресу (little-endian). Он читается и записывается двумя командами, младшее слово первым (9.7). Такая раскладка совпадает с 32-битными полями файловой системы ФС16: поле записи каталога или описателя файла описывается как `ulong` без вспомогательных структур.

Логического типа нет: условие истинно, если его значение не равно 0. Операции сравнения и логические операции дают `int` со значением 0 или 1.

### 4.2. Указатели

`ptr T` — адрес объекта типа T. Элемент указателя — тип T, размер элемента — `sizeof(T)`; для `ptr fn(...)` размер элемента не определён. Значение 0 — нулевой указатель; разыменование нулевого указателя не запрещено и обращается к адресу 0.

**Совместимость.** Два типа указателей совпадают, если совпадают типы элементов: скаляры — по виду (`ptr byte` и `ptr char` — разные типы), массивы — по длине и типу элемента (`ptr [4]int` и `ptr int` — разные), структуры — по имени, функциональные типы — по числу и типам параметров и результатов и признаку `interrupt`. Значение типа `ptr T` неявно присваивается (6.2) только объекту типа `ptr T` с тем же T или нетипизированному указателю. Целое значение не присваивается указателю, а указатель — целому, кроме константы 0, которая присваивается любому указателю. Другие преобразования выполняются только явно (4.6).

**Нетипизированный указатель** `ptr` (запись без типа элемента) — адрес данных неизвестного типа: для функций, работающих с памятью вообще (копирование, заполнение, распределитель), и для данных, которые интерпретируются по-разному в зависимости от содержимого. Он скаляр размером 2 байта, беззнаковый, и допустим везде, где допустим скалярный тип: в переменных, параметрах, результатах, полях, элементах массивов, в переменных `at`.

- Любой `ptr T`, кроме указателя на функцию, неявно присваивается `ptr`, и `ptr` неявно присваивается любому `ptr T`, кроме указателя на функцию. Указатель на функцию преобразуется в `ptr` и обратно только явно.
- Над `ptr` запрещено всё, что требует размера элемента: разыменование `*p`, индексирование `p[i]`, доступ к полю `p.f`, `++` и `--`, сложение и вычитание с целым, `+=` и `-=`, разность двух указателей. Для адресной арифметики указатель явно приводится к `ptr byte`.
- Разрешены присваивание, сравнение, проверка в условии (`if p`, `!p`) и операции над 16 битами, которые дают `uint` (6.6), например проверка выравнивания `p & 1`.
- Встроенные функции, которым нужен указатель определённого типа (`xchb`), нетипизированный указатель не принимают.

### 4.3. Массивы

`[N]T` — N расположенных подряд объектов типа T, N — константное выражение больше 0. Размер — N · sizeof(T). Многомерный массив — массив массивов: `[3][5]int`. Массив не копируется и не сравнивается целиком. В выражении массив **сводится** к указателю на свой первый элемент (`[N]T` → `ptr T`). Исключений нет: операнд `sizeof` — тип, а не выражение (4.8).

### 4.4. Структуры

Структура — именованная раскладка полей в памяти (5.4). Размещение полей:

- поля располагаются в порядке объявления;
- **выравнивание** типа: байтовые типы — 1, массив — выравнивание элемента, структура — наибольшее выравнивание её полей, остальные типы — 2;
- поле с выравниванием 2 получает чётное смещение (при необходимости перед ним вставляется байт заполнения);
- размер структуры округляется вверх до чётного числа байт.

Над структурой целиком допустимы только доступ к полю `.`, взятие адреса `&` и операция `sizeof` её типа. Присваивание, сравнение, передача в функцию и возврат структур по значению — ошибки.

### 4.5. Функциональные типы

`fn(T1, ..., Tn): R1, ..., Rk` — тип функции с параметрами-скалярами T1…Tn и результатами-скалярами R1…Rk (без `:` — без результатов). Результаты занимают не более четырёх слов: слово занимают `byte`, `char`, `uint`, `int` и указатели, два слова — `long` и `ulong` (9.3). Функциональный тип допустим только как тип элемента указателя: `ptr fn(int): int`, `ptr fn(int, ptr byte, uint): int, uint`. Имя функции в выражении сводится к указателю на функцию её типа. Через указатель вызов возвращает все результаты в R0–R3, как обычный вызов (9.3).

Запятая после типа результата продолжает список результатов ближайшего функционального типа, если за ней следует скалярный тип: в `ptr fn(ptr fn(): int, uint)` у внутреннего типа два результата, а у внешнего — один параметр. Чтобы закончить список раньше, результаты записывают в скобках: `ptr fn(ptr fn(): (int), uint)` — функция от двух параметров. Тот же нетерминал `Результаты` стоит в объявлении функции (5.5); там неоднозначности нет, и скобки необязательны: `fn f(): (int, uint)` и `fn f(): int, uint` означают одно и то же.

`interrupt fn()` — тип обработчика прерывания (5.6). Обработчик выходит из прерывания иначе, чем функция из вызова, поэтому `ptr interrupt fn()` и `ptr fn()` несовместимы: обработчик присваивается только указателю на обработчик, а вызов через такой указатель — ошибка. Таблица векторов описывается как `[16]ptr interrupt fn()`.

### 4.6. Приведения типов

```
Приведение = СкалярныйТип "(" Выражение ")" .
СкалярныйТип = "byte" | "char" | "uint" | "int" | "long" | "ulong" | "ptr" [ Тип ] .
```

| Приведение | Результат |
| --- | --- |
| `uint(x)`, `int(x)` | те же 16 бит, другой тип; x — целое или указатель. Для x типа `long` или `ulong` — младшие 16 бит |
| `long(x)`, `ulong(x)` | x типа `byte`, `uint` — расширение нулями; `char`, `int` — расширение знаком; `long`, `ulong` — те же 32 бита, другой тип. Указатель — ошибка: сначала `uint(p)` |
| `ptr T(x)`, `ptr(x)` | те же 16 бит, тип указателя; x — словное целое или любой указатель. Значение типа `long`, `ulong` — ошибка: сначала `uint(x)` |
| `byte(x)` | младший байт, расширенный нулями; для x типа `long`, `ulong` — младший байт младшего слова |
| `char(x)` | младший байт, расширенный знаком; для x типа `long`, `ulong` — младший байт младшего слова |

Операнд приведения — скаляр (массив сводится к указателю). `byte(p)` и `char(p)` от указателя — ошибка: сначала `uint(p)`. Приведение константы — константа; значение константы должно помещаться в целевой тип (4.7).

### 4.7. Нетипизированные константы

Числовой и символьный литералы, имя константы (`const`) и `sizeof(T)` — **нетипизированные константы**. В операции с типизированным операндом такая константа принимает его тип (6.4). Константное выражение только из нетипизированных констант вычисляется **точно**, в знаковых целых без обёртывания по ширине типа, и остаётся нетипизированным. Результат или промежуточное значение вне диапазона −2^62…2^62−1 — ошибка. Деление округляет к нулю, остаток имеет знак делимого, `>>` арифметический, константный сдвиг на 63 бита и больше — ошибка.

**Приведение константы к типу T** допускает значение из диапазона −2^(n−1)…2^n−1, где n — ширина T в битах (8, 16 или 32); значение вне диапазона — ошибка. Значение, которое не помещается как знаковое, но помещается как беззнаковое (и наоборот), сохраняет битовый образ: `int($FFFF)` равно −1, `uint(-1)` равно 65535, `ulong(-1)` равно $FFFFFFFF. Тот же диапазон проверяется, когда нетипизированная константа принимает тип в операции (6.4), при присваивании, передаче аргумента и инициализации (6.2).

Если в выражении участвует приведение или типизированный операнд, результат типизирован и вычисляется по правилам 6.5 в ширине своего типа с обёртыванием по модулю 2^n.

**Инверсия константы.** Унарные `~` и `-` над нетипизированной константой тоже вычисляются точно, и результат может не поместиться в тип второго операнда. Типичный случай — сброс флага маской:

```
const F_DIR = $8000
var flags: uint
...
flags = flags & ~F_DIR          // ошибка: ~$8000 = -32769, вне -32768..65535
flags = flags & ~uint(F_DIR)    // правильно: ~ в uint, $7FFF
flags = flags & $7FFF           // правильно: маска записана явно
```

Если старший бит константы не установлен, ошибки нет: `~$4000` = −16385, и в `uint` это `$BFFF`. Для 32-битных операндов то же относится к константам от `$80000000`: `size & ~$80000000` — ошибка, `size & ~ulong($80000000)` — правильно.

### 4.8. sizeof и offsetof

`sizeof(T)` — размер типа T в байтах, нетипизированная константа. Операнд — только тип, не выражение. Размер функционального типа не определён (ошибка).

`offsetof(S, f)` — смещение поля f от начала структуры S в байтах, нетипизированная константа. Поле может быть путём через вложенные структуры: `offsetof(Rec, pos.hi)`. Структура должна быть определена выше по тексту.

## 5. Объявления

### 5.1. Пространства имён и области видимости

Имена делятся на четыре пространства:

| Пространство | Что в нём | Область видимости |
| --- | --- | --- |
| глобальные имена | константы, глобальные переменные, переменные `at`, функции | вся единица трансляции (3.3); `static` — файл (5.8) |
| локальные имена | параметры и локальные переменные | от объявления до конца блока |
| структуры | имена структур | вся единица трансляции |
| метки | метки `goto` | вся функция (7.6) |

Поля каждой структуры образуют своё пространство имён. Повторное объявление имени в одном пространстве на верхнем уровне — ошибка. Локальное имя может скрывать глобальное и локальное имя внешнего блока. Параметры функции находятся во внешнем блоке её тела.

### 5.2. Константы

```
ОбъявлениеКонстанты = "const" IDENT "=" КонстантноеВыражение EOS .
```

Константа — имя для значения константного выражения (6.10). Она не занимает памяти и является нетипизированной константой (4.7).

### 5.3. Переменные

```
ОбъявлениеПеременной = "var" СписокИмён ":" Тип EOS
                     | "var" IDENT [ ":" Тип ] "=" Инициализатор EOS
                     | "var" IDENT "at" КонстантноеВыражение ":" Тип EOS .
СписокИмён = IDENT { "," IDENT } .
Инициализатор = Выражение | "{" [ Элемент { "," Элемент } [ "," ] ] "}" .
Элемент = [ "." IDENT "=" ] Инициализатор .
```

Инициализатор допустим только при одном имени. Тип переменной не может быть функциональным.

**Тип по инициализатору.** Если тип не указан, он выводится:

| Инициализатор | Глобальная переменная | Локальная переменная |
| --- | --- | --- |
| строка длины n | `[n+1]byte`, байты строки — содержимое переменной | `ptr byte`, строка в области данных |
| нетипизированная константа | по значению (ниже) | по значению (ниже) |
| выражение типа T | T после сведения массивов | T после сведения массивов |

**Строка в локальной переменной.** Локальная `var s = "tmp0000"` без типа — указатель на строку в области данных, а не её копия: запись `s[3] = '1'` пишет в литерал (12.1), а при `option data` литерал лежит в ПЗУ. Изменяемый шаблон внутри функции объявляют массивом: `var s: [8]byte = "tmp0000"` — копия создаётся при каждом выполнении объявления (13.6), и запись в неё безопасна. Вернуть из функции указатель на такой локальный массив нельзя (он живёт в кадре, 9.4); указатель на литерал вернуть можно.

**Тип по значению константы** — первый из `int`, `uint`, `long`, `ulong`, в диапазон которого входит значение: −32768…32767 — `int`, 32768…65535 — `uint`, −2147483648…−32769 и 65536…2147483647 — `long`, 2147483648…4294967295 — `ulong`. Значение вне −2^31…2^32−1 — ошибка. Явный тип задаётся приведением или аннотацией: `var x: long = 5`, `var y = ulong(5)`.

**Глобальные переменные** существуют всё время выполнения программы. Без инициализатора они содержат нули. Инициализатор вычисляется при трансляции и может быть:

- константным выражением;
- строкой — для массива байтового типа (строка с нулём должна поместиться; остаток заполняется нулями) или для указателя (тогда переменная указывает на строку в области данных);
- адресом глобального объекта: `&g`, `&g[k]`, `&g.f` с константными индексами, или именем массива;
- именем функции (адрес функции);
- адресом метки `__image_end` или `__bss_end` (9.1);
- приведением одного из перечисленного;
- списком `{ ... }` — для массива или структуры, в том числе вложенным.

Значения проверяются по правилам присваивания (6.2). Скаляр байтового типа инициализируется только числом, массив байтового типа — также строкой.

**Списки инициализации.** Элементы списка массива задают элементы по порядку; их не больше длины массива. Элементы списка структуры задают поля: позиционный элемент — следующее поле, элемент `.f = значение` — поле f, после него позиционные элементы продолжаются с поля, следующего за f. Поле, заданное дважды, и несуществующее поле — ошибки. Незаданные элементы и поля, а также байты выравнивания — нули. `.f =` допустимо только в списке структуры.

```
struct Key { scan: byte; name: ptr byte }
var keys: [2]Key = { { $48, "^" }, { .scan = $50, .name = "v" } }
```

**Локальные переменные** объявляются оператором `var` в теле функции (7.2). Они существуют, пока выполняется функция, независимо от блока. Инициализатор локального скаляра — любое выражение. Локальный массив или структуру можно инициализировать списком (для массива байтового типа — строкой) с любыми выражениями в элементах; объект заполняется при каждом выполнении объявления, незаданные части — нулями. Без инициализатора значение не определено.

**Статические локальные переменные** объявляются в теле функции как `static var` с тем же синтаксисом, но только с одним именем. Такая переменная хранится в области данных, как глобальная, существует всё время выполнения программы и сохраняет значение между вызовами; её имя видно только в своём блоке. Инициализатор — как у глобальной переменной.

**Переменная по адресу** (`at`) — глобальное имя для объекта типа T, расположенного по указанному адресу. Памяти она не занимает, инициализатора не имеет. T — скаляр, массив или структура. Каждое обращение к такой переменной в программе выполняется как обращение к памяти по этому адресу (9.7), поэтому через `at` описываются порты устройств и таблица векторов.

### 5.4. Структуры

```
ОбъявлениеСтруктуры = "struct" IDENT "{" { СписокПолей EOS | EOS } "}" .
СписокПолей = IDENT { "," IDENT } ":" Тип .
```

Поля разделяются `EOS` — переводом строки или `;`. Тип поля — любой тип, кроме функционального; поле может иметь тип `ptr S`, где S — эта же структура. Раскладка полей описана в 4.4. Повторное определение структуры и повторное имя поля — ошибки.

### 5.5. Функции

```
ОбъявлениеФункции = [ "static" | "export" | "extern" ] [ "interrupt" ] "fn" IDENT "(" [ Параметры ] ")" [ ":" Результаты ] ( Блок | EOS ) .
Параметры = ГруппаПараметров { "," ГруппаПараметров } .
ГруппаПараметров = IDENT { "," IDENT } ":" Тип .
```

Нетерминал `Результаты` определён в 4.5 (список типов, в скобках или без). Пометки `static`, `export` и `extern` входят в `ОбъявлениеФункции`, как и `interrupt`; допустимые сочетания пометок описаны ниже.

- Типы параметров и результатов — скаляры. Запись `a, b: int` объявляет два параметра типа `int`.
- Функция возвращает результаты общим размером не более четырёх слов (`long` и `ulong` — по два слова, прочие — по одному), то есть от 0 до 4 результатов, из них не более двух двухсловных.
- Объявление без тела — **прототип**. Функция может иметь не более одного определения с телом и любое число прототипов. Прототип и определение должны совпадать по типам параметров и результатов, признакам `interrupt` и `static`.
- Пометка `export` делает функцию точкой входа. Функция `export` должна быть определена в программе; прототип `export` без определения — ошибка. Она всегда попадает в образ, от неё считается достижимость (3.5), её имя в ассемблере не меняется (10.3), поэтому её можно вызывать из ассемблерных модулей. Пометка действует во всех режимах, в том числе в программах с `main`; достаточно поставить её в одном из объявлений функции. `export` и `interrupt` совместимы, `export` и `static` — ошибка.
- Функция, у которой есть только прототип, должна быть определена вне программы на B16, например в ассемблерном модуле (10.4).
- Пометка `extern` объявляет, что функция определена вне B16. Объявление `extern fn` — всегда прототип: тело у него — ошибка, а определение той же функции с телом в программе (до или после `extern`-объявления) — тоже ошибка. Достаточно пометить одно из объявлений функции. Прототип без `extern`, для которого в программе нет определения, допустим, но реализация предупреждает о нём (12.2): так обнаруживается забытое тело функции. `extern` применяется только к функциям, в том числе к `interrupt fn` (обработчик в ассемблере, адрес которого программа записывает в таблицу векторов); `extern` вместе со `static` или `export` — ошибка. Имя `extern`-функции в ассемблере образуется по 10.3.

### 5.6. Обработчики прерываний

`interrupt fn` объявляет обработчик прерывания. У обработчика нет параметров и результатов. Вызвать его как функцию нельзя (ошибка); его адрес типа `ptr interrupt fn()` (4.5) получают по имени и записывают в таблицу векторов. Отличия кода обработчика от обычной функции описаны в 9.5.

### 5.7. Проверки при трансляции

```
Проверка = "assert" КонстантноеВыражение [ "," STRING ] EOS .
```

Объявление верхнего уровня `assert` вычисляет константное выражение при трансляции. Если оно равно 0, это ошибка трансляции с текстом строки, если она задана. Проверки нужны для раскладок, заданных внешними форматами (записи каталога ФС16, заголовок CX16, PIB):

```
assert sizeof(DirEntry) == 64
assert offsetof(Header, bss_end) == 14, "заголовок CX16"
```

Имена в выражении должны быть объявлены выше по тексту (3.3).

### 5.8. Видимость в пределах файла

Пометка `static` перед объявлением функции или глобальной переменной (в том числе `at`) делает имя видимым только в файле, где оно объявлено: в том исходном файле, а не во всей единице трансляции. Внутри файла `static`-имя скрывает одноимённое глобальное имя другого файла. Два `static`-имени в разных файлах, а также `static`-имя одного файла и глобальное имя другого, могут совпадать; два имени одного файла — нет. `static` применяется только к `fn` и `var`. В ассемблере такие имена получают вид `файл.имя` (10.3).

## 6. Выражения

### 6.1. Приоритет и ассоциативность

| Уровень | Операции | Ассоциативность |
| --- | --- | --- |
| 1 (высший) | `f(...)` `a[i]` `s.f` `x++` `x--` | слева направо |
| 2 | унарные `-` `~` `!` `*` `&` `++x` `--x` | справа налево |
| 3 | `*` `/` `%` | слева направо |
| 4 | `+` `-` | слева направо |
| 5 | `<<` `>>` | слева направо |
| 6 | `&` | слева направо |
| 7 | `^` | слева направо |
| 8 | `\|` | слева направо |
| 9 | `==` `!=` `<` `>` `<=` `>=` | неассоциативны |
| 10 | `&&` | слева направо |
| 11 | `\|\|` | слева направо |
| 12 (низший) | `=` `+=` `-=` `*=` `/=` `%=` `&=` `\|=` `^=` `<<=` `>>=` | справа налево |

Битовые операции связывают сильнее сравнений: `x & M == 0` означает `(x & M) == 0`. Цепочка сравнений `a < b < c` — ошибка.

### 6.2. Значения, l-значения, сведение

**L-значение** обозначает объект в памяти или регистре: имя переменной (локальной, глобальной, `at`), `*p`, `a[i]` и `s.f`. Остальные выражения — r-значения. Присваивание, `++`, `--` применимы только к l-значениям скалярного типа; `&` — к любому l-значению.

В выражении значение массива сводится к указателю на первый элемент, имя функции — к указателю на функцию. Значение байтового типа продвигается до слова (4.1). Операнды всех операций, кроме `&`, `.` и `sizeof`, должны быть скалярами после сведения; иначе — ошибка.

**Неявное присваивание** значения объекту типа T происходит при присваивании, инициализации, передаче аргумента, возврате результата и множественном присваивании. Целые типы взаимно присваиваемы, кроме сужения: значение типа `long` или `ulong` не присваивается объекту типа `byte`, `char`, `uint`, `int` — нужно явное приведение (4.6). Значение более узкого целого типа присваивается объекту типа `long` или `ulong` с расширением по знаку источника: `byte` и `uint` расширяются нулями, `char` и `int` — знаком. `long` и `ulong` взаимно присваиваемы без преобразования битов. В объект байтового типа записывается младший байт. Указатель не присваивается объекту типа `long`, `ulong`, и наоборот. Указатели подчиняются правилам 4.2: указатель присваивается только указателю совместимого типа, целое — указателю только как константа 0, указатель целому — никогда. Нарушение — ошибка.

### 6.3. Первичные выражения

```
Первичное = NUMBER | СИМВОЛ | STRING | IDENT | "(" Выражение ")"
          | "sizeof" "(" Тип ")" | "offsetof" "(" IDENT "," IDENT { "." IDENT } ")"
          | Приведение | ВызовВстроенной .
```

- **Имя** обозначает локальную переменную, глобальную переменную, константу или функцию. Неизвестное имя — ошибка.
- **Строка** обозначает безымянный массив `[n+1]byte` в области данных, существующий всё время выполнения. Его содержимое можно изменять. Одинаковые строки — разные объекты.

### 6.4. Знаковость и тип результата

Каждый скалярный тип либо знаковый (`int`, `char`), либо беззнаковый (`uint`, `byte`, указатели).

**Правило знаковости.** У операций `/`, `%`, `<`, `>`, `<=`, `>=` оба операнда должны иметь одинаковую знаковость. Если один из операндов — нетипизированная константа, он принимает знаковость другого. Исключение: беззнаковый операнд не шире слова (`byte`, `uint`, указатель) вместе со знаковым двухсловным (`long`) допустим — он расширяется без потери значения, операция знаковая. Остальные нарушения — ошибка: например, `int` с `ulong` и `long` с `ulong`. Операция выполняется как знаковая или беззнаковая в зависимости от общей знаковости. У `>>` знаковость определяет только левый операнд. Остальные операции не зависят от знаковости, и смешивать операнды в них разрешено.

**Тип результата** бинарной операции `+ - * / % & | ^`:

1. если один из операндов двухсловный — результат двухсловный: при двух двухсловных операндах это тип левого, иначе тип двухсловного операнда; другой операнд расширяется по знаку своего типа (4.1, 6.2), нетипизированная константа принимает двухсловный тип;
2. иначе, если левый операнд — нетипизированная константа, тип результата — продвинутый тип правого операнда;
3. иначе — продвинутый тип левого операнда;
4. если так получился указатель, а операция не арифметика указателей (6.6), тип результата — `uint`.

Операция над двухсловным и более узким операндами выполняется над двойными словами. Поэтому `uint(a) * uint(b)` — 16-битное произведение, а `ulong(a) * ulong(b)` — полное 32-битное.

У `<<` и `>>` тип результата — продвинутый тип левого операнда, а тип правого может быть любым целым; у двухсловного правого операнда используется младшее слово. Нетипизированная константа слева от сдвига с неконстантным счётчиком имеет тип `int` (для 32-битного сдвига константу приводят: `ulong(1) << n`). Сравнения, `!`, `&&`, `||` дают `int`.

### 6.5. Арифметические и битовые операции

Операции над значениями не шире слова выполняются над 16-битными словами, результат берётся по модулю 2^16. Операции над двухсловными значениями выполняются над 32-битными, результат берётся по модулю 2^32. Переполнение не обнаруживается.

| Операция | Значение |
| --- | --- |
| `-x` | дополнительный код: 0 − x |
| `~x` | побитовая инверсия |
| `!x` | 1, если x = 0, иначе 0 |
| `a * b` | младшие 16 (для двухсловных — 32) бит произведения (одинаково для знаковых и беззнаковых) |
| `a / b` | частное; знаковое деление округляет к нулю |
| `a % b` | остаток; при знаковом делении знак остатка — знак делимого, a = (a / b) · b + a % b |
| `a + b`, `a - b` | сумма, разность |
| `a & b`, `a \| b`, `a ^ b` | побитовые И, ИЛИ, исключающее ИЛИ |
| `a << n` | сдвиг влево |
| `a >> n` | сдвиг вправо: логический для беззнакового a, арифметический для знакового |

**Деление на ноль.** Беззнаковое деление слов: `a / 0` = $FFFF, `a % 0` = a (зависит от процессора). Беззнаковое деление двойных слов (`ulong`): `a / 0` = $FFFFFFFF, `a % 0` = a, на любом процессоре. Знаковое деление и остаток на 0 — неопределённое поведение.

**Наименьшее значение, делённое на −1.** Для `long`: `-2147483648 / -1` равно −2147483648, `-2147483648 % -1` равно 0 (обёртывание, неопределённости нет).

**Сдвиги.** Если n — константа: при n ≥ 16 результат `<<` и беззнакового `>>` равен 0, знакового `>>` — 0 или −1 по знаку a. Если n вычисляется при выполнении, используются младшие 4 бита n (сдвиг на n mod 16), а для двухсловного левого операнда — младшие 5 бит (сдвиг на n mod 32). Для двухсловного левого операнда при константном n ≥ 32 результат `<<` и беззнакового `>>` равен 0, знакового `>>` — 0 или −1 по знаку a; реализация предупреждает о константном сдвиге на число, не меньшее ширины типа (12.2).

### 6.6. Арифметика указателей

Пусть p, q имеют тип `ptr T`, i — целого типа, s = sizeof(T):

| Выражение | Значение | Тип |
| --- | --- | --- |
| `p + i`, `i + p` | адрес p + i · s | `ptr T` |
| `p - i` | адрес p − i · s | `ptr T` |
| `p - q` | (p − q) / s, знаковое | `int` |
| `p + q` | ошибка | — |

Для `p - q` указатели должны быть одного типа, а размер s — степенью двойки, иначе — ошибка. Над нетипизированным указателем и указателем на функцию эти операции недопустимы (4.2). Указатели сравниваются как беззнаковые числа. Другие операции над указателем выполняются над его 16 битами и дают `uint`.

### 6.7. Сравнения и логические операции

Сравнение даёт 1, если отношение выполняется, иначе 0. Операнды сравнения приводятся к общей ширине: если один из них двухсловный, другой расширяется до двойного слова по знаку своего типа (6.4); при `==` и `!=` сравниваются полученные битовые образы. Двухсловные значения сравниваются целиком. Условие с двухсловным значением истинно, если не равны нулю оба слова вместе, то есть если значение не равно 0. Два указателя сравнимы, только если их типы совпадают или один из них нетипизированный (`ptr`, кроме сравнения с указателем на функцию); указатель с константой 0 сравним всегда, с другим целым — нет. `a && b` вычисляет b, только если a ≠ 0; `a || b` вычисляет b, только если a = 0. Результат обеих — 0 или 1.

### 6.8. Указатели, индексы, поля

- `*p` — объект типа T, на который указывает `p` типа `ptr T`. Операнд другого типа или T функционального типа — ошибка.
- `&x` — адрес l-значения x, тип `ptr T`. `&f` для функции f равно f; `&*p` равно p; `&v` для переменной `at` — её адрес как константа типа `ptr T`. Взятие адреса локальной переменной допустимо: такая переменная размещается в памяти (9.4).
- `a[i]` означает `*(a + i)`. `a` — массив или указатель, i — целое не шире слова (не указатель; значение типа `long`, `ulong` приводится явно: `a[uint(i)]`). То же относится к `p + i`, `p - i`, `p += i`, `p -= i`. Нетипизированная константа в индексе и в арифметике указателей принимает тип `int`. Элемент функционального типа — ошибка. Выход за границы массива не проверяется.
- `s.f` — поле f структуры s. Если s — указатель на структуру, разыменование выполняется автоматически: `p.f` означает `(*p).f`.

### 6.9. Присваивание, инкремент и вызов

**Присваивание** `l = e` записывает значение e в l и само имеет значение записанного (для байтового l — усечённого) значения типа l. Составное присваивание `l op= e` равносильно `l = l op e`, но l вычисляется один раз. Для `+=` и `-=` над указателем действует масштабирование 6.6; запись `i += p`, где i — целое, а p — указатель, — ошибка.

**Инкремент и декремент.** `++x`, `--x` изменяют x на 1, а указатель — на размер элемента, и дают новое значение. `x++`, `x--` дают прежнее значение.

**Вызов** `f(e1, ..., en)`: f — имя функции или выражение типа `ptr fn(...)`. Число аргументов должно совпадать с числом параметров; аргумент — скаляр, присваиваемый типу параметра (6.2). Аргумент байтового параметра усекается до байта. Значение вызова — первый результат функции. Вызов функции без результатов как значение — ошибка. Вызов обработчика прерывания — ошибка.

**Порядок вычисления** операндов и аргументов не определён, кроме `&&` и `||`. Изменение и чтение одного объекта в одном выражении без промежуточной `&&` или `||` (например, `a[i] = i++`) — неопределённое поведение.

### 6.10. Константные выражения

Константное выражение составлено из нетипизированных констант, приведений констант и операций над ними, кроме присваиваний, инкрементов и вызовов. Нетипизированные константы вычисляются точно (4.7), типизированные — по правилам 6.5. Деление на ноль в константном выражении — ошибка.

Константное выражение обязательно в объявлении `const`, в `assert`, в размере массива, в адресе `at` и в аргументе `trap`. В остальных местах константные подвыражения вычисляются при трансляции.

## 7. Операторы

```
Оператор = Блок | [ "static" ] ОбъявлениеПеременной | ОператорВыражение | If | While | Loop
         | Break | Continue | Return | МножественноеПрисваивание
         | Метка | Goto | Atomic | Asm .
Блок = "{" { Оператор | EOS } "}" .
```

Операторы выполняются последовательно. Простой оператор завершается `EOS` или стоит непосредственно перед `}`. Тело `if`, `else`, `while`, `loop`, `atomic` — всегда блок в фигурных скобках; условие записывается без скобок.

### 7.1. Блок

Блок открывает область видимости локальных имён (5.1). Пустой блок `{}` допустим.

### 7.2. Объявление переменной

Оператор `var` внутри функции объявляет локальные переменные (5.3), `static var` — статическую локальную переменную. Объявление `var` с инициализатором выполняет присваивание (для массива и структуры — заполнение объекта) в том месте, где стоит. Переход `goto` через объявление допустим; переменная тогда не инициализирована. Локальная переменная без типа с инициализатором-строкой — указатель на литерал (5.3); для изменяемого текста нужен массив с типом.

### 7.3. Оператор-выражение

```
ОператорВыражение = Выражение EOS .
```

Выражение вычисляется, значение отбрасывается. Чаще всего это присваивание, инкремент или вызов. Значение вызова функции без результатов в операторе допустимо. Если оператор не является присваиванием, инкрементом, декрементом или вызовом, реализация предупреждает, что значение не используется (12.2): так обнаруживается перенос `x = a` / `- b`, где вторая строка стала отдельным оператором.

### 7.4. if

```
If = "if" Выражение Блок [ "else" ( If | Блок ) ] .
```

Условие — скаляр. Если его значение не 0, выполняется первый блок, иначе — ветвь `else`, если она есть.

### 7.5. Циклы

```
While = "while" Выражение Блок .
Loop = "loop" Блок .
Break = "break" EOS .
Continue = "continue" EOS .
```

`while` проверяет условие перед каждой итерацией и выполняет блок, пока условие не 0. `loop` выполняет блок бесконечно. `break` завершает самый внутренний охватывающий цикл; `continue` переходит к проверке условия самого внутреннего `while` или к началу самого внутреннего `loop`. `break` и `continue` вне цикла — ошибка.

### 7.6. Метки и goto

```
Метка = IDENT ":" .
Goto = "goto" IDENT EOS .
```

Метка — идентификатор, за которым на той же строке следует `:`, в начале оператора. После метки может идти оператор на той же или следующей строке; метка может стоять последней в блоке.

- Метка видна во всей функции, в том числе до своего определения. Метки разных функций независимы.
- Повторная метка в функции и `goto` на неопределённую метку — ошибки.
- `goto L` передаёт управление оператору, следующему за меткой L. Допустим переход внутрь блока и цикла, а также наружу из них.
- Переход внутрь блока `atomic`, не содержащего сам `goto`, — ошибка. Переход наружу из блоков `atomic` допустим: при нём восстанавливается состояние прерываний каждого покидаемого блока (7.9).

### 7.7. return

```
Return = "return" [ Выражение { "," Выражение } ] EOS .
```

Число выражений должно в точности равняться числу результатов функции. `return` завершает функцию и возвращает значения; для результата байтового типа значение усекается. Выход из функции без результатов через конец тела допустим. Функция с результатами, которая может дойти до конца тела, — ошибка. Достижимость конца определяется по управлению без учёта значений условий, кроме констант: `loop` без `break` и `while 1` конец не достигают, `if` без `else` — достигает.

### 7.8. Множественное присваивание

```
МножественноеПрисваивание = Цель "," Цель { "," Цель } "=" Вызов EOS .
Цель = ВыражениеБезПрисв | "_" .
```

`ВыражениеБезПрисв` — выражение без присваивания на верхнем уровне (определено в разд. 11): иначе в `a, b = f()` цель `b = f()` читалась бы как присваивание.

Справа — вызов функции, слева — от 2 до 4 скалярных l-значений или `_`. Результаты функции присваиваются целям по порядку; `_` отбрасывает соответствующий результат. Целей не может быть больше, чем результатов; лишние результаты отбрасываются. Вызов через указатель на функцию возвращает столько результатов, сколько их у функционального типа (4.5). Каждый результат присваивается своей цели по правилам 6.2.

### 7.9. atomic

```
Atomic = "atomic" Блок .
```

На время выполнения блока маскируемые прерывания запрещены. При любом выходе из блока — через его конец, `break`, `continue`, `return` или `goto` — восстанавливается состояние флага IF, которое было до входа. Блоки `atomic` могут вкладываться; вложенный блок при выходе восстанавливает состояние внешнего, то есть запрещённые прерывания.

### 7.10. asm

```
Asm = "asm" "{" ТекстАссемблера "}" .
```

Текст между фигурными скобками (вложенные пары `{}` допустимы) передаётся ассемблеру. `{` должна стоять на той же строке, что и `asm`. Правила оформления текста и взаимодействия с кодом компилятора — в разделе 10.

## 8. Встроенные функции

```
ВызовВстроенной = ИмяВстроенной "(" [ Выражение { "," Выражение } ] ")" .
ИмяВстроенной = "mulhu" | "ror" | "xchb" | "di" | "ei" | "wfi" | "trap" .
```

Встроенная функция транслируется в одну команду процессора без вызова. Без скобок имя встроенной функцией не является (2.4), поэтому взять её адрес нельзя. Неверное число аргументов — ошибка.

| Функция | Результат | Действие | Команда |
| --- | --- | --- | --- |
| `mulhu(a, b)` | `uint` | старшие 16 бит беззнакового произведения a · b | `MULHU` |
| `ror(x, n)` | `uint` | циклический сдвиг x вправо на n mod 16 бит | `ROR` |
| `xchb(p, v)` | `uint` | атомарно записывает младший байт v по адресу p и возвращает прежний байт, расширенный нулями; p — указатель на байтовый тип | `XCHB` |
| `di()` | нет | запрещает маскируемые прерывания (IF = 0) | `CLI` |
| `ei()` | нет | разрешает маскируемые прерывания (IF = 1) | `STI` |
| `wfi()` | нет | ожидает прерывания | `WFI` |
| `trap(n)` | нет | программное прерывание с вектором n; n — константное выражение 0…15 | `TRAP` |

Вызов `di`, `ei`, `wfi`, `trap` как значение — ошибка. Младшие 16 бит произведения даёт операция `*` (6.5). Аргументы `mulhu`, `ror` и второй аргумент `xchb` — целые, указатель — ошибка.

## 9. Модель выполнения и двоичный интерфейс

Этот раздел обязателен для кода, который взаимодействует с программой на B16 на уровне машины: ассемблерных модулей, обработчиков, отладчиков.

### 9.1. Размещение в памяти

Программа собирается в формате исполняемого файла CX16 («Монитор CPU16: формат исполняемого файла и запуск программ», разд. 3). Образ по возрастанию адресов:

| Адреса | Содержимое |
| --- | --- |
| `$0000`–`$001B` | заголовок CX16 (9.2) |
| с `$001C` | стартовый код, затем код функций в порядке исходного текста, затем рантайм (9.6) |
| сразу за кодом | инициализированные глобальные переменные в порядке объявления, затем строковые литералы |
| далее | `.align 2`, метка `__image_end`, неинициализированные глобальные переменные, метка `__bss_end` |
| ниже вершины стека | стек, растёт вниз |

Неинициализированные переменные (bss) в файл не попадают: их обнуляет загрузчик монитора или стартовый код на голой машине. Вершина стека — `top` под монитором и `$FF00` на голой машине. На голой машине `$FF00`–`$FF1F` — таблица векторов прерываний, `$FF20`–`$FFFF` — порты устройств.

Если начало данных задано отдельно от кода (`option data`, 3.6), все глобальные переменные, инициализированные и нет, лежат с этого адреса, а начальные значения инициализированных — в **образце** рядом с кодом; стартовый код копирует образец в область данных. Строковые литералы остаются рядом с кодом. Так программа может работать из ПЗУ.

`__image_end` и `__bss_end` — встроенные имена типа `ptr`: адреса конца образа и конца статических данных. От `__bss_end` отсчитывается начало кучи; на голой машине по нему видна граница, к которой растёт стек.

Каждый объект в области данных занимает чётное число байт и начинается с чётного адреса. Объекты словного типа, поля словного типа и стек всегда выровнены по слову. Переполнение стека не обнаруживается.

### 9.2. Стартовый код

Если в программе есть `main`, образ начинается с заголовка CX16 и стартового кода:

```
__header:
        JMP   #__start
        .ascii "CX16"
        .word 1, 0                    ; version, flags
        .word __image_end, __bss_end
        .word min_free, max_top        ; option min_free, max_top; по умолчанию 2048 и 0 (3.6)
        .word 0, 0, 0, 0
__start:
        LD    R4, [$0006]             ; "CXPB" - монитор, "CX16" - голая машина
        CMP   R4, #$4250
        JZ    @monitor
        ...                           ; голая машина: SP, векторы, bss, argc = argv = 0
        LD    LR, #__halt
@monitor:
        PUSH  LR
        ...                           ; копирование образца данных, если он есть
        CALL  main
        LD    R0, #0                  ; если у main нет результата
        POP   IP
```

Один и тот же образ запускается двумя способами («Монитор CPU16», разд. 8).

- **Под монитором** по адресу `$0004` лежит PIB с сигнатурой `"CXPB"`. Стек, таймер и векторы принадлежат монитору, bss обнулён, R0 = argc, R1 = argv, LR — процедура выхода. Стартовый код не устанавливает SP, не трогает таймер и векторы, не выполняет `CLI` и `WFI`. Он сохраняет LR, вызывает `main` с argc и argv и завершает программу переходом по LR с кодом завершения в R0.
- **На голой машине** по `$0004` лежит сам заголовок (`"CX16"`). Стартовый код устанавливает SP = `$FF00`; ставит вектор ERRCMD на `__fault` (остановка), а остальные векторы — на пустой обработчик `__irq_ignore` (`IRET`); обнуляет bss, потому что состояние памяти после сброса не определено; вызывает `main` с argc = 0 и argv = 0. После возврата из `main` `__halt` выключает таймер, принимает висящий запрос прерывания (`STI`, затем `CLI`) и останавливает процессор (`WFI`). Принять запрос нужно: запрос IRQ0, выставленный при IF = 0, не снимается выключением таймера, и `WFI` при IF = 0 просыпается по нему снова и снова, не входя в обработчик, так что машина не останавливается. Все неиспользуемые векторы ведут на `__irq_ignore`, поэтому запрос принимается пустым обработчиком. Так же останавливает машину `__fault`.

Регистры при входе в `main`, кроме R0, R1 и SP, не определены. Состояние прерываний при входе — как задал способ запуска: IF = 1 под монитором, IF = 0 на голой машине.

### 9.3. Соглашение о вызовах

| Ресурс | Назначение | Кто сохраняет |
| --- | --- | --- |
| R0–R3 | первые четыре слота аргументов и результатов | не сохраняются |
| R4–R11 | переменные | вызываемая функция |
| LR | адрес возврата, записывает `CALL` | не сохраняется |
| SP | указатель стека | должен быть восстановлен |
| FLAGS | флаги | не сохраняются (IF функция не меняет) |

1. **Слоты.** Аргумент типа `byte`, `char`, `uint`, `int` и указатель занимает один слот, `long` и `ulong` — два подряд: младшее слово в первом, старшее во втором. Слоты нумеруются от 0 по порядку аргументов слева направо, слоты 0–3 — регистры R0–R3. Аргумент передаётся в регистрах, если все его слоты — 0–3; иначе он и все следующие за ним аргументы передаются в стеке, даже если часть регистров осталась свободной (например, в `fn(a, b, c: uint, d: long, e: uint)` значения d и e идут в стек).
2. **Стек.** Стековые аргументы кладутся справа налево, каждый занимает слово или два слова; при входе в функцию первый стековый аргумент лежит по адресу SP, следующий — выше. У двухсловного аргумента младшее слово лежит по меньшему адресу. После возврата стековые аргументы снимает вызывающий.
3. **Результаты.** Результаты занимают слоты 0–3 по тем же правилам, суммарно не более четырёх слов; результат i возвращается в регистрах своих слотов (`long`: младшее слово в Rk, старшее в Rk+1).
4. Аргумент байтового параметра расширяет вызывающий; результат байтового типа расширяет вызываемый. Значение байтового типа в регистре всегда расширено (`byte` — нулями, `char` — знаком).
5. Вызов выполняется командой `CALL`, возврат — переходом по адресу из LR. Функция, которая сама вызывает другие, сохраняет LR в стеке.

Пример: `fn f(a: uint, b: long, c: uint): ulong` получает a в R0, b в R1 (младшее слово) и R2 (старшее), c в R3 и возвращает результат в R0 (младшее слово) и R1 (старшее).

### 9.4. Кадр функции

Функция, которой нужны сохранения или память в стеке, строит кадр:

```
        PUSH  LR              ; если функция вызывает другие
        PUSH  Rk ...          ; используемые R4..R11 по возрастанию номера
        SUB   SP, #размер     ; память переменных, если нужна
```

и разбирает его в обратном порядке. Последней командой нелистовая функция загружает сохранённый LR прямо в IP (`POP IP`), листовая выполняет `RET` (`LD IP, LR`).

В памяти кадра (по возрастанию адресов от SP) лежат переменные, которым не выделен регистр: локальные массивы и структуры, переменные, чей адрес берётся, и переменные сверх доступных регистров. Переменная типа `long` или `ulong` занимает в регистрах два регистра (не обязательно соседних) или четыре байта в кадре. Каждая занимает чётное число байт. Над областью переменных лежат сохранённые регистры, над ними — LR, ещё выше — стековые аргументы. Указателя кадра нет.

### 9.5. Прерывания

Процессор при входе в обработчик сохраняет в стеке IP и FLAGS и запрещает прерывания. Обработчик, объявленный `interrupt fn`:

- сохраняет все регистры R0–R11, которые использует;
- если вызывает функции — дополнительно сохраняет R0–R3 и LR;
- завершается командой `IRET`, которая восстанавливает FLAGS (включая IF) и IP.

Обработчик устанавливается записью его адреса в таблицу векторов, например через переменную `at`:

```
var VEC at $FF00: [16]ptr interrupt fn()
interrupt fn on_tick() { ticks++ }
...
VEC[0] = on_tick
```

Назначение векторов: 0–7 — IRQ0–IRQ7, 8 — недопустимая команда (ERRCMD), 9–15 — свободны для `trap(n)`. Под монитором векторы принадлежат монитору, и программа их не записывает.

### 9.6. Рантайм

Знаковые `/` и `%` над словами с делителем, не являющимся константой (а также с делителем −32768), и операции над двухсловными значениями, которые не выполняются на месте, выполняются вызовами функций рантайма. Реализация добавляет их в образ при необходимости:

| Функция | Действие |
| --- | --- |
| `__divs` | R0 = R0 / R1 (знаковое, округление к нулю) |
| `__mods` | R0 = R0 % R1 (знак делимого) |
| `__mul32` | R0:R1 = R0:R1 · R2:R3 (младшие 32 бита; для знаковых и беззнаковых одинаково) |
| `__divu32`, `__modu32` | R0:R1 = R0:R1 / R2:R3 и R0:R1 % R2:R3, беззнаковые; деление на 0 — 6.5 |
| `__divs32`, `__mods32` | то же, знаковые; частное округляется к нулю, остаток имеет знак делимого |
| `__shl32`, `__shr32`, `__sar32` | R0:R1 = R0:R1 сдвинутое на R2 mod 32 бит влево, логически вправо, арифметически вправо |
| `__udivc32`, `__umodc32` | беззнаковые R0:R1 / R2 и R0:R1 % R2 при константном делителе 3…255: четыре шага `DIVU`/`REMU` по байтам делимого; частное в R0:R1, остаток в R2 (`__udivc32`) или в R0:R1 (`__umodc32`) |

Двухсловное значение в R0:R1 — младшее слово в R0, старшее в R1; все функции подчиняются соглашению о вызовах (9.3) и совпадают по сигнатуре с функциями `fn(a, b: long): long` (сдвиги — `fn(a: long, n: uint): long`). Функция, содержащая такую операцию, считается вызывающей другие функции (9.3, п. 5). Деление и остаток на другие константы выполняются на месте: на степень двойки — сдвигами и масками, знаковое над словами на прочие константы — умножением на обратное через `MULHU`; умножение на степень двойки — сдвигом.

Над двухсловными значениями на месте выполняются `+`, `-`, унарный минус, `~`, `&`, `|`, `^`, сравнения и сдвиги на константу. Произведение двух значений типов `byte` или `uint`, приведённых к `ulong` (`ulong(a) * ulong(b)`), выполняется командами `MUL` и `MULHU` без вызова рантайма.

### 9.7. Обращения к памяти

- Каждое вхождение глобальной переменной или переменной `at` в выражении выполняется как отдельное обращение к памяти в момент вычисления этого вхождения. Значения глобальных переменных не хранятся в регистрах между обращениями. Составное присваивание и инкремент читают и записывают объект по одному разу.
- Чтение и запись словного объекта по выровненному адресу выполняются одной командой и не прерываются. Чтение и запись объекта типа `long` или `ulong` — две команды, младшее слово первым; между ними возможно прерывание, поэтому двухсловный объект, который меняет или читает и обработчик прерывания, читают и пишут в блоке `atomic`. Это относится и к объектам `at`: сначала выполняется обращение к младшему слову, затем к старшему. Составное присваивание и инкремент глобальной переменной (`g++`) — несколько команд; если ту же переменную меняет обработчик прерывания, такую операцию нужно выполнять в блоке `atomic`.
- Для локальных переменных число и порядок обращений не определены.

## 10. Ассемблерные вставки

### 10.1. Текст блока

Каждая строка блока `asm`, кроме пустых, передаётся ассемблеру как строка программы; комментарий `;` до конца строки отбрасывается. Строка может начинаться с метки:

- допустимы только локальные метки вида `@имя` (их область — функция, в которой стоит блок);
- метки `@L` с цифрами после `L` зарезервированы реализацией;
- глобальная метка (без `@`) — ошибка.

Компилятор не проверяет команды блока: ошибки в них сообщает ассемблер.

### 10.2. Взаимодействие с кодом функции

Блок `asm` — оператор. Перед ним и после него действуют следующие правила.

1. Состояние флагов после блока считается неизвестным.
2. Компилятор считает, что значения переменных, размещённых в регистрах, после блока остались прежними. Если блок изменяет регистр переменной, переменная получает новое значение.
3. Между операторами промежуточных значений нет: регистры, не занятые переменными, в блоке свободны. Используемые блоком регистры R4–R11, которые компилятор не отвёл переменным, блок обязан сохранить сам.
4. Если в тексте блока (вне комментариев) встречается мнемоника `CALL`, функция считается вызывающей другие функции: компилятор сохраняет LR и размещает переменные функции в R4–R11. Поэтому в такой функции R0–R3 в блоке свободны, а вызываемая из блока функция может их портить.
5. Имена глобальных переменных и функций, встречающиеся в тексте блока, доступны как метки ассемблера (10.3) и делают функции достижимыми (3.5). Имена `static`-объектов текущего файла и статических локальных переменных, видимых в месте блока, заменяются в тексте их именами в ассемблере (`helper` → `util.helper`).
6. Если `interrupt fn` не содержит операторов, кроме `asm`-блоков без команды CALL, компилятор не сохраняет регистры: при входе в блок `[SP]` — сохранённый FLAGS, `[SP+2]` — адрес возврата. Блок сам сохраняет всё, что портит.
7. Если тело функции начинается с `asm`-блока, то при входе в этот блок R0–R3 содержат аргументы функции по соглашению 9.3, а пролог функции R0–R3 не изменяет. Это относится и к параметрам, которые в коде B16 не используются: регистр им не отводится, и они остаются в R0–R3 нетронутыми.

Размещение переменных по регистрам язык не определяет. Эталонная реализация гарантирует только два случая (13.6): в функции, не вызывающей других, параметр находится в регистрах своих слотов (9.3: параметр типа `long` — в Rk и Rk+1); в функции, вызывающей другие, единственная **используемая в коде B16** переменная находится в R4, а единственная используемая в коде B16 переменная типа `long` или `ulong` — в R4 (младшее слово) и R5 (старшее). Переменная, к которой обращается только `asm`-блок, регистра не получает.

### 10.3. Имена в ассемблере

Каждая функция, глобальная переменная, строковый литерал, функция рантайма и часть стартового кода — отдельный объект с глобальной меткой. Метки внутри функций локальные, поэтому функция — один объект карты памяти ассемблера.

| Объект B16 | Имя в ассемблере |
| --- | --- |
| функция, глобальная переменная | её имя |
| имя, совпадающее с регистром или мнемоникой ассемблера | `__` + имя |
| `static`-функция или переменная | `файл.имя` |
| статическая локальная переменная | `функция.имя` (`функция.имя.2` … при повторе) |
| строковый литерал | `владелец.s<n>`: функция или переменная, в которой он стоит |
| образец инициализатора локального объекта | `функция.i<n>` |
| метки внутри функций | `@L<n>` |
| рантайм | `__divs`, `__mods`, `__mul32`, `__divu32`, `__modu32`, `__divs32`, `__mods32`, `__shl32`, `__shr32`, `__sar32`, `__udivc32`, `__umodc32` |
| заголовок и стартовый код | `__header`, `__start`, `__halt`, `__fault`, `__irq_ignore` |
| границы данных | `__data_start`, `__image_end`, `__bss_start`, `__bss_end`, образец `__data_init` |

`файл` — имя исходного файла без каталога и расширения, знаки вне `[A-Za-z0-9_]` заменяются на `_`, перед цифрой ставится `_`. Если префиксы двух файлов совпадают, это ошибка. Имя с точкой не совпадает ни с мнемоникой, ни с регистром.

**Константы.** Для ассемблерного кода компилятор выводит константы директивой `.equ`: каждую `const` — с её значением, каждую переменную `at` — с её адресом, для каждой структуры S — `S.поле` со смещением каждого поля и `S.sizeof` с размером. При изменении структуры в B16 ассемблерный код, обращающийся к ней по этим именам, пересобирается без правок.

Регистр букв при сравнении с мнемониками не учитывается. Зарезервированные ассемблером имена: регистры `R0`–`R15`, `LR`, `SP`, `IP`, `FLAGS`; мнемоники команд, условных переходов и псевдокоманд; `lo`, `hi`. Например, функция `neg` в ассемблере называется `__neg`.

### 10.4. Внешние модули

Функцию, определённую в ассемблерном модуле, объявляют в B16 как `extern fn` (5.5). Такая функция подчиняется соглашению о вызовах (9.3). Ассемблерный код может вызывать функции B16 по имени (с учётом 10.3) или по указателю. Функция B16, на которую ссылается только внешний модуль, должна быть помечена `export` (5.5): иначе она недостижима (3.5) и в образ не попадёт.

**Модуль в образе.** Ассемблерный модуль подключают строкой `include asm "файл"` (3.2) в любом файле программы, обычно рядом с объявлениями `extern fn` этого модуля; реализация допускает и ключ `--asm файл` (13.2). Компилятор выводит `.include "файл"` после функций и рантайма и перед данными (13.3), поэтому код и инициализированные данные модуля (`.word`, `.byte`) лежат в образе до `__image_end` и загружаются монитором. В модуле допустимы только код и инициализированные данные: `.reserve` не допускается, потому что до `__image_end` такая область попала бы в файл нулями и не была бы bss; неинициализированные данные объявляют в B16. Подключение модуля ассемблерным файлом после вывода компилятора (`.include "prog.s"`, затем `.include "mod.asm"`) помещает его код за `__bss_end`: на голой машине программа работает, под монитором вызов уходит в нули, потому что монитор загружает из файла только байты до `__image_end`. `cpu16asm --exec` такую сборку отвергает и называет адрес первого байта за `image_end`.

## 11. Сводная грамматика

Грамматика описывает поток лексем после подстановки `include` и вставки `EOS` (2.3); строки `include asm` (3.2) в поток не попадают. Ограничения, которые не выражаются грамматикой (типы, l-значения, константность), заданы в разделах 4–8. Определения нетерминалов здесь те же, что в основном тексте; исключение — `Первичное` и `Оператор`, записанные развёрнуто: `Приведение`, `ВызовВстроенной` и операторы `If`, `While`, … подставлены в них, а вызов встроенной функции в грамматике выглядит как обычный вызов.

```

Объявление      = ОбъявлениеКонстанты | [ "static" ] ОбъявлениеПеременной | ОбъявлениеСтруктуры
```

## 12. Неопределённое поведение и диагностика

### 12.1. Неопределённое поведение

- изменение и чтение одного объекта в одном выражении без промежуточной `&&` или `||` (6.9);
- знаковое деление и остаток при делителе 0 (6.5);
- чтение локальной переменной до присваивания, в том числе после `goto` через её объявление;
- обращение за границы массива и через указатель, не указывающий на объект подходящего типа;
- переполнение стека;
- запись в строковый литерал;
- изменение `asm`-блоком регистров R4–R11, не отведённых переменным, без восстановления, а также SP;
- вызов через указатель, полученный явным приведением, функции с другими типами параметров или результатов, чем у типа указателя.

### 12.2. Диагностика

Реализация выводит сообщения в формате

```
файл:строка: error: текст
файл:строка: warning: текст
```

Строка и файл — место в исходном тексте до подстановки `include`. После ошибки трансляция продолжается со следующего оператора или объявления, так что за один запуск выводится несколько ошибок; результат при ошибках не выдаётся. Предупреждение не прерывает трансляцию; реализация может считать предупреждения ошибками по требованию пользователя. Подробности поведения `b16c` — в 13.5.

Реализация предупреждает:

- о неиспользуемой локальной переменной, параметре и метке (имена, начинающиеся с `_`, не проверяются; в функции с `asm`-блоками переменные и параметры не проверяются, потому что блок может обращаться к ним через регистры; параметры `main` в цели `std` не проверяются: сигнатуру задаёт соглашение о запуске (3.4), и взять только `argv`, пропустив `argc`, нельзя);
- о чтении локальной переменной, которая не присвоена ни на одном пути (`variable x is used before it is assigned`);
- о чтении локальной переменной, которая на каком-то пути может быть ещё не присвоена (`variable x may be used before it is assigned`) — **только с ключом `-Wmaybe-uninit`** (13.2). Анализ не связывает условия: если переменная присваивается и читается под одним и тем же условием, чтение безопасно, а предупреждение ложное. Присваивание в теле цикла считается достигающим начала следующего прохода;
- о сравнении беззнакового значения с отрицательной константой;
- о константном сдвиге на число, не меньшее ширины типа левого операнда (16 для слова, 32 для двойного слова);
- о значении выражения, которое не используется (7.3);
- о прототипе функции без определения, кроме объявленных `extern fn` (5.5);
- о параметре образа, значение которого заменено значением извне (ключом `b16c`), если значения различаются (3.6, 13.2);
- о `max_top` больше `$E000`: монитор всё равно ограничивает память этим адресом.

## 13. Реализация b16c

Раздел описывает эталонную реализацию: запуск компилятора, все ключи командной строки и их связь с параметрами образа (3.6), раскладку образа в каждой цели, правила отбора функций, диагностику, свойства генерации кода и ограничения. Это не часть языка, но на перечисленные здесь свойства можно опираться в сборочных сценариях и ассемблерном коде, пока используется `b16c`.

### 13.1. Запуск

```
b16c [ключи] prog.b16
```

На вход подаётся один исходный файл в UTF-8; подключаемые файлы `include` подставляются в него (3.2). Результат — ассемблерный текст для `cpu16asm` («Справочник ассемблера»), по умолчанию в stdout. Ключи и имя входного файла можно писать в любом порядке. Сообщения выводятся в stderr.

| Код завершения | Значение |
| --- | --- |
| 0 | трансляция выполнена (предупреждения возможны) |
| 1 | ошибки в программе; выходной файл, если задан `-o`, удаляется |
| 2 | неверные ключи или их значения; выводится краткая справка |

Числовые значения ключей (`АДРЕС`, `N`) записываются десятичным числом, шестнадцатеричным с префиксом `$` или `0x`. Знак `$` в командной строке оболочки берётся в одинарные кавычки: `--data '$8000'`.

Без аргументов `b16c` выводит краткую справку по ключам.

### 13.2. Ключи командной строки

Ключи делятся на две группы. **Параметры образа** — то, без чего программа не работает: цель, адреса, поля заголовка, ассемблерные модули. Их место — исходный текст (`option`, 3.6; `include asm`, 3.2), а ключи нужны для разовых сборок (стенд на другом адресе, адрес, вычисленный сценарием сборки). **Остальные ключи** описывают окружение сборки (`-o`, `-I`), политику диагностики и отладку; в исходном тексте их нет.

| Ключ | Значение по умолчанию | В исходном тексте | Действие |
| --- | --- | --- | --- |
| `-o файл` | stdout | — | выходной файл |
| `-I каталог` | — | — | каталог поиска `include`, можно повторять (до 32) |
| `--target std` | да | `option target = std` | исполняемый файл CX16 (13.3) |
| `--target kernel` | — | `option target = kernel` | код без заголовка и стартового кода (13.3) |
| `--code АДРЕС` | 0 | `option code` | начало кода; только для `kernel` |
| `--data АДРЕС` | сразу за кодом | `option data` | начало всех глобальных переменных; обе цели |
| `--min-free N` | 2048 | `option min_free` | поле `min_free` заголовка CX16; только для `std` |
| `--max-top N` | 0 | `option max_top` | поле `max_top` заголовка CX16; только для `std` |
| `--asm файл` | — | `include asm "файл"` | ассемблерный модуль в образе до `__image_end` (13.3); можно повторять |
| `-n` | — | — | все функции, кроме `static`, — точки входа (13.4); устарел, точки входа размечают `export` |
| `-a` | — | — | в образ выводятся все функции (13.4) |
| `-s` | — | — | исходный текст комментариями в выводе |
| `-Werror` | — | — | предупреждения считаются ошибками |
| `-w` | — | — | предупреждения не выводятся |
| `-Wmaybe-uninit` | — | — | предупреждение и о возможном чтении переменной до присваивания (12.2) |
| `-fcopy-params` | — | — | всегда копировать параметры в R4–R11 (13.6); для сравнения и отладки |

**Ключ и `option`.** Действующее значение параметра — значение ключа, иначе `option` главного файла, иначе значение по умолчанию. Если заданы и ключ, и `option` с другим значением, выводится предупреждение на строке `option`:

```
kernel.b16:9: warning: --data $9000 overrides option data = $8000
```

С `-Werror` это ошибка, поэтому ключ, забытый в сценарии сборки после переноса параметра в исходный текст, обнаруживается сразу. Совпадающие значения сообщений не дают. Значения ключей проверяются так же, как значения `option` (3.6, правила 4 и 5); ошибка значения ключа (диапазон, чётность) завершает работу с кодом 2, параметр не той цели — обычная ошибка трансляции (код 1).

**Ассемблерные модули** из ключей `--asm` выводятся после модулей `include asm`; модуль, уже подключённый строкой `include asm`, повторно не выводится. Вместе — не больше 16 модулей.

**Комментарий в выводе.** В начале результата перечислены действующие параметры образа и источник каждого — строка `option`, ключ или «по умолчанию»; каждая строка `.include` модуля помечена местом `include asm` или ключом `--asm`:

```
; параметры образа:
;   target    kernel           kernel/kernel.b16:7
;   code      $0004            kernel/kernel.b16:8
;   data      $8000            kernel/kernel.b16:9
```

**`-o файл`.** Без ключа результат пишется в stdout. При ошибках файл не создаётся (уже созданный удаляется); при выводе в stdout часть текста к этому моменту может быть выведена.

**`-I каталог`.** Путь в `include "файл"` ищется сначала относительно каталога включающего файла, затем в каталогах `-I` в порядке их указания. Абсолютный путь используется как есть. Найденный путь приводится к короткому виду (без `./` и `каталог/../`) и в этом виде попадает в сообщения и директивы `.line`. Повторное включение того же файла (по каноническому пути) игнорируется, как требует 3.2.

**`--target std`** (по умолчанию; `option target = std`). Программа должна иметь `main` (3.4), иначе — ошибка с подсказкой об `option target = kernel`. Образ начинается с заголовка CX16 и стартового кода (9.2), запускается монитором и на голой машине и проходит проверку `cpu16asm --exec`.

**`--target kernel`** (`option target = kernel`). Заголовка и стартового кода нет; `main`, если есть, — обычная функция, её сигнатура не проверяется. Используется для ядра монитора, модулей, вызываемых из ассемблера, кода в ПЗУ с собственным прологом.

**`--code АДРЕС`** (`option code`). Начало кода цели `kernel`: перед первой функцией выводится `.org АДРЕС`. Без параметра код начинается с адреса 0. Для `std` код всегда начинается с 0 (заголовок обязан стоять там), и параметр — ошибка `option code applies only to target kernel` (для ключа — `--code applies only to target kernel`). Адрес чётный.

**`--data АДРЕС`** (`option data`). Начало области всех глобальных переменных, инициализированных и нет, в обеих целях. Начальные значения инициализированных переменных лежат образцом `__data_init` сразу за кодом, а по адресу `--data` для них отводится место (`.reserve`). Строковые литералы остаются рядом с кодом и не копируются (2.7). Образец переносит в область данных стартовый код цели `std` или подпрограмма `__init_data` цели `kernel` (13.3). Параметр нужен для программы в ПЗУ с данными в ОЗУ и для ядра. Адрес чётный и не меньше конца образца (`__image_end`); иначе ассемблер сообщит о перекрытии. Под монитором область данных должна лежать ниже `$E000`. Без параметра данные лежат сразу за кодом, а образца и копирования нет.

**`--min-free N`, `--max-top N`** (`option min_free`, `option max_top`). Поля заголовка CX16 («Монитор CPU16: формат исполняемого файла», разд. 3): `min_free` — сколько памяти, кроме bss, нужно программе под стек и кучу (чётное, не больше `$E000`); `max_top` — желаемая верхняя граница памяти процесса, 0 — вся доступная. Монитор отказывает в запуске, если `min_free` не помещается; `max_top` больше `$E000` монитор ограничивает этим адресом, и компилятор об этом предупреждает. В цели `kernel` заголовка нет, и параметры — ошибка (`option min_free applies only to target std`).

**`--asm файл`** (`include asm "файл"`). Подключает ассемблерный модуль к образу: после функций и рантайма (и после `__init_data` цели `kernel`), перед данными выводится `.include "файл"`. Файл должен существовать, иначе ошибка. Путь ключа задаётся относительно текущего каталога, путь `include asm` ищется по правилам 3.2. Путь в `.include` пересчитывается относительно каталога выходного файла (так его ищет ассемблер), поэтому результат можно записать в другой каталог. Ключ можно повторять: модули подключаются в порядке указания, после модулей `include asm`. Код и инициализированные данные модуля оказываются до `__image_end`; ограничения модуля — в 10.4.

**`-n`** (устарел). Все функции, кроме `static`, становятся корнями достижимости, как будто каждая помечена `export` (5.5). В цели `std` заголовок и стартовый код остаются. Ключ нужен, только пока точки входа модуля не размечены `export`; в исходном тексте его замена — `export`.

**`-a`.** В образ выводятся все функции, в том числе недостижимые `static`-функции; корни достижимости при этом не меняются. Ключ нужен, чтобы посмотреть код всех функций, например при отладке компилятора. Разница с `-n` — в 13.4.

**`-s`.** Перед командами каждого оператора выводится его исходная строка комментарием, перед функцией — её заголовок и комментарии над ним. Если между двумя показанными строками не больше восьми строк того же файла, промежуточные строки тоже выводятся. Уже показанная строка повторяется, только когда её код снова встречается дальше (например, условие `while` внизу цикла). Смена файла отмечается строкой `; ---- файл`. Код не меняется.

**`-Werror`.** Каждое предупреждение выводится как `error` и считается ошибкой: код завершения 1, выходной файл не создаётся.

**`-w`.** Предупреждения не выводятся. Вместе с `-Werror` предупреждения не выводятся и ошибками не считаются.

**`-Wmaybe-uninit`.** Включает предупреждение о чтении переменной, присвоенной не на всех путях (12.2). По умолчанию оно выключено, потому что при согласованных условиях бывает ложным; предупреждение о переменной, не присвоенной ни на одном пути, действует всегда.

**`-fcopy-params`.** Отключает размещение параметров в регистрах аргументов (13.6): параметры функций с вызовами всегда копируются в R4–R11. Программа должна работать одинаково с ключом и без него; тесты используют это для сравнения.

Действие ключей по целям:

| Ключ | `std` | `kernel` |
| --- | --- | --- |
| `--code` | ошибка | начало кода |
| `--data` | данные с адреса, копирует стартовый код | данные с адреса, копирует `__init_data` |
| `--min-free`, `--max-top` | поля заголовка | ошибка |
| `-n` | все функции — корни, `main` и стартовый код остаются | все функции — корни |
| `--asm` | после функций и рантайма | после рантайма и `__init_data` |
| `-a`, `-s`, `-I`, `-o`, `-Werror`, `-w`, `-Wmaybe-uninit`, `-fcopy-params` | одинаково | одинаково |

### 13.3. Цели и раскладка образа

**Цель `std`.** Раскладка — 9.1, заголовок и стартовый код — 9.2. Порядок объектов:

```
__header        заголовок CX16 (28 байт)
__start         стартовый код
__fault, __halt остановка на голой машине (ERRCMD и возврат из main)
__irq_ignore    пустой обработчик неиспользуемых векторов
функции         в порядке исходного текста
рантайм         __divs, __mods, __mul32 и другие функции 9.6, если нужны
модули          .include каждого модуля: include asm, затем --asm (10.4)
данные          см. ниже
```

**Цель `kernel`.** То же без первых четырёх объектов; с `option code` им предшествует `.org`. Модули в цели `kernel` выводятся после `__init_data`, перед данными. Если задан `option data`, после рантайма выводится подпрограмма `__init_data`: она копирует образец `__data_init` в `__data_start` … `__bss_start`, обнуляет `__bss_start` … `__bss_end` и возвращается по `RET`, портя R0–R2. Пролог ядра вызывает её до первого обращения к глобальным переменным. Без `--data` bss (`__image_end` … `__bss_end`) обнуляет тот, кто загружает ядро.

**Данные без `option data`:**

```
__data_start:            инициализированные переменные (.word, .byte, .space)
                         строковые литералы
        .align 2
__image_end:
__bss_start:             неинициализированные переменные (.reserve)
__bss_end:
```

**Данные с `option data = АДРЕС`:**

```
                         строковые литералы (рядом с кодом)
__data_init:             образец инициализированных переменных
        .align 2
__image_end:
        .org  АДРЕС
__data_start:            инициализированные переменные (.reserve, заполняются копированием)
__bss_start:             неинициализированные переменные (.reserve)
__bss_end:
```

Каждая переменная занимает чётное число байт. Образцы инициализаторов локальных объектов (`функция.i<n>`) и статические локальные переменные относятся к инициализированным данным. Образец локального инициализатора выводится, только если выведена его функция. Глобальные переменные выводятся всегда, даже если не используются.

Перед данными выводятся константы для ассемблера (`.equ`, 10.3): сначала `const` и адреса переменных `at` в порядке объявления, затем смещения полей и размеры структур.

### 13.4. Отбор функций

В образ выводится функция, достижимая (3.5) из корней. Корни зависят от цели и ключей:

| Корень | `std` | `kernel` | с `-n` |
| --- | --- | --- | --- |
| `main` | да | нет | да |
| функции `export` | да | да | да |
| обработчики `interrupt fn` | да | да | да |
| функции из инициализаторов глобальных переменных | да | да | да |
| остальные функции без `static` | нет | нет | да |
| функции `static` | нет | нет | нет |

`-a` выводит все функции независимо от достижимости. Поэтому `-n` и `-a` различаются только для `static`-функций, на которые никто не ссылается: с `-n` они отбрасываются, с `-a` выводятся. По назначению ключи разные: `-n` задаёт точки входа модуля, `-a` — отладочный ключ.

Недостижимые функции всё равно транслируются: их ошибки и предупреждения сообщаются, но код не выводится.

### 13.5. Диагностика

Формат сообщений и перечень предупреждений — 12.2. Тексты сообщений — на английском: так они читаются в любой консоли.

- **Восстановление после ошибки.** Ошибка в операторе пропускает остаток оператора до конца строки или `}`; ошибка в объявлении верхнего уровня — остаток объявления. Переменные из ошибочного `var` остаются объявленными, чтобы не было каскада сообщений `unknown name`. После 20 ошибок трансляция прекращается сообщением `too many errors`.
- **Порядок проверок.** Трансляция идёт в три этапа: объявления верхнего уровня, тела функций, генерация кода. Ошибки первого этапа (заголовки функций, `const`, `struct`, `assert`, `option`, размеры массивов) останавливают трансляцию после него, и тела функций не проверяются. После первого этапа собираются действующие параметры образа (13.2): ошибки параметра не той цели тоже останавливают трансляцию, затем проверяется `main` цели `std`. Ошибки генерации кода (например, `function f can reach the end without return`) сообщаются, только если на первых двух этапах ошибок не было.
- **Фатальные ошибки** прекращают трансляцию сразу: конец файла внутри блока, незакрытый `asm`-блок, ошибки `include` и `include asm` (файл не найден, вложенность больше 16, больше 16 модулей).
- **Предупреждения о переменных** выводятся после разбора функции, поэтому могут идти не по порядку строк.
- **Ассемблер.** Благодаря `.line` (13.6) сообщения `cpu16asm` о сгенерированном тексте указывают строку B16, а в скобках — строку `.s`.

### 13.6. Генерация кода

- **Распределение регистров.** Локальным скалярам, у которых не берётся адрес, выделяются регистры по взвешенному числу обращений (обращение в цикле весит больше). Переменная типа `long` или `ulong` занимает два регистра; они не обязаны быть соседними, а в функции, вызывающей другие, единственная используемая в коде B16 такая переменная получает R4 и R5. В функции, не вызывающей других, параметр остаётся в регистрах своих слотов (9.3), всего регистровых слов не больше 9. Если в функции есть вычисления над long и ulong (а не только пересылки), регистровых слов не больше 6: остальные регистры нужны под временные значения. В функции, вызывающей другие, переменные размещаются в R4–R11 (не больше 8). Остальные переменные — в кадре (9.4). Анализа времени жизни нет.
- **Параметры до первого вызова.** Параметр функции, вызывающей другие, остаётся в регистре аргумента (9.3), если он читается только до первого оператора верхнего уровня, способного испортить R0–R3, — вызова функции или рантайма, `asm`-блока, множественного присваивания, метки. С этого оператора параметр уже не читается, поэтому копия в R4–R11 и сохранение этого регистра в прологе не нужны. Оператор, в котором параметр читается, сам не может быть таким оператором: аргументы вызова вычисляются в R0–R3 по очереди и затёрли бы параметр. Правило не действует в функциях с метками (`goto`), при ключе `-fcopy-params` и когда после размещения осталось меньше двух временных регистров из R0–R3 (трёх при вычислениях над `long` и `ulong`): тогда параметр копируется как обычно.
- **Нехватка регистров.** Если промежуточным значениям выражения не хватает регистров, соответствующий участок генерируется заново с промежуточными значениями в стеке. Ошибка `expression too complex` возможна только при вложенности таких участков глубже 256 уровней.
- **Порядок вычисления.** Вызовы функций и более сложные подвыражения обычно вычисляются раньше других операндов.
- **Умножение и деление на константу** — сдвигами, масками и умножением на обратное через `MULHU` (9.6), без вызова рантайма. Для двухсловных значений: умножение на степень двойки — сдвигом; деление и остаток на степень двойки — сдвигом и маской; деление и остаток на константу 3…255 — четырьмя шагами `DIVU`/`REMU` по байтам делимого.
- **Половины двухсловных значений.** Выражения `uint(x)`, `uint(x >> 16)`, `int(x >> 16)`, а также `ulong(h) << 16 | l` (h, l — слова без знака) не порождают вычислений: они выбирают и собирают регистры или слова памяти. Сравнение 32-битного значения с нулём — один `OR` слов, проверка знака `x < 0` и `x >= 0` — `TEST` старшего слова.
- **Локальные инициализаторы.** Объект до 16 байт заполняется присваиваниями, больший копируется пословно из образца `функция.i<n>`, затем присваиваются неконстантные части.
- **Места строк.** Перед кодом каждой строки B16 выводится `.line "файл", N` (при смене файла) или `.line N`, перед заголовком, стартовым кодом и рантаймом — `.line` без аргументов. Перед глобальной переменной и константой — строка объявления, перед литералом — строка, где он стоит. Карта памяти ассемблера (`cpu16asm -m`) поэтому раскладывает объекты по файлам и строкам B16.
- **Имена** объектов в ассемблере — 10.3.

### 13.7. Сборка и запуск

Компилятор выдаёт только ассемблерный текст. Параметры образа и модули задаёт сам исходник, поэтому сборка не зависит от программы:

```
b16c -I lib prog.b16 -o prog.s
cpu16asm --exec -m prog.map -l prog.lst -o prog.bin prog.s
cpu16 prog.bin
```

`--exec` проверяет заголовок CX16 (для цели `std`), `-m` выводит карту памяти, `-l` — листинг. Сценарий `run.sh prog.b16 [ключи cpu16]` выполняет те же три шага с `-I lib`; дополнительные ключи компилятора (обычно диагностика или `-s`) передаются в переменной `B16FLAGS`, пути к инструментам — в `CPU16ASM` и `CPU16`.

Модуль цели `kernel` (`option target = kernel`) подключается к ассемблерной программе директивой `.include "kmod.s"`; пример — `tests/kernel` в каталоге компилятора.

Раздел описывает, что менялось от ревизии к ревизии; отметка **несовместимо** означает, что программа ревизии 1 может перестать компилироваться или изменить поведение.

Остальные изменения для программ ревизии 1 безопасны: они затрагивают только `long` и `ulong` либо записывают прежнее правило явно.

**Изменения семантики без несовместимости для 16-битных программ.**

- Результаты функции считаются словами: не более четырёх слов, `long` и `ulong` занимают по два; прежний предел в четыре результата для остальных типов сохраняется (4.5, 5.5).
- Индекс `a[i]` и слагаемое `p + i` — целое не шире слова; значение `long` или `ulong` приводят явно: `a[uint(i)]` (6.8).
- Запись `long` или `ulong` в `uint`, `int`, `byte`, `char` без приведения — ошибка; расширение в обратную сторону неявное (6.2).
- Нетипизированная константа слева от сдвига с неконстантным счётчиком имеет тип `int` (так было и раньше); теперь это записано явно. Для 32-битного сдвига константу приводят: `ulong(1) << n` (6.4).
- Тип результата бинарной операции, в которой есть `long` или `ulong`, — тип более широкого операнда; сравнения и `/`, `%` допускают беззнаковый операнд не шире слова вместе со знаковым `long` (6.4). Для операндов не шире слова правила прежние.
- Сдвиг по переменной: у `long` и `ulong` счётчик берётся по модулю 32, у остальных по модулю 16 (6.5). Константный сдвиг на ширину типа и больше даёт 0 (для знакового `>>` — знак) с предупреждением.
- Деление `ulong` на 0 даёт `$FFFFFFFF`, остаток равен делимому, на любом процессоре; `-2147483648 / -1` для `long` — `-2147483648`, остаток 0 (6.5).
- Соглашение о вызовах считает **слоты**: слово занимает один слот, `long` и `ulong` — два подряд; аргумент, которому не хватило слотов R0–R3, и все следующие идут в стек (9.3). Для программ без `long` и `ulong` интерфейс прежний: аргументы 1–4 в R0–R3, остальные в стеке.
- Чтение и запись `long` и `ulong` — две команды и не атомарны; общее с обработчиком прерывания значение читают и пишут в `atomic` (9.7).
- Рантайм пополнен функциями умножения, деления и сдвигов над 32 битами (9.6, 10.3).
- Нетипизированная константа проверяется по диапазону типа везде, где принимает тип: присваивание, аргумент, возврат, инициализатор, приведение, операнд операции (4.7).

### 14.3. Ревизия 2: уточнения и исправления текста

- **Грамматика.** Нетерминал `Результаты` определён один раз (4.5) и используется в функциональном типе и в объявлении функции; пометки `static`, `export`, `extern` входят в `ОбъявлениеФункции` во всех разделах (3.1, 5.5, 11); `Объявление` в сводной грамматике совпадает с 3.1, добавлено определение `Проверка`.
- В грамматике также приведены к одному виду: `Оператор` (7.1) получил `[ "static" ]` перед `ОбъявлениеПеременной`, как в 7.2; `СкалярныйТип` (4.6) — `"ptr" [ Тип ]`; `ОбъявлениеСтруктуры` (5.4) — пустые строки между полями; `Первичное` (6.3) — `offsetof`; `Цель` (7.8) — `ВыражениеБезПрисв`. Нетерминалы `Первичное` и `Оператор` в разделе 11 записаны развёрнуто, это оговорено.
- **Строки.** Локальная `var s = "..."` без типа — указатель `ptr byte` на литерал, писать в него нельзя; изменяемый текст в функции объявляют массивом `var s: [N]byte = "..."` (2.7, 5.3, 7.2).
- **Регистры в `asm`.** Формулировка «единственная переменная в R4» уточнена: речь о единственной переменной, **используемой в коде B16** (10.2, 13.6).
- **Запуск.** Описано, что `__halt` и `__fault` принимают висящий запрос прерывания (`STI`, затем `CLI`) перед `WFI`: иначе запрос таймера, выставленный при IF = 0, будит процессор снова и снова, и машина не останавливается (9.2).
- **Образ.** Сказано, что подключение ассемблерного модуля после вывода компилятора помещает его за `__bss_end`: на голой машине программа работает, под монитором нет; `cpu16asm --exec` такую сборку отвергает (10.4).
- **Инверсия константы.** Добавлен пример `flags & ~F_DIR` при `F_DIR = $8000`: точное вычисление констант делает его ошибкой, правильная запись — `~uint(F_DIR)` (4.7, 14.1).
- **Связанные документы.** Во введении документы названы так же, как в проекте, с ревизиями; добавлены «Монитор CPU16: формат исполняемого файла», ревизия 3, и «Монитор CPU16: системные вызовы» (1, 13).
