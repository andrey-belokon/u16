# Компоновка B16 и ассемблера

`main.b16` вызывает функции из `util.asm`, а `util.asm` вызывает функции B16 через указатели.

```
b16c -I ../../lib main.b16 -o main.s
cpu16asm --exec -o main.bin main.s
cpu16 main.bin
```

- Строка `include asm "util.asm"` в `main.b16` подключает модуль директивой `.include` **после кода и рантайма, перед данными**, поэтому его код и инициализированные данные (`.word`, `.byte`) лежат в образе до `__image_end`. Монитор загружает из файла только эти байты. Если подключить модуль ассемблерным файлом после вывода компилятора (`.include "main.s"`, затем `.include "util.asm"`), код окажется за `__bss_end`: на голой машине программа заработает, а под монитором вызов уйдёт в нули. `cpu16asm --exec` такую сборку отвергает.
- В модуле допустимы код и инициализированные данные. Области `.reserve` в нём не нужны: неинициализированные данные объявляйте в B16.
- Функции из `.asm` объявляются в B16 как `extern fn` — прототип без тела, определение вне B16. Предупреждения о них нет, поэтому пример собирается с `-Werror`.
- `util.asm` соблюдает соглашение о вызовах B16 (руководство, разд. 8).
- Функция B16, которую ассемблерный модуль вызывает **по имени**, а B16-код нигде не упоминает, будет удалена как неиспользуемая. Пометьте её `export`.
