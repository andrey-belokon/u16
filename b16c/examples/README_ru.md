# Примеры B16

Примеры разложены по тому, где программа работает. Образ CX16 один и тот же для обоих способов запуска (B16, разд. 9.2), но то, чем программа пользуется, привязывает её к одному из них: на голой машине программа владеет векторами, таймером и клавиатурой, под монитором всё это принадлежит монитору и доступно только через системные вызовы («Монитор CPU16: системные вызовы», разд. 2.2).

| Каталог | Где работает | Чем пользуется |
| --- | --- | --- |
| `universal/` | голая машина и монитор | `lib/io.b16`: порт консоли или стандартные потоки — по сигнатуре по адресу `$0004` |
| `bare/` | только голая машина | своя таблица векторов, таймер `$FF29`, клавиатура и дисплей через порты (`lib/console.b16`) |
| `monitor/` | только монитор | системные вызовы (`sys.b16` монитора): аргументы, файлы, процессы, события клавиатуры, тики |

## universal — голая машина и монитор

| Пример | Что показывает |
| --- | --- |
| `hello` | минимальная программа |
| `sieve` | массивы, вложенные циклы, константы |
| `sort` | рекурсия, указатели на функции, арифметика указателей, строки |
| `list` | структуры, пул памяти, указатель на указатель, несколько результатов |
| `calc` | рекурсивный разбор, пары «значение + позиция», знаковое деление |
| `fsm` | конечный автомат на `goto` |
| `dispatch` | таблица команд: структуры с указателями на функции |
| `funcptr` | обратные вызовы, таблица переходов, «объекты» с таблицей методов, функция как результат |
| `bignum` | `ulong`: факториалы и числа Фибоначчи до 2³² |
| `echo` | ввод строк: клавиатура на голой машине, стандартный ввод под монитором (`echo < echo.txt`) |
| `asmlink/` | компоновка с ассемблерным модулем (`include asm`), вызовы в обе стороны |
| `tetris` | одна игра для обоих способов: на голой машине — свои векторы и таймер, под монитором — `TICKS`, `SLEEP`, `CON_GETEV`; дисплей ведёт сама |

Программы, кроме `tetris`, пишут текст через `lib/io.b16`. Под монитором вывод идёт в стандартный поток, поэтому `hello > A:/tmp/h.txt` работает; ввод `echo` берётся из файла при `echo < файл` (текст файла — в кодировке машины). Голая машина:

```
./run.sh examples/universal/hello.b16
./run.sh examples/universal/echo.b16 < examples/universal/echo.txt
```

Под монитором (из каталога `monitor/`):

```
tools/b16build.sh ../b16c/examples/universal/hello.b16      # -> out/hello.bin
```

`out/hello.bin` кладётся на том как `/bin/hello.cx` (`tools/fs16tool.py` или `cp` в оболочке) и запускается командой `hello`.

## bare — только голая машина

| Пример | Что показывает |
| --- | --- |
| `inline_asm` | функции на ассемблере, флаги, локальные метки, вызов B16 из `asm`, обработчики ERRCMD и TRAP |
| `devices` | регистры консоли как структура по адресу, клавиатура со сканкодами (`cpu16 devices.bin < devices.txt`) |
| `life` | «Жизнь»: двумерные массивы, указатели на массивы, `char`, экран, таймер |
| `clock` | таймер, обработчик прерывания, `atomic` |
| `timer` | минимальный обработчик IRQ0 и `wfi` |
| `screen` | координатный режим, псевдографика, цвета, режим атрибутов |
| `demo` | обзор языка в одном файле |
| `tetris_bare` | тетрис только для голой машины — сравните с `universal/tetris.b16` |

```
./run.sh examples/bare/screen.b16 --screen
```

Под монитором эти программы запускать нельзя: запись в таблицу векторов и в таймер, чтение клавиатуры из порта монитору мешают.

## monitor — только монитор

| Пример | Что показывает |
| --- | --- |
| `args` | `argv`, флаги перенаправления в PIB, `MEMINFO`, поток ошибок, код завершения, `option max_top` |
| `wc` | файлы: `OPEN`, `READ`, `CLOSE`; ошибки в стиле утилит; счётчики `ulong`; стандартный ввод |
| `keys` | сырой режим консоли (`CON_MODE`), события `CON_GETEV` со сканкодами и модификаторами |
| `ticks` | `TICKS` и `SLEEP`, обработчик тика `TICKHOOK`, обработчик Ctrl+C `ONEVENT` |
| `run` | `SPAWN` с выводом потомка в файл, код завершения и время выполнения |

`mon.b16` — общие функции этих примеров (способ запуска, вывод символа, чисел и ошибок); вывод строк и `puthex` даёт `sys.b16`. Сборка (из каталога `monitor/`):

```
tools/b16build.sh ../b16c/examples/monitor/wc.b16          # -> out/wc.bin
```

и запуск из оболочки после копирования на том как `/bin/wc.cx`:

```
wc /data/a.txt /data/b.txt
wc < /data/a.txt
run -o A:/tmp/ls.txt A:/bin/ls.cx -l /bin
ticks
```

`make test` компилятора эти примеры только собирает: `tests/monrun` выполняет лишь `READ`, `WRITE` и `EXIT`.

## Windows

Рядом с примерами лежат `b16c.exe`, `cpu16asm.exe` и два сценария:

- `c.bat пример.b16` — собрать один пример: компилятор с `-s` (исходный текст комментариями) даёт `пример.s`, ассемблер с `--exec` — образ, листинг `.lst` и карту памяти `.map`, всё рядом с исходником. Вид образа зависит от каталога: `bare\` — `пример.bin` для голой машины (`cpu16 пример.bin`), `monitor\` — `пример.cx` для монитора, `universal\` и `universal\asmlink\` — оба файла, это один и тот же образ. Примерам из `monitor\` компилятор получает пути `..\..\monitor\user\lib` и `..\..\monitor\kernel`. Дополнительные ключи компилятора — в переменной `B16FLAGS`.
- `call.bat` — собрать все примеры подкаталогов (`monitor\mon.b16` — библиотека, пропускается) и вывести итог: сколько собрано, сколько с ошибкой.

Файл `.cx` кладётся на том монитора как `/bin/пример.cx` (`monitor\tools\fs16tool.py` или `cp` в оболочке) и запускается командой `пример`. Результаты сборки перечислены в `.gitignore`.
