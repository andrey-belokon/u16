# Отладчик CPU16 в браузере

Каталог `webdbg/` лежит на верхнем уровне проекта рядом с `b16c/`, `cpu16/` и `monitor/`. Результат сборки — один файл `webdbg/cpu16_debugger.html`. Он открывается в любом браузере без установки.

## Файлы

| Файл | Назначение |
|---|---|
| `cpu16_debugger.html` | собранная страница отладчика |
| `build.py` | сборка страницы |
| `src/debugger.template.html` | интерфейс и контракт движка |
| `src/engine.js` | JS-движок: эмуляция (перенос `tools/cpu16.cpp`), менеджер памяти, устройства, контроллер дисков и дизассемблер |
| `src/fs16.js` | Реализация ФС16 ревизии 3: чтение, запись, выделение кластеров, каталоги и индексы; имена сравниваются без учёта регистра букв |
| `src/fs16_ui.js` | Отдельное окно файлового менеджера и перенос файлов drag-and-drop |
| `build_local.py` | Пересборка автономного архива отладчика без отсутствующих в нём C++-зависимостей |
| `tests/test_fs16.js`, `tests/test_fs16_ui.py` | Тесты формата ФС16 и интерфейса в Chromium |
| `src/assembler.js` | JS-ассемблер (перенос `tools/cpu16asm.cpp`) для встроенного редактора |
| `src/gen_isa_js.cpp` | генератор таблиц для JS: ISA из `tools/cpu16_isa.hpp`, кодировка, палитра, порты, константы дисков и менеджера памяти, сканкоды из `tools/cpu16_machine.hpp` |
| `src/demo.asm` | встроенная демо-программа (встраивается исходником и собирается в браузере) |
| `tests/gen_cases.cpp` | эталонные случаи на C++ для сверки движка |
| `tests/test_engine.js` | сверка JS-движка с C++ и проверка демо |
| `tests/test_disasm.js` | круговой тест дизассемблера через `cpu16asm` |
| `tests/asm_oracle.cpp` | эталон на C++ для сверки JS-ассемблера |
| `tests/test_assembler.js` | сверка JS-ассемблера с `cpu16asm` на общем корпусе исходников |
| `tests/test_ui.py` | сценарии интерфейса в headless Chromium |

В страницу встраиваются также стандартная библиотека `lib/stdlib.asm` (доступна в отладчике через `.include "stdlib.asm"`) и таблицы из `tools/`.

## Сборка

Нужен каталог `../cpu16` (таблицы ISA, ассемблер, стандартная библиотека):

```
make                          # в webdbg/; или: python3 build.py; из cpu16/ - make debugger
```

Если доступен только каталог `webdbg/`, без `../cpu16`, выполните `python3 build_local.py`: вспомогательный скрипт использует уже встроенные в HTML таблицы ISA и стандартную библиотеку, а изменённые JavaScript и HTML берёт из `src/`. Если менялись сами таблицы ISA или стандартная библиотека, нужна полноценная сборка `build.py` в полном проекте.

Страницу нужно пересобирать после правок `../cpu16/tools/cpu16_isa.hpp`, `../cpu16/tools/cpu16_machine.hpp`, `../cpu16/lib/stdlib.asm` или файлов в `src/`; `make` делает это сам.

## Тесты

В `webdbg/` (или из `cpu16/`: `make test-debugger`, `make test-ui`):

```
make test                     # сверка движка, дизассемблера и ассемблера с C++, тесты ФС16
make test-ui                  # сценарии интерфейса и файлового менеджера (нужен playwright с Chromium)
```

Тесты берут движок из собранной страницы, то есть проверяют ровно тот код, который работает в браузере. Сверка движка с C++ включает все устройства: экран во всех режимах, клавиатуру, таймер и часы реального времени на искусственных часах со скачками времени, контроллер дисков (команды мгновенные и по 1 мс на сектор, IRQ1 по уровню, одинаковые тестовые образы), менеджер памяти и пустые адреса окна устройств; сравнивается вся физическая память и содержимое дисков. Часть корпуса сверки ассемблера берётся из `../cpu16/tests/cpu16asm_tests.cpp` и `../cpu16/docs/cpu16_asm_reference_ru.md`.

## Устройства и память

Устройства описаны в документе «Машина CPU16: память и устройства», ревизия 8: консоль и таймер ($FF20–$FF29, модификаторы клавиатуры MODS — $FF3C), часы реального времени ($FF2A–$FF2E), контроллер дисков ($FF30–$FF3B), менеджер памяти ($FF40–$FF48). Окно $FF20–$FFFF не транслируется менеджером памяти; адрес без устройства читается как 0, запись в него игнорируется.

- **Консоль** (внизу) — журнал вывода в режиме телетайпа. Щёлкните по ней и печатайте, чтобы отправить программе нажатия клавиш (символ, сканкод и модификаторы Shift, Ctrl, Alt — регистр MODS); текст из буфера вставляется как символы.
- **Дисплей 80×25** — кнопка «Display» рядом с консолью. Отладчик пытается открыть отдельное окно; если окна запрещены (например, во встроенном просмотре в чате), показывает панель справа со своим разделителем. В окне и в панели есть полноэкранный режим (кнопка или двойной щелчок). Пока дисплей в фокусе, все клавиши уходят программе, а Pause/Break ставит выполнение на паузу. Если программа рисует на закрытом дисплее, кнопка подсвечивается.
- **Таймер** — реальные 20 мс, пока программа выполняется; на паузе и при пошаговом выполнении стоит. Если программа ждёт в `WFI` при включённом таймере, выполнение продолжается (в строке состояния «Running (WFI, timer)»). Скорость выполнения показывается в строке состояния.

- **Boot** — кнопка в панели управления всегда выполняет аппаратный сброс, загружает встроенный `src/rom.bin` по адресу `$0000` и сразу запускает код ПЗУ — даже если диск 0 не подключён. ПЗУ само проверяет наличие диска, читает секторы 1–3 и проверяет код загрузчика ФС16 (`CXBT`), который далее загружает монитор из `0:/sys/monitor.sys`. При отсутствии диска сообщение `ROM: no disk 0`, при ошибке чтения — `ROM: disk 0 read error`, при отсутствии загрузчика — `ROM: disk 0 is not bootable` выводит **само ПЗУ** на вкладку Console через эмулируемый порт `$FF20`, после чего останавливается. Сообщение также дублируется в строке состояния отладчика. Ошибки следующих стадий (`boot: …`) показываются аналогично. Boot сбрасывает прежнюю программу, поскольку это перезагрузка машины; подключённые образы дисков сохраняются. `rom.bin` включён в автономный HTML при сборке через `build.py` или `build_local.py`.
- **Диски** — вкладка «Disks» рядом с консолью. Для каждого из 8 дисков: «Attach file…» подключает образ с компьютера (размер кратен 512 байтам; можно также перетащить `.img` или `.dsk` на страницу), «New…» создаёт пустой образ заданного числа секторов. У подключённого диска есть флажок защиты от записи, «Download» и «Detach». Образы живут в памяти страницы: изменения сохраняются только скачиванием, изменённый образ помечен «• modified». Диски подключаются и отключаются на ходу (REMOVABLE = 1); отключение во время команды завершает её ошибкой IO. Сверху — время на сектор (по умолчанию 1 мс; 0 — мгновенно) и текущие регистры контроллера. Обмен идёт по реальному времени, пока программа выполняется; на паузе и при пошаговом выполнении стоит. Если программа ждёт в `WFI` завершения команды с IEN = 1, выполнение продолжается («Running (WFI, disk)»).
- **Файловый менеджер FS16** — кнопка «Files…» в строке подключённого диска на вкладке «Disks». Открывает отдельное окно с двумя панелями: слева файлы компьютера, выбранные через «Add files…» / «Add folder…» или перетаскиванием, справа содержимое FS16. Двойной щелчок по каталогу — переход в него, «↑ Up» — назад. Несколько файлов выбираются через Ctrl/Shift; можно перетащить выделенную группу справа налево для скачивания (в ZIP) или слева направо для копирования на диск. Сброс на значок каталога копирует файлы внутрь него. «Copy →» и «← Download» позволяют сделать то же без drag-and-drop. Выгрузка одного файла — исходный файл; нескольких файлов и/или каталогов — ZIP (без сжатия). Скопированные из хост-папки файлы сохраняют структуру подкаталогов. «New folder» создаёт каталог; «Delete» удаляет файлы и пустые каталоги. Имена на диске не различают регистр букв (ФС16, разд. 7.1): файл или каталог с именем, которое отличается от существующего только регистром, не создаётся (`Already exists`).
  - Для пустого неформатированного образа окно предлагает «Format FS16…» **с подтверждением удаления содержимого всего диска**. Требуется минимум 12 секторов, размер кратен 512; максимальный том ФС16 — 65535 кластеров.
  - ФС16 проверяет сигнатуру, версию, геометрию, контрольную сумму суперблока. Реализованы прямые, косвенные и двойные косвенные кластеры, обновление битовой карты, размера, свободных кластеров и CHECKSUM, DIRTY на время записи, имена в кодировке CPU16. Совпадающие имена не перезаписываются: такие файлы пропускаются с сообщением. Недопустимые имена и символы не транслитерируются молча.
  - **Ограничения безопасности:** изменения запрещены, пока процессор выполняет программу, контроллер обслуживает команду или образ имеет флаг `readOnly`/`DIRTY`. Если гостевая ОС держит диск смонтированным на запись, сначала корректно размонтируйте его: у гостя могут быть кешированные метаданные. Монитор CPU16 ставит DIRTY = 1 на томе, смонтированном на запись, поэтому файловый менеджер такой том сам не изменит; том, смонтированный монитором только на чтение, менять можно, но монитор увидит изменения только после `umount` и `mount` (или перезагрузки). При сбое посреди изменения ФС16 оставляет `DIRTY=1`, чтобы потребовать проверки тома. После копирования **скачайте полный образ кнопкой «Download» во вкладке «Disks»**, иначе изменения пропадут при закрытии страницы. Браузер не может напрямую записывать файлы в произвольную папку компьютера — экспорт осуществляется скачиванием.
- **Менеджер памяти** — раздел «Memory manager» в панели регистров: бит EN (щелчок переключает), регистры PAGE0..PAGE7 (двойной щелчок — правка) и физический адрес каждой страницы.
- **Часы** — раздел «Clock» в панели регистров: значение часов в виде `ДД.ММ.ГГГГ ЧЧ:ММ:СС` (24-часовая запись), под ним регистры обмена TIME, DATE и ERR с расшифровкой. Двойной щелчок по значению — правка в том же формате; недопустимое значение (например, 29.02.2027 или год вне 2025–2088) не принимается. Кнопка «Host time» ставит местное время компьютера. Правка из отладчика меняет только сами часы: регистры TIME, DATE и ERR принадлежат программе. Часы идут и на паузе, и при пошаговом выполнении: это время, а не тики. При открытии страницы часы показывают местное время компьютера.
- **Память** — кнопка «Logical / Physical» в панели памяти. В логическом режиме дамп идёт через менеджер памяти, как его видит процессор; адреса окна устройств показывают значения регистров без побочных эффектов (событие клавиатуры не забирается) и не редактируются. В физическом режиме — 21-битные адреса всех 2 МБ; «Go to» принимает адрес `$XXXXXX` или метку (её физический адрес по текущему отображению).

Сброс и пересборка сбрасывают экран, очередь клавиатуры, таймер, регистры часов (TIME, DATE, ERR), регистры контроллера дисков и менеджер памяти (выключен, PAGE = 0). Подключённые диски и ход часов остаются.

## Скачивание

Кнопка «Download .zip» отдаёт архив с `.asm`, `.bin`, `.lst` и `.map` (карта памяти в формате `cpu16asm -m`). Кнопка «Open .map» загружает такую карту к образу `.bin`: метки и константы появляются в дизассемблере. В опубликованной на claude.ai странице это делается через возможность платформы `downloads` (зритель подтверждает сохранение; `.asm` и `.bin` по отдельности платформа не разрешает, поэтому архив). Если страница открыта как локальный файл, работает обычное скачивание браузера.

## Переход на WebAssembly

Интерфейс общается с движком только через контракт, описанный в комментарии в `debugger.template.html`. WebAssembly-сборка `cpu16.cpp` должна реализовать тот же объект. Тогда её можно подставить вместо `Cpu16Engine`, и `test_engine.js`/`test_ui.py` сразу проверят её на тех же сценариях. Так же можно заменить `Cpu16Assembler` сборкой `cpu16asm.cpp`: интерфейс использует только `assembleText`, `diags`, `image`/`owner`, `listing`, `memoryMap`, `symbols` и `lineMap`.

### Проверка загрузки с диска (автономный архив)

В каталоге `disk.img/` архива лежат исходный `rom.bin` и системный `system.img`.
Проверить загрузку без стороннего C++-ассемблера можно из каталога `webdbg/`:

```sh
node tests/test_boot_engine.js
python3 tests/test_boot_ui.py
```

Для второго теста нужен Playwright с Chromium.
Для повторной сборки автономного `cpu16_debugger.html` используйте `python3 build_local.py`; в полном исходном дереве CPU16 доступен также `python3 build.py`.
